# 竞品功能矩阵 · 简电云 OCPP 充电运营管理平台

> 采集时间：2026-07-29 · 采集方式：**运营端后台真实菜单树导出**（非公开资料推测）
> 来源系统：`https://jdy-gocpp-dev.nat.ujtek.cn/platform/`（广州优匠科技 ujtek.cn 的 dev 环境，用户自有账号会话）
> 采集手段：AngularJS 应用作用域 `permissionMenu` 全量导出（含 L1/L2/L3 + 中英文名 + 路由 state + 子页面 `sub_links`）
> 采集账号角色：平台方（`包年` 套餐），**菜单为该角色可见范围**——更高权限或其他角色可能另有菜单，本表不代表产品全集。

## ⚠️ 三条使用前提（影响一切对比结论）

1. **这是 OCPP 充电桩产品线，不是共享充电宝产品线。** 平台名即「简电云 **OCPP** 充电运营管理平台」，业务对象是**站场 / 充电桩 / 充电枪 / 充电订单 / 车辆**，不是柜机/充电宝/借还订单。优匠两条线同构但不同实例。
2. 因此**不能逐行等价对标**我们的 [运营端功能清单 §三](../../requirements/运营端功能清单.md)。可对标的是**结构与经营模型**（分成链路、财务分账、设备台账、告警、结算），不可对标的是**业务名词层**（枪/桩 vs 仓位/充电宝）。
3. 与我们的 [ADR-014 设备类型抽象](../../technical/ADR/) 高度相关：对方用**同一套后台**承载充电桩业态，正是我们"充电宝/充电桩双业态"抽象要面对的形态。

## 二、结构观察（先于逐项比对的判断）

| 观察 | 说明 |
|---|---|
| **三级导航同构** | 域(L1 图标栏) → 模块(L2) → 子功能(L3)，与我们 Rail→面板→叶子完全同构；印证我们导航层级选型没跑偏 |
| **角色链 = 平台 → 运营商 → 商户 → 会员** | 佣金、财务两个域都**按角色切三份**（运营商/商户/会员各一套流水与提现），是典型多级分销结构 |
| **分成建模在「站场」而非「合同」** | 站场分成 + 商户分成两个菜单挂在站场管理下，没有独立的场地方/合同实体——比我们 `场地方→站点→点位 + 进场合同` 两层建模粗 |
| **财务用「流水 + 提现审核」而非复式记账** | 未见账务分录/对账/凭证类菜单；发票只是「发票设置」（税率配置），无开票管理 |
| **支付是明确的国际化重投入** | 7 个支付渠道各占一个菜单（Stripe/Paypal/Braintree/Yedpay/ABA/Selcom），覆盖东南亚(ABA 柬埔寨/Selcom 坦桑)与港澳(Yedpay) |
| **OCPI 平台对接是充电桩独有** | EMSP 平台/角色/Token/订单/日志 + POS/Kiosk 终端——漫游互联，充电宝业态无对应物 |
| **无工单/运维闭环** | 只有告警记录 + 告警通知 + 问题管理，**没有派单/接单/处理/验收**；运维靠告警通知人工消化 |
| **无营销体系** | 该角色菜单下只有充值套餐 + 免费用户/免费订单，**无优惠券/活动/会员等级/裂变/广告**（与公开资料宣称的"月卡/积分商城"不符，可能属充电宝线或其他角色） |
| **权限模型简单** | 只有「用户管理 + 角色管理」两项，无组织架构、无数据权限、无操作审计菜单 |
| **有而我们没有的经营对象** | 车辆品牌/车辆管理（电车业态）、RFID 卡号、充电电量、银行管理、短信记录/拉黑、预约订单与预约调价 |
