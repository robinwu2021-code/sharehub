## 二、关键特征

| 特征 | 判断 |
|---|---|
| **全球版做法明确** | 区号选择器、邮箱绑定、密码+验证码双登录、登录页语言切换——都是出海标配，与我们 MENA 定位同路 |
| **首页是 Hub 不是列表** | 公告 + 进行中订单常驻 + 附近门店 + 扫码 CTA 四件套 |
| **申诉链路完整** | 疑问反馈 → 问题详情 → 投诉商家，且运营端有对应的「投诉订单」列表承接——**端到端闭环**，我们目前只有 toast |
| **合规动作齐** | 注销账户 + 隐私政策独立成屏（PDPL/GDPR 硬需求）|
| **买断/封顶是一等状态** | 不是价格展示，而是订单的独立状态 + 动作 |
| **原型中没有** | 换肤/明暗、多主题、优惠券、会员、钱包、裂变、蓝牙——这些是我们 c-app 超出原型的增强 |

## 三、我们的对齐结论（已落地）

该原型的差距盘点与对齐方案已成文：[TDD-c-app-v2-alignment.md](../../technical/TDD-c-app-v2-alignment.md)。用户 2026-07-13 决策：
1. 注册**两者都要**（OTP 静默建户 + 显式注册填信息）
2. **密码 + OTP 双登录**（含忘记/修改密码）
3. 附近门店用**真实 Google 地图**
4. 锁定全量功能骨架 + UI
5. 保留我们超出原型的增强（3 皮肤×明暗、中英阿 + RTL、券/会员/钱包、组件库/动效）不回退
