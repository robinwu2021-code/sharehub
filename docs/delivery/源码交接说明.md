# 源码与依赖交接说明

日期：2026-10-29　·　对应运营方原始需求 DLV-14

> 目的：把「交接时拿到本仓库就能独立构建、部署、运维」需要的东西列全，并标出**不随本仓库移交**、需要在合同里写清的部分。

## 一、本仓库（powerbank）包含

| 目录 | 内容 |
|---|---|
| `backend/` | Spring Boot 4 / Java 21 后端（`sharehub-app` 单体 + 各业务模块），Flyway 迁移 `V*__*.sql` |
| `ops-web/` | 运营端与商家门户（Next.js 静态导出） |
| `c-app/` | C 端（uni-app，H5 / 小程序） |
| `deploy/` | 腾讯云部署 README、systemd、nginx、cron、`ops/` 备份与恢复演练脚本、OpsKit 部署说明 |
| `docs/` | 需求、技术方案、ADR、接口契约 `api/contract.json`、上线检查清单、本交付目录 |

## 二、**不随本仓库移交**的依赖（需在合同中写清）

| 依赖 | 是什么 | 不移交的后果 | 建议的处理方式 |
|---|---|---|---|
| **neargo-framework** 私有仓库 | 后端底座：`neargo-common-core / -security / -data` 等（Maven 坐标 `ai.neargo:*`） | **后端无法编译**：Maven 拉不到这些包 | 移交源码，或把构建产物发布到运营方自己的 Maven 仓库，并约定后续升级方式 |
| **ai-shop** 托管的服务 | 支付（ai-shop pay，ADR-025）、定时任务服务、会话方案 | 收款、定时任务不可用 | 写明服务等级、迁出方案与费用；若要独立运行，需要单独立项迁移 |
| **OpsKit** | 审批流与工单服务（独立 jar） | 审批与工单不可用 | 移交 jar 或源码，以及 `bootstrap.yml` 与各项密钥的生成和轮换方法 |
| 部署机 | 与 ai-shop 共用的腾讯云主机 | — | 见《第三方服务与持续费用》 |

## 三、构建与运行（交接验收时按此走一遍）

```bash
# 后端：需要能访问 neargo-framework 的 Maven 仓库
cd backend && mvn -q install -DskipTests && mvn -pl sharehub-app test
# 运营端
cd ops-web && npm ci && npx vitest run && npm run build
# 前后端接口对齐检查
python3 backend/scripts/api-extract.py && python3 backend/scripts/api-align.py --strict
```

验收标准：后端全量测试与运营端测试全部通过、对齐检查通过（截至 2026-10-29：后端 894+、运营端 1475）。

## 五、约定与护栏（继续开发前必读）

- 仓库根目录的 `CLAUDE.md`：规定了设计规范、日志规范、并发开发纪律。
- 约束测试：后端约 30 类「只准变短」的台账测试，运营端还有设计 token、漂移检查等棘轮测试。新代码不得让台账变长。
- **未确认的业务取值一律做成系统参数**：带类型、可选值、范围与「待拍板」标记（V191），管理员可在「系统设置 › 系统参数 › 只看待拍板」里统一调整。
