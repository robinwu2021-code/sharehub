> 交接日期：2026-10-30。代码基线：`main@222670341687095472ee99362e865f42053aafef`，已推送 `origin/main`。本交接覆盖此前未完成的运营端 Web 功能、库存微服务接入，以及相关后端和测试依赖。本文不表示全系统已完成或已具备生产发布条件。

接手人员应先完成契约核对与库存调用收口，再分模块交付 Web 页面。现有界面、HTTP 路径、模拟数据和数据库结构不等同于业务闭环；禁止以“按钮可点”“返回 200”或“mock 可演示”作为完成标准。

## 1. 已确认的产品和架构边界

1. **库存相关功能默认调用 ai-shop 独立库存微服务 SERVICE。** 现有代码仍默认 LOCAL，默认路由调整尚未实施。远端故障时不得自动写本地库存，历史操作按冻结的执行端恢复。
2. **不设置独立人工业务设备注册前置步骤。** 收货时在库存服务登记物料与 SN；设备专属检测、安装或通信接入需要时自动建立/复用本地业务身份。不能先要求在本地设备台账建档才能采购收货。
3. **powerbank 保留设备业务。** 商家/站点/点位、安装、上线门禁、心跳、指令、柜槽、租借归还、现场维修和撤机属于本地业务，不将它们变成库存入出库。
4. **库存服务持有库存事实。** 仓内 SN、余额、库存单据、过账、盘点和交接由微服务负责。本地只保存必要映射、业务关联、只读投影、调用意图和恢复证据，不再建设第二套库存权威账。
5. **需要审核的统一依赖 OpsKit。** 本地不再新增审核列表或审核引擎；审批状态与实际执行状态分开显示。主分支已包含盘点统一审核的实现，但真实依赖发布与联调仍待完成。
6. **仓内质检目标归库存服务，本地负责设备检测执行。** 当前仓内质检仍在本地，完整远端任务/模板/证据/结论合同需核实，不得把目标当已实现接口。
7. **出库必须选择商家；安装按商家筛选已出库设备。** 查询候选不扣库，领取由远端原子裁决，安装/上线不再次扣库。实际退仓走 RETURN 实收，不将 release+revoke 当成通用退仓。
8. **完整采购订单暂归采购业务，收货记账归库存微服务。** 尚未证实远端提供完整采购合同、价格和交期管理；不能为“默认微服务”虚构采购 API。

调用链：

```text
库存 Web → powerbank Controller → 接入 Service（权限/范围/映射/恢复）
        → InventoryApi → HttpInventoryApi → 库存微服务公开业务 API

设备 Web → powerbank Controller → 本地设备/工单/网关/租赁 Service

审批 Web → OpsKit 反代 → 统一审批
        → 签名 webhook → 本地决定处理/执行任务 → 库存微服务
```

库存系统凭证只保存在服务端；浏览器不直接调库存业务或管理 API。OpsKit 页面已有其自身的反代路径，不要求改成经库存 Controller。

## 7. 接手环境与已知依赖

### 7.1 前端

以 `ops-web/lib/api/http-client.ts` 和 `.env.local.example` 为准；旧 README 仍有历史目录/配置描述，不能照抄 `NEXT_PUBLIC_API_BASE=/api` 导致双 `/api`。

```sh
cd ops-web
npm ci
# 真后端同源反代：NEXT_PUBLIC_API_BASE 留空
# 本地跨源：填后端 origin，例如 http://localhost:8080，不带 /api 后缀
NEXT_PUBLIC_USE_MOCK=0 NEXT_PUBLIC_API_BASE=http://localhost:8080 NEXT_PUBLIC_FLOW_API=http npm run dev
```

OpsKit 还需按实际环境配置 workspace/account 和反代/认证；生产脚本在 `scripts/deploy-frontend.sh` 有现有约定，不复制本机账号或明文凭证到新环境。`NEXT_PUBLIC_USE_MOCK` 只在明确为 `0` 时走真实业务后端，`NEXT_PUBLIC_FLOW_API=http` 才是真实流程；两个开关分别核验。NEXT_PUBLIC 变量在构建期生效，改服务环境变量不等于已生成的静态站点自动切模式。
