# 代码结构（Code Structure）

> 状态：活文档 · 最近更新 2026-07-12
> 配套：[实现状态总表](./实现状态总表.md)（进度）· [architecture](./architecture.md)（架构决策）

> 🔤 **平台定名 ShareHub**（[ADR-014](./ADR/ADR-014-平台更名ShareHub与设备类型抽象.md)）：平台承载共享充电宝/充电桩/储物柜等**多类共享设备**，`dev`/`gw` 层本就设备无关。**目标命名** `ai.neargo.sharehub.*`、`sharehub-app`、仓库 `ai/sharehub`；powerbank 降级为一个 `device.powerbank` 设备类型模块。**本文仍描述现名 `ai.neargo.powerbank`**——机械重命名待与并行会话协调后一次性切换（DB schema `pb_core` 与表名前缀不变）。下文出现 `powerbank` 处，迁移后一律读作 `sharehub`。

仓库根 `powerbank/`（→ `sharehub/`）四个平级目录：`backend/`（服务端）· `ops-web/`（运营端前端）· `cend/`（C端前端）· `docs/`（文档）。

```
powerbank/
├── backend/            Spring Boot 4 / JDK21 单体 powerbank-app（模块化单体 ADR-001/010）
├── ops-web/            Next.js 运营端（App Router）
├── cend/               uni-app C端（Vue3，App + 微信小程序）
└── docs/               需求 / 技术 / API 文档（开发合同）
```

---

## 一、backend（`backend/powerbank-app`）

`ai.neargo.powerbank` 包，**按领域分包 + 横切分包**。分层：`Controller`（薄：路由 + `@PreAuthorize` + 编排）→ `Service`（业务规则，经 SecurityUtils 取上下文，不判功能权限）→ `Mapper/Entity`（MyBatis-Plus）→ MariaDB `pb_core`。三层逐域现状与缺口对照见 [后端三层架构梳理](./后端三层架构梳理.md)。

```
ai/neargo/powerbank/
├── PowerbankApplication.java
│
├── common/                     统一契约与兜底（envelope 复用 neargo-common-core，M3）
│   ├── ApiResponseWrapper          ResponseBodyAdvice → neargo Result.ok(body)（{code,message,data}）
│   ├── Pages                       内存分页 → neargo PageResult（{total,list}）
│   ├── BaseEntity                   ★实体基类：自增 Long 物理主键 + tenant_id + 审计 + 乐观锁 + 逻辑删除（agt/dev/wo 继承）
│   ├── GlobalExceptionHandler      返 Result；保留 IllegalArgument→400 / AccessDenied→403 / 其它→500
│   └── Kw                           关键词命中助手
│   （业务键 <x>No 复用 neargo IdGenerator；物理主键库内自增不对外）
│   （已退役自有 ApiResult/PageData，改用 ai.neargo.common.core.Result/PageResult）
│
├── auth/                       ★横切：认证 / 鉴权 / 数据范围（权限对话产出）
│   ├── SecurityUtils               业务层唯一上下文入口（realm 无关薄门面）
│   ├── LoginUser / Realm           统一 principal（hasPerm 通配镜像前端 can()）
│   ├── SessionStore                token→LoginUser（内存）
│   ├── StaffContext / ConsumerContext   运营端 / C端 分离门面
│   ├── StaffTokenAuthFilter / ConsumerTokenAuthFilter
│   ├── RolePerms / PermChecker      角色→权限码（静态，@perm.can 通配）
│   ├── DataScope / ScopeDim / DataScopeResolver
│   ├── DataScopeHandler             MyBatis 数据权限（仅返回追加条件段）
│   ├── DataScopeTableRegistry       锚点列注册（现仅 loc_site）
│   ├── DataScopeContext             runAsSystem 豁免
│   └── AuthController               /api/auth/{login,me,logout}
│
├── config/
│   ├── SecurityConfig               双安全链（@Order1 /mp · @Order2 运营端）
│   └── MybatisPlusConfig            数据权限→分页→乐观锁拦截器 + @MapperScan
│
├── seed/SeedData.java          内存种子（镜像 ops-web mock 数据量；*Seeder 灌库）
├── dto/Dto.java                嵌套 record（镜像 ops-web/lib/types.ts），复用为 VO+入参
│
│   ── ★接入层 portal/（端分离，[TDD-接入层分端与common复用](./TDD-接入层分端与common复用.md) M1 已归位）──
├── portal/ops/                 运营端 controller（/api、/internal；StaffContext+@PreAuthorize RBAC+DataScope）
│   ├── OpsController               /api/ops：dashboard + 转 dev/wo/loc service（设备/工单/场所）
│   ├── TradeController          🟡 /api/trade：订单/计费/财务（内存，未分层）
│   ├── UserController          🟡 /api/user/* + /internal/user/credit/blacklist（内存）
│   ├── PlatformController      🟡 /api/platform：employees/roles/audit-logs（内存）
│   ├── VendorController        🟡 /internal/gw/vendors（内存）
│   └── AgentController            /api/agent/agents → agent 域服务
├── portal/ops/  ...            + TradeInternalController（/internal/trade/orders/{no}/return 归还结单）
├── portal/mp/                  C端 controller（/mp/**；ConsumerContext 属主鉴权，无 RBAC）
│   ├── ConsumerAuthController      /mp/auth/{login,otp,logout} → user.consumer 域服务（路径待 M4 对齐 README）
│   ├── RentController              /mp/trade/orders/{rent,,/{no}} → trade 域（借出/我的订单/详情，属主鉴权防 IDOR）
│   └── MpController                /mp/user/profile · /mp/orders/{ownerNo}（读）
│
│   ── 领域核心（端无关，两端共享；✅=四件套已分层落库）──
├── loc/  ✅   entity{Site,Location,Venue,Contract} · mapper/LocMappers · LocService · LocSeeder
├── agent/ ✅  entity/AgtAgent · mapper/AgentMapper · service(+impl) · AgtSeeder
├── dev/  ✅   entity/DevCabinet · mapper/CabinetMapper · service(+impl，派生仓位) · DevSeeder
├── wo/   ✅   entity/WoOrder · mapper/WoMapper · service(+impl) · WoStateMachine(独立状态机) · WoSeeder
├── trade/ ✅  entity/OrdRent · mapper/OrdMapper · service(RentOrderService+impl) · OrdStateMachine(独立) · TradeSeeder(120单)
└── user/                       用户域核心
    ├── entity{UsrUser,UsrIdentity} · mapper/UserMappers   （C端登录落库）
    └── consumer/                    ★C端认证域核心（controller 已移出至 portal/mp）
        ├── ConsumerAuthService       grantType 分发
        └── {PhoneOtp,WechatMiniapp,WechatOauth,Apple,Google}Strategy + OtpService
```

> **接入层分端（M1 已完成，测试 26 绿）**：8 个 controller 按端归位 `portal/ops`（运营端 6）/ `portal/mp`（C端 2），端点路径不变（前端零感知），域包只留 service/mapper/entity 共享核心。后续 M2（拆 Ops/Trade 为按资源多 controller）· M3（envelope 采用 neargo `Result`/`PageResult` 改前端）· M4（C端路径对齐 README + 补 Nearby/Rent/Report）· M5（common 复用 neargo-common-*）见 [TDD-接入层分端与common复用](./TDD-接入层分端与common复用.md)。

**测试**（`src/test`，JDK HttpClient + `@SpringBootTest(RANDOM_PORT)`，Boot4 无 web 测试助手）：
```
├── SmokeTest                        契约冒烟（dashboard/cabinets/vendors）
├── auth/DataScopeAuthTest           数据权限 handler 纯单测（无 DB）
├── support/ApiTestSupport           ★HTTP 客户端基类（login/get/post/okData/fixtures）
├── scenario/OperatorDailyFlowTest   运营方日常叙事 E2E（7 步，多角色）
```

**构建/运行坑**（详见 [powerbank-backend 记忆] / [TDD-backend-integration](./TDD-backend-integration.md)）：JDK21 强制（enforcer 锁 [21,22)）；`mybatis-plus-extension` 须显式加（starter 不传递）；JDBC `characterEncoding=UTF-8`（非 utf8mb4）。

## 二、ops-web（运营端，Next.js App Router）

```
ops-web/
├── app/                        页面（每目录一 page.tsx）
│   ├── login · (root=看板) · devices · devices/detail · locations · agents
│   ├── orders · finance · pricing · marketing · users · work-orders
│   ├── employees · system/vendors
├── lib/
│   ├── api/{index,http,http-client,mock,contract,types}   ★唯一切换点 USE_MOCK
│   ├── permissions.ts          角色→权限码（与后端 RolePerms 同源，后端为权威）
│   └── auth.ts                 Role 定义
```
- **API 切换**：`api/index.ts` `export const api = USE_MOCK?mock:http`；`.env.local` `NEXT_PUBLIC_USE_MOCK=0` + `NEXT_PUBLIC_API_BASE=http://localhost:8080` 联调真后端。
- http.ts 端点严格对齐后端（`/api/ops/*`、`/api/trade/*`、`/api/agent/agents`、`/api/platform/*`、`/internal/*`）。

## 三、cend（C端，uni-app Vue3）

```
cend/src/
├── pages/                      P0 页面（tabBar：找柜/订单/我的）
│   ├── index(找柜+扫码) · login · order/confirm(借出) · order/detail(进行中+归还)
│   ├── orders(我的订单) · profile(钱包+信用+RTL) · report(报障)
├── api/{index,http,http-client,mock,contract,types}   ★唯一切换点（同 ops-web 心智）
├── config.ts                   USE_MOCK / API_BASE
└── (Pinia auth 持久化 · vue-i18n en/ar RTL · UnoCSS)
```
- **现状**：H5 借还闭环跑通但基于 **mock**（`VITE_USE_MOCK=1`）。后端 `/mp` 业务端点大多未落地，且前端路径（`/mp/user/login`、`/mp/trade/orders/rent`、`/internal/trade/orders/{no}/return` 等）与后端现有 `/mp/auth/*`、`/mp/orders/{ownerNo}` 不完全一致 —— 见 [实现状态总表 §四](./实现状态总表.md) 与 [TDD-cend-bff](./TDD-cend-bff.md)。
- **坑**：UnoCSS ESM 与 uni CJS 冲突 → vite.config 动态 `import`；勿加 `"type":"module"`。
