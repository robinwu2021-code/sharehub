# 库存服务 · 宿主接口需求（powerbank → ai-shop 独立进销存）

> 2026-10-30 · 提出方：powerbank 运营端库存接入（[开发方案](运营端库存接入-开发方案.md)）· 接收方：ai-shop 独立进销存
>
> powerbank 按[设备全生命周期 Web 与服务对接明细](设备全生命周期-Web与服务对接明细.md)逐节点把库存改成以独立进销存为准（默认 SERVICE，故障不回落本地）。我方已对 ai-shop `codex/ai-shop-codex@c30b10189` 的 inventory-svc 宿主路由（`/api/inventory/v1`）逐个核对，本机 8088 联调实例与该提交契约一致。
>
> 下列能力在源码与宿主路由里都没有，或只在领域层、没有宿主 API。**不要求按这里的写法实现，只要能力**；请对每项回复「做 / 不做 / 用现有能力怎么做」与大致时间。现有路由请保持兼容。

## 按我方开发顺序

| # | 批次 · 节点 | 需要的能力 | 现状（c30b10189） | 我方在拿到之前怎么做 |
|---|---|---|---|---|

| 2 | T2 · A08 仓内质检 | 任务、模板、证据、结论（目标归库存服务） | 无 | 质检留本地，只用第 1 项衔接 |
| 3 | T2 · A01 仓库 | 建仓带本系统编码 `externalRef`；停用后重新启用 | **编码已在 60a614575 提供**（建仓收 `externalRef`、列表返回）；重新启用仍没有 | 宿主已改为建仓带仓号、认领先按编码；重新启用仍待 |

| 9 | T5 · E07 / E08 返厂维修 | 暂时送供应商维修后回到原库存（同 SN、同身份），与永久 `RETURN_SUPPLIER` 区分；返回入库能关联原出库 | 无 | 暂不支持返厂维修，只支持永久退供应商 |
| 10 | 确认项 | 盘点状态词表 `COUNTING / SUBMITTED / APPROVED / POSTED / VOIDED` 是否为对外稳定词表 | — | 我方在客户端换算为宿主词表 |
| 12 | **P0** · 生产业态档案 | 生产档案 `sharehub.json` 的用途补齐宿主在用的：入库 `TRANSFER_IN`，出库 `TRANSFER_OUT`、`REQUISITION`（物料领用）。另请确认 `OPENING` 要求附件时，宿主的「期初依据」文字之外怎么交附件（附件引用的来源） | 夹具只有入库 PURCHASE / OPENING / RETURN / CORRECTION / COUNT_GAIN、出库 ISSUE / SCRAP / RETURN_SUPPLIER / COUNT_LOSS；宿主本机业主是自开的档案才跑得通 | 照生产档案开户，调拨与物料领用会被拒；期初入库会因缺附件被拒 |
| 13 | 缺陷 · 入库 `basis` | `basis` 超过列宽（varchar(32)）时返回 400 并说明长度，而不是 500 | 实测超长 `basis` 直接 500（`Data too long for column 'basis'`）；另请在 API 文档写明 basis 是依据编号、≤ 32 | 宿主只传编号（入库单号 / 物料单号 / `MIGRATION`） |
| 14 | 缺陷 · 升级后幂等键冲突 | 命令指纹在请求体**新增可空字段**后保持不变（按规范化后的非空字段算，或带契约版本），否则升级前用过的键在保留期内一律 `inventory.command.conflict` | 实测：M9（`1726ee1ce`）给 `PUT /external-targets` 加了 `linkedOwner` / `linkedLocationRef`，升级前写过的同键请求在新版上 409；宿主出库全部被拒 | 宿主把主数据 upsert（物料、目标）改为每次新键（按 ref 的 PUT 本身幂等）。业务单据的键仍是稳定键，靠「升级时不重放旧键」，请对方保证 |
| 15 | 客户端 · `InventoryClient` 补齐宿主在用的接口 | `Session` 增加：仓库改名 / 停用（`PATCH /warehouses/{id}`、`/disable`）、业务放行（`/inbounds/{no}/business-clearance`）、按内部号查余额与在仓 SN（或保证所有库位都有 `externalRef`）、出库池其余筛选（`targetType` / `targetRef` / `outboundNo` / `itemId`）、释放领取（`/claims/{no}/release`）、出库调整（`/dispatch-pool/{id}/redirect`）、按请求号查领取（`/claims/by-request/{id}`）、流水（`/ledger`）、盘点全套（开单 / 详情 / 扫码 / 数量实盘 / 提交 / 审批 / 驳回 / 过账 / 作废）、期间汇总（`/reports/period-summary`）。另请：① 规格支持宿主自带拦截器（我方要发 `X-Trace-Id`）；② 认不出的错误码按原 HTTP 状态抛，不要一律算 `UNAVAILABLE`；③ 发布到 Nexus（U13） | 862bf06d4 的 `Session` 只覆盖主数据、入出库、调拨、成对单、出库池（状态 / 商家 / SN）、领取、撤回、查询、事件、命令 | 宿主已切到客户端：覆盖到的走 `Session`，其余仍直连同一地址与凭证；规格自己拼（挂链路号），走 `InventoryClient.of` |
| 11 | T2 · B04 库存流水 | `GET /ledger` 支持倒序（beforeId 游标或 order=desc）并返回总数 | 只有按 id 升序、afterId 往后翻，每次最多 500 条，无总数 | 按游标读全再倒序分页；超过 1 万条报错要求加筛选 |
