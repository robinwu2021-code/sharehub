## 〇、口径（一页）

| # | 裁决 | 技术含义 |
|---|---|---|
| U1 | 绑定商家**先出库**；出库必须选商家；绑定的设备一律从该商家的**出库池**里选 | 设备上新增「出库给了哪个商家」；调拨终点新增「商家」；绑定端点校验出库池归属 |
| U2 | 默认绑到商家的**默认站点、默认点位** | 默认站点已有（8271deaa）；**每个站点建站时同事务建默认点位** |
| U3 | 商家可以有**多个站点、多个点位** | 运营为商家建站点的端点；建站同事务写归属、责任行、默认点位 |
| U4 | 站点就是门店；**商家端叫「我的站点」**，全系统不再引入「门店」一词 | 门户菜单加「我的站点」；文案统一 |

**不变的规则**：商家归属只挂在站点上；点位、机柜、订单上的 `agent_no` 都从站点派生，由服务端同一个方法写；站点的商家 = 站点上生效的 `OPERATE` 责任方，两者同事务写。

## 二、数据库设计

> 约定：新列可空、带注释；状态类列加 CHECK；「只能有一个」用生成列 + 唯一键（MySQL / MariaDB 都支持，避开可空唯一键失效）。迁移按表拆，编号 V160 起。

### 2.1 `dev_cabinet` · `dev_powerbank`：出库池归属

```sql
ALTER TABLE dev_cabinet
  ADD COLUMN issued_agent_no    VARCHAR(36) NULL COMMENT '出库池归属：出库给了哪个商家；退回仓库 / 撤机回仓签收后清空',
  ADD COLUMN issued_at          DATETIME(3) NULL COMMENT '进入出库池的时刻（出库单签收）',
  ADD COLUMN issued_transfer_no VARCHAR(36) NULL COMMENT '出库单号',
  -- 数据范围锚点：已绑定看 agent_no，未绑定看出库池 —— 商家在「我的设备」里能看到待安装的设备
  ADD COLUMN scope_agent_no VARCHAR(36)
      GENERATED ALWAYS AS (COALESCE(agent_no, issued_agent_no)) STORED COMMENT '数据范围锚点（派生）',
  ADD KEY idx_cab_issued (tenant_id, issued_agent_no, status),
  ADD KEY idx_cab_scope2 (tenant_id, scope_agent_no, status),
  -- 在仓与在出库池互斥
  ADD CONSTRAINT chk_cab_pool_vs_wh CHECK (warehouse_no IS NULL OR issued_agent_no IS NULL),
  -- 绑定了点位就必须在某个商家的出库池里（平台直营站点例外：见 2.6）
  ADD CONSTRAINT chk_cab_bound_issued CHECK (location_no IS NULL OR issued_agent_no IS NOT NULL OR agent_no IS NULL);

ALTER TABLE dev_powerbank
  ADD COLUMN issued_agent_no VARCHAR(36) NULL COMMENT '出库池归属（随柜出库或单独补货出库）',
  ADD COLUMN issued_at       DATETIME(3) NULL,
  ADD KEY idx_pb_issued (tenant_id, issued_agent_no, status);
```

- **存储态不扩**：出库池里的柜子仍是 `IN_STOCK`（`warehouse_no` 为空、`location_no` 为空）。展示态「已出库待绑定」「已绑定待安装」由列派生（生命周期设计 §3.1）。
- **数据范围**：`dev_cabinet` 的锚点从 `agent_no` 改为 `scope_agent_no`（`DataScopeRegistration` 一行改动）；`dev_powerbank` 按 `COALESCE(柜子的商家, issued_agent_no)` 登记——宝没有 `agent_no` 列，建议同样加生成列，或按所在柜子关联（数据范围拦截器只认本表列，倾向加列）。
- 存量回填：已绑定的柜子 `issued_agent_no = agent_no`（不为空时）；在仓的为空。

### 2.2 `inv_transfer`：出库到商家、退回仓库

```sql
ALTER TABLE inv_transfer
  ADD COLUMN reason_code VARCHAR(24) NULL COMMENT 'ISSUE 出库给商家 / POOL_RETURN 出库池退回 / REBALANCE / REMOVAL_RETURN / REPAIR_SEND / REPAIR_RETURN / RETURN_VENDOR / OTHER',
  ADD COLUMN reason_note VARCHAR(256) NULL,
  ADD CONSTRAINT chk_transfer_status CHECK (status IN ('DRAFT','IN_TRANSIT','DONE','CANCELLED')),
  ADD CONSTRAINT chk_transfer_from_type CHECK (from_type IS NULL OR from_type IN ('WAREHOUSE','SITE','LOCATION','AGENT')),
  ADD CONSTRAINT chk_transfer_to_type   CHECK (to_type   IS NULL OR to_type   IN ('WAREHOUSE','SITE','LOCATION','AGENT'));

ALTER TABLE inv_transfer_item
  ADD UNIQUE KEY uk_transfer_cabinet (transfer_no, cabinet_no),
  ADD UNIQUE KEY uk_transfer_powerbank (transfer_no, powerbank_no);
```

| 单据 | `from_type / from_ref` | `to_type / to_ref` | `reason_code` |
|---|---|---|---|
| 出库给商家 | `WAREHOUSE / 仓号` | `AGENT / 商家号` | `ISSUE` |
| 出库池退回仓库 | `AGENT / 商家号` | `WAREHOUSE / 仓号` | `POOL_RETURN` |
| 撤机回仓（已有，自动） | `SITE / 站点号` | `WAREHOUSE / 仓号` | `REMOVAL_RETURN` |

`AGENT` 终点替代 S10 §五 #2 建议里的「终点只到仓」：**出库到商家、具体站点在绑定时选**（一批货可以分给同一商家的几个站点）。站点 / 点位终点保留给存量单据只读，新建不再允许（前端下拉去掉，后端新建 400）。

### 2.3 `loc_location`：默认点位、归属

```sql
ALTER TABLE loc_location
  ADD COLUMN is_default TINYINT(1) NOT NULL DEFAULT 0 COMMENT '站点的默认点位（建站时自动建）',
  ADD COLUMN default_key VARCHAR(36)
      GENERATED ALWAYS AS (IF(is_default = 1 AND deleted = 0, site_no, NULL)) STORED,
  ADD UNIQUE KEY uk_loc_default (default_key);          -- 每个站点至多一个默认点位
-- 存量：每个站点补一个默认点位；agent_no 按站点回填（今天建点位从不写它）
```

### 2.4 `loc_site`：商家站点

不加列。`agent_no` 已有；**建站时同事务写 `agent_no` + `OPERATE` 责任行 + 默认点位**（与默认站点同一个方法）。商家站点允许不填 `venueNo`、`regionId`（D10：场地方一期只记录；默认站点今天就是这么建的）。

### 2.5 `agt_assignment`

不改表。`target_type` 的 `CABINET / LOCATION` 停止新写入（存量流水保留），只剩 `SITE` = 整站换商家。

### 2.6 不变式（服务端强制，测试覆盖）

| # | 不变式 | 落在哪 |
|---|---|---|
| I1 | 在仓（`warehouse_no` 有值）与在出库池（`issued_agent_no` 有值）互斥 | CHECK `chk_cab_pool_vs_wh` |
| I2 | 绑定的点位所属站点的商家 = `issued_agent_no` | 绑定端点；装机完工改绑同一方法 |
| I3 | `agent_no` 只由点位派生 | 绑定 / 改绑 / 站点换商家级联共用一个方法；请求体里的 `agentNo` 一律忽略（今天已是） |
| I4 | 一台设备同一时刻只在一张未完结出库单上 | 出库单加明细时校验；S10 OPT-S10-04 |
| I5 | 平台直营站点（`agent_no` 为空）的设备不经出库池 | 直营：从仓直接绑定直营站点（`issued_agent_no` 留空）；CHECK `chk_cab_bound_issued` 放行 |

### 3.3 出库池

| 方法 | 路径 | 新增筛选 | 新增出参字段 |

### 3.4 绑定 / 解绑

| 方法 | 路径 | 权限 | 入参 → 出参 |
|---|---|---|---|
| POST | `/api/ops/devices/{deviceNo}/bind` | `device:cabinet:update` | `BindReq {locationNo?, openInstallWo?: boolean, expectedAt?}` → `BindResult {cabinet, woNo?}` |
| POST | `/api/ops/devices/bind-batch` | 同上 | `{agentNo, locationNo?, deviceNos[], openInstallWo?}` → `BindResult[]`；**一个事务**，任一失败整批回滚，`data` 列出 `{deviceNo, code}` |
| POST | `/api/ops/devices/{deviceNo}/unbind` | 同上 | `{reason}`；仅「已绑定、未上线」；回到同一商家的出库池 |

- `locationNo` 缺省：取 `issued_agent_no` 商家的**默认站点的默认点位**（`agt_agent.default_site_no` → `loc_location.is_default`）。
- 校验：设备在库、未上线；`issued_agent_no` 有值（直营站点例外 I5）；点位所属站点的商家 = `issued_agent_no`，否则 409 `error.bind.agent_mismatch`；点位 `ACTIVE`。
- 写入：`location_no`、`location_name`、`site_no`、`agent_no`（派生）、`bound_at`；`openInstallWo = true` 时同事务建 `INSTALL` 工单（`cabinetNo`、`locationNo`、`siteNo`、`agentNo` 由服务端填）。
- **`POST /api/ops/cabinets/{no}` 的 `locationNo` 停止受理**（带了 400 `error.device.bind_via_action`），绑定只经本端点；装机完工改绑调同一个服务方法，同样校验 I2。

### 3.5 撤机去向

`POST /api/ops/work-orders`（`type = REMOVE`）入参加 `disposition`：`RETURN_TO_POOL`（同商家换点位 / 换站点）· `RETURN_TO_WAREHOUSE`（退出、维修、返厂），默认后者。完工监听器：

| `disposition` | 设备 | 调拨 |
|---|---|---|
| `RETURN_TO_POOL` | `undeploy`：清点位与派生的 `site_no / agent_no`，**保留 `issued_agent_no`** → 回到出库池 | 不生成 |
| `RETURN_TO_WAREHOUSE` | 同上清点位；`issued_agent_no` 签收回仓后清 | 自动生成回仓单（`REMOVAL_RETURN`，今天已有） |

撤机原因写状态日志，不再写进 `fault_reason`（S5 P0-6）。
