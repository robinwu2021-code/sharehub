## 零、现状

| 项 | 现状 |
|---|---|
| 对象存储 | **仓库里没有任何接入**，也没有接收文件字节流（`MultipartFile`）的端点 |
| 合同附件 | `loc_contract_attach` 只存文件名与大小；`POST /api/ops/contracts/{no}/attachments` 收 JSON 元数据，注释写明「接对象存储前不编假地址」 |
| 运营端 | 合同附件抽屉用原生 `<input type=file>`，只记录名字和大小（假上传） |
| 网关 | nginx `client_max_body_size 30m` |

所以这是一块**从零开始**的公共能力，一次建好，所有业务共用。

## 一、为什么经应用服务器上传

「前端拿临时签名直传 COS」是另一种常见做法，这里不用。经服务器上传的好处在本项目里都用得上：

| 好处 | 在本项目里的意义 |
|---|---|
| **密钥永远不出服务器** | 不需要给前端发临时凭证，没有凭证过期、范围配错的问题 |
| **校验只有一处** | 类型、大小、文件头、图片处理都在服务端做；前端的校验只是提示，不是防线 |
| **鉴权与数据范围复用现有链路** | 上传与下载都走 `@PreAuthorize` 与数据范围，代理只能传、只能看自己范围内的文件 |
| **审计与日志统一** | 谁在什么时候传了什么，带 `traceId` 与 `actor`，与其他操作一样可查 |
| **换存储只改一处** | 业务只认 `fileNo`，将来换存储或加一份备份，业务代码不动 |

**代价**：文件字节要多经过一跳服务器。本项目的文件都是文档和照片（单个 ≤ 20MB），量级不大，可以接受。
若以后出现大视频之类的场景，再单独评估，不影响本方案的接口。

## 二、整体链路

```
上传
 浏览器 / App ──multipart──▶ nginx ──▶ sharehub-app  POST /api/platform/files        （运营端、代理门户）
                                                   POST /mp/files         （C 端）
                                        │ ① 鉴权 + 用途校验（category 决定谁能传、传什么）
                                        │ ② 大小 · 扩展名 · 文件头嗅探 · 图片处理
                                        │ ③ 算 SHA-256
                                        │ ④ 以流的方式写入 COS（服务端密钥）
                                        │ ⑤ 写 sys_file（状态 TEMP）
                                        ◀── 返回 { fileNo, name, size, contentType, previewable }

绑定（业务保存时）
 业务请求带 fileNo 列表 ──▶ 业务服务 ──▶ FileService.bind(fileNos, bizType, bizNo)
                                        │ 校验：文件是本人刚传的、状态 TEMP、用途与业务匹配
                                        ◀── sys_file 状态 → BOUND，记下归属对象

下载 / 预览
 浏览器 ──▶ GET /api/platform/files/{fileNo} ──▶ ① 鉴权：按归属对象判断能否查看
                                        ② 普通文件：302 到 COS 预签名 GET（有效 5 分钟）
                                           个人数据：服务端流式转发，不暴露任何 COS 地址
```

**两步式（先传后绑）** 的理由：表单里可以先传照片、后点保存；用户中途放弃时，未绑定的文件由清理任务回收（§六），不会留下「没有主人」的对象。

## 三、用途与策略

每个文件在上传时声明**用途** `category`，用途决定一切策略。不接受「通用上传」。

| 用途 `category` | 谁能传 | 允许类型 | 单个上限 | 图片处理 | 存储桶 | 下载方式 | 绑定到 |
|---|---|---|:-:|---|---|---|---|
| `CONTRACT_SCAN` 合同签署件 | BD（`location:contract:update`） | PDF · JPG · PNG | 20MB | 不处理（原件） | 私有 | 预签名 | 合同 |
| `WO_PHOTO` 工单现场照片 | 运维 / 代理运维（`workorder:wo:handle`） | JPG · PNG · HEIC | 10MB | HEIC 转 JPG · 长边压到 2560 · **保留拍摄时间与定位** | 私有 | 预签名 | 工单 |
| `SURVEY_PHOTO` 点位勘测照片 | BD / 运维（`location:poi:update`） | JPG · PNG · HEIC | 10MB | 同上 | 私有 | 预签名 | 点位 |
| `LEAD_PHOTO` 选址评估照片 | BD（`location:lead:update`） | JPG · PNG · HEIC | 10MB | 同上 | 私有 | 预签名 | 商机 |
| `AGENT_QUALIFICATION` 代理资质（执照 / 证件 / 银行证明） | 申请人本人（匿名入驻带 OTP 会话）/ 运营代建 | PDF · JPG · PNG | 10MB | 不处理 | **私有 · 个人数据** | **流式转发** | 入驻申请 |
| `CS_EVIDENCE` 用户报障截图 | C 端用户本人 | JPG · PNG · HEIC | 5MB | 转 JPG · 压缩 · **去掉定位等全部 EXIF** | 私有 · 个人数据 | 流式转发 | 报障单 |
| `PUBLIC_IMAGE` 公开图片（品牌 Logo、公告配图、广告素材） | 运营（对应模块的写权限） | JPG · PNG · WebP | 5MB | 压缩 · 去 EXIF | **公开读** | 直接用 CDN 地址 | 品牌 / 公告 / 广告 |

几条硬规则：

- **不收 SVG、HTML、任何可执行或脚本类文件**：它们能带脚本，预览即 XSS。
- **按文件头判断类型**，扩展名和 `Content-Type` 只作参考；三者不一致时拒绝。
- 运维照片**保留**拍摄时间与定位：这正是「人真的到过现场」的证据。C 端截图**去掉**定位：那是用户的隐私。
- 非图片文件下载时带 `Content-Disposition: attachment`，不在浏览器里直接渲染。

## 四、COS 的组织方式

### 4.1 存储桶

| 桶 | 读权限 | 放什么 |
|---|---|---|
| `sharehub-private` | 私有 | 除个人数据与公开图片以外的全部业务文件 |
| `sharehub-pii` | 私有 · 独立密钥 | 个人数据：代理资质、用户报障截图。与 `sharehub_pii` 库同一口径（PDPL） |
| `sharehub-public` | 公开读 · 挂 CDN | 公开图片 |

**单一地域**（2026-09-25 定：不考虑多区域），三个桶与应用服务器同地域，走内网访问。三个桶都开**服务端加密**；私有桶开**版本控制**，防误覆盖。

### 4.2 对象键

```
{category小写}/{yyyy}/{MM}/{fileNo}.{ext}
例：wo_photo/2026/09/FL20260925000123.jpg
```

- **键里不放业务号和原始文件名**：原始名存在 `sys_file`，避免个人信息和奇怪字符进入对象键；
- 键由服务端生成，客户端无法指定，也就无法覆盖别人的文件；
- 按月分目录，便于按用途设置生命周期规则（如工单照片 3 年后转低频存储）。

### 4.3 访问凭证

- 应用服务器用**子账号**的永久密钥（或 CAM 角色），权限只到这三个桶的读写，不给删桶、改桶策略等权限；
- 密钥走配置中心或环境变量，**不进仓库、不进日志**；
- 预签名下载地址含签名，**日志里只记 `fileNo`，不记完整地址**（项目日志规范：不打令牌与凭据）。

## 五、服务端设计

### 5.1 元数据表 `sys_file`

| 字段 | 说明 |
|---|---|
| `file_no` | 业务键，前缀 `FL` |
| `category` | 用途（§三），词表列 |
| `status` | `TEMP` 已上传未绑定 · `BOUND` 已绑定 · `REMOVED` 业务上已移除（软删）· `PURGED` 对象已清理 |
| `biz_type` · `biz_no` | 归属对象（绑定后写入） |
| `original_name` · `content_type` · `size` · `sha256` | 文件属性 |
| `storage` · `bucket` · `object_key` | 存储位置（`storage` 首版只有 `COS`，测试环境为 `LOCAL`） |
| `image_width` · `image_height` · `taken_at` · `geo_lat` · `geo_lng` | 图片信息（仅运维照片保留定位） |
| `uploaded_by` · `uploader_realm` | 上传人与身份域（员工 / 代理 / C 端用户） |
| `agent_no` | 数据范围锚点（代理上传或归属对象属于某代理时写入） |
| 审计列 | `created_at` 等，按现有 BaseEntity |

个人数据用途（`AGENT_QUALIFICATION`、`CS_EVIDENCE`）的元数据行放在 **`sharehub_pii`** 库，其余在 `sharehub_core`。

### 5.2 接口

| 端点 | 说明 | 权限 |
|---|---|---|
| `POST /api/platform/files`（multipart：`file` + `category`） | 上传，返回文件引用 | 按用途映射到对应业务的写权限码（§三「谁能传」列），**不新增权限码** |
| `GET /api/platform/files/{fileNo}` | 下载 / 预览：302 或流式 | 按归属对象的读权限；`TEMP` 状态只有上传人本人可看 |
| `GET /api/platform/files/{fileNo}/thumb` | 图片缩略图（服务端生成、缓存在 COS） | 同上 |
| `POST /mp/files` · `GET /mp/files/{fileNo}` | C 端同上，只开放 `CS_EVIDENCE` | C 端登录态，只能看自己的 |

**不提供删除端点**（契约禁止 `delete*`）。业务上「移除附件」走各业务自己的 `…/remove`，把文件置为 `REMOVED`；
对象本身按保留策略由后台清理（§六）。

业务侧只改请求体：**原来传文件名和大小的地方，改传 `fileNo`**。例：

```
现在：POST /api/ops/contracts/{no}/attachments   { "fileName": "...", "size": 123 }
改为：POST /api/ops/contracts/{no}/attachments   { "fileNo": "FL..." }
```

`loc_contract_attach` 加 `file_no` 列；文件名、大小从 `sys_file` 取，不再由前端声明（前端声明的大小不可信）。

### 5.3 存储端口

```
FileStoragePort            put(stream, key, meta) · presignGet(key, ttl) · openStream(key) · remove(key)
 ├─ CosFileStorage          腾讯云 COS SDK，生产与测试环境
 └─ LocalFileStorage        本机目录，单元测试与离线开发；预签名地址由应用自己签、自己校验
```

- 按项目的依赖倒置惯例：端口由使用方声明，适配器放在应用装配层；业务模块只依赖 `FileService`（上传、绑定、查询）。
- `sharehub.storage.type=cos|local` 切换；**集成测试默认 `local`**，不依赖外网与真实桶。

### 5.4 上传实现要点

| 要点 | 做法 |
|---|---|
| 内存 | multipart 落临时文件，校验后**流式**写 COS，不把整个文件读进内存 |
| 大小限制 | Spring `max-file-size: 20MB` · `max-request-size: 25MB`；各用途的更小上限在业务层再校验；nginx 现有 30MB 足够 |
| 超时 | 上传到 COS 设独立超时与一次重试；失败时不写 `sys_file`，返回可重试的错误 |
| 一致性 | 先写 COS、后写元数据。写元数据失败会留下孤儿对象，由 §六 的对账任务清理 —— 不做分布式事务 |
| 秒传 | 同一上传人、同一用途、同一 SHA-256 在 24 小时内重复上传时，直接返回已有的 `TEMP` 文件 |
| 限流 | 按账号限速（每分钟 30 个），匿名入驻上传复用现有匿名限流过滤器 |
| 日志 | 上传成功记 INFO：`fileNo`、用途、大小、上传人；失败记 WARN 并写明原因与「谁该做什么」（日志规范） |

## 六、清理与保留

| 对象 | 规则 |
|---|---|
| `TEMP` 超过 24 小时未绑定 | 定时任务删除对象、元数据置 `PURGED` |
| `REMOVED`（业务移除） | 保留 90 天后清理（「曾经有过一个附件后来被删了」本身是信息，合同附件的软删注释即此意） |
| `BOUND` | 随业务保留。合同签署件与资质材料**长期保留**；工单照片 3 年后转低频存储 |
| 孤儿对象（COS 有、元数据无） | 每日对账，超过 24 小时的孤儿删除 |
| 账户注销 / 个人数据删除请求 | `CS_EVIDENCE` 与该用户相关的对象一并清理（PDPL 删除权，与 C 端注销流程联动） |

清理任务进 [v4/07 定时任务](./v4/07-定时任务.md) 的清单，首版以进程内任务运行（与 S-JOB-01 同批）。

## 八、安全清单

| 风险 | 对策 |
|---|---|
| 伪装类型（改扩展名的脚本） | 文件头嗅探；三者不一致拒绝；不收 SVG / HTML |
| 越权读别人的文件 | 下载一律经服务端按归属对象鉴权；`fileNo` 不可预测也**不作为鉴权依据** |
| 越权绑定别人的文件 | 绑定时校验上传人即当前操作人、状态为 `TEMP` |
| 预签名地址外泄 | 5 分钟有效；个人数据不发预签名、只流式转发；日志不记地址 |
| 隐私泄露 | C 端截图去 EXIF；个人数据独立桶、独立库、独立密钥 |
| 大文件拖垮服务 | 请求体上限 + 流式处理 + 按账号限流 |
| 密钥泄露 | 子账号最小权限；密钥只在配置中心 / 环境变量 |
