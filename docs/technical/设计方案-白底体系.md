# 设计方案 · 白底体系（整体方案，待评审）

2026-07-30 · **未实施**

---

## 0. 先承认上一版做错在哪

上一版我加了个 `data-ground="flat"`：画布改白、描边加强、把投影换成 1px 环。
结果是**白底上摆着一堆描边盒子**——这不是白底设计，是"灰底方案换了个底色"。

根本问题：**灰底体系是「容器思维」**——内容装在卡片里，卡片浮在画布上，
层次 = 卡片与画布的明度差。把画布刷白，容器还在，只是失去了浮起的理由，
于是只能补一圈线把它框住。越补越像表格套表格。

**白底体系是「留白与分隔线思维」**：没有容器，内容直接坐在纸上，
层次 = 空间节奏 + 分隔线 + 字重。这是 Linear / Notion / Stripe 文档台的路子。

两者是**两套不同的构图逻辑**，不是一个 token 开关能切换的。

---

## 1. 核心原则

| | 灰底体系（现有） | 白底体系（本方案） |
|---|---|---|
| 层次来源 | 卡片 vs 画布的明度差 | **留白节奏 + 分隔线 + 字重** |
| 内容容器 | 白卡片 + 圆角 + 投影 | **无容器**，内容直接坐在白纸上 |
| 灰色的角色 | **底**（画布/侧栏） | **点缀**（表头带、hover、输入填充） |
| 分隔手段 | 卡片边界 | **横向发丝线 + 大间距** |
| 投影 | 卡片浮起 | **只给真浮层**（下拉/抽屉/弹窗），静态内容零投影 |
| 圆角 | 卡片 10px | 容器没了，圆角只剩控件 6px 与徽章药丸 |

> 一句话：**灰底靠"块"分区，白底靠"行"分区。**

## 2. 逐个界面的构图变化

### 2.1 应用外壳

```
现在                          白底体系
┌──┬─────┬──────────────┐    ┌──┬─────┬──────────────┐
│灰│ 灰  │ 灰画布        │    │白│ 白  │ 白            │
│图│ 面板│  ┌──────────┐ │    │图│ 面板│  内容直接铺   │
│标│     │  │ 白卡     │ │    │标│     │               │
│栏│     │  └──────────┘ │    │栏│     │               │
└──┴─────┴──────────────┘    └──┴─────┴──────────────┘
   灰块区分三栏                 **两条竖发丝线**区分三栏
```

- 图标栏、二级面板、内容区**全部纯白**
- 三栏之间各一条 `border-subtle` 竖线（1px）
- 导航激活项：不用整块灰底，用 **accent 淡色填充 + 6px 圆角**，只包住文字宽度
- 顶栏与内容之间一条横发丝线

### 2.2 页面头部

- 标题用 `txt-title`（18/700），与内容之间给 **24px** 留白
- 面包屑与标题之间 **8px**
- **不要**给页头加背景色或卡片

### 2.3 工具栏（搜索 + 筛选 + 操作）

- 直接坐在白底上，**下方一条横发丝线**与表格分开
- 上下各 **12px** 内边距
- 输入与下拉保留 `bg-subtle` 灰填充（这是灰色作为"点缀"的正当用法——
  表示"这里可输入"）

### 2.4 表格（最重要的一块）

```
现在：白卡片包住整张表，卡片有圆角+投影
白底：**没有卡片**，表格全宽铺开
```

- 表头：**无背景色**，靠 `txt-label`（12/500）+ 下方一条 `border-default` 稍重的线
- 行分隔：`border-subtle` 发丝线
- 行 hover：`bg-hover` 淡灰填充（灰色的第二个正当用法）
- 选中行：`accent-subtle` 填充 + 左侧 2px accent 竖条
- **表格不加外框、不加圆角、不加投影**
- 分页条：表格下方，一条线之上

### 2.5 统计条（KPI）

```
现在：5 个白卡片并排
白底：一行数字，**竖发丝线**分隔
```

```
今日 GMV        │ 今日订单     │ 在线设备
AED 4,820.00    │ 386         │ 42
+8.2% 环比      │ +5.1% 环比   │
```

- 数值 `txt-display`（24/700）+ `tabular-nums`
- 标签 `txt-label`，次要文字色
- 分隔用 1px 竖线 + 左右 24px 留白
- 整条下方一条横线与下文分开

### 2.6 表单与抽屉

- 抽屉仍是浮层 → **保留投影**（`elevation-3`）
- 抽屉**内部**按白底逻辑：分组之间用横线 + 20px 留白，不套卡片
- 表单标签 `txt-label` 在上，控件在下，行距 12px

### 2.7 浮层（下拉/气泡/提示）

白底体系下浮层是**唯一允许投影的地方**——因为它们真的浮着。
`elevation-2` + 1px 描边（白底上纯投影边界太软，需要线兜底）。

## 3. Token 影响

白底体系需要的**不是**改几个值，而是这些语义的重新定义：

| token | 灰底 | 白底 |
|---|---|---|
| `--canvas` | gray-3 | **#FFFFFF** |
| `--card` | #FFFFFF | **#FFFFFF**（且组件不再画容器）|
| `--sidebar` | gray-3 | **#FFFFFF** |
| `--card-shadow` | elevation-1 | **none** |
| `--muted`（表头带）| gray-2 | **透明**（表头不再有底色）|
| `--border` | gray-6 | gray-6（不变，但**用量大增**）|
| 新增 `--rule` | — | **gray-6**，专用于结构分隔线 |
| 新增 `--rule-strong` | — | **gray-7**，表头下方那条 |

**关键：`--card-shadow: none` 之后，组件必须自己不画容器。**
这正是上一版做不到的地方——`Card` 组件永远会渲染一个盒子，
所以白底体系**必须动组件**，不可能纯 token 实现。

---

## 4. 需要改的组件（诚实评估）

| 组件 | 改动 |
|---|---|
| `Card` | 新增 `variant="bare"`（不画容器，只提供间距）；白底下列表页一律用它 |
| `DataTable` | 去掉外层卡片；表头改无底色+重线；行 hover/选中态重做 |
| `StatCard` | 从盒子改成"数值 + 竖线分隔"的条 |
| `Toolbar` | 加下边线 |
| `AppShell` / `Rail` / `SecondaryNav` | 三栏改白底 + 竖分隔线；激活态改窄填充 |
| `Drawer` | 内部分组改横线分隔 |
| `Tabs` / `TabHeader` | 分段控件在白底上需要更明确的槽（灰槽保留）|

约 7 个组件，**都是共享组件，页面文件不用动**。

## 5. 两套体系怎么共存

三个选项：

**A. 白底取代灰底**（推荐）
一套体系做透。理由：两套并存意味着每个组件都要写两种构图，
测试面翻倍，且长期一定会有一套年久失修。

**B. 保留开关，但组件按体系分叉**
`data-ground` 保留，组件内按体系切换构图。代价：组件复杂度显著上升。

**C. 灰底留给"工作台/看板"，白底给"列表页"**
按页面类型分工。看板本来就适合卡片（信息块状），列表页适合白底铺开。
这个分法有真实理由，不是折中。

---

## 6. 建议

1. **先做 A（白底取代）的一个试点页**——设备台账，改完对比
2. 试点确认后再铺开其余组件
3. 若试点后觉得工作台仍需卡片，再退到方案 C

需要你定的：**选 A / B / C 哪个**，以及试点页选哪一张。
