## 二、⚠️ 关键前置：共享组件能力不足（这决定了开发顺序）

盘完 16 页的字段规格后核对现有组件，发现**多数页面用现有组件做不出来**。若不先补组件，16 页会各自手搓，风格立刻发散——这正是我们两轮前刚统一掉的问题。

### 2.1 现状与缺口

| 组件 | 现有能力 | 待建页需要但**没有** | 被谁卡住 |
|---|---|---|---|
| `FormDrawer` | `text` / `number` / `select` / `switch` / `password`；`readOnlyOnEdit` | **`textarea`**（多行文本）| 公告正文三语 · 问题管理答复 · 告警建议处置 |
| | | **`date` / `daterange`** | 公告生效期 · 白名单有效期 · 应用版本 · 税率生效日 |
| | | **`multiselect`** | 充值套餐适用市场 · 触达拉黑渠道 · 通知规则目标 |
| | | **字段级校验 + 错误提示** | 几乎全部（现在只能在 `onSubmit` 里 `notify.error`，体验差） |
| | | **分组/分区（Section）** | 业务规则页（提现/预约/计费 三分区） |
| | | **联动禁用**（A 选中才启用 B）| 白名单 `quotaType≠UNLIMITED` 才填额度 · 版本 `forceUpdate` 才填最低版本 |
| `DataTable` | 列配置 + 加载/空态 | **行选择（checkbox）** | 批量指令 · 批量派单（G3）|
| | | **列排序** | 分润统计 · 发送记录 |
| | | **行展开（展开详情）** | 设备日志（展开完整 payload）|
| `Toolbar` | 搜索 + 筛选槽 + 单个新增按钮 | **导出按钮槽** | 全部报表/流水页（G2）|
| | | **日期范围筛选** | 发送记录 · 设备日志 · 充值订单 |
| | | **批量操作条**（选中 N 项后浮出）| G3 |
| — | 无 | **地图组件** | 设备地图分布（G4）|
| — | 无 | **删除确认弹窗** | G1 全站无删除 |

### 2.2 结论

**必须先做「组件能力补齐」批次（B0），再铺页面。** 否则：
- 16 页里至少 11 页要手搓表单控件
- 风格发散后再统一的成本远高于现在补
- 组件补齐是一次性投入，收益覆盖全部 36 项

## 三、页面细节规范（所有新页统一遵守）

### 3.1 列表页三段式骨架

```
┌─ TabHeader ─────────────────────────────┐  标题=当前子功能名，tab 悬停展开
├─ [StatCard 行]（可选，统计型页面才有）  │  如 发送记录：今日发送量/失败率/今日成本
├─ Toolbar ───────────────────────────────┤  搜索 + 筛选槽 + [导出] + [新增]
├─ DataTable ─────────────────────────────┤  列配置；操作列固定最右
├─ Pagination ────────────────────────────┘  统一分页
   └─ Drawer / FormDrawer（按需）
```

### 3.2 强制规范

| 项 | 规范 |
|---|---|
| **空态** | 一律用 `DataTable` 的 `empty` 文案，**写清"为什么空"和"下一步做什么"**（如"暂无告警记录——设备运行正常，或告警规则尚未配置"），不要只写"暂无数据" |
| **加载** | `DataTable` 自带 Skeleton，勿自搓 spinner |
| **错误** | 全局 `MutationCache.onError → notify.error` 已接管，页面**不要重复 catch 弹窗** |
| **权限降级** | 无写权限时**显式提示"仅可查看"**（沿用退款记录页做法），**不要静默隐藏操作列**——静默隐藏会让人以为功能坏了 |
| **分期** | 页面 `TABS` 的 `phase` 必须与 nav 叶子、与矩阵「阶段」列三处一致 |
| **金额** | 一律 `money()` 格式化 + 币种前缀（`AED 12.00`），禁止裸数字 |
| **时间** | 一律 `fmtTime()`，列表用相对/绝对混合，详情用绝对 |
| **状态** | 一律 `Badge` + `tone`（success/warning/danger/muted/outline），**同一状态在全站同色** |
| **主键列** | 单号类列固定第一列、等宽字体；`readOnlyOnEdit` |
| **操作列** | 固定最右、表头「操作」；>2 个动作时收进「更多」 |
| **深链** | 跨模块跳转用 `<Link>` + 完整 href，不要 `router.push` 拼串 |
| **搜索域** | 新增可见列时同步扩搜索域（规格 §17.1-9） |

### 3.3 抽屉规范

| 场景 | 用什么 | 例 |
|---|---|---|
| 配置类增改（字段规整）| `FormDrawer` + `FieldDef[]` | 告警代码 · 银行管理 |
| 审批类（需二次确认 + 必填原因）| `Drawer` 自定义 | 提现审核 · 退款审批 · 投诉处理 |
| 只读详情（含长文本/时间轴）| `Drawer` 自定义 | 设备日志 payload · 订单详情 |
| 分区表单（多个独立保存块）| `Card` 分区 + 各自保存按钮 | 业务规则页 |

## 六、代理端（D 类）的取舍建议

代理端 5 页有两种做法：

| 方案 | 做法 | 优点 | 缺点 |
|---|---|---|---|
| **A. 同工程角色视图**（推荐）| 不建新页；`AGENT` 登录后 nav 只出「我的」域，复用现有页面 + 数据范围收敛到 `agent_no` | 零新页面；权限与数据范围逻辑复用；后端数据范围已有 AGENT 档 | 页面文案要按角色切换（"设备台账"→"我的设备"）|
| B. 独立前端 | 另建 agent-web | 体验可定制 | 多一个工程要维护；与 ops-web 逻辑重复 |

**建议 A**，且**放到最后做**——它依赖后端数据范围真正生效，现在做等于做假。

### 追加：B1.5 API/Mock 层结构治理（2026-07-29 用户定调）

> **总路线拍板**：**先完成全部前端 + 统一封装 api/mock → 全端完成后再整体开发后端**。
> 因此在铺 B6–B8 之前插入一次结构治理——否则新功能继续往失控的结构里堆。

**治理前的失控现状**（6 个 agent 追加式修改的累积后果）：

| 文件 | 规模 | 问题 |
|---|---|---|
| `lib/api/contract.ts` | 282 行 / **单个 `Api` interface 挂 161 个方法** | 扁平巨型接口，无域边界 |
| `lib/api/mock.ts` · `http.ts` | 253 / 210 行 | 各有 4–5 段分散的 `import type`（不同 agent 各加各的）|
| `lib/mock/db.ts` | **1747 行** | 单文件承载全域 mock |
| `lib/types.ts` | **1196 行** | 单文件承载全域类型 |
| 查询参数 | `PageQ`/`StatusQ`/`AlarmQ`/`ShareSummaryQ`/`RechargeQ` 散落 | 无统一规范 |

**治理方案（硬约束：公开导入路径与调用方式一律不变，40 个页面零改动）**：
- `lib/types.ts` → `lib/types/{common,device,alarm,...}.ts` + `index.ts` re-export（`@/lib/types` 不变）
- `lib/mock/db.ts` → `lib/mock/db/{helpers,device,...}.ts` + `index.ts`（`@/lib/mock/db` 不变）
- `lib/api/{contract,mock,http}.ts` → 每域一个切片，入口文件组合（`api.listCabinets()` 写法不变）
- 查询参数收进 `lib/api/query.ts`
- **新增契约一致性单测**：断言 `mockApi` / `httpApi` / `Api` 三者方法名集合完全一致 —— **161 个方法靠人眼查不出漏实现**，这是本次治理最有价值的产出

**原则**：纯搬运不重写；发现 bug/重复/签名不一致一律**上报不自行修**（避免重构与修 bug 混在一起，出问题无法二分定位）。

**每批次验收（统一）**：`tsc` 零错 → `vitest` 全过 → `build` 成功 → **实机核对字段与交互** → 删 nav 对应叶的 `soon` → **回填矩阵「前端」列 + 实现状态总表变更日志**。

### 关键路径

```
B0 组件 ──┬─→ B2 治理 ─┐
          ├─→ B3 配置 ─┤
          ├─→ B4 业务 ─┼─→ B6 横向能力 ──→ B7 闭环改造 ──→ B8 地图/代理端
          └─→ B5 资金 ─┘
```
B2–B5 之间**无依赖，可并行**（不同页面、数据层追加式）。

## 八、四个决策点 —— ✅ 已拍板（2026-07-29 用户「按建议实施」）

| # | 决策点 | **结论** | 落地约束 |
|---|---|---|---|
| 1 | B0 是否先做 | ✅ **先补组件再铺页** | B2–B5 任何页面**不得绕过共享组件手搓控件**；缺能力先回头补 B0 |
| 2 | 导出实现 | ✅ **前端 CSV 先行**（当页数据）| 统一走 `lib/export-csv.ts`，**必须带 UTF-8 BOM**（否则 Excel 中文乱码）；全量导出等后端 |
| 3 | 代理端方案 | ✅ **A 角色视图**（不建新工程/新页）| AGENT 登录后 nav 只出「我的」域，复用现有页面 + 数据范围收敛到 `agent_no`；**排最后（B8）**，依赖后端数据范围真正生效 |
| 4 | 删除语义 | ✅ **软删除**（置状态，不物理删）| 契约方法命名 `archive*` / `disable*` 而非 `delete*`；列表默认过滤已归档，提供「显示已归档」开关；与审计要求一致 |
