# 运营端开发 数据库变更清单

> 2026-10-30；下表是数据库设计与迁移工作包。兼容结构首批已实现V212—V218；作业隔离续批新增V219报废归属快照，并在专用测试库验证；各工作包仍须分别验收，不代表业务能力全部完成。详见[执行记录](../superpowers/plans/2026-10-30-ops-execution-progress.md)。

## 一 迁移原则

- V211为菜单更名迁移；首批新增V212—V218，续批新增V219。后续实施取当时下一个可用编号，禁止修改已执行历史迁移。
- 先新增可空字段／索引、回填可证实数据、双读兼容，再收紧约束；旧历史不编造商家、成本、质检或签收证据。
- 金额DECIMAL+currency，数量明确单位，时区按项目规范；业务编号／外部来源键在正确scope内唯一，不用全局约束误伤再次投放。
- 独立库存权威余额不复制到宿主；OpsKit流程状态不另建第二份可写流程账。设备经营商家不等于法律所有权。
- 每次增加唯一索引先查历史重复；高体量索引、锁表时间、回填脚本和回退读路径需验证。回退不得删除已发生业务事实。

## 三 已确认应复用的现表

- inv_intake／inv_intake_item：到货／期初、单价、质检与逐件处置；补采购和来源关联，不重建第二入库账。
- inv_material／inv_material_doc／inv_material_doc_line／inv_material_threshold：宿主物料档案和单据引用；真实物料账在SERVICE。
- inv_shipment：物流及发货引用；先核是否足以承载交付记录，再决定DB-06，不重复建物流账。
- dev_protection：已有设备保护机制，DEV-14先核覆盖性；停用设计不先默认新增另一可用性表。
- pay_refund：已存在支付退款实体与表，DEV-24接通执行和回调，不新建另一张同义退款表。
- dev_qc_record、dev_movement_log、wo_order／wo_handle及票据现表：补来源和必要约束，保留历史事实。

## 四 每个迁移的验收清单

- [ ] 对照当前schema、全部后续ALTER与实体，确认字段／索引不是已经存在。
- [ ] 确认应用写入方、唯一性作用域、失败重试及并发更新条件。
- [ ] 空库完整迁移、旧数据升级、重复执行保护和历史异常检测通过。
- [ ] 检查关键列表索引与EXPLAIN，验证分页和查询范围。
- [ ] 记录回填数量、未能映射的数据和回退策略；检查不覆盖历史账务和归属。

## DEV-02 续批：报废归属快照（V219）

`dev_movement_log`兼容新增可空的`scope_region_id`、`scope_site_no`、`scope_agent_no`。记录柜内充电宝报废前的实际归属，原机柜之后划拨不改写该快照；在仓设备以明确的仓库来源为准，不能用机柜旧区域覆盖实际仓库。未知历史保持NULL，不能猜测回填。此变更不新增余额表或状态枚举，也不意味着完整遗失／差异处置已交付。

先在专用测试库验证增量迁移及真实报废、原柜后续转区和跨仓负对照；业务库尚未执行。生产迁移演练和大表执行影响仍需验收。
