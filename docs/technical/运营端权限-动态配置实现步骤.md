## 0. 目标态数据流（一图）

```
后台配置(管理员)                      登录/请求(员工)
─────────────                        ─────────────
iam_permission(码目录)  ─┐            login → PermissionService.load(employeeNo)
iam_menu(菜单树) ────────┤              ├─ iam_employee_role → roleNos
iam_role / iam_role_perm ┤─(缓存)──▶    ├─ iam_role_perm     → perms(含通配)
iam_employee_role ───────┤              ├─ iam_data_scope    → DataScope(ROLE∪EMPLOYEE)
iam_data_scope ──────────┘              └─ 组装 LoginUser{perms,dataScope} → SessionStore
                                        GET /api/auth/menus       → MenuService 按 perms 过滤菜单树
                                        GET /api/auth/permissions  → 前端 can() 用的码集合
                                        @PreAuthorize("@perm.can") / DataScopeHandler 照旧生效
```

**关键改动点**：`RolePerms`（硬编码）→ `PermissionService`（读库+缓存）；`DataScopeResolver`（硬编码）→ 读 `iam_data_scope`；前端 `nav.ts`（静态）→ `GET /api/auth/menus`（服务端下发）。

## 步骤 1 · 数据模型：新增 `iam_menu` + 复用现有 iam_*

### 1.1 DDL（追加到 `ddl/pb_core-loc-agt-iam.sql` + `resources/schema.sql` 幂等）
```sql
CREATE TABLE IF NOT EXISTS iam_menu (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  menu_no     VARCHAR(36)  NOT NULL,
  parent_no   VARCHAR(36)      NULL COMMENT '父菜单(顶层空)',
  name        VARCHAR(64)  NOT NULL,
  name_ar     VARCHAR(64)      NULL COMMENT 'ar 文案(RTL)',
  type        VARCHAR(8)   NOT NULL DEFAULT 'MENU' COMMENT 'DIR/MENU',
  path        VARCHAR(128)     NULL COMMENT '前端路由 href',
  icon        VARCHAR(32)      NULL,
  sort        INT          NOT NULL DEFAULT 0,
  perm        VARCHAR(64)      NULL COMMENT '所需权限码(空=公开)；可见性=hasPerm(perm)',
  visible     TINYINT(1)   NOT NULL DEFAULT 1,
  status      VARCHAR(16)  NOT NULL DEFAULT 'ACTIVE',
  created_at  DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  updated_at  DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE KEY uk_menu_no (menu_no),
  KEY idx_menu_parent (parent_no, sort)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;
```
> 菜单与权限码分离：`iam_permission`=动作码目录（按钮/接口鉴权用）；`iam_menu`=导航树（UI，绑定一个「查看用」权限码）。可见规则：`perm` 空或 `LoginUser.hasPerm(perm)` 为真；`DIR` 若无可见子节点则隐藏。

### 1.2 种子（与现状**行为等价**迁移，务必先对齐再切换）
- `iam_permission`：灌 [功能权限清单.md](../requirements/功能权限清单.md) 全部码（供后台"分配权限"选择器 + 校验）。
- `iam_role`（已有种子）：内置 7 角色 `builtin=1`（只读，不可删/改码）。
- `iam_role_perm`：**从当前 `auth/RolePerms.MAP` 逐条导出**（ADMIN=`*`，OPS=`device:cabinet:*`…），保证切库后权限矩阵不变。
- `iam_menu`：**从前端 `ops-web/lib/nav.ts` 12 模块导出**（顶层 MENU：dashboard/device/location/order/pricing/finance/workorder/user/marketing/agent/org/system），每条 `perm` 绑定该模块代表性查看码（如 device→`device:cabinet:read`、finance→`finance:share_rule:read`）。
- `iam_data_scope`：内置角色默认（ADMIN=ALL、AGENT=AGENT、其余 ALL/按需）。

> 种子放 `IamSeeder`（幂等，仿 `LocSeeder`）：表空才灌，避免覆盖后台改动。

### 2.2 `PermissionService`（取代硬编码 `RolePerms`）
```java
@Service

  // employeeNo → 该员工所有角色的权限码并集（含通配），带缓存
  @Cacheable(value="perms", key="#employeeNo")     // Caffeine/Redis；失效见步骤7
  public List<String> loadPerms(String employeeNo) {
    List<String> roleNos = employeeRoleMapper.roleNosOf(employeeNo);
    if (roleNos.isEmpty()) return List.of();
    return rolePermMapper.permCodesOf(roleNos).stream().distinct().toList();
  }
  @Cacheable(value="scope", key="#employeeNo")
  public DataScope loadScope(String employeeNo, List<String> roleNos, String agentNo) {
    // iam_data_scope: subject_type=ROLE(roleNos) ∪ EMPLOYEE(employeeNo)；任一 ALL→ALL；AGENT realm 强制 agent_no
    ... // 见步骤 8
  }
}
```
- `RolePerms` 保留为**种子来源**（导入 `iam_role_perm`）后即从鉴权路径下线；`DataScopeResolver` 改为委托 `PermissionService.loadScope`。

### 2.3 `MenuService`（菜单树 + 按权限过滤）
```java
@Service
public class MenuService {
  @Cacheable(value="menuTree")                       // 全量树缓存(与人无关)
  public List<MenuNode> fullTree() { /* iam_menu → 建 parent 树，按 sort */ }

  public List<MenuNode> visibleFor(LoginUser u) {    // 按 perm 过滤 + 剪空目录
    return prune(fullTree(), n -> n.perm()==null || u.hasPerm(n.perm()));
  }
}
```

## 步骤 3 · 登录接线：`LoginUser` 由库装配

改 `auth/AuthController.login`（及未来 auth-core 真登录）：
```java
List<String> roleNos = employeeRoleMapper.roleNosOf(employeeNo);
List<String> perms   = permissionService.loadPerms(employeeNo);   // ← 来自 iam_role_perm
DataScope scope      = permissionService.loadScope(employeeNo, roleNos, agentNo); // ← iam_data_scope
LoginUser u = new LoginUser(realm, employeeNo, name, primaryRole, perms, "MAIN", agentNo, scope);
sessionStore.issue(u);
```
> `@PreAuthorize("@perm.can(...)")`、`DataScopeHandler`、`StaffContext`/`SecurityUtils` **零改动**——它们只读 `LoginUser.perms/dataScope`，来源从硬编码换成库即可（业务/权限分离的红利）。

新增（`auth/AuthController` 或 `platform`）：
| 端点 | 用途 |
|------|------|
| `GET /api/auth/menus` | 返回**当前登录人可见的菜单树**（`MenuService.visibleFor(SecurityUtils.currentUser())`）|

## 步骤 5 · 后台配置 API（管理员运行时改）

均挂 `@PreAuthorize`（`org:role:*` / `org:menu:*` / `org:employee:*`，见功能权限清单 §11）；**内置 `builtin=1` 角色只读**（改码/删除→409）。

| 端点 | 用途 |
|------|------|
| `GET /api/platform/permissions` | 权限码目录（`iam_permission`，构建分配选择器）|
| `GET/POST/PUT/DELETE /api/platform/roles` | 角色 CRUD（自定义角色）|
| `PUT /api/platform/roles/{no}/permissions` | 给角色分配权限码集合（覆盖写 `iam_role_perm`）|
| `GET/POST/PUT/DELETE /api/platform/menus` | 菜单树 CRUD（`iam_menu`）|
| `PUT /api/platform/employees/{no}/roles` | 给员工分配角色（`iam_employee_role`）|
| `PUT /api/platform/employees/{no}/data-scope` · `.../roles/{roleNo}/data-scope` | 配数据范围（`iam_data_scope`，员工级/角色级）|

每次写配置后 → **失效相关缓存**（步骤 7）+ 写 `iam_audit_log`。

## 步骤 6 · 前端接线（ops-web，去静态化）

1. **菜单**：删/降级 `lib/nav.ts` 静态表 → 登录后 `GET /api/auth/menus`，用返回树渲染侧边栏（`icon` 名映射到 lucide 组件）。路由守卫：进页面校验该 path 在可见菜单内。
2. **按钮级**：`lib/permissions.ts` 的 `ROLE_PERMS` 硬编码 → 改为登录后 `GET /api/auth/permissions` 拿码集合存 store；`can(code)`/`canModule(module)` 逻辑不变（仍是 `endsWith("*")+startsWith` 通配），只是数据源从硬编码换成后端下发。
3. **管理页**：`app/employees`（角色/员工/数据权限 tab）接步骤 5 的真接口（当前是 mock）：角色列表/建角色/勾选权限码（来自 `/permissions` 目录）/给员工派角色/配数据范围抽屉。菜单管理可加 `app/system/menus`。
> 前后端仍**同一套通配语义**（`运营端权限方案` §4.2），保证「前端显示的按钮 = 后端放行的操作」。

## 步骤 7 · 缓存与失效（改完即生效）

- **缓存**：`perms:{employeeNo}`、`scope:{employeeNo}`、`menuTree`（Caffeine 单机/Redis 多实例）。
- **失效策略**（后台写配置后精准清）：
  - 改角色权限（`iam_role_perm`）→ 清所有**属于该角色的员工** `perms:*`（或按 roleNo 维度缓存 `perms:role:{roleNo}` 再组合，减小失效面）。
  - 改员工角色/数据范围 → 清该 `perms:{emp}`/`scope:{emp}`。
  - 改菜单 → 清 `menuTree`。
- **已登录会话的生效口径**（重要）：`LoginUser.perms` 在**登录时快照进 SessionStore**。改权限后有两种口径，二选一并写清：
  - **A（简单）**：下次登录生效；配 `perms` 缓存 TTL（如 10min）兜底。
  - **B（即时）**：`SessionStore` 存 `permsVersion`，`StaffTokenAuthFilter` 每次请求比对全局版本号，变了则 `PermissionService` 重载并刷新会话 principal。推荐 B（改权限即时收敛，安全）。

## 步骤 8 · 数据范围动态配置（`DataScopeResolver` → 读库）

```java
// PermissionService.loadScope
List<Row> rows = dataScopeMapper.bySubjects(ROLE, roleNos, EMPLOYEE, employeeNo); // 角色级+员工级
if (rows.stream().anyMatch(r -> r.scopeType()==ALL)) return DataScope.ALL;
List<ScopeRule> rules = rows.stream().map(r -> new ScopeRule(r.scopeType(), r.refs())).toList();
if (realm==AGENT) rules = append(rules, new ScopeRule(AGENT, Set.of(agentNo)));   // 覆盖式硬约束
return new DataScope(false, mergeSameDim(rules));
```
- 后台在员工/角色上配 `REGION/SITE/LOCATION/VENUE` 范围（`scope_refs JSON`）→ 立即经 `DataScopeHandler` 生效。
- 同步**扩注册表**：`DataScopeTableRegistry` 增 `dev_cabinet`/`ord_rent`/`wo_order`（核实实际表有 `agent_no`/`region_id`/`site_no` 列），让新维度真过滤（[运营端权限方案 §10](./运营端权限方案.md)）。
