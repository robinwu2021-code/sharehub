# ADR-001 技术栈与服务粒度

状态：已接受（2026-07-11）· 修订：对齐 ai-neargo

## 背景
SaaS 多租户充电宝平台，需承接设备长连接、支付资金、复杂运营后台。用户要求**技术栈参考 ai-neargo，基础层框架能力共用与依赖**。

## 决策
- 后端：**Java 21 + Spring Boot 4.0.x（Spring Framework 7）+ Maven 多模块**，与 neargo 完全一致。
- 服务间调用：**Spring `RestClient`**，**不引 Spring Cloud、不用 Feign**（遵循 neargo）。
- 持久层：**MyBatis + MyBatis-Plus**，MySQL 8 优先 / PG 兼容。
- 事件：**`DomainEventPublisher`（默认 Logging，生产换 Kafka）**，**不用 RocketMQ**；跨事务一致性用本地事务 + Outbox + Kafka。
- 配置：**Nacos 裸 SDK**（`NacosConfigImporter`）。
- 服务粒度：划 **5 业务域 + access-gateway**；**部署遵循 neargo「域分而不裂、modulith 默认」**——MVP 业务域合并为模块化单体 + 独立 access-gateway，按信号（瓶颈/团队/合规）裂解为粗粒度服务。

## 备选与否决
- 我方初稿的 Spring Cloud Gateway + OpenFeign + RocketMQ → **否决**，与 neargo 基线冲突，无法共用 commons。
- 一开始即 5 服务独立部署 → 保留为规模化目标，非 MVP（避免早期基建成本）。

## 影响
- 相较初稿的修订点：网关层由 BFF 触点应用承担（非 Spring Cloud Gateway）；MQ 抽象为 DomainEventPublisher；服务发现/配置走 Nacos 裸 SDK。
- access-gateway 因私有协议长连接（Netty）为 powerbank 增量，独立进程。
