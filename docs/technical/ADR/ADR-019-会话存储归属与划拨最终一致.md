# ADR-019 会话存储归属 与 划拨改最终一致

状态：**已实施**（2026-07-30）· 决策一与决策二均已落地，三个卡口全绿

> ⚠️ **一处必须说清的局限**：单体形态下 `OutboxEventBus` 在 `afterCommit` 回调里**同步**投递，
> 所以 83 个测试全绿**不能证明异步路径正确** —— 它证明的是「事务回滚不留事件」与
> 「事件自带完整载荷」这两条不变量。真正的异步语义要到接 MQ 后才被检验，
> 届时 `AgentAssignmentSyncTest` 的断言需改为轮询等待。
· 解决 `arch-guard.py` G2 报出的 2 处跨服务事务
· 关联 [ADR-017](./ADR-017-单体与微服务双形态部署.md) 纪律二（不跨服务事务）

## 背景

`arch-guard.py` 的 G2 卡口报出 2 处跨服务事务，是拆分前必须清掉的最后两处：

| # | 违规 | 性质 |
|---|---|---|
| 1 | `ConsumerAuthService#login` 同事务写 `usr_user`(core) + `sys_token`(platform) | 新发现，**分类问题** |
| 2 | `AgentAssignmentServiceImpl#assign` 同事务写 platform 三表 + `dev_cabinet`(core) | 已知设计债，**真实跨界** |

两者性质完全不同，方案也不同。

---

## 决策一：`sys_token` 是基础设施，不是 platform 的业务表

### 关键事实（查证后才发现）

`TokenStore` **本来就是可切换 SPI**，已有四个实现：

```
auth/store/RedisTokenStore.java      ← 生产目标
auth/store/MysqlTokenStore.java      ← sys_token 表只服务于它
auth/store/MemoryTokenStore.java     ← 当前开发配置 token-store: memory
auth/store/LocalCacheTokenStore.java
```

所以**这不是「要不要改造」的问题，而是「分类错了」** ——
`sys_token` 是 MySQL 实现的存储细节，不是一张业务表。
把它算作 platform 的业务表，登录（发生在 core）就必然「跨界」，
但这个跨界是分类造成的幻象，不是真实的架构问题。

### 决策

1. **生产配 `token-store: redis`**，实现已存在，无需开发；
2. **`sys_token` 表降级为「MySQL 实现的开发/单体便利选项」**，不参与服务归属；
3. 在 `module-graph.py` 引入**显式的基础设施表集合**，`sys_token` 与 `flyway_schema_history` 入列。

### 判据必须硬，否则它会变成垃圾桶

一张表要被归为**基础设施表**，必须**同时**满足三条：

| 判据 | `sys_token` | 反例：`sys_biz_rule` |
|---|---|---|
| 所有服务都读写它 | ✅ 每个服务都要验令牌 | ❌ 只有计价/提现读 |
| 不承载业务语义 | ✅ 会话是技术概念 | ❌ 手续费口径是业务规则 |
| 拆分后走共享中间件而非业务库 | ✅ Redis | ❌ 必须落库 |

**集合必须显式枚举、每条写明理由，且加入需过评审** —— 这与「给违规开豁免」有本质区别：

- **豁免** = 承认它跨界，但假装没事 → 口子一开，卡口逐步退化成摆设；
- **重新分类** = 它根本不属于任何业务服务，所以不存在跨界。

我在实施 S3 时**刻意没有自行加豁免让报告变绿**，正是为了先把这个区别说清楚再动。

### 否决 JWT（无状态令牌）

JWT 能让问题消失（不落库就没有跨界），但**代价不可接受**：

现有 `StaffTokenAuthFilter` 实现了**权限版本戳（口径 B）**：
`d.permStamp() != permVersion.get()` → 重建会话。
这让**角色权限变更对在线员工下一个请求即生效**。JWT 签发后不可变，
做不到即时生效，也做不到吊销（踢下线）。

**为了消除一个架构告警而牺牲一个已实现的安全属性，是本末倒置。**

## 决策二：划拨改事件驱动最终一致

### 现状

`AgentAssignmentServiceImpl#assign`（`@Transactional`）在一个事务里：

```
platform 侧：agt_assignment(落单) + loc_site(agent_no) + loc_location(agent_no)
core     侧：dev_cabinet(agent_no + site_no)     ← 跨界
```

S3 已把 core 侧的直连改为经 `DeviceOwnershipPort`，但**仍在同一事务内同步执行** ——
Port 解决的是纪律三（不直连表），不解决纪律二。

### 决策

**拆成「本地事务 + 事件 + 补偿」三段**：

```
① platform 本地事务（原子）
     agt_assignment 落单
     loc_site / loc_location 回写 agent_no      ← 都是 platform 自己的表
     写 sys_outbox：AssetAssignedEvent{targetType,targetNo,agentNo,siteNo,locationNos}
② core 订阅 AssetAssignedEvent
     dev_cabinet 回写 agent_no + site_no（幂等：按 agent_no 幂等，重复投递无副作用）
③ 对账补偿（定时）
     比对「点位归属 vs 其下机柜归属」，不一致则修复并告警
```

**授权闸门保持同步**：`existsInScope` 是读，不需要事务，继续同步调用 ——
看不到的对象不该被划拨，这条不能变成最终一致。

**事件自带 `locationNos`**：消费方不需要回查 platform 的点位表，
否则等于把同步调用藏在事件里（ADR-017 §5.2 已定的规则）。

### 前置依赖

**必须先建 `sys_outbox`**（[设计v3-数据库变更](../设计v3-数据库变更.md) §七）。
没有 outbox，「落库」与「发事件」不原子，会出现划拨单落了但事件丢了 ——
那比现在的跨服务事务更糟：现在至少是一致的。

### 代价与可接受性

| 代价 | 评估 |
|---|---|
| 划拨后机柜归属有**秒级延迟** | 划拨是低频运营动作，不在借还主链路 |
| 延迟窗口内代理商看不到机柜 | UI 需表达「划拨已提交，资产归属同步中」，不能显示为已完成 |
| 多一套补偿任务 | 复用现有 `recon_task` 框架，不新建机制 |

**这是最终一致该付的价，不是设计缺陷。** 划拨若要求强一致，唯一办法是把
`dev_cabinet` 和 `agt_assignment` 放同一个服务 —— 那等于让「代理商」和「设备资产」
不能分开部署，代价远大于秒级延迟。

| 步 | 内容 | 状态 | 结果 |
|---|---|---|---|
| **1** | 基础设施表分类（决策一） | ✅ | `INFRA_TABLES` 在 `module_of()` 入口排除；G2 2→1 |
| **2** | 生产配 `token-store: redis` | ⬜ 待运维 | 实现已存在，只改配置 |
| **3** | `sys_outbox`(V15) + `DomainEventBus` + `OutboxEventBus` | ✅ | 3 条不变量单测；实测 7 条事件全 SENT |
| **4** | 划拨改事件驱动 + `OwnershipReconciler` | ✅ | G2 写跨界归零；83 测试全绿 |
| **5** | 对账比对（点位归属 ⋈ 机柜归属） | ⬜ | 需跨表比对，正是 G1 禁止的跨服务 JOIN —— 待 M1 读模型落地后由 core 侧自行比对 |
| **6** | 投递器调度 + 分布式锁 | ⬜ | **刻意没加 `@Scheduled`** —— 多副本下会并发跑，需与 MQ 投递器一起设计 |

### G2 卡口的一处精度改进

改造后 G2 只剩 `existsInScope`（授权闸门，**读**）跨界。这暴露了卡口的精度问题：
纪律二要防的是**写**的原子性（拆开后无法回滚），跨服务**读**是延迟/韧性问题，不是原子性问题。

已让 G2 区分二者：**写跨界=违规，读跨界=警告**。两者混报会让「授权闸门查一次」
和「跨服务写」等价，真正危险的那类被噪音淹没。

**反向对照同步升级**：原探针只 `new` 实体不写库，被判为读是正确的 ——
换成真调 `updateById` 的探针后，G2 如期抓到（证据带 `W:` 前缀）。

**步 1 可以立刻做**（零风险），步 3–4 建议与 M1（订单拆表）同批 ——
两者都需要 outbox，一起做省一次回归。

## 风险

**最大风险是步 4 改坏划拨的两条安全属性**：
级联必须完整（豁免数据范围）、授权闸门必须保留数据范围。
现有 `AgentAssignmentSyncTest` 的 4 个用例 + 反向对照（禁用回写后 3 例如期失败）
是这两条的护栏，**改造时必须保持它们有效，只把断言改成异步等待**，不能删。
