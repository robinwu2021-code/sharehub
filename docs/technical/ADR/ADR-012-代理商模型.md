# ADR-012 代理商（Agent）模型 —— 运营方体内的分润伙伴

状态：已接受（2026-07-11 用户补充）
· **2026-09-23 补充定案**：代理端形态在下文「模型 · 代理端」里原本留了两条路，现定为 **ops-web 的角色视图**，不建独立前端（见下文加粗处）。

## 背景
共享充电宝行业运营方普遍**招募代理商**：代理商投资/拓展一片区域或一批点位，用运营方的品牌与系统经营，按约定**分润**。用户要求把代理商纳入单运营方系统。必须与多租户口子（ADR-011）严格区分。

## 决策：代理商 ≠ 租户
代理商是**运营方体内**的一等概念，**不是**独立租户。

| 维度 | 代理商 Agent | 🔒 租户 Tenant（口子, ADR-011）|
|------|-------------|------------------------------|
| 定位 | 运营方招募的区域/点位合作伙伴 | 另一个独立运营方（多品牌）|
| 数据归属 | 同一租户（`tenant_no=MAIN`）内 | 独立 `tenant_no`，行级隔离 |
| 品牌 | 用运营方品牌 | 自己品牌 |
| 可见数据 | 运营方数据的**受限子集**（自己的设备/点位/订单/收益）| 完全隔离的另一套 |
| 隔离机制 | **数据权限**（data scope = `AGENT`/自己经手）| `tenant_id` 行级隔离 |
| 分润 | 分润对象（`share_rule.dimension=AGENT`）| 各自独立核算，不互分 |
| 后台 | **代理端**（受限视图）| 租户运营后台（完整，口子）|
| 优先级 | **MVP 纳入**（运营方核心商业模式）| P1+ 口子 |

## 模型
- **代理商实体** `agt_agent`：主体/联系人、辖域、默认分润比例、结算账户、状态。（`tenant_id=MAIN`）
- **归属分配**：机柜/点位可归属到代理商（`cabinet.agent_no`/`location.agent_no`）——运营方把设备/点位划给代理经营。
- **数据权限新增维度 `AGENT`**：代理只能看/操作自己归属的设备/点位/订单；由数据范围拦截器按 `agent_no` 收敛。
- **分润/结算复用现有**：`share_rule(dimension=AGENT)` → `share_record` → `settlement(payeeType=AGENT)` → `withdrawal`。代理分润执行/打款仍走 nearpay（ADR-004/005）。
- **代理端**：**定为 ops-web 的角色视图**（2026-09-23 定案）—— 不建独立前端、不建独立 BFF。
  代理登录 = `AGENT` Realm + 自己 `agent_no` 数据范围；菜单只出门户三组（[nav.ts](../../../ops-web/lib/nav.ts) 的 `portalFor: ["AGENT"]`），
  页面复用运营端既有页。**否决「uni-app 换角色做独立代理端」**：代理自助的 6 个菜单叶背后全是既有 `/api/**` 端点，
  接口面零增量，独立工程的成本 100% 落在前端与打包上；要移动端就把这几个页面做响应式。
  详见 [接口清单-按端 §三](../../api/接口清单-按端.md)。

## 影响
- 新增运营端模块「代理商管理」（运营方侧：代理 CRUD、设备/点位划拨、分润配置、代理结算）。
- 新增 `AGENT` 角色（受限、面向代理端），数据范围 = 自己。
- 强化了「数据权限」必要性（ADR/权限清单待确认 #2）：代理是 `LOCATION`/`AGENT` 数据范围的首个刚需场景 → 数据权限 MVP 就要做。
- db：`pb_core` 增 `agt_*`；`dev_cabinet`/`loc_location` 增 `agent_no` 列。

## 备选与否决
- 把代理商当租户（用 tenant_id 隔离）→ 否决：代理用运营方品牌、数据是运营方数据的子集、要参与运营方统一分润，不是独立运营方；用租户隔离会切断统一运营与分润。
