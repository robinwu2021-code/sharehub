# ADR-021 通用设备命名与使用形态 —— 以充电宝为主，按摩椅等共享设备同一模型

状态：**提议 · 待确认**（2026-09-23，依据用户同日要求起草）
· 延续 [ADR-014](./ADR-014-平台更名ShareHub与设备类型抽象.md)（平台层名不得含单一设备语义）与 [ADR-018](./ADR-018-多设备类型与多供应商的抽象边界.md)（订单主表 + 扩展表、驱动分族）
· **修订 ADR-014**「库名 `pb_core` 与表前缀不变」中的库名部分（改为 `sharehub_*`）

细化文档：[v4/01 通用设备与命名](../v4/01-通用设备与命名.md) · 图 `diagrams/13-device-model.svg`

## 背景

用户 2026-09-23：本项目是充电宝项目，将来扩到充电桩以及共享按摩椅等共享设备；**架构、接口、API 名称尽量通用，不能通用的优先考虑充电宝业务**。

现状实测：订单已拆成通用主表 + 扩展表（V16），设备类型注册表已有（`md_device_type`）；
但平台层仍残留大量充电宝名字 —— 表 `dev_cabinet`、19 张表的 `cabinet_no` 列、约 24 个接口路径（`/cabinets` `/orders/rent` …）、
权限码 `device:cabinet:*`、端口 `CabinetQueryPort`、订单状态 `IN_USE` / `RETURNED`、类型码 `EV_PILE`、库名 `pb_core`、MQTT 前缀 `pb/`。

按摩椅是第一种**与充电宝几乎每一维都不同**的设备：没有物品、没有归还、先付后用、按套餐计时。它是检验抽象够不够的样本。

## 决策

### 一、按「使用形态」而不是按设备名分化

| 形态 `usage_mode` | 判据 | 设备 |
|---|---|---|
| `RENTAL` 借还 | 物品离开设备，需要归还（可异地、可能丢失买断） | 充电宝 |
| `SESSION` 就地使用 | 在设备上用一段时长 / 电量 / 一次存取 | 充电桩、按摩椅、储物柜 |

计量（`MINUTE` / `KWH` / `PACKAGE` / `COUNT`）与付费模式（`PREAUTH` / `DEPOSIT` / `PREPAY` / `CREDIT`）是独立的两维，由设备类型登记默认值、计价引擎执行。

### 二、按形态命名的扩展，下一种设备优先复用

- 订单扩展表新增 **`ord_session_ext`**（不叫 `ord_massage_ext`）：计时会话型设备共用；
- 驱动新增 **`SESSION` 指令族**（`START_SESSION` / `STOP_SESSION` / `EXTEND_SESSION`；`SESSION_STARTED` / `SESSION_ENDED`）：同上；
- 充电桩因有电量与表底、且有行业标准（OCPP），保留独立的 `ord_charge_ext` 与 `EV_CHARGER` 族。

### 三、类型模块 SPI

订单服务按通用流程编排，类型相关的决定（选槽、扩展行、开始 / 停止指令、设备事件判定、计量）委托给 `DeviceTypeModule`，
每种设备一个实现，放在 `device.<type>` 包。**新增一种设备 = 登记类型 + 一个类型模块 +（可复用的）扩展表与指令族 + 厂商驱动**；
资金、场地、代理、工单、告警、客服不动。

### 四、命名三条规则

1. 平台层（表、列、接口、字段、Port、事件、权限码、菜单）只用通用名：`device` · `slot` · `order` · `start` / `end` / `stop` · `vendor` · `command` / `event`；
2. 设备名只出现在类型层：`device.<type>` 包、`ord_<x>_ext`、驱动族、登记过的类型专属资产与动作（充电宝台账、买断）；
3. 通用不了的，用充电宝的叫法，并登记进类型专属清单。

### 五、一次性改名，不留别名

`dev_cabinet` → `dev_device`；`cabinet_no` → `device_no`（19 张表）；`EV_PILE` → `EV_CHARGER`；`IN_USE` / `RETURNED` → `ACTIVE` / `ENDED`；
`CabinetQueryPort` → `DeviceQueryPort`；`device:cabinet:*` → `device:asset:*`；约 24 个接口路径；前端类型与存储键；
库名 `pb_*` → `sharehub_*`；MQTT 前缀 `pb/` → `sh/`。
**不保留旧路径别名**：两个前端与后端同仓同发，尚无外部调用方；全部是元数据操作，现网数据量小。

### 六、命名卡口（棘轮）

新增 `naming-guard`：类型专属清单之外出现 `cabinet` / `powerbank` / `rent` / `eject` / `pile` 即计数，基线只降不升。

## 否决的方案

| 方案 | 否决理由 |
|---|---|
| 保留 `cabinet` 等名字，只在界面层显示成「设备」 | 名字会继续渗进新代码与新接口；第二种设备上线时改名成本只会更高 |
| 每种设备一张扩展表（`ord_massage_ext`） | 计时型设备的列完全相同，按形态复用更少表、更少代码 |
| 按设备类型拆服务 | 订单 / 计价 / 结算 / 分润复制 N 份（ADR-018 已否决） |
| 保留旧接口别名一个版本 | 没有外部调用方，别名只增加维护面 |
| 建通用物品表 `dev_item` | 目前只有充电宝有可移动物品；等出现第二种借还型设备（如雨伞）再抽 |

## 后果

**正面**：接按摩椅时资金侧、运营端列表页、支付、工单全部复用；命名卡口防止设备名再次渗入平台层。

**代价**：一次覆盖后端、两个前端、迁移脚本、生成文档的改名（S1 阶段）；改名窗口需要短暂停机（分钟级）。

## 待确认

1. 库名改为 `sharehub_*`（推荐），还是维持 ADR-014 的 `pb_core`；
2. 设备权限码用 `device:asset:*`（推荐），还是其他写法；
3. 不保留旧接口别名（推荐）。
