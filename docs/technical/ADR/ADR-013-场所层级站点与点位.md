# ADR-013 场所层级：站点 → 点位（两层）

状态：已接受（2026-07-11 用户确认）

## 背景
场所建模有两种：单层（只有「点位」）或两层（「站点」含多「点位」）。需定稿以锁 `loc_` 表结构与「站点与点位管理」模块粒度。

## 决策
采用**两层**：**场地方 Venue → 站点 Site（网点）→ 点位 Point → 机柜 Cabinet**。
- **站点 Site**：一个物理经营场所（如某商场/机场/写字楼），是**运营与归属的单元**。归属 = 场地方(venue) + 代理商(agent_no,可空=直营) + 区域(region)。
- **点位 Point**：站点内的具体投放位置（如「L1 东门」），一个点位放一台或几台机柜。
- **机柜 Cabinet**：设备，属点位。

## 关键理由
- 贴合运营现实：一个商场=一个站点，内部多个投放位=多个点位，各放机柜。
- **归属只需挂在站点**：代理经营、场地方分成、区域数据权限都以站点为粒度，点位/机柜继承，避免逐机柜维护归属。
- **业务粒度对齐**：坪效分析、工单派单归属、合同分成 都以站点为单位更自然。

## 影响（定稿）
- `loc_` 层级固定：`loc_venue` → `loc_site`(agent_no/venue_no/region) → `loc_location`(点位, site_no) → `dev_cabinet`(location_no)。
- 合同 `loc_contract` 绑 场地方×站点。
- 分润：站点归属驱动 场地方分成(合同) + 代理分成(规则)。
- 数据权限：REGION/站点/AGENT 均以站点归属链解析。
- 运营端模块「站点与点位管理」= 站点(建档/归属) + 点位(投放位) + 场地方 + 合同。

## 备选与否决
- 单层（仅点位）→ 否决：归属要逐点位/机柜维护，坪效/派单/分成缺少自然聚合单元。
