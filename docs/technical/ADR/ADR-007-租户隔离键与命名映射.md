# ADR-007 租户隔离键与 neargo 映射

状态：已接受（2026-07-11）

## 背景
neargo 实测代码（`BaseEntity` v2 / ADR-010）：
- `BaseEntity` 只含 6 列：`id`(BIGINT AUTO) / `region_id` / `created_at` / `updated_at` / `version` / `deleted`，**不含 tenant_id/merchant_id**。
- 隔离键是**域列 `merchant_id`**（各表按需声明）；`NeargoTenantLineHandler` 硬编码列名 `merchant_id`，值取 `TenantContext.getMerchantId()`，头 `X-Merchant-Id`。
- 全局表按前缀 `md_/iam_/rgn_/hw_sku` 及白名单放行不注入。

powerbank 是 SaaS 多品牌，隔离锚点 = **品牌运营商租户**；且 powerbank 另有「点位商户/场地方」概念，若沿用 `merchant_id` 列名会与之语义冲突。

## 决策
1. **隔离列用 `tenant_id`**（语义正确），不用 `merchant_id`。所有需隔离的业务表声明域列 `tenant_id VARCHAR(36)`（存租户全局键 `tenant_no` 值）。
2. powerbank 提供**自有 `PowerbankTenantLineHandler`**（实现 MyBatis-Plus `TenantLineHandler`，`getTenantIdColumn()="tenant_id"`，值取 `TenantContext` 隔离槽），复用 commons 其余全部能力，不改 commons。
3. 复用 commons 的上下文/头**管道**：边缘 `OpaqueTokenAuthFilter` 把租户写入 `TenantContext` 的隔离槽（沿用 `getMerchantId()` 槽承载 tenantId，或后续向 commons 提 PR 加 `tenantId` 槽），头沿用 `X-Merchant-Id` 承载 tenant（powerbank 内部语义即租户）。
4. **命名去歧义**：powerbank「点位商户/场地方」实体命名 **`venue`**（`loc_venue`），不叫 merchant；`merchant`/`商户` 一词在 powerbank 语境保留给「场地方」的口语，物理落 `venue`。
5. 全局表（无租户归属）：租户注册表 `tenant` 自身、权限目录 `iam_permission`、字典 `dict`、供应商目录 `gw_vendor`、硬件型号目录等，经 handler 放行前缀（powerbank 用 `md_/iam_/dict_/gw_vendor`）。

## 影响
- powerbank 库表统一带 `tenant_id`（域列），与 neargo `merchant_id` 平行；DB 可读性强。
- 需 powerbank 侧写 ~15 行 `PowerbankTenantLineHandler` + `DataAutoConfiguration` 装配（`neargo.mp.tenant-enabled` 对等开关）。
- 若 neargo 愿意把 `TenantContext` 加通用 `tenantId` 槽 + 头，powerbank 可更干净复用（列为可选回馈项）。
