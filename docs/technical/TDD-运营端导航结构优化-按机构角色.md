# TDD · 运营端导航结构优化（按机构/角色重组）

状态：**阶段一已实现**（2026-07-29）· 阶段二待放行
关联：[TDD-运营端三级导航](TDD-运营端三级导航.md)（菜单结构 SSOT）· [运营端功能清单 §三](../requirements/运营端功能清单.md)（逐项 SSOT）· [竞品对照](../competitor/jiandianyun/04-菜单对照表.md)

## 1. 动机

对标 [简电云](../competitor/jiandianyun/01-运营端功能矩阵.md)发现：对方把**财务按资金主体切成四个 L2**（平台财务 / 运营商财务 / 商户财务 / 会员财务），每个下面挂各自的收支流水与提现审核。好处是**"这是谁的钱"一眼可见**——运营商想看自己的账，不用在一堆功能里挑维度。

我们原来是**纯职能切分**（分润规则 / 明细 / 结算 / 分录 / 提现 / 对账 / 发票 平铺七项），看不出主体。同样的问题也存在于：
- 站点与点位模块里，**「场地方」（机构主体）和「站点/点位」（物理资产）平级混排**
- 代理商模块里，档案、分润、划拨、结算、绩效平铺，看不出"建档→授权→分钱→看经营"的顺序
- 设备、用户、员工模块同样是长列表平铺

## 2. 约束：为什么不直接拆模块

我们的 nav 用 **`findActiveModule(pathname)` 按路径前缀反推当前域/模块**。一个页面（如 `/locations`）只能归属**一个**模块，否则面包屑与高亮会错乱。

所以"把场地方从站点里拆出来独立成机构模块"必须**先拆页面**（`/locations` → `/locations` + `/venues`），属于有实际成本的改动。

**结论：分两阶段。**

## 3. 阶段一（已实现）：L3 分组小标题

不动域/模块结构、不动路由、不动页面，只在 **L3 层加分组**，用小标题把叶子按「机构/对象」聚类。以最低成本拿到对方那个"一眼看清是谁的"的收益。

### 3.1 数据结构

`NavLeaf` 增加可选字段：

```ts
group?: string;   // L3 分组标题；同 group 的叶子必须相邻
```

纯函数 `groupedLeaves(leaves)` 把叶子聚成连续段，只合并**相邻**同名 group（不跨段合并 → 渲染顺序恒等于数据顺序，不做隐式重排）。

### 3.2 分组方案

| 模块 | 分组 | 组内叶子 |
|---|---|---|
| 设备管理 | 资产台账 / 在线运行 / 资产流转 | 台账·充电宝 / 监控·远控 / 库存·OTA |
| 站点与点位 | **场地资产** / **场地方机构** | 站点·点位·坪效 / 场地方·合同·Onboarding·生命周期·CRM |
| 代理商管理 | **机构档案** / **机构收益** / **机构经营** | 档案·账号·划拨 / 分润配置·收益结算 / 绩效 |
| 财务管理 | **分润与结算** / **平台账** / **伙伴账** / **用户账** | 规则·明细·结算单 / 分录·对账·发票 / 代理分润配置·提现审核 / 用户钱包 |
| 用户管理 | 用户主体 / 风险治理 / 用户资产 | 用户列表 / 风控·黑名单 / 会员·钱包 |
| 员工与权限 | 人与组织 / 授权 / 留痕与考核 | 员工·组织架构 / 角色权限 / 审计·绩效 |

顺带的结构调整（不只是加标题）：
- 站点坪效从"机构区"移到**场地资产**组（它是资产分析，不是机构档案）
- 代理账号管理从末尾提到**机构档案**组（开通账号属于建档动作）
- 财务新增跨域深链 **用户钱包** → `/users?tab=wallets`（补齐"用户账"这一主体，与对方的"会员财务"对齐）

### 3.3 渲染与约束

- `components/layout/secondary-nav.tsx` 新增 `renderLeafSegments()`，panel 与 miller 两种呈现共用；段首出 11px 大写小标题，无 group 时退化为原平铺
- 分组标题全部纳入三语（`lib/i18n/nav-labels.ts`），并由单测强制覆盖
- 单测约束（`lib/nav.test.ts`）：① 同名 group 必须相邻 ② 模块内不得混用「有 group / 无 group」 ③ 财务四组顺序 ④ RBAC 过滤后不产生空组

### 3.4 验证

`tsc` 零错 · `vitest` **56/56**（新增 6 例）· `next build` 全绿 · 实机确认财务渲染为 `分润与结算 / 平台账 / 伙伴账 / 用户账`，场地渲染为 `场地资产 / 场地方机构`，中英文均正常，无 console 错误。

## 4. 阶段二（待放行）：真正按机构拆模块

阶段一是"视觉分组"，机构仍寄生在功能模块里。若要彻底按机构组织，需要：

### 4.1 目标结构

```
渠道与场地  →  改为「合作机构」域
├── 场地方（新页面 /venues）      ← 从 /locations 拆出 venues/contracts/onboarding/lifecycle/crm
├── 代理商（/agents）
└── 站点与点位（/locations 保留 sites/points/analysis）→ 移入「设备运营」或独立「场地资产」域
```

### 4.2 必须先做的两件事

1. **拆页面**：新建 `app/venues/page.tsx`，把 `/locations` 的 5 个机构类 tab 迁过去（含 types/mock/api 不变，仅页面归属变）
2. **nav 解析改造**：`findActiveModule` 需支持**同路径多模块**时按 tab 消歧（签名加 `tab`/`view`），并同步改造调用方 `rail.tsx`（目前只读 pathname、不读 query，改后需包 `<Suspense>`）

### 4.3 收益与成本

- 收益：机构主体（场地方 / 代理商）成为一级经营对象，BD 与 FINANCE 岗的心智路径变短
- 成本：1 个新页面 + nav 解析改造 + 面包屑/高亮回归测试；**风险集中在 `findActiveModule`**，它是整个导航的地基

### 4.4 建议

阶段一已拿到大部分体感收益。阶段二**建议等 `/locations` 页面因业务需要必须拆分时顺带做**，不单独为导航结构去改地基。
