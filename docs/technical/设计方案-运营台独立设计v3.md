# 设计方案 v3 · 运营台独立设计

状态：实施中 · 2026-07-30
**定位变更**：ops-web 只从 C 端取**四个主色**，其余全部独立设计，对标业界密集型后台最佳实践。

---

## 零、这次推翻了什么

前几轮的隐含前提是「ops-web 要长得像 C 端」，于是把手机端的形状语言整体搬了过来。
现在定位澄清后，**这个前提不成立**，以下决定要回退：

| 之前（对齐 C 端 v1/v2） | 现在（独立设计） | 为什么 |
|---|---|---|
| 按钮/输入/筛选全部**药丸** `9999px` | 控件 **6px** | 药丸是消费端语言。密集表格里每行 3~5 个按钮，药丸吃掉横向空间、削弱扫描性 |
| 卡片 `14px` | **10px** | 大圆角在手机端显亲和，在数据台显松散 |
| 抽屉 `20px` | **14px** | 同上 |
| 徽章药丸 | **保留药丸** | 状态芯片是唯一该用药丸的地方——它本来就是「标签」隐喻 |

参照：Linear / Vercel / Stripe Dashboard 的控件圆角都在 4~8px 区间，卡片 8~12px。
shadcn 默认 `--radius: 0.375rem`（6px），也是这个量级。

## 一、Color

**只保留 C 端的四个主色**（品牌一致性的唯一载体），其余独立设计。

| token | 值 | 说明 |
|---|---|---|
| 主色 · mono（默认） | `#18181B` | 运营台默认无彩，主色只做交互标记 |
| 主色 · brand | `#17C3C0` | 需要品牌感时切换 |
| 主色 · blue | `#2F6BFF` | |
| 主色 · purple | `#7C3AED` | |

**中性色：微冷灰，非纯中性。** 纯中性灰读起来像"没选过"；偏冷一档与产品的
科技/设备属性相合，且四套主色（含青绿与蓝紫）都能坐得住。

| 层 | 值 | 对卡片对比度 |
|---|---|---|
| 画布 | `#F1F2F5` | 1.12 —— 卡片浮起来 |
| 卡片 | `#FFFFFF` | — |
| 表头/隔行 | `#F6F7F9` | 1.07（卡片内浅带）|
| 填充块（输入/分段）| `#F1F2F5` | 与画布同深，读作"凹陷" |
| 发丝边 | `#E2E4EA` | 1.27 —— 真的看得见 |
| 正文 | `#16171D` | |
| 次要文字 | `#6E717A` | 4.88:1 过 AA |

**语义色与主色严格分离**（skill 明确要求）：`#12B76A` / `#F79009` / `#F04438` / `#2F6BFF`，
换肤时恒定不变——状态的含义不能随皮肤漂移。

## 二、Type

保持 Nunito + Tajawal + Noto Sans SC 三族不变。

**开放问题（未实施，待定）**：Nunito 是圆润的消费端字体，用在处理金额/设备号的
密集台账上偏"软"。业界密集后台更常用中性无衬线（IBM Plex Sans 有完整的
SC/Arabic 家族，适配我们的三语需求且不是"安全默认选择"）。
但字体已经折腾过两轮（Noto Sans SC 的 CDN 问题），**不在这一轮再动**，单独评估。

已落实：标题 800 字重 / 负字距、金额与计数一律 `tabular-nums`。

## 三、Layout & 信息设计

skill 的核心指引：**dashboard 是被扫描和操作的**，工艺重心从排版转向信息设计。

1. **密度优先**：`--ctl-h` / `--row-h` 两档要真正被消费（此前只定义未使用），
   列表页默认 dense，表单/抽屉用常规档。
2. **状态用形态编码，不只用数字**：告警等级、工单优先级这类需要"一眼看到"的，
   除了色彩还要有形态差异（严重度色条 / 芯片），而不是只靠一个彩色文字。
3. **摘要先于明细**：列表页顶部的统计条是入口不是装饰。
4. **可交互的要看起来可交互**：焦点环已全覆盖（P2 完成）。
