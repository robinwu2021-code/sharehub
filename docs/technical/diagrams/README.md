## 改图

**内容改 `build.py`，样式改 `gen.py`**，然后：

```bash
cd docs/technical/diagrams && python3 build.py
```

生成后会自动跑**越界自检**（元素跑出画布是最常见的低级错误，本次 `05` 就踩了两处：
「请求/响应」卡片落在 x=-33 与 1641）。肉眼看截图不可靠，靠脚本兜。

本地预览：`python3 -m http.server 8899` 后开 `preview.html`。

### 00 与 01 的分工（有意重叠）

`00` 是「这就是整个系统」的单图汇报页，服务层完全展开；`01` 只讲分层关系，服务层抽象成一个盒子。
两张都保留是因为汇报场景不同 —— 若只需一张，用 `00`。

### 让完整图不糊的两个关键决定

架构总图最容易糊在**边数**上。`00` 用两个手法把连线压到 8 条，同时不丢信息：

1. **表前缀写进服务卡内部** —— 省掉 10 条「服务 → 数据层」连线；
2. **横切支撑做成整条色带 + chip，不画连线** —— 它被全域依赖，画线就是 10 条边覆盖全图，
   改用一条带 + 括注「全域依赖，不画连线」表达同一件事。

## 风格约定

| 项 | 取值 | 为什么 |
|---|---|---|
| 画布 | 1600×900（16:9） | 与幻灯片比例一致，插入不留黑边 |
| 底色 | 纯白 | 投影与打印都干净；深色底在会议室投影常糊 |
| 字号 | 标题 42 · 卡片标题 27 · 说明 19 · 连线标签 18 | **本次「文字太小」的核心修正**：按 1600 宽画布定，投到大屏仍清晰 |
| 强调色 | 深青 `#0F7173` | 电力/充电语义；明暗底都立得住 |
| 层色相 | 蓝灰(基础) 绿(场地) 琥珀(设备) 绛红(资金) 紫(用户) | 与文档 mermaid `classDef` 一致，两处可对照 |
| 阴影/渐变 | **不用** | 投影和打印都会糊，且显旧 |
| 字体 | PingFang SC / 微软雅黑 / Source Han Sans 回退栈 | 不依赖网络字体，Mac 与 Windows 都能落地 |

> 中文文件名在部分 PPT 素材管线里会出问题，故文件名一律 ASCII，中文标题写在 SVG 内部。

## 与仓库内 mermaid 图的关系

| | mermaid（`架构图.md` 等） | 本目录 SVG |
|---|---|---|
| 用途 | 仓库内阅读、GitHub 直接渲染 | **PPT / 汇报** |
| 维护 | 随文档改 | 改 `build.py` 重新生成 |
| 覆盖 | 12 张（含细节图） | 10 张（挑汇报要用的） |

**两处内容重叠，改架构时需同时更新**。mermaid 已统一注入 `fontSize: 20px` 主题（原为默认 16px，是「文字太小」的另一半原因）。
