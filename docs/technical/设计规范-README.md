## 被否决的方案与原因（**再次提出前先看这里**）

过时的方案文档已删除（正文见 git 历史：`git log --diff-filter=D -- 'docs/technical/设计*'`）。
它们唯一的长期价值——"为什么不那样做"——蒸馏在下表，避免同一个方案被反复提出：

| 曾提出的方案 | 为什么否决 |
|---|---|
| 按钮/输入用**药丸**（9999px）| 药丸是消费端语言。密集表格每行 3~5 个按钮，药丸吃横向空间且削弱扫描性。业界密集后台控件圆角都在 4~8px。**药丸只留给徽章**（"标签"隐喻）|
| 拉丁字族用 **Nunito** | 圆润的消费端气质，用在处理金额/设备号的台账上偏"软"。改 IBM Plex Sans：为技术界面设计、数字辨识度高，且**一族覆盖拉丁/阿语/中文**，三语混排字重字宽基线一致 |
| 默认主色用**简电青** `#17C3C0` | 运营台主色会出现在每个链接/激活态/主按钮上，频率远高于手机端，彩色主色显跳。默认保留黑白灰，简电青作可选皮肤 |
| 引入 C 端三个表现手法（渐变 hero / tint 图标底片 / 票根虚线）| 与"密集后台克制表达"冲突，且都是装饰性收益。对应 token 已删 |
| `data-ground` 灰底/白底**双轨** | 布局定案"两级色调 + 灰块作分隔"后与之矛盾——画布若也是白的，分隔手段就失效。双轨还意味着每个组件维护两种构图、测试面翻倍 |
| 白底体系用**统一描边**做卡片边界 | 线太多界面发"碎"，密集表格里每行一条线噪音极大。改用**色块 + 阴影**：色块是"面"的语言、阴影是"层"的语言，都比线安静 |
| 外壳用**三级灰阶梯**表达导航层级 | 导航整片发灰、喧宾夺主。一级菜单是主功能入口，不该被压到背景里。改两级：一级白、二级灰，**直接对应主次关系**而非靠深浅暗示 |
| 白底体系**溶解容器**（表格全宽铺开、KPI 变数字行）| 矫枉过正，失去了"卡片式边界"的整齐感 |

## 自动化守卫

`lib/design-tokens.test.ts` 会在 `npx vitest run` 时检查：

1. `components/` 不使用废弃圆角类（`rounded-sm/md/lg/xl/2xl/full`）
2. 组件层不写死颜色字面量（hex / rgb / oklch）
3. **豁免清单不许变长** —— 加豁免必须改数字，从而在 review 里显形

新增页面/组件时这些会自动拦住最常见的偏离。

## 给后续会话的三条提醒

1. **颜色一律改 token，不在组件里写值。** 改一个 hex 就能让守卫测试变红。
2. **改 `globals.css` 的 token 后必须清 `.next` 重启验证。** Turbopack 会缓存
   类名候选与部分 CSS，出现过三次"源码改了但 served CSS 是旧的"，
   且**肉眼看不出来** —— 用 `curl` 拉 served CSS 逐字确认最可靠。
3. **写类名示例文案要避开完整类名形状。** Tailwind 4 扫描所有源文件的字符串与注释，
   写 `z-[var(--z-*)]` 这种带通配符又像类名的文本会生成非法 CSS、
   **让整站白屏**。用省略号或举真实档位名。
