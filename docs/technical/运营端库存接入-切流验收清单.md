# 运营端库存接入 · 切流验收清单

> 适用：运营端库存从「本地设备表 + 本地库存」切到「独立进销存（ai-shop `inventory-svc`）为准」。
> 依据：[开发方案](运营端库存接入-开发方案.md) 阶段 7、[对接明细](设备全生命周期-Web与服务对接明细.md) §9.4 T6、[宿主接口需求](库存服务-宿主接口需求-2026-10-30.md)。
> 已定：**所有代码开发完成后再切**（Q3）；引擎默认 SERVICE，不回落本地。

## 一、切流前必须为「是」

| # | 条件 | 怎么确认 | 现状（2026-10-30） |
|---|---|---|---|
| 1 | 库存服务版本已锁定 | 负责人给出提交号与部署包；`e2e.py` 开头的契约探测全过 | 本机临时连 8086（`d936435f5` 构建），**未经负责人确认** |
| 2 | 生产档案含宿主用途 | 生产 `sharehub.json` 有 TRANSFER_IN / TRANSFER_OUT / REQUISITION；OPENING 的附件来源已定 | **阻塞**：需求 #12、D5 |
| 3 | 升级不会让旧键冲突 | 对方确认需求 #14，或切流后不再升级服务直到确认 | 待对方回复；宿主主数据已改为每次新键 |
| 4 | 事件拉取（F06） | 系统任务拉取、去重、失败重试、旧事件不覆盖新状态 | **未做** |

## 二、故障场景（每条都要在真实库存服务上过一遍）

| # | 场景 | 操作 | 期望 |
|---|---|---|---|
| S1 | 远端已提交、宿主丢响应 | 断网或杀进程卡在远端返回之后（入库 / 出库 / 签收 / 调拨发货 / 处置） | 执行异常里出现「结果不明」；查回后判为已执行；原人「原样重试」补完本地，远端不重复记账 |
| S2 | 宿主重启 | 有 PREPARED 操作时重启后端 | 5 分钟内自动查回任务把步骤判清；页面能看到并重试 |
| S3 | 远端拒绝 | 库存不足、对象停用等 4xx | 操作记 REJECTED，本地未改；修正后同键重提成功 |
| S4 | 两人争抢领取同一台 | 两个账号同时安装 / 签收同一柜 | 只有一人成功；另一人看到明确提示；出库池状态与本地一致 |
| S5 | 部分实收 | 调拨发 N 台只收到 N−k 台 | 收到的进目的仓，差异留在途或走盘点；不丢账 |
| S6 | 旧事件 | 重放一条比当前状态旧的事件 | 不覆盖新状态（依赖 F06） |
| S7 | 远端不可达 | 停掉库存服务 | 写操作 409 带原因、本地不变；查询给出不可达提示而非 0；恢复后自动补完 |
| S8 | 服务升级 | 升级库存服务后重放升级前的业务键 | 不冲突（需求 #14）；e2e 全过 |

## 三、迁移演练（在业务库副本上）

1. 先处理执行异常，直到为空。
2. 「迁移到独立进销存」看计划：在仓、已出库的数量与本地台账一致。
3. 执行；中途杀进程再执行，确认没有重复入库、重复出库（稳定键）。
4. 跑「对账」（全部），差异应只剩已知的历史脏数据；逐条按处置建议清掉。
5. 记录迁移耗时与失败条目，作为生产切流窗口的依据。

## 四、切流步骤

1. 冻结库存写操作（公告时间窗）。
2. 确认第一节全部为「是」。
3. 执行迁移 → 对账清零（或差异已逐条认可）。
4. 系统参数 `inv.engine = SERVICE`（默认已是；确认无本地回落）。
5. 解冻；第一天每 2 小时跑一次对账，执行异常有人值守。

## 五、回退

库存服务不回写本地，切流后**不回切本地引擎**。出现问题时：停写 → 用对账定位差异 → 在库存服务或本地按处置建议逐条纠正 → 恢复。
