## 〇、阶段结论

账务这一段的**原则写对了**：分录不继承 `BaseEntity`、服务只暴露「查 + 记一组分录」、借贷平衡在服务端判、凭证下钻的 `balanced` 由服务端出（`LedgerService.java:9-35` · `FinanceController.java:417-431`）；对账处置人只认会话、逐笔留痕、`NULL` 未处置行不漏（`ReconcileServiceImpl.java:92-121` · V115）；取号用数值序而非字典序，避开了 S8 的 `BizNoAllocator` 问题（`FinNos.java:29-52`）。

**问题的形状是「账本有了，没人记账；对账页有了，没人对账」**：ADR-032 规定内部复式账是第一阶段的**账务记录来源**，但全仓只有「手工凭证」一个写入方，收款、退款、分润、结算、提现打款没有一笔进账；对账批次只来自演示种子。现存的那一个写入口还能写出不平的账。共 **6 个 P0**（现有代码 2、新建 4，其中 2 个以网关能力为前提）：

### 2.1 「注释说有、代码没有」（本阶段 3 处）

### 2.2 「桩实现对外报告成功」的对账版本

S5、S9 已出现两次。`StubPaymentPort` 无条件装配、一律 `PAID`（`StubPaymentPort.java:24-60`）；类注释说「真正的闸做在会把钱变成余额的那条路上」——充值有闸，**对账没有**。只要渠道侧取自本地支付单或桩，三方对账永远平，且「平」会被当作验收证据（AC-10）。

**规则**：对账、网关核销在 `PaymentPort.simulated()` 为真时只能产出 `SIMULATED`，页面显示「模拟通道，结论无效」；`MATCHED` 只能由**外部来源**的数据对出来（OPT-S12-08 / 14）。演示种子里的 `RCN0001 MATCHED` 同理应改为 `SIMULATED`（种子归属会话处理）。

### 2.4 账务与对账的数据范围

`acct_account`、`acct_ledger`、`recon_diff` 未登记，`recon_task` 在台账（`known-unscoped-owned-tables.txt:64`）。今天**没有可达泄露**：`AGENT` 角色不持任何 `finance:ledger:*` / `finance:recon:*`（`RolePerms.java:108-122`）。但 S0 的「空范围 = 全部」（OPT-S0-11）意味着任何被授予这些码的自定义角色都看全量。这些是**平台账**，没有「按商家收敛」的语义（应付商家的商家视图走 S11 应付台账）。方案：登记为「平台级」——带 `SITE / REGION / AGENT` 范围的会话一律拒绝，并加卡口「`AGENT` 及带范围角色不得持 `finance:ledger:*`、`finance:recon:*`、`finance:gateway:*`」（OPT-S12-12，与 OPT-S0-13 同批）。另：真源表给 VIEW 角色 `finance:ledger:read`（`功能权限清单.md:107`），`RolePerms.VIEWER` 没有，随同一任务对齐。
