**采购单状态机**（功能清单的「草稿 → 已提交 → 已审核 → 部分收货 → 已完成 / 已关闭」）：

```
DRAFT ──SUBMIT──▶ SUBMITTED ──APPROVE──▶ APPROVED ──RECEIVE(未收齐)──▶ PARTIAL ──RECEIVE(收齐)──▶ COMPLETED
  ▲                   │                      │  └──RECEIVE(一次收齐)──────────────────────────▶ COMPLETED
  └──────REJECT───────┘                      │                           │
DRAFT / SUBMITTED ──CLOSE──▶ CLOSED          └────────CLOSE──────────────┴──▶ CLOSED（剩余在途核销为 0）
```

- `RECEIVE` 只由收货确认触发，不出按钮；`COMPLETED`、`CLOSED` 为终态。
- 有未确认的收货单时 `CLOSE` 返回 409（先取消草稿收货单），避免关单后又入库。
- 词表：`DRAFT / SUBMITTED / APPROVED / PARTIAL / COMPLETED / CLOSED`，DDL 用 CHECK 固定（`V112__cabinet_status_vocabulary_check.sql` 同形），文档化进 `known-undocumented-status-columns` 的检查范围。

**三条硬规则在库层与服务层各由什么保证**：

| 规则 | 库层 | 服务层 |
|---|---|---|
| 确认收货才入库 | 采购来源的设备行 `origin_ref NOT NULL`（CHECK）；`origin` 进 CHECK | 收货确认是唯一建档调用方；**关闭直接建档入口**（OPT-S4-08） |

### 2.3 设备状态词表与 RQ-AST-07

运营方要的是**看板与报表上的十个状态**，不是十个状态机节点。把采购阶段塞进设备状态机会让「没有设备行的东西有状态」——「已订购」时设备还不存在。建议**存储态不扩、展示态派生**，与 S5 机柜共用一张对照：

| 运营方状态 | 派生口径（建议） | 今天能否表达 |
|---|---|---|
| 已订购 | 采购单行在途数（`ordered_qty − received_qty`，单据 `APPROVED / PARTIAL`） | ❌ → OPT-S4-01 |
| 已收货 | `IN_STOCK` 且 `qc_status = PENDING` | ◐ 机柜可；充电宝 → OPT-S4-14 |
| 库存可用 | `IN_STOCK` 且质检放行 | ✅ |
| 已安装 | 机柜 `DEPLOYED` / 宝 `IN_CABINET`、`RENTED` | ✅ |
| 维修中 / 损坏 | 今天合并为 `FAULT` | ❌ 需拆：选项 A 加 `REPAIRING`（维修工单开工即进入）；选项 B 用 `fault_kind` 区分。**需运营方确认判定规则**，与 S5 SF-DEV-01 同口径 |
| 遗失 | 宝 `LOST`；机柜无 | ◐ 机柜遗失是否需要，需运营方确认 |
| 已撤出 | 撤机后随回仓调拨在途（`inv_transfer.source_type = REMOVAL`、`IN_TRANSIT`） | ◐ 有数据，无派生 |
| 退回仓库 | 撤机回仓调拨已签收后的 `IN_STOCK` | ◐ 同上；与「库存可用」的区别在是否已复检 |
| 报废 | 机柜 `RETIRED` / 宝 `SCRAP` | ✅ |

派生态作为出参字段 `assetStatus` 提供给台账、报表与导出，存储态与状态机不变（OPT-S4-16）。

### 2.4 资产价值不落在设备表上

期初价值与采购成本是财务数据，而 `dev_cabinet` 是代理可读的表（`device:cabinet:read`、`DataScopeRegistration` 按代理收敛），出参 `Cabinet` 也在代理视图里用。**方案**：新表 `inv_asset_cost`——`(item_type, device_no)` 唯一 · `origin / origin_ref` · `cost_basis`（`INVOICE / OPENING_DOC / OPENING_ESTIMATE / NONE`，CHECK）· `net_cost / vat_amount DECIMAL(18,2)`（可空，期初「无可靠依据」时为空）· `currency` · `supplier_no / po_no` · 记录人与时间；只经 `device:procurement:read` 的端点与报表读模型读取。更正以审计留痕，不覆盖原值。
