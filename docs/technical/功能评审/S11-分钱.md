## 〇、阶段结论

分钱这一段**逐单分润做得认真**：基数取实收、比例写快照、唯一键 `(order_no, dimension, payee_no, basis)` 防事件重投（`V53__share_basis.sql:60`）、金额向下取整保证合计不超基数、欠费单不分润（只在收款成功的 `markPaid` 后发事件，`RentOrderServiceImpl.java:764-770`）；提现审批人、放款人服务端回填，渠道流水号唯一（`V57:36`），「审批人 ≠ 放款人」三态可配且默认拦截；资金四表的数据范围用生成列锚点补上了（`DataScopeRegistration.java:138-143`）。

**问题集中在「分完之后」**：结算单确认后仍会被改；钱从系统里出去有两条互不相认的路（结算单与提现），中间没有应付台账，于是**提现可以提任意金额**；第一阶段已决「场地方不结算」而定时任务照样给场地方出单。共 **8 个 P0**：

### SF-FIN-03 应付台账（无代码，评审设计）

**结论**：新建，P0。它是本阶段多数 P0 的共同解：提现余额（#3）、结算单 `PAID`（#4）、冲回结转（#6）、清退结清（S10）都需要「欠这个商家多少钱」这一个真值。今天这个数分散在结算单、提现单、`acct_account.balance`（无人写）三处，彼此不相认。

**证据**：无代码；设计依据 ADR-032 §1.2 / §2.2 ③、架构设计 §6.2 / §八、功能清单 SF-FIN-03、RQ-SHR-04/05/06、AC-06、`AgentExitServiceImpl.java:124-131`（清退门禁今天用三张表拼）。

#### 设计评审

**1. 两张表：流水只追加，余额是投影**

```sql
-- 流水：唯一真值。只 INSERT，不 UPDATE、不 DELETE
CREATE TABLE stl_payable_entry (
  id            BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  entry_no      VARCHAR(36)  NOT NULL,
  tenant_id     VARCHAR(36)  NOT NULL DEFAULT 'MAIN',
  agent_no      VARCHAR(36)  NOT NULL COMMENT '商家（ADR-032 结算单元）',
  period        VARCHAR(7)   NOT NULL COMMENT '应付归属账期 YYYY-MM',
  currency      VARCHAR(8)   NOT NULL,
  kind          VARCHAR(24)  NOT NULL COMMENT 'ACCRUE/ADJUST/PAYOUT/PAYOUT_REVERSAL/HOLD/RELEASE/CARRY_OUT/CARRY_IN',
  direction     VARCHAR(8)   NOT NULL COMMENT 'CREDIT=应付增加 / DEBIT=应付减少（平台视角，应付是负债）',
  amount        DECIMAL(18,2) NOT NULL COMMENT '恒为正，方向由 direction 表达',
  source_type   VARCHAR(24)  NOT NULL COMMENT 'SETTLEMENT/ADJUSTMENT/PAYOUT/WITHDRAWAL/CARRY',
  source_no     VARCHAR(64)  NOT NULL,
  external_ref  VARCHAR(64)      NULL COMMENT '付款外部单号（银行回单 / 会计系统付款号）',
  payout_source VARCHAR(16)      NULL COMMENT 'LOCAL / ACCOUNTING（PayoutSource 实现名）',
  occurred_at   DATETIME(3)  NOT NULL COMMENT 'UTC',
  created_by    VARCHAR(36)  NOT NULL,
  created_at    DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE KEY uk_payable_entry_no (entry_no),
  UNIQUE KEY uk_payable_entry_src (source_type, source_no, kind),
  UNIQUE KEY uk_payable_entry_ext (payout_source, external_ref),
  KEY idx_payable_entry_agent (agent_no, period)
) COMMENT='应付流水（只追加）';

-- 余额：按 商家 × 账期 × 币种 的投影，与流水同事务更新
CREATE TABLE stl_payable (
  id          BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  tenant_id   VARCHAR(36)  NOT NULL DEFAULT 'MAIN',
  agent_no    VARCHAR(36)  NOT NULL,
  period      VARCHAR(7)   NOT NULL,
  currency    VARCHAR(8)   NOT NULL,
  accrued     DECIMAL(18,2) NOT NULL DEFAULT 0 COMMENT '应得：已确认结算单',
  adjusted    DECIMAL(18,2) NOT NULL DEFAULT 0 COMMENT '调整：已审批调整单（可负）+ 结转',
  paid        DECIMAL(18,2) NOT NULL DEFAULT 0 COMMENT '已付',
  held        DECIMAL(18,2) NOT NULL DEFAULT 0 COMMENT '在途冻结：未办结的提现',
  outstanding DECIMAL(18,2) AS (accrued + adjusted - paid) STORED COMMENT '未结',
  version     BIGINT NOT NULL DEFAULT 0,
  updated_at  DATETIME(3) NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  PRIMARY KEY (id),
  UNIQUE KEY uk_payable (tenant_id, agent_no, period, currency),
  CONSTRAINT ck_payable_held CHECK (held >= 0)
) COMMENT='应付台账（商家 × 账期，投影）';
```

- **为什么余额要单独一张**：可提余额判断需要一行可以加锁、可以做条件更新的记录；每次从流水求和既慢、又无法防并发超提。投影可由流水**全量重建**（`rebuild(agentNo)`），每日对账任务比对两者，不等即告警。
- **只追加的库层保证**（承接 OPT-S0-20 WORM）：应用账号对 `stl_payable_entry` 只授 `INSERT, SELECT`；另加 `BEFORE UPDATE` / `BEFORE DELETE` 触发器 `SIGNAL SQLSTATE '45000'`（MariaDB 支持）作为纵深防御；实体不继承 `BaseEntity`（无 `version / updated_at / deleted`），Mapper 只暴露 `insert / select*`，卡口测试扫描 `StlPayableEntryMapper` 的 `update / delete` 调用为 0。更正一律追加反向分录（`PAYOUT_REVERSAL`、反向 `ADJUST`）。

**2. 借贷方向**（平台视角，应付商家是负债）

| 动作 | kind | direction | 对投影 | 写入时机（同一本地事务） |
|---|---|---|---|---|
| 结算单确认 | `ACCRUE` | CREDIT | `accrued += total` | `SettlementService.confirm`，状态条件更新成功之后 |
| 调整单审批（正 / 负） | `ADJUST` | 正数 CREDIT / 负数 DEBIT | `adjusted += amount` | `AdjustmentService.approve` |
| 付款登记 | `PAYOUT` | DEBIT | `paid += amount` | `PayoutService.record`（经 `PayoutSource`） |
| 付款冲正（银行退票） | `PAYOUT_REVERSAL` | CREDIT | `paid -= amount` | `PayoutService.reverse` |
| 提现申请（冻结） | `HOLD` | —（备查，不计入 outstanding） | `held += amount` | `WithdrawalService.apply` |
| 提现驳回 / 失败 / 登记到账 | `RELEASE` | — | `held -= amount` | `audit(REJECT)` / `pay(FAIL)` / `pay(PAY)`（到账时同事务再写一条 `PAYOUT`） |
| 负数结转 | `CARRY_OUT` / `CARRY_IN` | DEBIT 本期 / CREDIT 下期（金额为负额的绝对值，方向相反） | 本期 `adjusted += x`、下期 `adjusted -= x` | 结算单确认时若本期 `outstanding < 0`，按 §五 #5 裁决 |

`HOLD / RELEASE` 只动 `held`，不进 `outstanding`——冻结不是付款；会计复式分录（`acct_ledger`）只对 `ACCRUE / ADJUST / PAYOUT / PAYOUT_REVERSAL` 过账，由 S12 记账在同事务调用 `LedgerService.post`（本文不展开）。

**3. 可提余额与防超提**

- 可提余额 = `Σ outstanding − Σ held`（该商家、该币种，**只取已确认结算单所在账期**；未出账的 `PENDING` 分润不可提——它还可能被冲回）。
- 申请时一条条件更新完成「判余额 + 冻结」，影响行数必须为 1：
  `UPDATE stl_payable SET held = held + :amt WHERE agent_no=:a AND currency=:c AND period=:p AND outstanding - held >= :amt`；跨多个账期时按账期从早到晚逐行冻结，任何一行失败整笔回滚。并发两笔申请只能有一笔拿到余额。
- 提现单记 `hold_entries`（冻结到哪些账期各多少），到账时按同样分布写 `PAYOUT`。

**4. 与相邻单据的衔接**

| 单据 | 衔接 | 今天 |
|---|---|---|
| 结算单 | 确认 → `ACCRUE`；台账某账期 `outstanding = 0 且 held = 0` 时把该期结算单置 `PAID`（`SettlementStateMachine` 的 `PAY` 边第一次有调用方）；`PAID` 由台账驱动，不开放手工改 | `PAY` 边无调用方 |
| 调整单 | 审批 → `ADJUST`；已出账的调整不可作废，更正开反向单 | 只进结算单、可作废 |
| 付款登记 | `stl_payout_record`（来源、外部单号唯一、可部分可多次）→ `PAYOUT`；`PayoutSource` 第一阶段唯一实现 `LocalPayoutSource`，会计系统读回时加实现、按 `(payout_source, external_ref)` 幂等 | 不存在 |
| 提现 | 申请 `HOLD`、到账 `PAYOUT + RELEASE`、驳回 / 失败 `RELEASE`；**提现单是付款登记的一种来源**（架构设计 §九：「以应付台账为唯一真值」） | 与一切无关 |
| 退款冲回 | `REVERSAL` 分润进下一期结算单，确认时随 `ACCRUE` 减少；若当期为负走结转 | 不存在 |
| 商家清退（S10） | 结清门禁改为：无 `PENDING` 分润、无 `GEN` 结算单、所有账期 `outstanding = 0 且 held = 0`；替换 `AgentExitServiceImpl.java:124-131` 的三表拼凑与跨模块直查 SQL | 门禁不可达 |
| 会计系统（ADR-032 接缝③） | 「已付」只经 `PayoutSource` 写入，表结构不变 | — |

**5. API 与代码结构**

- 端点见 §4.1、§4.2；包 `finance.payable`（服务 `PayableService`：`accrue / adjust / hold / release / payout / reversePayout / carry / rebuild`，**其他服务只经它写台账**）；`PayoutSource` 接口与 `LocalPayoutSource`。

- 测试：并发两笔提现只成一笔；结算单确认重复调用只写一条 `ACCRUE`（唯一键）；`rebuild` 与投影一致；对流水表执行 `UPDATE` 被触发器拒绝。

### 2.1 两条出钱路径互不相认（本阶段 P0 #3、#4 的根）

## 四、给前端的契约草案

**草案，后端实现前可再议**；字段 camelCase、`xxxNo`、`xxxAt`、枚举大写下划线；端点只用既有前缀。新权限码**先登记真源表再用**。

### 4.1 应付台账（OPT-S11-04、16）

| 方法 | 路径 | 权限 | 说明 |
|---|---|---|---|
| GET | `/api/trade/payables?agentNo=&period=&currency=&hasOutstanding=&page=&size=` | `finance:payable:read`（新） | 行：`{agentNo, agentName, period, currency, accrued, adjusted, paid, held, outstanding, settleNo, settlementStatus}` |
| GET | `/api/trade/payables/{agentNo}/{period}` | 同上 | 行 + `entries: [{entryNo, kind, direction, amount, sourceType, sourceNo, externalRef, occurredAt, createdBy}]` |
| GET | `/api/agent/my/payables?period=` | `agent:settlement:read` | 同列表形状，限本商家（数据范围 `AGENT`） |
| GET | `/api/trade/payables/{agentNo}/available?currency=` | `finance:payable:read` · 商家用 `/api/agent/my/payables/available` | `{currency, outstanding, held, available}` |

- `kind` 取 `ACCRUE / ADJUST / PAYOUT / PAYOUT_REVERSAL / HOLD / RELEASE / CARRY_OUT / CARRY_IN`；`direction` 取 `CREDIT / DEBIT`
- 「应付对账单」导出走导出中心（S13），不另开端点

### 4.2 付款登记（OPT-S11-05）

| 方法 | 路径 | 权限 | 入参 / 出参 |
|---|---|---|---|
| POST | `/api/trade/payouts` | `finance:payout:record`（新） | `PayoutReq {agentNo, period, currency, amount, paidAt, externalRef, channel, note, requestNo}` → `Payout` |
| GET | `/api/trade/payouts?agentNo=&period=&page=&size=` | `finance:payout:read`（新） | `PageResult<Payout>` |
| POST | `/api/trade/payouts/{payoutNo}/reverse` | `finance:payout:reverse`（新） | `{reason}` → `Payout`（追加冲正，不改原记录） |

- `Payout {payoutNo, agentNo, period, currency, amount, paidAt, externalRef, channel, source, status, createdBy, createdAt}`；`source` 取 `LOCAL / ACCOUNTING / WITHDRAWAL`；`status` 取 `RECORDED / REVERSED`

### 4.3 提现（OPT-S11-03、16、20）

- `POST /api/trade/withdrawals` 入参改 `WithdrawApplyReq {amount, currency, requestNo, note?}`（商家会话）；运营代申请另加 `payeeNo`，需 `finance:withdrawal:apply_on_behalf`（新）。删除 `payeeType / payeeName / bankCode / accountNo`——收款账户在审批时按默认账户快照

- `Withdrawal` 出参加 `holdEntries: [{period, amount}]`、`accountChangedAfterApply: boolean`
- `GET /api/agent/my/withdrawals?status=&page=&size=` · `agent:settlement:read` · 出参不含审批人编号
