## 〇、一页结论

- **按运营顺序**把 90 个功能排成 16 个阶段：从平台底座、商家入驻，一路到分钱、报表；每个功能只评一次。
- **每个功能评三个维度**：数据库、API、代码结构，各有固定检查清单（§三）；结论必须有证据（类、表、端点、测试、棘轮台账条目），不凭印象。
- **只评审、不改代码**。每条优化方案落成一个带编号的任务（`OPT-S<n>-<序号>`），标优先级、规模、依赖、是否需运营方裁决，最后汇总成一份可排期的清单。
- **先做一个样板阶段**（建议 S1 商家入驻），确认格式与深度后，再按批推进。

## 一、运营顺序与阶段划分

顺序取自项目已有的两条主线并补上运营方需求新增的环节：
[必要功能清单-从入驻到到账](../../requirements/必要功能清单-从入驻到到账.md)（入驻段 ①–⑥、分钱段 ⑪–⑮）与

## 二、评审方法

每个阶段按四步走：

| 步 | 做什么 | 产物 |
|---|---|---|
| ① 取证 | 用证据包脚本按功能切出：涉及的类（取自代码清单）、表（实体注解与迁移）、端点（`contract.json`）、测试、**棘轮台账命中条目**（`backend/known-*.txt`）、卡口脚本输出 | 每个功能一份证据摘要 |
| ② 逐项检查 | 按 §三 的三张清单逐条过；对照运营方需求与运营端矩阵看差距 | 每个检查项：通过 / 问题（带 `文件:行`） |
| ③ 定方案 | 每个问题给优化方案：数据库变更（DDL 草案与迁移顺序）、API 变更（新增 / 修改 / 废弃端点与形状）、代码变更（包归位、拆分、状态机、事务、测试） | 优化方案 |
| ④ 落任务 | 方案拆成可排期的任务，标优先级、规模、依赖、是否需裁决 | `OPT-S<n>-<序号>` |

**证据纪律**：

- 结论引用到 `文件:行` 或端点、表名；「无问题」也要写清看了什么；
- 子代理或脚本给出的结论，涉及缺陷与冲突的一律回到代码亲自复核后再写入；
- 运营方尚未裁决的口径（对齐文档 K4–K8、整理稿 🔴 待确认项）**给选项与各自的代价，不替运营方选**。

## 三、检查清单

### 3.1 数据库

| 编号 | 检查项 | 证据来源 |
|---|---|---|
| DB-1 | **表归属**：每张表在 `module-graph.py` 有唯一主模块；与目标包一致；无跨模块 JOIN（例外只有 `ReportMappers`） | `module-graph.py` · `arch-guard.py` |
| DB-2 | **业务键与幂等键**：`xxx_no` 唯一；写操作的请求号、事件号、外部单号有唯一约束 | 迁移脚本 · 实体 |
| DB-3 | **状态列**：有词表校验、有状态机、有文档 | `known-unvalidated-vocab-columns` · `known-undocumented-status-columns` |
| DB-4 | **金额与币种**：精度、币种列、只增不改的账务表 | db-design §1 · 实体 |
| DB-5 | **时间**：UTC 存储、`xxx_at` 命名、业务时区换算 | 实体 · `BizClock` |
| DB-6 | **归档与软删**：无物理删除；归档字段一致 | 实体 · `Archivable` |
| DB-7 | **数据范围锚点**：按商家、站点收敛的表带锚点列并已登记 | `known-unscoped-owned-tables` |
| DB-8 | **个人数据**：是否应进 `sharehub_pii`；哈希或脱敏 | ADR-009 · 实体 |
| DB-9 | **索引**：列表筛选、报表查询、外键关联有索引 | 迁移脚本 · 查询 |
| DB-10 | **实体与库一致** | `entity-column-diff.py` |
| DB-11 | **迁移策略**：只加新版本、不改旧版本；MariaDB 兼容；存量数据回填 | `db/migration` |

|---|---|---|
| API-1 | **前缀**：B 端只用 6 个 `/api` 前缀；C 端 `/mp`；内部 `/internal` | `contract.json` |
| API-2 | **出入参形状**：请求只能是 `XxxReq`，响应只能是 `XxxVO` / `PageResult<XxxVO>`；不许实体、不许 `Map`；只赋白名单字段 | `known-entity-request-bodies` · `known-map-request-bodies` · `known-entity-writable-fields` |
| API-3 | **权限码**：在真源表中；读写分离；高风险动作（退款、调整、作废、放款）独立码 | `known-perm-ssot-gaps` · `perm-ssot-align.py` |
| API-4 | **数据范围与属主**：B 端按数据范围收敛；C 端属主校验 | `known-mp-unscoped` |
| API-5 | **幂等**：写端点可安全重试；重复提交返回同一结果 | 实现 · 测试 |
| API-6 | **列表与筛选**：分页、筛选维度满足运营端矩阵；导出走导出中心 | `known-single-page-search` · 矩阵 |
| API-7 | **错误**：错误码 + 三语文案；非法状态迁移用统一异常 | `known-chinese-error-literals` · `known-raw-illegal-state` |
| API-8 | **前后端契约对齐**：字段、表单、状态动作一致 | `api-align.py` · `known-api-align-gaps` · `known-form-field-drift` · `known-missing-ui-transitions` |
| API-9 | **命名**：动作端点用动词；不提供 `delete*`，用 `archive` / `unarchive` / `remove` | `contract.json` |

### 3.3 代码结构

| 编号 | 检查项 | 证据来源 |
|---|---|---|
| CODE-1 | **包归位**：与包名规划一致；控制器随域；无反向依赖跨 Maven 模块 | 代码清单 §三 · `arch-guard.py` |

## 七、边界与风险

| 项 | 处理 |
|---|---|
| 评审期间不改代码 | 只写评审文档；需要验证的猜测（如并发重复扣款）在任务里写「先写复现用例」 |

| 多会话并行开发（`CLAUDE.md`） | 评审读的是当前分支代码；提交只用显式路径 |
| 规模 | 90 个功能、16 份评审；样板确认前不批量推进 |
