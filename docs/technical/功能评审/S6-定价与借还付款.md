## 〇、阶段结论

借还主链路的**计价内核**写得认真：全程 `BigDecimal`、计价快照「展开结构而非引用」、倍率下单时定格、券与免单「先算后核销、抢输重算」、出宝回执用条件更新且幂等、补缴金额只从订单取。

### 2.4 需运营方裁决：K4、K5、C04（给选项与代价，不替运营方选）

## 四、给前端的契约草案

**草案，后端实现前可再议**；字段命名遵循 camelCase、`xxxNo`、`xxxAt`、枚举大写下划线；金额一律十进制字符串（`"17.50"`），不用浮点数。

### 4.1 运营端订单列表与详情（OPT-S6-26、27）

- `GET /api/trade/orders` · 权限 `order:order:read`（数据范围照旧）
- 入参：`page, size, from, to`（业务日 `YYYY-MM-DD`，按 `startedAt` 折算业务时区，区间 ≤ 93 天）· `agentNo, siteNo, cabinetNo, powerbankNo, cUserNo`（均精确）· `orderNo`（精确，替代 `keyword` 的模糊匹配）· `status`（`DISPENSING / IN_USE / RETURNED / SETTLED / CLOSED / EXCEPTION`，可多值逗号分隔）· `payStatus`（`PENDING / UNKNOWN / PAID / UNPAID`）
- `keyword` 保留一个版本周期（仍按订单号 / 用户号），之后下线
- 行 `OrderRow`：`orderNo, cUserNo, agentNo, agentName, siteNo, siteName, cabinetNo, returnCabinetNo, powerbankNo, status, payStatus, startedAt, endedAt, durationMin, amount, paidAmount, couponAmount, memberDiscountAmount, waivedAmount, capTotal, buyout, planNo, payNo, payChannel, paidAt, currency`
- 删除：`feeAmount`、`depositAmount`（双写退役）；`IN_USE` 行附 `estimate {durationMin, payable, capped}`
- 详情 `GET /api/trade/orders/{orderNo}`：行字段 + `priceHit {level, ref, filters, multiplier}`（来自快照）+ `payments: PaymentRow[]`
- 导出：不在本端点，走导出中心（S13）

### 4.2 支付流水（OPT-S6-19）

- `GET /api/trade/payments?from=&to=&orderNo=&cUserNo=&type=&status=&channelCode=&page=&size=` · 权限 `order:payment:read`（拟新增，先登记真源表）
- `PaymentRow {payNo, orderNo, cUserNo, type, amount, currency, channelCode, status, requestNo, channelTxnNo, initiatedAt, paidAt, settledAt, failReason}`
- `type`：`RENT / MAXCHARGE / REPAY / DEPOSIT / RECHARGE / MEMBERSHIP`；`status`：`INIT / UNKNOWN / PAID / FAILED / CLOSED / REFUNDED`

### 4.3 收费方案（OPT-S6-01、02、05）

- `POST /api/trade/price-plans` · `pricing:plan:create`；`POST /api/trade/price-plans/{planNo}` · `pricing:plan:update`（不存在 404）
- 入参 `PricePlanReq {name, deviceType, currency, freeMinutes, unitMinutes, unitPrice, capAmount, capMode, maxCharge, maxDurationMin?, lostFee?}`
  - `capMode`：`PER_RENTAL / ROLLING_24H / BIZ_DAY`（取值待 C04，今天只开放裁决选中的那一个）
  - `maxCharge` 取代 `buyoutPrice`（读出参保留 `buyoutPrice` 一个版本周期）；`maxDurationMin`、`lostFee` 待 K4 / K5，裁决前不出现在表单
  - 服务端同事务写费用项与阶梯；返回 `PricePlanEntry` + `items[]`（只读展示）
- 新增 `POST /api/trade/price-plans/quote` · `pricing:plan:read`：入参 `{cabinetNo | siteNo, startAt, minutes}`，出参 `{planNo, hit, lines[], multiplier, capApplied, payable, maxCharge}`

### 4.4 C 端借出确认页（OPT-S6-10、11）

- `GET /mp/nearby/cabinets/{cabinetNo}/availability`（不变，需登录）
- 出参：`cabinetNo, siteName, borrowable, planNo, currency, unitMinutes, unitPrice, pricePerHour, freeMinutes, capAmount, capMode, maxCharge, maxDurationMin, multiplier, freezeAmount`
  - **删除** `dailyCap`（改 `capAmount + capMode`）、`buyoutPrice`（改 `maxCharge`，来源 = 借出时将写进快照的值）、`depositAmount / freeQuota`（改 `freezeAmount`）
  - `multiplier` 为当前时段倍率（无则 `null`），端上需显示「当前时段 ×1.5」
- `POST /mp/trade/orders/rent` 入参增加 `planNo`（来自确认页）：服务端按机柜解析结果与之不同 → 409 `error.rent.price_changed`，端上刷新确认页

### 4.5 C 端买断（OPT-S6-10）

- `POST /mp/trade/orders/{orderNo}/buyout`：无请求体（不变）；金额 = 订单快照 `maxCharge`；快照无最高收费 → 409 `error.order.buyout_unavailable`；状态已变 → 409 `error.common.state_changed`
- 订单详情 `GET /mp/trade/orders/{orderNo}` 增加 `maxCharge`，端上买断确认弹窗显示它

### 4.6 C 端补缴（OPT-S6-16）

- `POST /mp/trade/pay` 入参 `{orderNo, scene, requestNo}`：`requestNo` 由端上生成（UUID），同一 `requestNo` 重放返回同一 `payNo` 与状态
- 出参 `status` 取 `SUCCESS / FAILED / PENDING`；`PENDING` 时端上轮询订单详情的 `payStatus`
- 错误：已付 409 `error.pay.already_paid`；处理中 409 `error.pay.in_progress`（另一笔补缴或 `UNKNOWN` 未收敛）

### 4.7 C 端免押与借出（OPT-S6-12、14）

- `POST /mp/trade/deposit/free` 入参 `{cabinetNo, requestNo}` → `{authNo, frozen, expireAt}`；同一 `requestNo` 幂等
- `POST /mp/trade/orders/rent` 入参 `{cabinetNo, useFreeDeposit, couponNo, planNo, requestNo, authNo}`：
  - `useFreeDeposit=true` 时 `authNo` 必填，须属本人、`FROZEN`、未绑定订单，否则 409 `error.rent.auth_required`
  - 同一 `requestNo` 重放返回同一 `orderNo`；在途单达上限 409 `error.rent.ongoing_exists`；黑名单 403 `error.rent.blocked`
- 出宝失败撤单后，端上文案可以写「冻结额度已释放」（以订单详情 `authStatus=RELEASED` 为准）

### 4.8 系统设置 · 业务规则（OPT-S6-08、09）

- `GET /api/platform/biz-rules` 出参删除 `billing`；`POST` 带 `billing` → 400 `error.biz_rule.billing_retired`
- 前端删除「计费默认值」分区（含「超时判定阈值」）；最长时限与最高收费在收费方案页配置
- 提现分区保存权限改判 `finance:withdraw_rule:update`（拟新增）

### 4.9 审计视图（OPT-S6-25）

- `GET /api/trade/order-interventions`、`GET /api/trade/order-events` 形状不变；代理会话下只返回本商家订单的记录，他人订单号 → 404
