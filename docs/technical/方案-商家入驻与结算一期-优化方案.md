## 一、现状：哪些能直接用

| 需要的能力 | 现状 | 用法 |
|---|---|---|
| 税率 | `sys_tax_setting` 按国家存税率百分数、是否含税价、生效日 | 税前折算直接读它，不另建参数 |
| 系统开关 | `sys_param` 键值参数 | 放「分成基数口径」「场地方分成开关」「自助注册开关」 |
| 提现状态机 | 申请 → 审核 → 出款中 → 已到账 / 失败；驳回落「失败」并带驳回原因，与打款失败原因分列 | 付款任务内的提现单沿用，不另起状态机 |
| 同人校验 | 审核人与申请人不能相同（V138），已有配置卡片 | 复核人 ≠ 发起人直接复用 |
| 打款登记 | 逐笔登记，渠道流水号全局唯一 | 批量确认在循环里调它，流水号用「任务号-序号」 |

## 二、关键设计决策

### 2.1 手机号可空、未验证的标识不占唯一

```
agt_principal
  phone_hash      改为可空
  phone_verified  新增，0/1
  email_verified  新增，0/1
  phone_uk        生成列 = 已验证时取 phone_hash，否则 NULL      → 唯一键挂这里
  email_uk        生成列 = 已验证时取 email_hash，否则 NULL      → 唯一键挂这里
```

**这里是有意利用「唯一键不约束 NULL」**。V48 的注释警告过「可空列进唯一键等于没进」，那是在需要约束时踩的坑；这里要的恰好是**未验证的不约束**，同一机制反过来用。代码注释里要写清这一点，防止后人照着 V48 的注释把它「修」掉。

申请单的在途唯一（`active_key`）从按手机号改为按邮箱。

### 2.2 税前分成

| 项 | 做法 |
|---|---|
| 折算 | 税前基数 = 实收 ÷ (1 + 税率)，四舍五入两位。税率按订单结算日取 `sys_tax_setting` 中商家所在国家的生效行；该行标为价外税时不折算 |
| 口径参数 | `sys_param` 新增分成基数口径，取值 税前 / 含税实收，默认税前 |
| 快照 | `share_record` 新增四列：基数口径、税率、税前基数、分成比例。原有的实收列保留不动 |
| 计算位置 | 只改分成生成器的基数一处，下游结算、汇总读金额列，不受影响 |
| 存量 | 已生成的明细不回算；新列为空表示旧口径 |

### 2.3 场地方不分成

`sys_param` 新增场地方分成开关，默认关。关闭时三处跳过：

| 位置 | 现状 | 改为 |
|---|---|---|
| 分成生成器的场地方分支 | 站点关联了场地方就写一条场地方分成 | 开关关闭时跳过，并在 DEBUG 记一笔 |
| 结算单生成 | 不指定受益方类型时，场地方与商家一起生成 | 开关关闭时只生成商家 |
| 保底补足 | 结算单生成时对场地方执行保底补足 | 开关关闭时不执行 |

存量场地方明细与结算单保留不删，不进入付款任务（付款任务只取商家）。

### 2.4 默认站点

商家档案首次保存位置时，自动建一个站点：名称取店名，地址与坐标取商家位置，归属商家，并写一条责任行。之后位置变更时同步更新站点地址与坐标。

| 要点 | 做法 |
|---|---|
| 模块依赖 | 商家与站点同在平台服务，但领域间已有循环风险（必要功能清单记录过 ArchUnit 抓到的环）。由商家侧声明「站点开通」端口、站点侧实现，同 `AgentIdentityPort` 的做法 |
| 幂等 | 商家档案记默认站点编号；已有则更新，不重复建 |
| 划拨门禁 | 设备划拨服务在划给商家前检查位置与行业已补齐，不齐则拒绝并返回缺项 |

### 2.5 付款任务

```
stl_payout_task（新表）
  task_no · cutoff_date 付款截止日 · currency · count · total_amount · status
  created_by/at · reviewed_by/at · confirmed_by/at · bank_batch_ref · transfer_date

stl_withdrawal（加列）
  task_no      所属付款任务
  origin       来源：商家申请 / 付款任务

stl_settlement（加列）
  withdraw_no  在途或已付的提现单；非空即不再被新任务纳入
```

| 环节 | 做法 |
|---|---|
| 预览 | 取账期结束日不晚于截止日、已确认、`withdraw_no` 为空的商家结算单，按商家分组；收款账户未核验的单列为不可付款 |
| 生成 | 一个事务：建任务 → 每个商家建一张提现单（收款账户快照）→ 回写结算单的 `withdraw_no`。同一时刻已有待复核或待转账的任务时拒绝 |
| 手续费 | 付款任务生成的提现单**不收提现手续费**；手续费口径只作用于商家申请来源。见 §八 待确认 1 |
| 复核 | 任务级复核，通过则任务内全部提现单推进到出款中；驳回则全部落为失败并带驳回原因，同时清空结算单的 `withdraw_no` |
| 导出 | 生成 Excel 与 CSV，含完整 IBAN；每次导出写操作审计（人、时间、文件摘要） |
| 确认 | 整批成功：填银行批次参考号与转账日期，逐笔调用现有打款登记，流水号为「任务号-序号」。部分失败：传失败清单，失败的走失败迁移并清空结算单的 `withdraw_no`。导入回单：按附言中的提现单号匹配 |
| 联动 | 提现单到账 → 关联结算单置为已付 → 写应付冲减分录 → 发到账邮件 |

**为什么在结算单上加列而不是建关联表**：一张结算单同一时刻至多属于一张在途提现单，一列就能表达，也让「已被纳入」的判断是一个等值条件。

### 2.6 端点

全部在既有前缀下，不新增前缀；契约不出现删除语义。

| 端点 | 权限码 |
|---|---|
| `POST /api/agent/applies/create-and-activate` 创建并开通 | `agent:apply:create` + `agent:apply:approve` |
| `POST /api/agent/accounts/{accountNo}/invite` 重发邀请 | `agent:account:manage` |
| `POST /api/auth/otp`、`POST /api/auth/login` 入参改为单一标识字段 | 免鉴权 |
| `GET /api/trade/payout-tasks/preview?cutoffDate=` | `finance:withdrawal:read` |
| `POST /api/trade/payout-tasks` 生成 | 拟新增 `finance:withdrawal:create` |
| `GET /api/trade/payout-tasks`、`/{taskNo}` | `finance:withdrawal:read` |
| `POST /api/trade/payout-tasks/{taskNo}/audit` | `finance:withdrawal:audit` |
| `GET /api/trade/payout-tasks/{taskNo}/export?format=` | 拟新增 `finance:withdrawal:export` |
| `POST /api/trade/payout-tasks/{taskNo}/confirm`、`/confirm-import` | `finance:withdrawal:pay` |
| `GET /api/trade/merchant-revenue/summary`、`/trend`、`/by-device` | `dashboard:overview:read`，商家范围 |

两个拟新增码**先登记进功能权限清单，再写代码**。

### 2.7 结算页 403

`GET /api/trade/settlements` 的判权改为「持 `finance:settlement:read` 或 `agent:settlement:read`」。结算单的商家锚点 V58 已注册，商家只会读到自己的。不让商家改持运营码，是为了保住「商家端码是运营码的受限子集」这条约定的可读性。

## 六、风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 邮件服务商未接 | 邮箱验证码与邀请发不出去，商家无法首登 | 立项即启动服务商选型；上线前的验收以真实投递为准 |
| 税前折算的尾差 | 结算单合计与逐笔加总差几分 | 逐笔先舍入再汇总，结算单金额等于明细之和；对账单注明口径 |
| 导出文件含完整 IBAN | 泄露风险 | 单独权限码；导出审计；文件不落服务器 |
| 存量场地方结算单 | 运营误以为要付 | 列表默认只显示商家；场地方结算单标「一期不付款」 |
| 付款任务跨多个账期 | 金额较大，复核压力大 | 预览按商家与账期双层展开；导出前必须复核 |
| 自助注册关闭后的旧链接 | 访问报错 | 公开路径重定向到「请联系运营开通」说明页，不暴露端点存在 |
