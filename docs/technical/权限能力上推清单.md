# 权限能力上推 neargo commons —— 能力盘点与上推清单

> 状态：提案（待确认）· 创建 2026-07-12 · 依据 [ADR-015](./ADR/ADR-015-权限模块化与打包方式.md)（决策②：若是标准通用能力则上推）。
> 目的：把 powerbank 的**通用**权限基础设施上推 neargo commons，供 neargo 家族共享；先厘清**上推什么、退役什么、保留什么**。

---

## 0. 结论（先看这里）

盘完 neargo commons（`neargo-common-security` + `neargo-auth-core`）后，一个反直觉的事实：**neargo 已经有会话/Token/OTP/realm 分链的完整基座**——powerbank MVP 因"零基础设施"而**重复造了一批已存在的东西**。所以"上推"分三堆：

| 堆 | 含义 | 动作 |
|----|------|------|
| **A · 上推**（neargo 缺）| RBAC 功能鉴权、数据权限执行引擎、会话即时刷新 | **上推 neargo commons** |
| **B · 退役对齐**（neargo 已有）| TokenStore/Realm/双 Filter/OTP/发吊销/头剥离 | **退掉 powerbank 自造，改用 neargo 现成** |
| **C · 保留本地**（业务/app 专属）| IAM 管理业务模块、链路径、Result 形态、AGENT/SITE 维度 | 留 powerbank（或另立 neargo-iam 业务模块）|

> 一句话：**上推的不是"整套权限"，而是 neargo 唯独缺的「RBAC 权限码层 + 数据权限引擎 + 口径B 刷新」三件；其余对齐 neargo 已有件。**

## 1. neargo commons 现有能力盘点（→ 决定复用，不重造）

| 能力 | neargo 现有类 | 模块 |
|------|--------------|------|
| 会话存储 SPI | `security.session.SessionStore`（`issue(Subject,claims,TtlPolicy)` / `touchAndGet`（滑动TTL）/ `revoke` / **`revokeAllByUser`**（踢人））| common-security |
| 会话后端 | `InMemorySessionStore` · `RedisSessionStore` | security / auth-core |
| 会话模型 | `Session`（token/realm/subjectId/regionId/**roles**/**storeScope**/…）· `Subject` · `SessionClaims`（ROLES/**STORE_SCOPE**）· `TtlPolicy` | common-security |
| 认证过滤器 | `OpaqueTokenAuthFilter(**allowedRealms**…)`（**按 realm 分链**、roles→authorities、注入可信头、401 JSON）| common-security |
| Realm | `security.session.Realm` | common-security |
| 可信头 + 剥离 | `AuthHeaders` · `TrustedHeadersRequestWrapper`（剥客户端伪造头）· `BearerToken` | common-security |
| 租户上下文 | `TenantContext` · `TenantContextFilter` · `TenantPropagationInterceptor` | common-security |
| Token 发/吊销 | `TokenIssuer`/`DefaultTokenIssuer` · `RevokeService`/`DefaultRevokeService` | auth-core |
| 凭据/密码/OTP | `CredentialService` · `PasswordAuthenticator` · `OtpAuthenticator`/`OtpStore`/`OtpSender` | auth-core |
| 租户行隔离 | `NeargoTenantLineHandler`（MyBatis-Plus）| common-data |
| 自动装配 | `SecurityAutoConfiguration` · `SessionStoreAutoConfiguration` · `AuthCoreAutoConfiguration` | 各 |

> **注意**：`Session` 已带 `roles` + `storeScope`（数据范围柔性 JSON 载体），`SessionStore` 已有踢人/滑动TTL，`OpaqueTokenAuthFilter` 已支持 realm 分链。→ powerbank 的 `TokenStore`/`Realm`/双 Filter/`OtpService` **属重复**。

## 2. 堆 A · 上推清单（neargo 缺的通用能力）★ 本文重点

### A1. RBAC 功能鉴权层 ★★★（价值最大，neargo 全无）
- **powerbank 现有**：`auth/PermChecker`(`@perm.can(code)`) + `LoginUser.hasPerm`（通配 `*`/`device:*`/`device:cabinet:*`，语义同前端 `can()`）。
- **neargo 缺口**：`OpaqueTokenAuthFilter` 只把 **roles** 当 authorities，**无权限码层**、无通配 `hasPerm`、无 `@perm`。
- **上推内容**：`@perm` SpEL bean + 通配匹配器 + `hasAuthority` 之上的 **permission-code 语义**。
- **泛化改造（关键）**：neargo **不能依赖 powerbank 的 iam 表**。→ 上推一个 **`PermissionResolver` SPI**（`Set<String> permsOf(Subject/roles)`），neargo 提供 `@perm` 校验 + 默认"roles 即 perms"实现；powerbank 的 `PermissionService`（读 iam_role_perm）作为 app 实现注入。
- **目标模块**：`neargo-common-security`（新增子包 `rbac`）。

### A2. 数据权限执行引擎 ★★★（neargo 有"数据范围载体"但无"执行引擎"）
- **powerbank 现有**：`auth/DataScopeHandler`（MyBatis-Plus `MultiDataPermissionHandler`）+ `DataScopeTableRegistry`（表→锚点列）+ `DataScopeContext`（豁免）+ `DataScope`/`ScopeDim`。
- **neargo 缺口**：`SessionClaims.STORE_SCOPE`/`Session.storeScope` 只是**数据**；`common-data` 只有租户 `NeargoTenantLineHandler`，**无通用数据范围→SQL 的执行引擎**。
- **上推内容**：`DataScopeHandler` + `DataScopeTableRegistry` + `DataScopeContext` + 通用 `ScopeDim`（`ALL/REGION/DEPT/SELF/CUSTOM`）。
- **泛化改造**：① 数据范围**来源对齐 `Session.storeScope`**（不自造 DataScope，从会话 claim 取）；② 维度**可扩展**——neargo 出通用维度，app 注册自有维度与列（powerbank 的 `AGENT`/`SITE`/`VENUE` = app 扩展）；③ 与 `NeargoTenantLineHandler` 并列注册（租户→数据范围→分页）。
- **目标模块**：`neargo-common-data`（挨着 TenantLineHandler）或 `neargo-common-security`。

### A3. 会话即时刷新（口径 B）★★（neargo 有 TTL 无"变更即时收敛"）
- **powerbank 现有**：`auth/PermVersion`（全局版本）+ `auth/PrincipalRefresher`（会话重载 SPI）+ `StaffTokenAuthFilter` 每请求比对版本→`rebuild` 刷新。
- **neargo 缺口**：`touchAndGet` 只做**TTL 续期**；**权限变更后不重登即生效**没有。
- **上推内容**：`PermVersion`（可换 Redis 全局计数）+ `PrincipalRefresher` SPI + 让 `OpaqueTokenAuthFilter` 支持"版本戳变则经 `PrincipalRefresher` 重载 session"。
- **目标模块**：`neargo-common-security`。

### A4. 当前主体读取门面 `SecurityUtils` ★（小，看 neargo 是否已有等价）
- **powerbank 现有**：`auth/SecurityUtils`（`currentUser()/userNo()/realm()`），业务只经它读身份、不碰 `SecurityContextHolder`。
- **neargo**：有 `TenantContext`，但主体读取门面似缺。→ 上推一个 realm 无关的 `AuthContext`/`SecurityUtils`。
- **目标模块**：`neargo-common-security`。

### A5.（可选）Ehcache / MySQL 会话后端 ★
- **powerbank 现有**：`auth/store/{LocalCacheTokenStore, MysqlTokenStore}` + `sys_token` 表。
- **neargo 现有**：memory + redis 两后端。→ 若 neargo 需要，补 `EhcacheSessionStore` / `JdbcSessionStore`（实现 neargo `SessionStore` 接口，非另造 SPI）。
- **优先级**：低（memory+redis 通常够）。

## 3. 堆 B · 退役对齐清单（powerbank 改用 neargo 已有，**不上推**）

> powerbank MVP 因零基础设施自造了这些；接入真基座时**退掉自造、改依赖 neargo**。

| powerbank 自造（退役）| 改用 neargo 现成 |
|----------------------|------------------|
| `auth/TokenStore` + `store/{Memory,Redis}TokenStore` + `SessionData` | `security.session.SessionStore` + `InMemory/RedisSessionStore` + `Session` |
| `auth/Realm` | `security.session.Realm` |
| `auth/{StaffTokenAuthFilter,ConsumerTokenAuthFilter}` | `OpaqueTokenAuthFilter(allowedRealms=[STAFF,AGENT])` / `(…=[CONSUMER])` |
| `user/consumer/OtpService` | auth-core `OtpAuthenticator`/`OtpStore`/`OtpSender` |
| 登录发 token（AuthController 内）| auth-core `TokenIssuer` / `RevokeService.revokeAllByUser`（踢人）|
| 忽略客户端 X-Roles 红线（自实现）| `TrustedHeadersRequestWrapper`（已剥离伪造头）|
| `auth/DataScope` 作独立载体 | 对齐 `Session.storeScope` / `SessionClaims.STORE_SCOPE` |

> 注：A（上推）的三件要能**插在 B 之上**——即 `@perm`/数据权限引擎/口径B 刷新 都基于 neargo 的 `Session`/`SessionStore`/`OpaqueTokenAuthFilter` 扩展，而非 powerbank 的自造件。

## 4. 堆 C · 保留本地清单（业务/app 专属，不上推 infra）

| 保留 | 原因 |
|------|------|
| **IAM 管理业务模块** `platform.iam`（`PermissionService`/`MenuService`/`IamAdminController`/`IamSeeder`/`iam_*` 表）| 有表有业务=业务模块（ADR-015 的 `powerbank-iam`），非 infra。可**另立 `neargo-iam` 业务模块**复用，但那是业务件不是安全 starter |
| `SecurityConfig` 链的 **securityMatcher/permitAll 路径** | 每 app 路径不同 |
| 401/403 **Result JSON 形态**（powerbank `ApiResult{code,msg,data}`）| 与 neargo `{code,message,data}` 有别（既定），上推需做成可插 body-writer |
| **数据范围维度** `AGENT`/`SITE`/`VENUE` + 表锚点注册 | powerbank 领域（ADR-012/013）|
| `StaffContext`/`ConsumerContext` 两个 realm 门面 | app thin wrapper（或上推通用 `AuthContext`，realm 门面留 app）|

## 4.1 IAM 管理（有表业务）该不该上推 / 独立模块？—— 明确答复

**结论：不上推 commons；默认留 app-local；"通用"落在 SPI 契约层而非 schema 层。**

- **上推 `neargo-common-*` ❌ 类别错误**：commons 是**无表基础设施库**（连 BaseEntity 也只是基类）。IAM 管理**拥有 `iam_*` schema + 管理 API + 迁移 + 业务规则**，性质是"有表业务能力"，塞进 commons 违背其"零表"原则；且 schema 跨 app 共享 = 迁移/版本/列归属的经典耦合痛点。
- **独立通用模块 `neargo-iam` ⚠️ 缓做**：可做成"业务能力 starter"（自带 Flyway schema + admin API + `@AutoConfiguration`），但 IAM 表极易 app 化（powerbank 的 `agent_no` 维度、租户模型、菜单结构），强共享 schema 互相掣肘。**待 ≥2 个 app 确需相同角色/菜单管理再抽**，且它**不是 commons** 而是业务能力件。
- **app-local `powerbank-iam` ✅ 推荐**：YAGNI，与 ADR-015 一致。

**关键洞察——共享"执行契约"而非"管理实现"**：跨 app 通用的是**堆 A 基础设施 + 契约**，它们只消费**会话里的 `perms` + `storeScope`**，不关心这些怎么配、存哪张表。`PermissionResolver` SPI 即缝：neargo 定契约（subject→权限码 / 数据范围），各 app 用自己的表实现。→ 各 app 的 IAM 表/管理可完全不同，却共享同一套 enforcement。

**中间减耦方案（可选）**：neargo 只上推**接口层**（`RoleRepository`/`MenuProvider`/`PermissionResolver` SPI + DTO，**无表**），各 app 实现——"通用"落在接口而非表。

## 5. 上推的贯穿原则（保证 neargo 通用、不反向依赖 powerbank）

1. **neargo 不含任何业务表**：RBAC/数据范围的**数据来源经 SPI**（`PermissionResolver`、维度/锚点注册），app 提供实现。
2. **建在 neargo 现有件之上**：复用 `Session`/`SessionStore`/`OpaqueTokenAuthFilter`/`storeScope`，A 三件是**增强**不是并立。
3. **默认可用 + 可覆盖**：`@AutoConfiguration` + `@ConditionalOnMissingBean`，app 可换实现（如自定义 `PermissionResolver`）。
4. **泛化命名**：去 powerbank 专有（`agentNo`/`SITE`）→ 通用（`dataScope`/`CUSTOM` 维度）。

## 6. 建议上推顺序与目标

| 批次 | 上推 | 目标模块 | 价值 |
|------|------|---------|------|
| U1 ✅ **已上推（2026-07-13）** | **A1 RBAC**：`rbac/{AuthSubject,PermissionResolver,PermissionCarrier,Permissions,PermChecker(@perm),RbacAutoConfiguration}` 已入 neargo-common-security 并 install；powerbank 依赖之、`LoginUser implements PermissionCarrier`、`PermissionService implements PermissionResolver`、删本地 `PermChecker/PermissionResolver/AuthSubject`，`@perm` 由 neargo auto-config 提供。29 测试全绿 | neargo-common-security `rbac` | 最高 |
| U2 | **A2 数据权限引擎 + 通用 ScopeDim** | neargo-common-data / -security | 高 |
| U3 | **A3 口径B（PermVersion + PrincipalRefresher）+ A4 SecurityUtils** | neargo-common-security | 中 |
| U4 | （可选）A5 Ehcache/MySQL SessionStore | neargo-common-security/auth-core | 低 |

> powerbank 侧配套：接入 neargo 真基座时执行**堆 B 退役对齐**（换 SessionStore/Realm/Filter/OTP），IAM 业务模块（堆 C）保留于 `powerbank-iam`。
