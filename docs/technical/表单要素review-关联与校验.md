# 表单要素 review · 关联与校验

> 2026-09-23 · 对着 [经营链条方案](./经营链条方案-主体到分账.md) 逐个表单过一遍：
> **哪些字段本该是「选出来的」却写成了自由文本**，哪些校验缺失，地址怎么接地图。
>
> 判据只有一条：**这个字段的值会不会被别的地方拿去连表、算钱、判权限**。
> 会 —— 就必须是选择器（存编号），不能是文本框（存名字）。

---

## 一、总问题：关联字段写成了自由文本

本仓库已经为此付过两次代价：

- **分润链路**：`loc_site` 只写了 `venue_name`、`loc_contract` 只写了名字，编号列全空，
  于是「订单 → 站点 → 场地方 → 合同费率」在第二跳就断了，V38 才按名字一次性回填 —— 而
  同名场地方会把钱分错家，那次回填只能「名字唯一命中时才填」。
- **区域**：`md_region` 的树曾按名称连边，`Sharjah City` 这类名字在多国之间重复，必然连错。

表单是这些数据的**入口**。入口放任自由文本，下游再怎么修都是补。

## 二、逐表单清单

图例：🔴 会连错 / 算错 / 判错权限（必改） · 🟡 体验与准确性 · ⚪ 可保留

### 2.1 站点（`/operation/sites`、`/locations?tab=sites`）

| 字段 | 现状 | 问题 | 应为 |
|---|---|---|---|
| `venueName` 场地方 | 文本，必填 | 🔴 分成按场地方结算，而这里存的是**名字**。同名场地方分错家 | **场地方选择器**，存 `venueNo`，名字只做展示 |
| `regionName` 区域 | 文本，必填 | 🔴 字段说明写着「数据权限按区域收敛」—— 打错一个字，**数据权限静默失效**（错的不是报错，是看不到/看得到不该看的） | **区域选择器**（三级树），存 `regionId` |
| `address` 地址 | 文本 | 🟡 手打地址与经纬度对不上时，C 端「找附近」指到别处 | 地址 + **地图选点**，选点回填经纬度 |
| `lat` / `lng` | 两个手填数字 | 🟡 让人手抄坐标；填反（纬度填成经度）无人拦 | 由地图选点写入；保留手填做兜底，加范围与「疑似填反」校验 |
| `sceneType` 场景 | select ⚪ | — | — |
| `openHours` 营业时间 | 文本 | 🟡 格式靠 help 文字约束，填错不报 | 加格式校验（`HH:MM-HH:MM`，多段逗号分隔） |
| — | **缺 `brandNo`** | 🔴 站点「以哪个品牌运营」在模型里是必要的，表单里没有 | 等品牌落地后补（见经营链条方案 B1） |

### 2.2 进场合同（`/locations?tab=contracts`）

| 字段 | 现状 | 问题 | 应为 |
|---|---|---|---|
| `venueName` 场地方 | 文本 | 🔴 同上。**合同是场地方分成的唯一依据**，连错等于分错 | 场地方选择器 → `venueNo` |
| `siteName` 站点 | 文本 | 🔴 同上，而且种子里就有同名站点（同一商场不同楼层） | 站点选择器 → `siteNo`（按已选场地方过滤） |
| `shareRate` 分成比例 | number，标签写「0~1」 | 🔴 极易填成 `20` 而不是 `0.2` —— 填错就是**二十倍分成**，且没有上限校验 | 百分比输入（界面填 20%，存 0.2），或保留小数但加 `max: 1` 与二次确认 |
| `startAt` / `endAt` | **文本** | 🟡 组件已有 `date` 类型却没用；手打日期格式错了才发现 | `type: "date"`；并校验 `endAt > startAt` |
| `entryFee` 进场费 | number ⚪ | 🟡 缺币种 | 与站点币种联动（依赖区域→市场，见方案 S2） |

### 2.3 场地方（`/locations?tab=venues`）

| 字段 | 现状 | 问题 | 应为 |
|---|---|---|---|
| `locationCount` 站点数 | number，**可编辑** | 🔴 这是**聚合值**（该场地方名下有几个站点），不是属性。手填必然与实际脱节 | **从表单删除**；后端已于 2026-09-23 改为查询时现算 |
| `contact` 联系方式 | 文本 | 🟡 无格式校验 | 手机/邮箱格式校验 |

### 2.4 代理商（`/agents`）

| 字段 | 现状 | 问题 | 应为 |
|---|---|---|---|
| 分润配置 `agentNo` + `agentName` | **两个文本框都要填** | 🔴 让人填两遍，填不一致时以哪个为准无人知道 | 代理商选择器 → `agentNo`，名字自动带出且只读 |
| 代理账号 `agentNo` + `agentName` | 同上 | 🔴 同上 | 同上 |
| `rate` 分润比例 | number「0~1」 | 🔴 同合同的二十倍风险 | 同上 |
| `effectiveAt` 生效日期 | 文本 | 🟡 | `type: "date"` |
| — | **缺 `agentType`** | 🟡 ADR-027 定了代理商 / 城市合伙人两类，表单里没有 | 等列落地后补 select |

### 2.5 商机 / 场地方进件（`/locations?tab=crm|onboarding`）

| 字段 | 现状 | 问题 | 应为 |
|---|---|---|---|
| `venueName` 场地名称 | 文本 ⚪ | **这里保留文本是对的** —— 商机阶段对方还不是场地方，没有编号可选 | 不动；签约转站点时再落编号 |
| `owner` 负责人 | 文本 | 🔴 `loc_lead.owner` 只接受 `employee_no`，填名字对不上人 | 员工选择器 → `employee_no` |

### 2.6 收费方案（`/operation/fee-plans`）

| 字段 | 现状 | 问题 | 应为 |
|---|---|---|---|
| 六个计费字段 | number 必填 ⚪ | — | — |
| — | **缺「适用范围」** | 🔴 方案挂给谁完全不在这个表单里；今天靠另一个菜单「差异化定价」表达，而取价引擎读的是那一套 | 按 ADR-028 补：设备类型（必填）+ 层级 + 范围 + 厂商/型号/品牌过滤 |
| — | 缺币种 | 🟡 方案带币种，站点推不出币种，无法做「必须相符」硬过滤 | 依赖方案 S2 |

### 2.7 设备（机柜）建档（`/devices`）

| 字段 | 现状 | 问题 | 应为 |
|---|---|---|---|
| `locationNo` 点位 | **已是选择器** ⚪ | 复核后确认：已从点位列表选，空值项是「未上架（到货待部署）」，并回显所属站点 | 不动 |
| `siteNo` / `agentNo` | — | ⚪ **后端已强制反查回填、不接受前端指定**（2026-09-23） | 表单不该出现这两个字段 |

## 三、地图：先接高德，将来切 Google

### 3.1 为什么先高德

用户 2026-09-23 定：**先集成高德，用 ai-shop 中的信息，将来再切 Google**。
ai-shop 已有可直接移植的加载器 `lib/amap.ts`，且把三个坑写在注释里：

1. JS API 2.0 **必须配安全密钥**。只填 key 不填密钥，地图不是报错而是**一片空白**，
   控制台里才有 `INVALID_USER_SCODE` —— 所以缺密钥时**不加载**，由调用方说人话。
2. 安全密钥必须在**脚本加载之前**挂到 `window._AMapSecurityConfig`，晚一步不生效。
3. 同页重复加载会抛 `Multiple instances`，用一个 Promise 缓存。

### 3.2 与现有 Google 地图组件的关系

ops-web 已有 `components/ui/site-map.tsx`（Google Maps，站点撒点，无 key 时降级为列表）。
**两者职责不同，都保留**：

| | 用途 | 供应商 |
|---|---|---|
| `SiteMap` | 站点**分布**撒点（概览、G4） | Google（现状） |
| `AddressPicker` 🆕 | 建站点时**选一个点**并回填经纬度 | 高德（本次） |

> 将来切 Google 时，替换的是 `lib/amap.ts` + `AddressPicker` 内部实现，
> **调用方不动** —— 所以 `AddressPicker` 的入参只有「地址 / 经纬度 / onChange」，不暴露任何供应商概念。

### 3.3 配置

```
NEXT_PUBLIC_AMAP_JS_KEY=            # 服务平台选「Web端(JS API)」
NEXT_PUBLIC_AMAP_JS_SECURITY_CODE=  # 与 key 同时申请，缺了地图一片空白
```

**没配 key 时的行为**：不加载脚本，地址仍可手填，经纬度仍可手填，
并在选点按钮位置显示一句「未配置地图密钥，可手工填写经纬度」——
不白屏、不报错、不挡住建站点这件事本身。

## 四、改动优先级

| 批次 | 内容 | 理由 |
|---|---|---|
| **第一批** | 站点表单：场地方 / 区域 改选择器；地址接高德选点 | 用户点名；且区域那条**今天就在静默影响数据权限** |
| 第二批 | 合同：场地方 / 站点选择器 + 日期选择器 + 比例上限校验 | 分成的唯一依据，连错即分错 |
| 第三批 | 代理商分润配置 / 代理账号：代理商选择器（去掉填两遍） | 高频操作，错了要人工对 |
| 第四批 | 场地方表单删「站点数」；商机负责人改员工选择器 | 各自独立，随手可做 |
| 第五批 | 收费方案「适用范围」 | 依赖 ADR-028 的库改造，不是表单单独能解决的 |
