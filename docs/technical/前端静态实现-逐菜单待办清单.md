## 一、对齐标准（先定标准，再谈完成度）

「API 与后端一致」「mock 符合后端规范」需要可核验的标准。已核对后端源码，结论：

### 1.1 已经对齐的（无需改动）

| 项 | 后端 | 前端 | 结论 |
|---|---|---|---|
| 响应包裹 | `Result{code:0,message,data}` (`ApiResponseWrapper`) | `http-client` 按 `body.code!==0` 抛错、返回 `body.data` | ✅ 一致 |
| 分页返回 | `PageResult{list,total}` (`Pages.of`) | `PageResult{list,total,page?,size?}` | ✅ 兼容（page/size 可选）|
| 分页入参 | `page` 从 1 起、缺省 `page=1/size=10` | 同 | ✅ 一致 |
| 字段命名 | camelCase | camelCase | ✅ 一致 |
| 业务主键 | `xxxNo`（`cabinetNo`/`siteNo`/`agentNo`）| 同 | ✅ 一致 |
| 时间字段 | `xxxAt` 字符串 | 同 | ✅ 一致 |
| 枚举 | 大写下划线字符串（`IN_CABINET`/`ONLINE`）| 同 | ✅ 一致 |
| 端点前缀 | `ops/platform/trade/user/agent/auth` + `internal` | 已于 2026-07-29 收敛为同一套 | ✅ 一致 |

> **结论：规范层面前后端已经一致，不需要重构。** 这点比我预期的好。
