## 一、类型与迁移表（`lib/types/*.ts`）

后端每个状态机在前端有**同名**状态类型与 `X_TRANSITIONS`（`StateMachineEdgeAcrossEndsTest` 按类型名配对、`StatusVocabularyAcrossEndsTest` 比对取值）。**联合类型必须具名 `export type`**，内联在 interface 里的比对不到。

| 文件 | 新增 / 修改 | 迁移表（动作 → from / to） |
|---|---|---|
| `location.ts` | 🆕 `ContractStatus = "DRAFT"\|"PENDING"\|"SIGNED"\|"ACTIVE"\|"EXPIRED"\|"TERMINATED"`；`Contract.status` 改用它；追加合同新字段 | `CONTRACT_TRANSITIONS`：`submit` DRAFT→PENDING · `withdraw` PENDING→DRAFT · `approve` PENDING→SIGNED · `reject` PENDING→DRAFT · `terminate` ACTIVE→TERMINATED |
| `location.ts` | 🆕 `SiteStatus = "PREPARING"\|"ACTIVE"\|"PAUSED"\|"WITHDRAWING"\|"CLOSED"`；删除 `SITE_STAGES / nextSiteStages / canSiteStageTransition` | `SITE_TRANSITIONS`：`pause` · `resume` · `withdraw`（L1）· `close` |
| `location.ts` | 🆕 `LeadStage` 迁移表（L1，CRM 改造时） | `LEAD_TRANSITIONS` |
| `device.ts` | `CabinetStatus` 追加 `"IN_TRANSIT"`；🆕 `ProtectionAction`、`ProtectionHolder`、`TrialRentStatus` | `CABINET_TRANSITIONS`：`goLive` · `markFault` · `repair` · `undeploy` · `retire`；`POWERBANK_TRANSITIONS`（照抄后端 `PowerbankStateMachine`，并从 `known-missing-ui-transitions.txt` 划掉有按钮的边） |
| `alarm.ts` | 🆕 `AlarmDomain`、`AlarmSubjectType`、`AlarmCause`、`AlarmCloseReason`、`AlarmDisposition`、`ImpactScope`、`ImpactPeriod`、`AlarmTodoStatus`；`AlarmRecord` / `AlarmCode` 追加字段 | `ALARM_TRANSITIONS` 追加 `close`：OPEN/ACKED→CLOSED |
| `workorder.ts` | 🆕 `WoPriority`（与后端枚举同名）、`WoCloseReason`、`WoReviewStatus`；`WorkOrder` 追加字段 | `WO_TRANSITIONS` 不加按钮（撤单 / 并单为系统边） |
| `file.ts` 🆕 | `FileCategory`、`FileRef` | — |

**词表比对注意**：前端 `AlarmLevel`（INFO/WARN/CRITICAL）与 `WoPriority`（LOW/MEDIUM/HIGH/URGENT）是两个类型，**不得**在任何地方互相赋值；`PRIO` 映射只作用于 `WoPriority`。

## 三、mock（`lib/mock/db/*.ts`）

项目约定：**mock 必须真改 `db`（重开能读回），状态机在 mock 层强制、非法迁移抛错**。

| 文件 | 内容 |
|---|---|
| `file.ts` 🆕 | `files` 表；`uploadFile` 用 `URL.createObjectURL` 作预览地址并写一行 TEMP；`bind` 校验上传人与状态 |
| `location.ts` | 合同：六态 + 日志数组；`activate` 规则（签署件 + 开始日）与「同站点仅一份 ACTIVE」；站点：五态 + 状态日志；开业清单 / 关闭门禁按 mock 数据计算；`tick` 函数供测试推进时间 |
| `device.ts` | 机柜状态机；门禁五项；试借还（mock 以 `setTimeout` 推进 EJECTING → WAIT_RETURN → PASSED，测试里直接调推进函数）；保护动作引用计数；可借判定 |
| `alarm.ts` | **重写种子**：从设备码改为业务码（10 个 L0 + 其余 `enabled=false`）；业务告警记录带 `domain / subjectType / cause / impact / priority / evidence`；引擎的最小版：`tickAlarms(now)` 按 mock 设备状态产出 / 恢复告警、到期开单、恢复撤单；待办表 |
| `agent.ts` | **补划拨级联**（站点 → 点位 → 机柜），与后端一致（现为只改 `site.agentNo`） |
| `workorder.ts` | `openOrAttach` · `withdraw` · `mergeInto` · `recordReview`；完工必填；候选人从员工与代理种子取（**删除硬编码 `STAFF`**） |

时间推进：mock 层所有「现在」取自 `lib/mock/clock.ts`（🆕，默认 `Date.now`，测试可设定），让「离线 12 分钟」「到期次日」这类用例可写。
