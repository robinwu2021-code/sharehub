## 一、总体结构

```
          ┌───────────── 输入 ─────────────┐
 DeviceSignalEvent（04）  ──────▶ EventTrigger ─┐
 WorkOrderCompletedEvent（06）──▶ ReviewListener │
 /internal/ops/alarms/tick（每分钟）──▶ StateTrigger ─┤
                                                │
                  ┌──────────────── alarm.eval ─────────────────┐
                  │ AlarmEvaluator（每组码一个）→ List<Finding>      │
                  │   「此刻，这个对象，这个码的条件成立」              │
                  └──────────────────────┬──────────────────────┘
                                         ▼
                  ┌──────────────── alarm.engine ───────────────┐
                  │ ConditionTracker  持续时长 / 营业时间累计        │
                  │ AlarmLedger       开 / 累加 / 升级 / 恢复 / 关闭  │
                  │ ImpactAssessor    整站 · 高峰 · 等级 · 在途 → 优先级│
                  │ Superseder        柜级 → 站点级 层级取代          │
                  └──────────────────────┬──────────────────────┘
                                         ▼
                  ┌──────────────── alarm.dispose ──────────────┐
                  │ Router（按 码 × 根因 查 dev_alarm_route）         │
                  │ AUTO_FIX │ WORK_ORDER │ CS_CASE │ TODO │ NOTIFY  │
                  └─────────────────────────────────────────────┘
```

**两条铁律**：
1. 判定器只回答「现在是否成立」，**不写任何表**；开、关、处置全在引擎 —— 判定器可以随意重跑，天然幂等。
2. 同一对象同一码**任一时刻最多一条未关闭告警**，由数据库唯一约束保证（§二 `open_key`），不靠应用判断。

### 4.1 `AvailabilityEvaluator`

```
evaluate(scope, now):
  sites  = scope.sites 中 status=ACTIVE 的           // 暂停 / 撤场 / 筹备中的站点不判
  avail  = cabinetQuery.availabilityBySites(sites)   // 每柜：online, rentBlocked, rentableSlots, returnableSlots
  for site in sites:
     cabs = avail[site]（仅 DEPLOYED / FAULT）；无柜 → 跳过
     rentableTotal   = Σ(online && !rentBlocked ? rentableSlots : 0)
     returnableTotal = Σ(online ? returnableSlots : 0)
     if rentableTotal == 0:
         emit SITE_UNRENTABLE(site, cause = causeOf(cabs, RENT), scope=SITE, evidence=每柜一条)
     else for c in cabs where !rentable(c):
         emit CABINET_UNRENTABLE(c, cause = causeOf([c], RENT), scope=CABINET)
     同理 RETURN：SITE_UNRETURNABLE / CABINET_UNRETURNABLE（空仓维度，根因 FULL / OFFLINE / FAULT）
  inFlight：availability 同时带回每站点进行中订单数（可还域加成用）

causeOf(cabs, kind):
  all offline                      → OFFLINE
  kind=RENT   且 在线柜均无可借宝  → NO_STOCK（若在线柜全部被停借 → FAULT）
  kind=RETURN 且 在线柜均无空仓    → FULL
  其余                              → MIXED
```

`business_hours_only=1`、`hold_minutes=10` 由引擎处理（§5.2），判定器不管时间。

**「在线」的口径**：`CabinetAvailability.online = online_status='ONLINE' AND last_heartbeat_at >= now - 3 分钟`，在 core 的聚合查询里算出。
设备不会主动报「我离线了」，所以离线完全由心跳时间推断；`dev_cabinet.online_status` 仅作最近一次上报的快照，不单独信任。

### 4.4 `ContractCoverageEvaluator`

站点状态 ∈ {ACTIVE, PAUSED} 且 `ContractQueryPort.activeBySites` 无结果 → `SITE_WITHOUT_CONTRACT`（subject=SITE，cause=NO_CONTRACT）。

### 5.1 `AlarmEngine`（`alarm.engine`，对外唯一入口）

### 5.2 STATE 码的每分钟流程

```
tick(now):
  for batch of 200 sites（SiteQueryPort，状态 ∈ ACTIVE/PAUSED）:
     profiles = siteProfiles(batch)
     for evaluator in stateEvaluators:
        findings = evaluator.evaluate(scope, now)              ← 纯读
        reconcile(evaluator.codes(), batch, findings, now)     ← 每站点一个 REQUIRES_NEW 事务
  dispatchDue(now)          // §7.1
  closeRecovered(now)       // §5.4
  return 计数

reconcile(codes, batch, findings, now):
  byKey = findings 以 dedupKey 建表
  // 1) 成立的条件
  for f in findings:
     code = codes[f.code]；!code.enabled → 跳过
     open = 未关闭告警[f.dedupKey]
     if open:
        if open.recoveredAt != null: open.recoveredAt = null；log RELAPSE      // 防抖期内复发
        bump(open, f, now)                                                    // last_occurred_at、证据、影响只升不降
        continue
     cond = conditions.upsert(f.dedupKey)：
        新建 → first_seen=now, last_seen=now, held=0
        已有 → held += countable(now - last_seen, site, code.businessHoursOnly)；last_seen=now
     if cond.held >= code.holdMinutes: open(f, now, firstSeen=cond.first_seen)；conditions.delete(key)
  // 2) 不再成立的
  for alarm in 未关闭告警 where code ∈ codes 且 站点 ∈ batch 且 key ∉ byKey:
     if code.recoverRule == SIGNAL_CLEAR and alarm.recoveredAt == null:
         alarm.recoveredAt = now；log RECOVER
  conditions.deleteWhere(code ∈ codes, 站点 ∈ batch, key ∉ byKey)            // 计时中断即清零

countable(delta, site, bizOnly):
  delta = min(delta, 5 分钟)          // tick 停摆后恢复，不把停摆期整段算进去
  !bizOnly → delta
  bizOnly  → delta 中落在站点营业时间内的分钟数（openHours 空 → 按 24 小时，并由站点概览提示补配）
```

### 5.3 `open`

```
open(f, now, firstSeen):
  code   = codes[f.code]
  impact = impactAssessor.assess(f, profile(f.siteNo), now)       // §六
  a = new DevAlarm(alarmNo=IdGenerator.next(ALARM), alarmCode, level=code.level, source=EVAL,
                   domain, subjectType, subjectNo, siteNo, cabinetNo, agentNo, regionId,
                   cause, impact.*, priority=impact.priority, evidence=json(f.evidence ≤ 20),
                   status=OPEN, dedupKey=f.dedupKey, count=1,
                   occurredAt=firstSeen, firstOccurredAt=firstSeen, lastOccurredAt=now,
                   dueAt = now + code.woDelayMinutes)
  insert —— 撞 uk_alarm_open（并发：别的线程刚开了同一条）→ 重读并按 bump 处理
  log OPEN
  supersede(a)                          // §5.5
  if dueAt <= now: dispose(a, now)      // 延迟为 0 的立即处置
  notify(a, "OPENED")                   // §八
```

`bump` 不改 `occurred_at`；`count` +1（事件型）或不变（状态型每分钟都「成立」，只刷新 `last_occurred_at`）。
**影响只升不降**：若新评估的优先级更高 → 更新 `priority` 与影响字段、log `IMPACT_UP`，已开的工单同步上调（`WoOpsService.raisePriority`）。

### 5.4 恢复与关闭

```
closeRecovered(now):
  for a in status∈{OPEN,ACKED} AND recovered_at <= now - code.recoverHoldMinutes:
     close(a, SELF_HEALED, "业务已恢复", SYSTEM)

close(a, reason, note, operator):                    // 所有关闭都走这里
  a.status = sm.next(a.status, "CLOSE")；closed_at / closed_by / close_reason / close_note
  条件更新（原状态）
  protectionPort.release(a.alarmNo, reason)          // 释放本告警持有的保护动作（04 §4.3）
  联动处置（§7.3）
  log CLOSE
```

**人工关闭**（`closeManually`，沿用在途的关闭端点与校验）：`RESOLVED` / `FALSE_ALARM` 必填说明；`domain=SAFETY` 或 `recover_rule=DISPOSITION_DONE` 的码拒绝人工 `RESOLVED`（409「该类告警只能随处置完成关闭」），`FALSE_ALARM` 允许（误报总得有出口），但需 `workorder:alarm:close` 权限。

### 5.5 层级取代

`dev_alarm_code.supersedes`：`SITE_UNRENTABLE → CABINET_UNRENTABLE`、`SITE_UNRETURNABLE → CABINET_UNRETURNABLE`。

```
supersede(upper):
  lowers = 未关闭告警 where code = codes[upper.code].supersedes AND site_no = upper.site_no
  for l in lowers:
     l.parent_alarm_no = upper.alarmNo
     close(l, SUPERSEDED, "并入 " + upper.alarmNo, SYSTEM)       // 其工单改挂到上层工单（§7.3）
```

上层恢复后，仍有问题的柜会在下一轮被判定器重新产出 `CABINET_UNRENTABLE` —— 新告警的 `first_occurred_at` 取**被取代那条的** `first_occurred_at`（按 dedupKey 查最近一条 `SUPERSEDED` 且 parent 已关闭的），持续时长不重置。

## 六、影响评估 `ImpactAssessor`

```
assess(f, profile, now):
  scope    = f.scope
  period   = !inOpenHours(site, now) ? CLOSED : (hour(now, bizZone) ∈ profile.peakHours ? PEAK : OPEN)
  tier     = profile?.tier ?: "B"                  // 无画像（新站）按 B
  inFlight = f.inFlightOrders
  if !code.impactAdjust: return (scope, period, tier, inFlight, code.basePriority)   // 安全域固定
  d = 0
  if scope == SITE: d++
  if period == PEAK: d++
  if tier == "A": d++
  if tier == "C" && period != PEAK: d--
  if domain == RETURNABILITY && inFlight >= 1: d++
  priority = WoPriority.valueOf(code.basePriority).plus(d)        // 封顶 URGENT、保底 LOW
```

**站点画像**（`SiteProfileService.recompute()`，由 `daily-tick` 调用）：
- `OrderQueryPort.gmvBySites(30 天)` → 按 GMV 排序，前 20% = A、后 20% = C、其余 B；开业不满 30 天（`first_live_at`）固定 B；
- `OrderQueryPort.ordersByHour(siteNos, 30 天)` → 每站订单最多的 3 个小时（业务时区）为高峰；样本 < 30 单的站点用区域内合计的高峰。
- 端口 🆕 `OrderQueryPort` 追加这两个方法（03 已为其定义 `inFlightCountBySites`）。

### 7.2 `dispose(a)`

```
route = routes[(a.code, a.cause)] ?: routes[(a.code, "*")] ?: 码的默认 disposition
switch route.disposition:
  AUTO_FIX   → r = autoFixers[a.code].fix(a)           // 最多 3 次（dev_alarm_log 中 FIX_TRY 计数）
               成功 → close(a, AUTO_FIXED)
               失败 → log FIX_FAIL；达 3 次 → 按 route.fallback 再 dispose
  WORK_ORDER → woNo = woOps.openOrAttach(draftOf(a, route))           // 06 §四
               a.disposition_type=WORK_ORDER, disposition_ref=woNo, wo_no=woNo（兼容旧列）
  CS_CASE    → ticketNo = csTickets.createFromAlarm(a)                  // cs 已有受理单；新增方法
  TODO       → todoNo = todos.create(a, code.ownerRole)                // §7.4
  NOTIFY     → notify(a, "DISPOSE")；不写 disposition_ref
log DISPOSE（写明处置方式与单号）
```

**工单草稿** `draftOf(a, route)`：`type=route.woType`、`priority=a.priority + route.priorityDelta`、`source=ALERT`、
`mergeKey` 见下表、`siteNo/cabinetNo/agentNo` 取告警、`description = 业务名称 + 影响标签 + 根因 + 预案 + 证据摘要`。

| merge_scope | 合并键（写 `wo_order.source_ref`） |
|---|---|
| DEVICE | `ALM:{cabinetNo}:{woType}` |
| SITE | `ALM:{siteNo}:{woType}` |
| REGION | `ALM:{regionId}:{woType}:{yyyyMMdd}` |

**L0 自愈器**（`alarm.dispose.fix`，经 🆕 `TradeRemedyPort` 调 core）：

| 码 | 动作 | 端口方法 |
|---|---|---|
| `RENT_NOT_DELIVERED` | 撤销订单、释放预授权 / 退款 | `TradeRemedyPort.cancelUndelivered(orderNo, reason)` |
| `RETURN_NOT_RECOGNIZED` | 按宝首次在柜中上报的时刻结束订单并计费、通知用户 | `TradeRemedyPort.finishAt(orderNo, cabinetNo, slotIndex, returnedAt)` |

### 7.3 关闭时联动处置

| 告警关闭原因 | 处置单处于 | 动作 |
|---|---|---|
| `SELF_HEALED` | 工单 `CREATED/DISPATCHED`，且该工单**所有**关联告警均已关闭 | `woOps.withdraw(woNo, "关联告警已自动恢复")` → 通知被派人（06） |
| `SELF_HEALED` | 工单已接单及之后 | `woOps.annotate(woNo, "关联告警已恢复")`，不撤 |

```java
// alarm/port/WorkOrderReviewListener.java —— wo 不认识 alarm，所以由 alarm 订阅 wo 的事件
@EventListener @Transactional(propagation = REQUIRES_NEW)
public void on(WorkOrderCompletedEvent e) {                       // 06 定义；工单进入 DONE 时发布
    List<DevAlarm> linked = alarms.byDisposition("WORK_ORDER", e.woNo());
    if (linked.isEmpty()) return;                                 // 人工单：不复核

}
reviewOne(a):

  recovered_at != null            → passed = true（防抖期内也算）
  否则                            → 立即对该对象重跑一次判定器：不再产出该码 → true；仍产出 → false
```
