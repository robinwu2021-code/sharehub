## 一、库表（迁移 M1）

```sql
SET NAMES utf8mb4;
-- M1：文件元数据。字节在 COS（或测试环境本地目录），这里只存「它是谁的、在哪、能不能看」。
-- 为什么先传后绑：表单里先传照片、后点保存；用户放弃时 TEMP 文件由清理任务回收，不留无主对象。
CREATE TABLE IF NOT EXISTS sys_file (
  id              BIGINT UNSIGNED NOT NULL AUTO_INCREMENT,
  file_no         VARCHAR(36)  NOT NULL                 COMMENT '业务键 FL*',
  tenant_id       VARCHAR(36)  NOT NULL DEFAULT 'MAIN',
  category        VARCHAR(32)  NOT NULL                 COMMENT 'CONTRACT_SCAN 合同签署件 / WO_PHOTO 工单照片 / SURVEY_PHOTO 勘测照片 / LEAD_PHOTO 选址照片 / AGENT_QUALIFICATION 代理资质 / CS_EVIDENCE 报障截图 / PUBLIC_IMAGE 公开图片',
  status          VARCHAR(16)  NOT NULL DEFAULT 'TEMP'  COMMENT 'TEMP 已上传未绑定 / BOUND 已绑定 / REMOVED 业务已移除 / PURGED 对象已清理',
  biz_type        VARCHAR(32)      NULL                 COMMENT 'CONTRACT 合同 / WORK_ORDER 工单 / LOCATION 点位 / LEAD 商机 / AGENT_APPLY 入驻申请 / CS_TICKET 报障 / BRAND 品牌 / NOTICE 公告',
  biz_no          VARCHAR(36)      NULL                 COMMENT '归属对象业务号（绑定后写入）',
  original_name   VARCHAR(255) NOT NULL,
  content_type    VARCHAR(64)  NOT NULL                 COMMENT '服务端嗅探结果，不取客户端声明',
  size_bytes      BIGINT       NOT NULL,
  sha256          CHAR(64)     NOT NULL,
  storage         VARCHAR(16)  NOT NULL                 COMMENT 'COS 腾讯云对象存储 / LOCAL 本地目录（测试与离线开发）',
  bucket          VARCHAR(64)  NOT NULL,
  object_key      VARCHAR(255) NOT NULL,
  pii             TINYINT(1)   NOT NULL DEFAULT 0       COMMENT '个人数据：只流式转发，不发预签名地址',
  image_width     INT              NULL,
  image_height    INT              NULL,
  taken_at        DATETIME(3)      NULL                 COMMENT '拍摄时间（EXIF，仅保留定位的用途写入）',
  geo_lat         DECIMAL(10,7)    NULL,
  geo_lng         DECIMAL(10,7)    NULL,
  uploader_realm  VARCHAR(16)  NOT NULL                 COMMENT 'STAFF 员工 / AGENT 代理 / CONSUMER C端用户',
  uploader_no     VARCHAR(36)  NOT NULL,
  agent_no        VARCHAR(36)      NULL                 COMMENT '数据范围锚点：代理上传，或绑定对象属于某代理',
  bound_at        DATETIME(3)      NULL,
  removed_at      DATETIME(3)      NULL,
  created_at      DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3),
  created_by      VARCHAR(36)      NULL,
  updated_at      DATETIME(3)  NOT NULL DEFAULT CURRENT_TIMESTAMP(3) ON UPDATE CURRENT_TIMESTAMP(3),
  updated_by      VARCHAR(36)      NULL,
  version         BIGINT       NOT NULL DEFAULT 0,
  deleted         TINYINT(1)   NOT NULL DEFAULT 0,
  PRIMARY KEY (id),
  UNIQUE KEY uk_file_no (file_no),
  UNIQUE KEY uk_file_object (bucket, object_key),
  KEY idx_file_biz (biz_type, biz_no, status),
  KEY idx_file_temp (status, created_at)          COMMENT '清理任务：TEMP 超 24h',
  KEY idx_file_dedup (uploader_no, category, sha256)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='文件元数据（字节在对象存储）';

-- 合同附件改为引用文件：原 file_name/size 由前端声明、不可信，改从 sys_file 取
ALTER TABLE loc_contract_attach
  ADD COLUMN IF NOT EXISTS file_no VARCHAR(36) NULL COMMENT '→ sys_file.file_no；NULL = 接入对象存储前的历史附件（只有名字没有字节）';
```

**数据范围**：`sys_file` 有 `agent_no` → 在 `DataScopeRegistration` 登记 `Map.of("AGENT","agent_no")`。
代理只能看到自己上传或归属自己对象的文件；员工按 ALL。

**PII**：v4/03 规划的 `sharehub_pii` 独立库**尚未建数据源**。首版 PII 文件的元数据落 `sharehub_core`、以 `pii=1` 标记，
字节进独立的 `sharehub-pii` 桶；独立库建成时按 `pii=1` 搬迁（只搬元数据行）。

### 2.1 存储端口（模块内）

```java
package ai.neargo.sharehub.platform.file.storage;

public interface FileStoragePort {
    /** 流式写入。实现方不得把整个流读进内存。 */
    void put(String bucket, String key, InputStream in, long size, String contentType);
    /** 私有桶的限时下载地址。 */
    URI presignGet(String bucket, String key, Duration ttl, String downloadName);
    /** 流式读（PII 转发、缩略图生成）。 */
    InputStream open(String bucket, String key);
    void remove(String bucket, String key);
    /** 公开桶的永久地址（CDN）。 */
    URI publicUrl(String bucket, String key);
}

@Component @ConditionalOnProperty(name = "sharehub.storage.type", havingValue = "cos")
class CosFileStorage implements FileStoragePort { … }        // com.qcloud:cos_api，子账号密钥

@Component @ConditionalOnProperty(name = "sharehub.storage.type", havingValue = "local", matchIfMissing = true)
class LocalFileStorage implements FileStoragePort { … }      // ${sharehub.storage.local.root}/{bucket}/{key}
```

`LocalFileStorage.presignGet` 返回 `/api/platform/files/{fileNo}/raw?exp=…&sig=…`（HMAC，密钥 `sharehub.storage.local.sign-secret`），
由 `FileController` 自己验签输出 —— 让测试与离线开发走通**与生产同一条**「302 到限时地址」路径。

配置（`application.yml`，密钥只走环境变量）：

```yaml

    cos:
      region: ${SHAREHUB_COS_REGION:}

      secret-key: ${SHAREHUB_COS_SECRET_KEY:}
      bucket-private: ${SHAREHUB_COS_BUCKET_PRIVATE:}
      bucket-pii: ${SHAREHUB_COS_BUCKET_PII:}
      bucket-public: ${SHAREHUB_COS_BUCKET_PUBLIC:}

    local:

      sign-secret: ${SHAREHUB_STORAGE_LOCAL_SIGN_SECRET:dev-only}
    presign-ttl: PT5M
spring.servlet.multipart: { max-file-size: 20MB, max-request-size: 25MB, file-size-threshold: 1MB }
```

启动自检：`type=cos` 且任一桶名或密钥为空 → **启动失败**（fail-fast），不允许带着空配置跑到第一次上传才报错。

### 2.2 跨模块端口（`sharehub-api`）

工单（ops）、报障（ops.cs）、入驻（platform.agent）要把文件绑到自己的对象上、并校验读权限：

```java
package ai.neargo.sharehub.api.platform.port;

public interface FileBindingPort {
    /** 把本人刚上传的 TEMP 文件绑到业务对象。校验：上传人 = 操作人、状态 TEMP、用途与 bizType 匹配。 */
    List<FileRef> bind(List<String> fileNos, String bizType, String bizNo, String agentNo);
    /** 业务移除：BOUND → REMOVED（软删，对象按保留期清理）。 */
    void remove(String fileNo, String bizType, String bizNo);
    List<FileRef> listBound(String bizType, String bizNo);
}

package ai.neargo.sharehub.api.platform.dto;
public record FileRef(String fileNo, String category, String originalName, String contentType,
                      long sizeBytes, boolean previewable, LocalDateTime takenAt, LocalDateTime uploadedAt) {}

/** 下载鉴权 SPI：由拥有该业务对象的域实现，文件服务按 bizType 找对应实现。 */
public interface FileAccessChecker {
    String bizType();
    /** 当前登录者能否查看该业务对象（含数据范围）。实现方用本域已有的读查询即可 —— 查不到即无权。 */
    boolean canRead(String bizNo);
}
```

各域实现 `FileAccessChecker`：`loc` 实现 `CONTRACT`（查合同，带数据范围）、`LOCATION`、`LEAD`；`wo` 实现 `WORK_ORDER`；`cs` 实现 `CS_TICKET`；`agent` 实现 `AGENT_APPLY`。
**未找到对应 checker 的 bizType 一律拒绝**（fail-closed）。

## 三、服务

```java
package ai.neargo.sharehub.platform.file.service;

public interface FileService {
    record Upload(FileCategory category, String originalName, long declaredSize,
                  InputStreamSource content, String uploaderRealm, String uploaderNo, String uploaderAgentNo) {}
    FileRef upload(Upload cmd);
    Download openForDownload(String fileNo);            // 鉴权后返回 302 地址或流
    sealed interface Download permits Redirect, Stream {}
    record Redirect(URI location) implements Download {}
    record Stream(InputStream in, String contentType, long size, String fileName, boolean inline) implements Download {}
}
```

### 3.1 `upload` 核心逻辑

```
upload(cmd):
  1. 大小：declaredSize > category.maxBytes → 400「超过 N MB」
  2. 落临时文件（Spring multipart 已落盘，直接用 InputStreamSource）
  3. 嗅探：Tika.detect(头 8KB) → MediaType；不在 category.allowed、或与扩展名 / 声明类型不一致 → 400「文件类型不符：期望 PDF/JPG/PNG」
     明确拒绝：image/svg+xml、text/html、application/x-*（即使用途允许 image/*）
  4. 边读边算 SHA-256；实际字节数 > maxBytes → 400（防声明造假）
  5. 秒传（L1）：同 uploader + category + sha256 且 24h 内 TEMP → 直接返回该行
  6. 图片（JPEG/PNG）：
       - 读尺寸；KEEP_EXIF → 读拍摄时间与 GPS 写入 taken_at/geo_*
       - STRIP_EXIF → ImageIO 重编码一次（去全部元数据），以重编码结果为上传内容
  7. fileNo = IdGenerator.next(BizKey.FILE)
     key    = "{category小写}/{yyyy}/{MM}/{fileNo}.{ext}"      ← 服务端生成，不含原始名与业务号
     bucket = 按 category.bucketKind 取配置
  8. storage.put(bucket, key, stream, size, contentType)       ← 失败：不写元数据，抛 409「上传失败，请重试」并 WARN
  9. insert sys_file(status=TEMP, pii, uploader_*, agent_no=uploaderAgentNo)
       ← 若 insert 失败：对象成孤儿，由每日对账清理（不做分布式事务）
 10. INFO「文件已上传 fileNo={} category={} size={} uploader={}」（不记地址、不记原始名以外的个人信息）
```

### 3.2 `bind` / `remove`（`FileBindingPort` 的实现，`platform.file.port.LocalFileBinding`）

```
bind(fileNos, bizType, bizNo, agentNo):          @Transactional（跟随调用方事务 REQUIRED）
  for each fileNo:
    f = 按 fileNo 取（无数据范围：绑定由业务服务在其鉴权之后调用）
    校验 f.status == TEMP                     否则 400「文件已被使用或已失效」
    校验 f.uploaderNo == 当前操作人          否则 400（同「不存在」文案，不泄露）
    校验 FileCategory.valueOf(f.category).bizType 匹配 bizType（PUBLIC_IMAGE 允许 BRAND/NOTICE/AD）
    update status=BOUND, biz_type, biz_no, bound_at=now, agent_no=coalesce(agentNo, f.agentNo)
       条件更新 WHERE status='TEMP'，影响行数 0 → 400（并发下已被别人绑定）
  return listBound(bizType, bizNo)
```

**调用方与业务保存同一事务**：业务行写失败 → 绑定一起回滚，文件回到 TEMP，按期被清理。

### 3.3 `openForDownload`

```
f = 取文件；status ∉ {TEMP, BOUND} → 400「文件不存在」
TEMP  → 仅上传人本人可看
BOUND → checker = checkers[f.bizType]；无 checker 或 !checker.canRead(f.bizNo) → 400「文件不存在」
pii 或 PUBLIC 以外的非图片需要 inline=false
f.pii → Stream(storage.open(...), inline=图片)
否则  → Redirect(storage.presignGet(bucket, key, ttl=5m, downloadName=originalName))
```

## 四、API（运营端只有 6 个前缀，文件归 `/api/platform`）

| 方法 | 路径 | 权限 | 入参 | 出参 |
|---|---|---|---|---|
| POST | `/api/platform/files` | 按 `category` 映射（见下） | multipart：`file`，`category` | `FileRef` |
| GET | `/api/platform/files/{fileNo}` | 登录即可，服务内按归属对象鉴权 | `?inline=true|false` | 302 或文件流 |
| GET | `/api/platform/files/{fileNo}/raw` | 仅 `LocalFileStorage` 签名链接 | `exp`、`sig` | 文件流 |
| POST | `/mp/files`（L1） | C 端登录 | 只接受 `CS_EVIDENCE` | `FileRef` |

```java
@RestController @RequestMapping("/api/platform/files")
class FileController {
    @PostMapping(consumes = MediaType.MULTIPART_FORM_DATA_VALUE)
    FileRef upload(@RequestParam("file") MultipartFile file, @RequestParam("category") String category) {
        FileCategory c = FileCategory.of(category);                 // 非法值 400
        if (c.uploadPerm() == null || !perm.can(c.uploadPerm()))     // 按用途判权
            throw new AccessDeniedException("category");
        return files.upload(new FileService.Upload(c, file.getOriginalFilename(), file.getSize(),
                file::getInputStream, SecurityUtils.realm().name(), SecurityUtils.userNo(),
                SecurityUtils.currentUser().map(LoginUser::agentNo).orElse(null)));
    }
    @GetMapping("/{fileNo}")
    ResponseEntity<?> download(@PathVariable String fileNo, @RequestParam(defaultValue = "true") boolean inline) { … }
}
```

- 上传端点**不用** `@PreAuthorize` 固定码，因为码随用途而变；在方法内以 `perm.can(...)` 判定 —— 注入与 `@PreAuthorize("@perm.can(...)")` **同一个** `perm` bean（由 neargo 权限组件提供，实现前先确认其类名与注入方式；不要自己按 `LoginUser.perms()` 另写一套通配匹配，两套规则会分叉）。
  这样**不新增任何权限码**，复用各业务已有的写权限。
- `AGENT_QUALIFICATION` 的上传人是尚未开户的申请人（匿名 + OTP 会话），走入驻申请自己的端点 `POST /api/agent/apply/files`，复用 `AnonymousRateLimitFilter`（L1，随入驻资质改造一起做）。
- 下载响应 `Cache-Control: private, no-store`；非图片 `Content-Disposition: attachment; filename*=UTF-8''…`。

## 六、测试

| 用例 | 断言 |
|---|---|
| 上传 PDF → 绑定到合同 → 下载 | 302 到本地签名地址；地址 5 分钟后失效 |
| 把 `.exe` 改名 `.pdf` 上传 | 400 类型不符 |
| 声明 1MB、实际 30MB | 400 超限（按实际字节） |
| A 上传的 TEMP 文件由 B 绑定 | 400 |
| 同一文件并发绑定两次 | 恰好一次成功 |
| 代理 X 下载代理 Y 合同的附件 | 400「文件不存在」 |
| 未注册 checker 的 bizType | 拒绝 |
| `pii=1` 的文件下载 | 流式返回，响应头无 `Location` |
| `type=cos` 且缺桶名启动 | 启动失败 |

测试一律 `sharehub.storage.type=local`（`application-test.yml`），不依赖外网。COS 适配器单独一个手动触发的冒烟用例（`@EnabledIfEnvironmentVariable("SHAREHUB_COS_SECRET_ID")`）。
