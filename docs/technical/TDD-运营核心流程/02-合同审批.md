# 02 · 合同审批

> 定调：[运营核心流程](../../requirements/运营核心流程.md) §十.1（合同走审批）。矩阵：S-CTR-01 / 02 / 03（L0）、S-CTR-04…07（L1 留位）。
> 模块：`sharehub-svc-platform` · 包 `ai.neargo.sharehub.loc` · Controller `sharehub-app/portal/platform/ContractController`（从 `OpsController` 拆出）

---

## 一、现状与改动面

| 现状 | 问题 | 改为 |
|---|---|---|
| `loc_contract.status` 只有 `ACTIVE/EXPIRED`，表单里自由下拉 | 没有审批、没有待生效；未签字的合同也能「生效」 | 六态状态机，状态只经动作改 |
| `OpsController.createContract(@RequestBody LocContract)` | 实体做请求体；`LocContract` 不继承 `BaseEntity`，恰好绕过了实体请求体卡口 | 改收 `ContractReq`（白名单） |
| `LocService.saveContract` 在「保存为 ACTIVE」时发 `ContractSignedEvent` | 手改状态即触发介绍费 | **只在 ACTIVATE 迁移时**发一次 |
| 附件在 `LeadFollowServiceImpl`（商机跟进服务里） | 归属错位 | 迁入 `ContractService.attach`，并改用文件编号（见 01 §五） |
| 无到期处理 | 过期合同仍被当作生效 | 定时迁移 |

合同相关方法从 `LocService`（具体类）抽成 `ContractService` 接口 + `ContractServiceImpl`；`LocService.saveContract` 删除，调用方改走新服务。

- `loc_contract` 已在 `known-unscoped-owned-tables.txt`（有 `site_no` 未登记数据范围）。**本次顺手登记**：`register("loc_contract", Map.of("SITE","site_no"))`，并从台账删除该行（台账只减不增）。

- `loc_contract_log` 不带归属列，无需登记。
- `share_rate` 在 `share_mode ∈ {ENTRY_FEE, FREE}` 时允许为 0；分润生成（`ShareGeneratorImpl`）读取 `share_rate` 的逻辑不变 —— 保底差额在结算单层补（S-STL-01，L1）。

### 4.1 统一的迁移骨架（`ContractServiceImpl` 私有）

```java
private LocContract transit(String contractNo, String event, String note, Consumer<LocContract> mutate) {
    LocContract c = requireForUpdate(contractNo);             // 带数据范围读；不存在 → 400
    String from = c.getStatus();
    c.setStatus(sm.next(from, event));                        // 非法迁移 → 400
    mutate.accept(c);
    int n = contracts.update(c, Wrappers.<LocContract>lambdaUpdate()
            .eq(LocContract::getContractNo, contractNo)
            .eq(LocContract::getStatus, from));               // 条件更新：并发下只有一个人赢
    if (n == 0) throw ServerException.of(ErrorCode.CONFLICT, "合同状态已变化，请刷新后重试");
    logs.insert(log(contractNo, event, from, c.getStatus(), operator(), note));
    return c;
}
```

所有动作方法 `@Transactional`，形如 `return toVO(transit(no, "SUBMIT", null, c -> { c.setSubmittedBy(uid); c.setSubmittedAt(now); }))`。

### 4.2 各动作的前置校验

| 动作 | 前置（不满足 → 409，文案写清缺什么） |
|---|---|
| `create` / `updateDraft` | 站点存在且属于该场地方；`endAt ≥ startAt`；`shareMode=GUARANTEE` 需 `guaranteeAmount>0` 且 `shareRate>0`；`SHARE` 需 `shareRate>0`；`ENTRY_FEE` 需 `entryFee>0`；`FREE` 时比例与费用置 0。归属锚点（`venueName/siteName`）服务端取 |
| `submit` | 同上全部复核；**期限不与该站点其他 PENDING/SIGNED/ACTIVE 合同重叠**，续签合同与其 `prevContractNo` 允许首尾相接 |
| `withdraw` | 操作人 = `submittedBy` |
| `approve` | 操作人 ≠ `submittedBy`（**不能自己批自己**）；重叠复核（提交后可能有别的合同已批） |
| `reject` | 意见非空 |
| `sign` | 状态 SIGNED；`signedAt ≤ today`；绑定文件（`fileBinding.bind(fileNos,"CONTRACT",no,…)`，写 `loc_contract_attach`）。之后若 `startAt ≤ today` → 同事务内执行 `activate(c)` |
| `terminate` | 状态 ACTIVE；`effectiveAt ≥ today`。`effectiveAt > today` 时**只记录**终止计划（`end_reason`，`end_at` 改为 `effectiveAt`），到日由 tick 走 `EXPIRE`；等于今天则立即 `TERMINATE` |
| `renew` | 原合同 ACTIVE 或 EXPIRED；复制条款，`startAt = 原 endAt + 1`、`prevContractNo = 原号`，状态 DRAFT |

### 4.3 `activate`（系统动作，`sign` 与 `tick` 共用）

```
activate(c):                                    // 已在事务内
  前置：c.signedAt != null 且 至少一个签署件（file_no 非空的附件）
        否则保持 SIGNED（tick 下次再看；前端「签署件」页签显示缺什么）
  old = 同站点现存 ACTIVE 合同（除 c 外）
  if old != null:
      old.status = sm.next(old.status, "EXPIRE"); old.endedAt = now; old.endReason = "被续签合同 " + c.no + " 替代"
      log(old, "EXPIRE", note=同上)
  c.status = sm.next("SIGNED", "ACTIVATE"); c.activatedAt = now
  log(c, "ACTIVATE")
  events.publish(new ContractSignedEvent(c.no, c.siteNo, c.venueNo, c.currency))   // 介绍费；只在这里发
  // 站点不因合同生效而改状态：营业由「首台设备上线」驱动（03 §4.5），合同只是上线门禁的一项
```

**不变式**：同一站点任一时刻最多一份 ACTIVE。靠「激活时先把旧的 EXPIRE」+「submit/approve 的重叠校验」共同保证；
另加一条集成用例在数据库层面断言（`SELECT site_no, COUNT(*) … WHERE status='ACTIVE' GROUP BY site_no HAVING COUNT(*)>1` 为空）。

### 4.4 `tick(today)`

```
@Transactional 每批一条合同（REQUIRES_NEW），一条失败不影响其他：
  1. 到期：status=ACTIVE AND end_at < today → EXPIRE（note="到期"或 end_reason 中的终止计划）
  2. 生效：status=SIGNED AND start_at <= today → activate(c)（缺签署件则跳过）
  返回计数；三项都为 0 时 AuditNoop.mark
```

「今天」按**业务时区**取：新增配置 `sharehub.biz-zone`（默认 `Asia/Dubai`），`LocalDate.now(bizZone)`。
数据库时刻列一律 UTC（规范），日期列（`start_at/end_at/signed_at`）是业务日期。

### 4.5 查询 `page`

- `pendingMine=true`：`status=PENDING AND submitted_by <> 当前人`（「待我审批」摘要卡）；
- 附带计算字段 `remainingDays = end_at - today`（VO 字段，不落库）；
- 摘要计数端点返回：待我审批 · 60 天内到期 · 已到期未续（EXPIRED 且站点仍 ACTIVE/PAUSED）· 缺签署件（SIGNED 且无附件）。

## 六、存量与兼容

| 存量 | 处理 |
|---|---|
| `status=ACTIVE` 的合同 | 保持 ACTIVE；`signed_at` 为空 → 不回填（在「缺签署件」摘要里显形，由 BD 补） |
| `status=EXPIRED` | 不变 |
| `attach_url` 列 | 废弃不删；实体保留映射，VO 不再输出 |
| 同站点多份 ACTIVE（若有） | 迁移脚本**只检测不修复**：头部注释给出检测 SQL；有则人工处理后再上线（修错合同 = 修错分成依据，不能由脚本替人决定） |
