# 04 · 设备状态机、上线门禁、停借保还、保护动作

> 矩阵：S-DEV-02 机柜状态机 · S-DEV-03 上线门禁 · S-DEV-04 试借还 · S-RENT-01 停借保还（均 L0）；S-DEV-05 入库质检（L1 留位）。
> 模块：`sharehub-svc-core` · 包 `ai.neargo.sharehub.dev`（门禁、保护、信号）与 `ai.neargo.sharehub.trade`（借出校验）
> Controller：`sharehub-app/portal/core/DeviceOpsController`（新建，承接机柜动作；`OpsController` 的机柜建档端点保留）

---

## 一、现状与改动面

| 现状 | 改为 |
|---|---|
| `CabinetServiceImpl.save` 从请求体原样写 `status`，无状态机 | `CabinetStateMachine`；`save` 只改属性，状态只经动作 |
| 上线没有门槛 | `GoLiveGate` 五项全过才能 `GO_LIVE` |
| `RentOrderServiceImpl.rent` 不查站点、设备状态与在线 | `RentabilityGuard`：只有「营业中站点 × 已布放在线柜 × 未被停借 × 有可借仓」能借；归还不查（保还） |
| 仓位禁用、停借没有统一表达 | `dev_protection`：保护动作 + 持有者 + 引用计数 |
| 设备信号（离线、卡宝、电池）无接入口 | `DeviceSignalService` + 信号字典 `dev_event_code`；网关事件与模拟事件同一入口 |

**信号字典与保护动作归设备域（core）**：它们是设备层的止损，与「是不是业务告警」无关（告警方案 v2 §6.2）。
业务告警（ops）只**订阅**信号事件、**读取**设备状态，并通过端口**申请 / 释放**保护动作。

## 四、服务

### 4.1 `CabinetLifecycleService`（`dev.service`，新）

```java
public interface CabinetLifecycleService {
    Checklist goLiveGate(String cabinetNo);
    Cabinet goLive(String cabinetNo);
    Cabinet markFault(String cabinetNo, String reason);
    Cabinet repair(String cabinetNo);
    Cabinet undeploy(String cabinetNo, String reason);
    Cabinet retire(String cabinetNo, String reason);
}
```

**上线门禁 `goLiveGate`**（只读；`goLive` 在事务内重跑一遍，任一不过 → 409，文案取第一项未通过的 `detail`）：

| key | 通过条件 | 来源 | fixHref |
|---|---|---|---|
| `LOCATION` | 已绑定点位且点位未归档 | 本表 | 设备编辑 |
| `SITE_OPEN` | 站点状态 ∈ {PREPARING, ACTIVE, PAUSED} | `SiteQueryPort` | 站点详情 |
| `CONTRACT` | 站点有 ACTIVE 合同 | `ContractQueryPort.activeBySites` | 合同 |
| `ONLINE` | `online_status=ONLINE` 且 `last_heartbeat_at` 在 3 分钟内（与可借判定同一口径） | 本表 | 设备详情 |
| `TRIAL` | `trial_passed_at` 非空且 `≥ bound_at`（换点位后需重测） | 本表 | 设备详情 › 试借还 |
| `PRICE` | 能为「该设备类型 × 该站点」解析出计费方案 | `PricingProbe` | 收费方案 |

`PricingProbe` 是**设备域声明、计价域实现**的模块内端口（`dev.port.PricingProbe`，实现在 `trade.price.port.PricingProbeImpl`，调 `PriceResolver.match(PriceQuery…)`），
这样依赖方向是 `trade → dev`，避免 `dev ↔ trade` 成环（ArchUnit 切片检查）。

**`goLive` 核心逻辑**：

```
@Transactional
goLive(no):
  c = 带范围读
  gate = evaluate(c)；!gate.allPassed → 409(第一项 detail)
  c.status = sm.next(c.status, "GO_LIVE")；c.wentLiveAt = now
  条件更新（原状态）；AuditChanges.record("状态", from, to)
  events.publish(new CabinetWentLiveEvent(no, c.siteNo, c.locationNo, now))   → 站点 PREPARING→ACTIVE（03 §4.5）
```

**`save`（建档 / 编辑）的收紧**：
- 请求体里的 `status` **忽略**（`CabinetServiceImpl.save` 删除该分支；`known-entity-writable-fields.txt` 相应行改为锁定）；
- 绑定 / 更换点位仅允许在 `IN_STOCK / IN_TRANSIT`；已布放设备换点位需先 `UNDEPLOY`（否则 409「已布放设备请先撤机再换点位」）；
- 换点位时 `bound_at=now`，`trial_passed_at` 保留但门禁按 `≥ bound_at` 判定为失效。

### 4.2 `TrialRentService`

```java
public interface TrialRentService {
    TrialRent start(String cabinetNo);                         // 选一个有宝的可用仓，下发 EJECT
    List<TrialRent> list(String cabinetNo);
    void onSignal(DeviceSignalEvent s);                        // 弹出回执 / 仓位识别到该宝

```

```
start(no):
  前置：设备 ONLINE；无进行中的试借还（EJECTING / WAIT_RETURN）
  slot = 选择：有宝、未被 SLOT_DISABLE/SLOT_LOCK、电量最高的仓
  cmd  = deviceCommandPort.send(commandId=trialNo+":EJECT", no, slot, "EJECT", bizType="TRIAL_RENT", bizRef=trialNo)
         // → POST /internal/gw/commands（commandId 幂等）；结果以 COMMAND_RESULT 设备事件回推，不同步等待
  insert dev_trial_rent(EJECTING, slot, powerbankNo, eject_command_no=cmd.no, operator)
onSignal:
  code=EJECT_OK 且 commandNo 匹配 → EJECTED（WAIT_RETURN, ejected_at）
  code=EJECT_TIMEOUT 匹配         → FAIL（fail_reason="弹出失败"）
  code=RETURN_SN_SEEN 且 powerbankNo 匹配、trial 为 WAIT_RETURN → RETURNED（PASSED）
        → dev_cabinet.trial_passed_at = now
```

> 试借还**不产生订单、不计费**：它走设备指令与信号，不经 `RentOrderServiceImpl`。

### 4.3 保护动作 `ProtectionService`（实现 `DeviceProtectionPort`）

```java
public interface ProtectionService extends DeviceProtectionPort {
    Protection applyManual(String cabinetNo, Integer slotIndex, String action, String reason);
    Protection releaseManual(String protectionNo, String reason);      // 只能释放 MANUAL 持有的
    List<Protection> list(String cabinetNo, boolean activeOnly);
    void applyBySignal(DeviceSignalEvent s, String action);            // holder=SIGNAL, ref=code+":"+cabinet+":"+slot
    void releaseBySignal(String clearedCode, String cabinetNo, Integer slotIndex);
}
```

- **幂等**：`apply` 先按 `(cabinet, slot, action, holderType, holderRef, active=1)` 查，有则返回；插入撞 `uk_protection_holder` 时重读返回；
- **释放**：置 `active=NULL`、写 `released_at/release_reason`。唯一键含 `active`：生效行（=1）同键只能一条，已释放行（NULL）不参与唯一性、可有多条历史 —— 若用 0 表示已释放，第二次释放同键就会撞键。
- 每次变更后**重算**并回写 `dev_cabinet.available_count`（现有冗余列），列表页不必实时联表。

### 4.4 可借判定 `RentabilityGuard`（`trade` 包内）与 `CabinetAvailability`

```
cabinetRentable(c) =
    site.status == ACTIVE                                 （SiteQueryPort）
 && c.status == DEPLOYED && c.online                         （online = 最近心跳 ≤ 3 分钟，见 05 §4.1）
 && 无生效的整柜 STOP_RENT
slotRentable(s) =
    有宝 && 宝状态 IN_CABINET && 电量 ≥ 阈值(sharehub.rent.min-battery, 默认 60%)
 && 无生效的 SLOT_DISABLE / SLOT_LOCK
slotReturnable(s) =
    空仓 && 无生效的 SLOT_DISABLE / SLOT_LOCK
cabinetReturnable(c) = c.status ∈ {DEPLOYED, FAULT} && c.online && 存在 slotReturnable
```

`RentOrderServiceImpl.rent` 在建单前调用 `RentabilityGuard.checkRent(cabinetNo)`：

| 不满足 | 响应 |
|---|---|
| 站点非 ACTIVE | 409「该站点暂停服务，可就近归还」 |
| 设备非 DEPLOYED / 离线 / 整柜停借 | 409「该设备暂不可借，请换一台」 |
| 无可借仓 | 409「暂无可借充电宝」 |

**归还路径不调用 `checkRent`**（保还）；设备离线时的归还依赖设备本地缓存上报后补记，业务侧不拦。
`CabinetAvailability` 由同一套规则批量计算（一条 SQL 取柜、仓、宝、生效保护的聚合，站点状态经端口一次取回），供告警判定用（05）。

### 4.5 信号入口 `DeviceSignalService`

```java
public interface DeviceSignalService {
    /** 网关推送（/internal/events/device）与测试模拟共用。 */
    void ingest(DeviceEventBatch batch);   // {events:[{eventId, type, deviceNo, slotIndex?, powerbankNo?, vendorCode, vendorErrorCode?, occurredAt, attrs}]}，逐条 EventIdempotency.once(eventId)
}
```

```
ingest(req):                                      @Transactional
  code = dev_event_code[req.code]；未知码 → 记 WARN（写明厂商与原始码，便于补映射）并按 NONE 处理
  c    = 取机柜（无范围）；补 siteNo / agentNo
  状态类信号更新本表：HEARTBEAT → online=ONLINE、last_heartbeat_at；SLOT_* → dev_slot
  code.clears_code 非空 → releaseBySignal(clears_code, cabinet, slot)
  code.protective_action：
     STOP_RENT / SLOT_DISABLE / SLOT_LOCK / DERATE → applyBySignal
     AUTO_EJECT_RETRY → 下发一次 EJECT 到该仓；仍失败的回执会以 SLOT_STUCK 再次进来 → SLOT_DISABLE
  events.publish(new DeviceSignalEvent(...))       → 业务告警（05）、试借还（本章 4.2）
```

**离线不是设备主动上报的信号**：由告警判定的定时扫描根据 `last_heartbeat_at` 推断，并由它（而非本服务）申请整柜 `STOP_RENT`（持有者 ALARM），心跳恢复时随告警恢复释放。

**端点**：`POST /internal/events/device`（`ROLE_INTERNAL`，`X-Internal-Token`；安全规则已存在，控制器新建于 `portal/core/DeviceEventInternalController`）。
接入网关建成前，这是**测试与联调注入信号的唯一入口**；不另开「模拟」后门。

## 五、API（`DeviceOpsController`，新端点直接用目标资源名 `/api/ops/devices/{deviceNo}`；现有 `cabinets` 端点随 D1 改名，见 v4/04 §三）


下表路径中的 `/{no}` 即 `/api/ops/devices/{deviceNo}`；过渡期 `deviceNo` = `cabinetNo`，权限码仍为 `device:cabinet:*`（D1 同批改 `device:asset:*`）。

| 方法 | 路径 | 权限 | 请求 | 响应 |
|---|---|---|---|---|
| GET | `/{no}/go-live-gate` | `device:cabinet:read` | — | `Checklist` |
| POST | `/{no}/go-live` | `device:cabinet:update` | — | `Cabinet` |
| POST | `/{no}/mark-fault` | `device:cabinet:update` | `FaultReq` | `Cabinet` |
| POST | `/{no}/repair` | `device:cabinet:update` | — | `Cabinet` |
| POST | `/{no}/undeploy` | `device:cabinet:update` | `FaultReq`（原因） | `Cabinet` |
| POST | `/{no}/retire` | `device:cabinet:update` | `RetireReq` | `Cabinet` |
| GET | `/{no}/trial-rents` | `device:cabinet:read` | — | `List<TrialRent>` |
| POST | `/{no}/trial-rents` | `device:command:send` | — | `TrialRent` |
| GET | `/{no}/protections` | `device:cabinet:read` | `activeOnly` | `List<Protection>` |
| POST | `/{no}/protections` | `device:cabinet:update` | `ProtectionReq` | `Protection` |
| POST | `/protections/{protectionNo}/release` | `device:cabinet:update` | `NoteReq` | `Protection` |
| POST | `/internal/events/device` | `ROLE_INTERNAL` | `DeviceEventBatch`（批量，按 `eventId` 去重） | `OkResult` |
| POST | `/internal/core/devices/tick` | 回环地址 | — | 过期试借还数 |

不新增权限码。先确认 `device:cabinet:update` 在真源表与角色种子中存在（运营端功能清单 §三·A 记为「机柜建档/编辑/退役」所用码）。

## 六、测试

| # | 场景 | 期望 |
|---|---|---|
| 1 | 门禁逐项置失败（无合同 / 离线 / 未试借 / 无计费方案 / 站点关闭） | `go-live-gate` 对应项 `passed=false`；`go-live` 409 |
| 2 | 全部通过上线 | DEPLOYED；站点从 PREPARING 转 ACTIVE |
| 3 | 换点位 | 已布放 → 409；撤机后换点位 → `TRIAL` 项重新变为未通过 |
| 4 | 试借还：注入 `EJECT_OK` 再注入 `RETURN_SN_SEEN` | PASSED；`trial_passed_at` 有值 |
| 5 | 卡宝信号 → 自动重弹失败 → 仓位禁用；随后 `SLOT_EJECT_OK` | 禁用解除 |
| 6 | 同一仓位被两个持有者禁用，释放一个 | 仍禁用 |
| 7 | 暂停站点借出 | 409；归还成功 |
| 8 | 整柜被告警停借（`DeviceProtectionPort.apply`）后借出 | 409；`release` 后可借 |
| 9 | 编辑接口带 `status=DEPLOYED` | 状态不变 |
| 10 | 未知信号码 | 不报错，WARN 日志含厂商与原始码 |
