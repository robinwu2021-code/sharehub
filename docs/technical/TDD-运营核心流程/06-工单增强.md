# 06 · 工单增强

> 矩阵：S-WO-04 完工复核（L0）· S-WO-05 按责任人派单（L1，但自动开单依赖它，**随 L0 一起做最小版**）· S-WO-03 装机 · S-EXIT-02 撤机（L1 留位）· S-WO-06 超时升级（L2 留位）。
> 模块：`sharehub-svc-ops` · 包 `ai.neargo.sharehub.wo`（主包：状态机、词表）与 `wo.ext`（新增服务能力，遵守「主包不知道 ext」）
> Controller：`sharehub-app/portal/ops/WoExtController`（扩展）

## 一、现状与改动面

| 现状 | 改为 |
|---|---|
| `priority` 列无词表注释；`source` 注释缺 `PLAN`（巡检实际在写） | 补齐注释（存量词表卡口会拦） |
| 优先级词表只在 `WoOpsServiceImpl.PRIORITIES` 里是个 `Set<String>` | `WoPriority` 枚举（告警也要用） |
| SLA 只按类型 | 类型 × 优先级 |
| 告警转工单：抛异常 / 假单号 | `openOrAttach`：按合并键开单或挂靠 |
| 没有撤单、并单 | 状态机加 `WITHDRAW`、`MERGE` 两条边（均到 CLOSED，分别写 `WITHDRAWN` / `DUPLICATE`） |
| 派单处理人前端硬编码 `STAFF` | 候选人接口；自动开单默认派给站点运维责任人 |
| 完工只要备注；照片是字符串 | 故障原因必填、照片经文件服务绑定；维修类至少 1 张 |
| 完工后没有任何复核 | 发 `WorkOrderCompletedEvent`，告警域复核，通过即自动验收 |

## 二、库表（迁移 M6）

```sql
SET NAMES utf8mb4;
-- M6：工单承接业务告警。补齐词表注释（存量已在写 PLAN），加撤单 / 并单 / 复核所需列。
ALTER TABLE wo_order
  MODIFY COLUMN source   VARCHAR(16) NOT NULL COMMENT 'ALERT 告警 / USER 用户报障 / VENUE 场地方 / MANUAL 人工 / PLAN 巡检计划',
  MODIFY COLUMN priority VARCHAR(8)  NOT NULL DEFAULT 'MEDIUM' COMMENT 'LOW 低 / MEDIUM 中 / HIGH 高 / URGENT 紧急',
  ADD COLUMN IF NOT EXISTS assignee_type      VARCHAR(16)  NULL COMMENT 'EMPLOYEE 平台员工 / AGENT 代理商',
  ADD COLUMN IF NOT EXISTS dispatch_strategy  VARCHAR(16)  NULL COMMENT 'OWNER 按运维责任人 / MANUAL 人工 / NEAREST 就近 / LOAD 负载 / GRAB 抢单',
  ADD COLUMN IF NOT EXISTS fault_reason_code  VARCHAR(32)  NULL COMMENT '故障原因分类（字典 wo_fault_reason）',
  ADD COLUMN IF NOT EXISTS review_status      VARCHAR(16)  NULL COMMENT 'PASSED 复核通过 / FAILED 复核未通过（仅告警来源的工单）',
  ADD COLUMN IF NOT EXISTS review_detail      VARCHAR(2000) NULL COMMENT '复核明细 JSON：[{alarmNo, code, passed, note}]',
  ADD COLUMN IF NOT EXISTS reviewed_at        DATETIME(3)  NULL,
  ADD COLUMN IF NOT EXISTS merged_into_wo_no  VARCHAR(36)  NULL COMMENT '并单去向（close_reason=DUPLICATE）',
  ADD COLUMN IF NOT EXISTS alarm_recovered_at DATETIME(3)  NULL COMMENT '关联告警全部恢复的时刻（已接单的单不撤，只标记）';

-- SLA 按「类型 × 优先级」。priority='*' 表示该类型的默认值（不用 NULL：NULL 不参与唯一键，会允许重复默认行）
ALTER TABLE wo_sla_rule
  ADD COLUMN IF NOT EXISTS priority VARCHAR(8) NOT NULL DEFAULT '*' COMMENT '* 类型默认 / LOW / MEDIUM / HIGH / URGENT',
  DROP INDEX IF EXISTS uk_sla_rule_type,
  ADD UNIQUE KEY IF NOT EXISTS uk_sla_rule_type_prio (tenant_id, wo_type, priority);

ALTER TABLE wo_dispatch
  MODIFY COLUMN strategy VARCHAR(16) NOT NULL DEFAULT 'MANUAL' COMMENT 'OWNER 按运维责任人 / MANUAL 人工 / NEAREST 就近 / LOAD 负载 / GRAB 抢单',
  MODIFY COLUMN action   VARCHAR(24)     NULL COMMENT 'DISPATCH 派单 / ACCEPT 接单 / REJECT 退回 / WITHDRAW 撤单 / MERGE 并单 / PRIORITY_UP 升优先级 / REVIEW 复核 / NOTE 备注';

ALTER TABLE wo_handle
  ADD COLUMN IF NOT EXISTS fault_reason_code VARCHAR(32) NULL,
  ADD COLUMN IF NOT EXISTS file_nos          VARCHAR(512) NULL COMMENT '现场照片 fileNo，逗号分隔（字节在 sys_file）';
```

- `wo_dispatch.action` 现无注释且存量值有 `DISPATCH/ACCEPT/REJECT` → 补注释后进 `DdlStatusVocabularyCommentTest` 的覆盖（`action` 列名不在 `status/state/type/mode` 范围，由 `StoredValueInVocabularyTest` 按「看起来像枚举」识别，同样要求存量值在注释里）。
- 故障原因字典：`sys_dict` 新增类型 `wo_fault_reason`，首版 8 项（`NETWORK 网络 / POWER 供电 / SLOT_MECH 仓位机械 / LOCK 锁 / BATTERY 电池 / SCREEN 屏 / DAMAGE 人为损坏 / OTHER 其他`），种子随 M6。
- SLA 默认值种子（告警方案 v2 §十）：`FAULT×URGENT 30/240`、`FAULT×HIGH 120/1440`、`FAULT×MEDIUM 480/2880`、`FAULT×* 1440/4320`、`REFILL×* 240/720`、`INSPECT×* 0/10080`（分钟：响应 / 解决）。

## 四、服务（`wo.ext.service.WoOpsService` 追加）

```java
public interface WoOpsService {
    // —— 现有：create / accept / handle / complete / close / dispatch / reject / rework / pageRich
    record AlarmDraft(String type, WoPriority priority, String mergeKey, String siteNo, String cabinetNo,
                      String locationNo, String agentNo, String regionId, String description, String alarmNo) {}
    /** 合并键已有未完结工单 → 挂靠并返回其号（必要时上调优先级）；否则新开并按责任人派单。 */
    String openOrAttach(AlarmDraft d);
    void raisePriority(String woNo, WoPriority p, String reason);
    void withdraw(String woNo, String reason);                   // CREATED / DISPATCHED → CLOSED(WITHDRAWN) + 通知被派人
    void annotate(String woNo, String note);                     // 追加处理记录（action=NOTE）
    void markAlarmRecovered(String woNo, LocalDateTime at);
    void mergeInto(String fromWoNo, String toWoNo, String reason);
    void recordReview(String woNo, boolean passed, List<ReviewItem> items);
    List<AssigneeCandidate> candidates(String siteNo);
}
public record ReviewItem(String alarmNo, String code, boolean passed, String note) {}
public record AssigneeCandidate(String type, String no, String name, boolean siteOwner) {}
```

### 4.1 `openOrAttach`

```
@Transactional
openOrAttach(d):
  existing = wo_order where source_ref = d.mergeKey
  if existing != null and status ∉ {CLOSED}:                  // 未完结（含 DONE：待验收也挂上，复核会一起看）
      if d.priority.higherThan(existing.priority): raisePriority(existing, d.priority, "新增关联告警 " + d.alarmNo)
      dispatchLog(existing, action=NOTE, "新增关联告警 " + d.alarmNo)
      return existing.woNo
  if existing != null and status == CLOSED:
      d.mergeKey = d.mergeKey + "#" + (n+1)                    // 完结后复发 = 新问题，新键新单
  woNo = create(WorkOrderDraft(type, source=ALERT, sourceNo=d.mergeKey, priority, cabinetNo, locationNo, …))
         ← 撞 uk_wo_source_ref（并发）→ 捕获 DuplicateKeyException 后重读返回（现有 create 未处理该情况，一并修）
  assignee = resolveOwner(d.siteNo)                           // §4.2
  if assignee != null: dispatch(woNo, assignee, strategy=OWNER)
  else: 留 CREATED；notify(运维主管, "工单 {} 无可派责任人")
  return woNo
```

### 4.2 `resolveOwner(siteNo)`

```
s = siteQuery.briefsByNos([siteNo])[0]
// SiteBrief 同时带出 operateAgentNo（loc_site_agent OPERATE）与 opsEmployeeNo（03 §三）
if s.operateAgentNo != null and agentDirectory(s.operateAgentNo) == ENABLED → (AGENT, s.operateAgentNo)
        // 代理 SUSPENDED 时不派给他（E8），落到下一条
if s.opsEmployeeNo != null and 员工在职（员工目录端口）→ (EMPLOYEE, s.opsEmployeeNo)
else → null
```

派给代理时 `assignee_type=AGENT`、`assignee_id=agentNo`；代理门户按 `agent_no` 数据范围已能看到该单，由代理内部再分派（代理侧多人协作 L2）。

### 4.3 `complete`（收紧）

```
入参 CompleteReq(handleNote*, faultReasonCode*, partChanged, deviceChanged, fileNos)
  type ∈ {FAULT, INSTALL, REMOVE} → fileNos 至少 1 个，否则 400「请上传至少一张现场照片」
  faultReasonCode 必须在字典 wo_fault_reason 中（type=FAULT 时必填）
  fileBinding.bind(fileNos, "WORK_ORDER", woNo, wo.agentNo)          // 同事务
  写 wo_handle(fault_reason_code, file_nos)；status = sm.next(PROCESSING, "DONE")
  events.publish(new WorkOrderCompletedEvent(...))                     // 告警复核
```

### 4.4 `recordReview`（告警域回调）

```
passed:
   review_status=PASSED；status: DONE → AUDITED → CLOSED（sm 两步），audit_result=PASS，audited_by=SYSTEM，close_reason=RESOLVED
   dispatchLog(action=REVIEW, "复核通过，自动验收")
!passed:
   review_status=FAILED，review_detail=items；状态保持 DONE，等验收人：返工（REWORK）或人工验收（现有 close）
```

人工验收时若 `review_status=FAILED`，`CloseReq.auditNote` 必填（为什么复核没过还放行）。

### 4.5 `withdraw` / `mergeInto`

- `withdraw`：`sm.next(status, "WITHDRAW")`，`close_reason=WITHDRAWN`；若已派单 → 经 `NotifyPort` 通知被派人「工单 X 已撤销：关联告警已自动恢复，无需前往」。
- `mergeInto(from, to)`：`sm.next(from.status, "MERGE")`，`close_reason=DUPLICATE`、`merged_into_wo_no=to`；在 `to` 上追加处理记录；`to` 优先级取两者较高。

### 4.6 SLA

`SlaRuleService.resolve(type, priority)`：先找 `(type, priority)`，无则 `(type, '*')`，再无则不设 SLA。
开单、升优先级时重算 `wo_sla.respond_due_at / resolve_due_at` 与 `wo_order.sla_due_at`（只会提前，不会推后）。
超时升级任务 `wo-sla-escalate` 为 L2，本设计不实现。

| 方法 | 路径 | 权限 | 变化 |
