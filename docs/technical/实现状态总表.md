## 〇、使用协议（强约束 · 对齐 [项目开发规范](../../CLAUDE.md) / project-dev-standards）

1. **文档驱动**：任何功能开发前，先在本表定位对应行 → 读关联需求/TDD → 按 [P5] 写/更新 `docs/technical/TDD-*.md` → 编码 → 测试 → **回填本表状态**。
2. **完成的定义**：一行标 ✅ 必须同时满足：后端可用 + 落库（若该域已进入持久化阶段）+ 自动化测试通过 + 前端联调（若有前端）。缺一为 🟡。
3. **状态回填是收尾动作**：每次 PR/提交涉及功能变更，必须更新本表对应行的「状态」与「测试」列，并在文末「变更日志」追加一行。
4. **图例**：
   - ✅ 已实现（可用 + 有测试/联调）
   - 🟡 部分（骨架 / 内存态未落库 / 只读 / 未分层 / 前端 mock）
   - ⬜ 未实现（仅设计文档）
   - 🔴 阻塞 / 有已知缺陷
   - 🔒 休眠口子（有设计，MVP 不做）

## 六、下一步优先级（基于当前缺口，供排期）

后端 API 层已收口，剩余缺口集中在**前端接线**、**运行时能力**与**生产化**三处：

1. **~~🔴 前端接线 131 条~~ —— 这个数字是错的，已作废（2026-09-24）**

   它出自 `scripts/api-align.py`，而该脚本当时在**三个方向同时出错**：
   - 调用点正则要求路径字面量紧跟 `(`，于是全站 `saveXxx` 的三元写法
     （`x.no ? \`/a/${x.no}\` : "/a"`）**整条漏扫** → 运营端 113 条里 **95 条是假的**；
   - 提取器只取多值映射 `@PostMapping({"", "/{no}"})` 的第一个路径 → 把**能用的功能报成 404**；
   - 字段比对把嵌套类型成员拍平 → `DashboardStats` 凭空多出 4 条缺口，而它一条不缺。

   **更危险的是它漏报的那一半**：A 类「前端调、后端没有」当时报 `0 ✅ 已清零`，
   实测有 **15 个写端点会 404**（场地方/合同/入驻/角色/钱包的新建与编辑）。
   脚本已修（b890bb1）并补了自测 `api-align-selftest.py`；那 15 个 404 已由
   3b0b23c 等提交清零。

   **2026-09-24 实测**：后端端点 419 · 前端调用点 377 · **A 类运行期 404 = 0**。

   > 教训：**排期依据必须自己有卡口**。这条链路今天被证明会自信地给出错的数字，
   > 而三个缺陷都不会让脚本报错。基于错数字的排期比没有排期更贵 ——
   > 它让人去做不存在的工作，同时对真坏的功能打勾。

2. **出参字段的前端侧裁决**：现为 **20 条**（已剔除嵌套误报），逐个判「该展示没展示」还是「后端赘余」。
   不要一律补齐 —— 把赘余字段也接上，等于把后端的临时产物固化成契约。
3. **定时调度**：巡检/对账/出账目前只能手动触发。需分布式锁（多副本并发跑会重复出单），与 outbox 投递器一并设计。
4. **access-gateway 南向进程**：远程指令仍是占位回执，接第一家真实桩企需其 OCPP 文档与测试桩（外部依赖）。
5. **生产化三件套**：`token-store: redis` · `sharehub.seed.enabled=false`（演示种子绝不能进生产）· `pb_pii`/`pb_auth` 分库
   （分库落地后 C 端密码/重置能力才能开，现在端点如实 400）。
6. **存量迁移债**：V13 因脚本不读 `@TableField` 误建了一批**永远为 NULL 的 JSON 影子列**（`wo_handle.assignee_no` 等 6 张表）。
   脚本已修（现读注解），删列迁移待做。另有 26 张表的 `json_valid` 约束里若干为标量语义误标。
