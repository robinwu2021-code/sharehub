## 二、四大结构性错配（按影响排序）

### 错配 ①：MVP 闭环断在「支付」与「IoT 下发」——P1 目标未真正达成
PDF 第一阶段目标：**「扫码租借 → 自动计费 → 在线支付 → 商户结算」完整闭环**。现状：
- 扫码/计费/结算：后端骨架有（`ord_rent` 落库、状态机、提现审核内存态）；
- **在线支付（nearpay）**：⬜ 完全未接 → 闭环断裂；
- **IoT 弹仓下发**：远控指令是 `CMD+nano` 占位，未经真实网关 → 「扫码后柜机弹出充电宝」这一物理动作在真机上不成立。

→ **P1 的"业务跑通"目前是 UI 跑通，不是资金+硬件跑通。**

### 错配 ②：缺两个完整的端——门店端、代理自助端
- **门店/店家后台**：PDF P1 就要「门店网络管理/收入查询/站点营运数据/推广支援」，P2「门店自助 Onboarding」。现系统零承载。运营端的「场地方(venue)」只是运营侧登记，不是**商户自己登录的后台**。
- **代理自助端**：PDF「经销商后台」是给代理商**自己用**的（我的设备/订单/收益/客服工具）。现 `/agents` 是运营侧管代理档案，代理本人无入口。总表 C端表也列了「代理端 5 项」全 ⬜。

### ~~错配 ③：C 端两套重复（cend vs c-app）——架构债~~ ✅ 已解决（2026-07-13）
- `cend/` 已删除，`c-app/` 为唯一 C 端主线；
- cend 的真实 auth 路径（`ConsumerRentFlowTest` 确认：`/mp/auth/login`、`/mp/auth/otp`、`/mp/auth/register`、`/mp/auth/password/reset`）已迁入 c-app `src/api/http.ts`；
- vue-tsc --noEmit 全绿，C 端架构债清零。

### 错配 ④：后端进度整体滞后于前端——"前端全绿、后端半空"
ops-web 14 模块前端 100% mock 完成，但后端：finance/marketing/report/cs/org/pricing/system 多为**只读内存态、未落库、未分层**。前端切 `USE_MOCK=0` 后大量页面无真实数据。分期屏蔽（P1/P2/P3）目前只约束**前端可见性**，后端未按阶段裁剪。

## 三、优化方案

### 方案总纲：**"补端 + 收敛 + 通闭环 + 后端追平"**，仍按 PDF 三阶段交付

原则：延续已落地的「一次性开发、分期屏蔽」机制；**前端可继续按阶段铺，但把资源重心压到 P1 真闭环与结构收敛上**，避免继续堆 P2/P3 前端 mock 而地基悬空。

---

### P1（MVP 真闭环）— 立即对齐项

| 优化项 | 动作 | 关联错配 |
|--------|------|:---:|
| **A. 打通支付闭环** | 接 nearpay：`/mp/trade/pay` + `/notify/pay/nearpay` 回调 + 押金冻结/扣费；结算单落库 | ① |
| **B. 打通 IoT 下发** | 建 `access-gateway` 南向进程（先 HTTP driver 一家供应商）；远控指令真下发 + 回执状态机 | ① |
| ~~**C. C 端收敛为一套**~~ ✅ 已完成 | `cend` 已删，auth 路径迁入 c-app；`c-app` 是唯一主线 | ③ |
| **D. 门店端 MVP（新端）** | 新建 `merchant-web`（或复用 ops-web 壳做角色视图）：门店网络/收入查询/站点营运数据/推广支援（P1 四项） | ② |
| **E. 代理自助端 MVP** | 代理登录入口 + 我的设备/我的订单/我的收益/设备报修（AGENT 数据范围已就绪，后端 agt 已落库） | ② |
| **F. 后端 P1 域追平** | trade(price_plan/pay) + finance(结算落库) + user(钱包/信用落库)，对齐前端 P1 可见功能 | ④ |

### P2（规模化）— 对齐项
- 门店**自助 Onboarding** 审核流（运营侧审核队列 + 门店端提交）——已在 ops-web 清单登记（P2）；
- 代理端**客服工具 / 区域绩效 / 区域经营权限**；
- 后端 marketing(券/活动)、cs(报障/会话)、report(设备/坪效/财务) 落库；
- IoT 扩多供应商 driver + OTA/库存调拨真链路。

### P3（生态）— 对齐项
- 平台广告管理 / 设备屏广告 / 会员营销系统；
- **多国家市场架构**（已在 ops-web 建 P3 页）+ 多币种/合规落库；
- 消费者数据分析 / 设备效率分析（已建 P3 报表页）接真数仓；
- **NearGo 服务打通** + OpenAPI 三方开放。
