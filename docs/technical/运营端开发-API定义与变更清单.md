# 运营端开发 API定义与变更清单

> 设备与库存的目标职责、逐节点 Web→Controller→Service→微服务 API 映射，见[设备全生命周期 Web 与服务对接明细](设备全生命周期-Web与服务对接明细.md)。其中 M/W/P/V 分别区分主分支、工作区、拟改造和待确认合同；库存默认 SERVICE，不以手工业务设备注册作为采购收货前置条件。

> 2026-10-30；规划及实施对照，不是已发布接口承诺。最新docs/api/contract.json为627端点；下表既有接口复用清单保留原626端点核查快照。源码Controller／DTO为最终依据，实际变更见[执行记录](../superpowers/plans/2026-10-30-ops-execution-progress.md)。

已实现的兼容扩展：物料单据POST新增可选requestKey，新Web自动发送稳定键；同键异载荷409，失败重试恢复原操作。未传键的旧客户端维持原行为，不保证请求级重放。INSTALL开单强制agentNo及core端安装资格校验，内部绑定开单保留直营例外；新增内部只读资格端点，不作为浏览器公共接口。独立恢复列表及retry端点仍未实现。

## 一 公共约束

- 继续使用现有响应信封、PageResult、错误码和认证方式，实施前读取docs/api/README.md；不在新模块另造分页和错误体系。
- 拟定DTO中*为必填；现有requestShape仅提供类型，未提供完整Bean Validation约束，必填性以DTO、Controller和Service校验为准。
- 修改后保留旧客户端兼容；数据范围和操作权限双重校验。金额用DECIMAL／BigDecimal，不用浮点累计。
- requestKey稳定到同一业务意图；同键不同载荷409；版本冲突409；权限不足403；外部未知结果保持处理中／待查证，不能直接成功。
- 权限码标“拟”者未登记，不视为现有授权。独立库存与OpsKit外部API复用其协议，不将数据库直连当接入方式。
