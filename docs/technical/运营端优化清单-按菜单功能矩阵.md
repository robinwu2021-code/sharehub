**三句话**：

1. **先定路径再动菜单**。矩阵把 `/finance` 的 tab 拆到财务 / 结算 / 发票 / 用户四个 L1，把 `/users` 拆到用户 / 销售 / 发票，把 `/system` 拆到系统 / 设备 / 销售 / 发票；而 `findActiveSection` 只按**路径前缀**归属，`?tab=` 不参与（`ops-web/lib/nav.ts` findActiveSection）。不先把页面按目标 L1 拆路径，重排后面包屑、Rail 高亮、二级面板必错一边。
2. **重排 = 整表重灌 `iam_menu`**（V148）。`menu_no` 与 `sort` 都是数组下标，任何移动都改键；重灌会冲掉「菜单管理」线上改动，且导出脚本 `lib/__dump_nav.test.ts` 已不在仓库里，要先补回生成链。
3. **一期新增的 34 项里有 20 项靠 6 个还不存在的实体**（支付流水、应付台账、付款登记、采购 / 供应商 / 收货、库存余额 / 盘点 / 履历、租赁票据 / 贷项单、导出任务）。先建实体与 mock，页面才有东西可挂。

## 二、结构性改造：导航重排的前置条件

### 2.1 冲突：目标 L1 与现有页面路径

`findActiveSection` 取**最长路径前缀**（`section.match ?? href 路径`），query 不参与；`nav.ts`、`app/locations/page.tsx`、`app/venues/page.tsx`、`nav.test.ts` 四处都把「一个 URL 只属于一个 L1」写成规则。目标矩阵违反这条规则的地方：

| 现页面 | 现 tab | 目标 L1 | 冲突 |
|---|---|---|---|
| `/finance` | rules · records · summary · settlements · withdrawals · payout-accounts | OM08 结算 | 同一路径下 |
| `/finance` | ledger · reconcile | OM07 财务管理 | 四个 L1 |
| `/finance` | invoices | OM09 发票 | |
| `/finance` | recharges | OM05 用户管理 | |
| `/users` | list · logoffs · risk · blacklist · whitelist · wallets · recharge | OM05 用户管理 | 同一路径下 |
| `/users` | members · plans | OM04 销售管理 | 三个 L1 |
| `/users` | invoices | OM09 发票 | |
| `/system` | 其余 | OM11 系统管理 | 同一路径下 |
| `/system` | vendors | OM03 设备管理 | 四个 L1 |
| `/system` | payment | OM04 销售管理 | |
| `/system` | tax | OM09 发票 | |
| `/orders` + `/operation/fee-plans` + `/marketing` | — | OM04 销售管理 | 一个 L1 跨四条路径（可用 `match` 解决，不冲突） |
| `/alarms` + `/work-orders` + `/cs` | — | OM06 运维管理 | 同上，可用 `match` |
| `/` + `/flow/todo` `approvals` `queue` `tickets` | — | OM00 工作台 | `/` 只精确匹配；`/flow/*` 其余四页归 OM11，靠 `match` 最长前缀可分，但 **`dashboard` 一旦有 children 就不再全宽**（`secondary-nav.tsx` 对无叶 section 不渲染），`nav.test.ts`「经营看板无子功能」要改 |

### 2.2 两种解法，建议取 A

| 方案 | 做法 | 代价 | 结论 |
|---|---|---|---|
| **A · 按目标 L1 拆路径** | 新建 `/settlement`、`/invoices`、`/sales`（或把 members / plans / payment 挂到 `/orders?tab=`）等路径，页面组件按 tab 抽到 `components/<模块>/` 后在新路径复用；旧 `?tab=` 做 302 到新路径 | 页面文件拆分、`useNavTabs` 路径改、深链全库 grep（`/finance` ×68、`/system` ×31 处硬编码路由） | **取**。与「一 section = 一权限模块 = 一页」的既有规则一致，`operation` 已是先例 |
| B · `findActiveSection` 认 `?tab=` | 归属算法改成「路径 + tab」最长匹配 | 改规则本身：面包屑、Rail、phase-guard、`activeLeafIndex` 全要跟，四处文档与测试要改；`sectionDefaultHref` 语义变 | 不取。省了拆页，但把「一个 URL 一个 L1」这条已被验证的规则推翻 |
