# ShareHub 运营台设计规范

版本 1.0 · 2026-07-30 · **规划稿（clean-sheet，不受现有实现约束）**
适用：ops-web 全部界面 · 对标：Linear / Vercel Dashboard / Stripe Dashboard / Radix Colors / shadcn

---

## 0. 这份规范要解决什么

现有实现的 token 是六七轮迭代里**逐步累加**出来的：命名按用途随手起
（`canvas` / `card` / `muted` / `secondary` / `accent` / `border`），彼此之间没有明确的
数量关系。后果是每次调色都要凭感觉试，改一个值不知道会不会撞到另一个，
所以越调越"杂乱"。

本规范用业界通行的解法：

1. **三层 token 架构** —— 原始值 → 语义角色 → 组件专用，组件只准消费语义层
2. **编号中性色阶** —— 12 档，每一档有**明文规定的岗位**（Radix Colors 模型）
3. **约束优先** —— 能用的档位是有限集合，不允许即兴取值

> 判断标准：**任何一个界面问题，都应该能追溯到"某一档 token 用错了岗位"，
> 而不是"这个颜色不好看"。** 做不到这一点，说明规范还不够。

---

## 1. Token 架构

```
Tier 1  原始层 (primitive)    --gray-1 … --gray-12, --teal-9, --red-9 …
   ↓    只有数值，没有含义。禁止组件直接使用。
Tier 2  语义层 (semantic)      --bg-canvas, --text-secondary, --border-strong …
   ↓    有岗位定义。**组件只准用这一层。**
Tier 3  组件层 (component)     --btn-height, --table-row-h …
        仅当语义层表达不了时才新增，且必须写明为什么。
```

**硬规则**
- 组件里出现任何 hex / rgb / oklch 字面量 = 违规
- 组件里出现 Tier 1 token = 违规（除非在 Tier 2 的定义处）
- 新增 Tier 2 token 必须先写出它的**岗位描述**，写不出来就说明不该新增

## 2. 色彩

### 2.1 中性色阶（12 档，每档有固定岗位）

> 下表是全站基线（经典风格、暗色）。**清爽风格亮色下按主题色另有一套带色相的灰**（§2.6「中性色随主题色」）。

这是整套规范的地基。岗位定义直接采用 Radix Colors 模型——它是目前唯一被广泛验证的
"每一档干什么"的中性色规范。

| 档 | 岗位 | Light | Dark |
|:--:|---|---|---|
| 1 | 应用最底层背景 | `#FCFCFD` | `#0C0D10` |
| 2 | 次级背景（画布/条纹）| `#F7F8FA` | `#111318` |
| 3 | UI 元件底（输入框/分段槽）| `#F1F2F5` | `#191C22` |
| 4 | UI 元件 hover | `#ECEDF1` | `#1E2128` |
| 5 | UI 元件 active / 选中 | `#E5E7EC` | `#23272F` |
| 6 | 弱分隔线（表格行线）| `#DEE0E6` | `#2A2E37` |
| 7 | 元件描边 / 焦点环底 | `#D2D5DD` | `#343945` |
| 8 | 元件描边 hover | `#B9BDC8` | `#454B59` |
| 9 | 实心中性底 / 占位符 | `#8B8F9C` | `#6C7280` |
| 10 | 实心中性底 hover | `#7E828F` | `#7A8090` |
| 11 | **次要文字**（≥4.5:1）| `#61656F` | `#A0A6B2` |
| 12 | **主要文字** | `#16171D` | `#F2F4F7` |

**色相偏冷（略带蓝）而非纯中性。** 纯灰读起来像"没选过"；微冷与产品的设备/科技
属性相合，且四套主色（青绿/蓝/紫/近黑）都能坐得住。

> 常见错误：拿第 6 档当描边、第 7 档当分隔线。
> **6 是"隐约的界"，7 是"明确的边"** —— 表格行线用 6，输入框描边用 7。

### 2.2 主色（九套皮肤）

品牌一致性的唯一载体。**换肤只换主色**；中性色与语义色由「风格」决定（§2.6），不随皮肤变。

| 皮肤 | solid (9) | 说明 |
|---|---|---|
| **黑白灰**（默认，2026-09-28 起）| `#1C2029`（暗色反相 `#F2F4F7`）| 用户定「颜色默认尽量用黑白灰」。主色只做交互标记，界面靠中性阶与明暗结构建立层级；链接常驻浅下划线（见下） |
| 墨青 | `#0F7173`（暗色 `#2AA7A8`）| 取自流程与工单原型；9-27 至 9-28 曾为默认 |
| 简电青 | `#17C3C0` | 品牌色（与 C 端同值） |
| 时尚蓝 | `#2F6BFF` | 与 C 端同值 |
| 科幻紫 | `#7C3AED` | 与 C 端同值 |

**9-28 新增四套「运营高端常用、耐看」色**（用户要求）。选色两条硬约束：低明度低饱和（主色出现在每个链接 / 选中态 / 主按钮上，高饱和显跳），
**避开语义色相**（红 = 超时 / 失败、琥珀 = 将超时 —— 所以没有酒红、金色）：

| 皮肤 | solid（亮 / 暗） | 白字 | 取向 |
|---|---|---|---|
| 藏青 | `#1D3557` / `#6C87AE` | 12.4 | 深海军蓝，金融与企业后台最常见 |
| 靛蓝 | `#4A55C8` / `#6F7FDC` | 6.1 | 现代 SaaS 常用 |
| 墨绿 | `#1E5B46` / `#559079` | 8.0 | 沉稳，财务 / 运营类后台 |
| 摩卡 | `#6B4E3D` / `#9E7F6C` | 7.6 | 唯一暖色，给需要区分品牌的租户 |

暗色：四套本身太暗，暗色下提亮到压暗卡 ≥5.0、按钮字改压深色（同色相，只抬明度）。
清爽风格下每套各有一块带色相的灰阶（§2.6）；墨绿、摩卡的灰彩度 ×0.7–0.75（绿、暖色相的灰带色多了显脏）。
墨青与这四套是运营台独有的皮肤，C 端暂无对应。新增皮肤：`THEMES` 加一项 → 补亮色 / 暗色 / 清爽灰阶三块 → `style-contrast.test.ts` 自动纳入。

每套皮肤需要 5 个派生档（而非完整 12 档——运营台用不到那么多）：

| 派生档 | 生成规则 | 用途 |
|---|---|---|
| `accent-subtle` | solid 混底色 12% | 选中行底、tint 卡片 |
| `accent-border` | solid 混底色 32% | 选中态描边 |
| `accent-solid` | 原值 | 主按钮、激活态、焦点环 |
| `accent-hover` | solid 压暗 8% | 主按钮 hover |
| `accent-text` | solid 保证 ≥4.5:1 | 链接、accent 文字 |

> **黑白灰皮肤的特殊性**：主色近黑，`accent-text` 与 `text-primary` 几乎重合，
> 于是"可点击"失去颜色线索。此皮肤下链接**必须**用下划线或其它非颜色线索区分。
> 这不是可选项——它是无彩皮肤的必然代价。
> **已落实**（2026-09-28，默认改回黑白灰时发现此前一直缺）：`globals.css` 的 `[data-theme="mono"] main a[class*="text-primary"]`
> 常驻浅下划线、悬停加深；按钮型链接除外。由 `style-contrast.test.ts` 锁住。

### 2.3 语义色（与主色严格分离）

状态的含义不能随皮肤漂移，所以语义色**所有皮肤下完全相同**。下表是经典风格的取值；
风格（§2.6）可以改语义色的**色调**，但**不改含义**：绿永远是正常、红永远是超时或失败。

| 角色 | solid | 用途 |
|---|---|---|
| success | `#12B76A` | 在线、已完成、成功 |
| warning | `#F79009` | 待处理、即将超时 |
| danger | `#F04438` | 故障、失败、不可逆操作 |
| info | `#2F6BFF` | 处理中、提示 |

每个语义色同样派生 `subtle` / `border` / `text` 三档，规则同上。

> **`text` 档是必须的，不是可选优化。** 直接把 solid 当作 tint 底上的文字色，
> 对比度只有 2.8:1 左右，小字过不了 AA。这是本项目真实踩过的坑。

### 2.4 语义层映射（组件只准用这一层）

| 语义 token | Light | Dark |
|---|---|---|
| `bg-canvas` | gray-3 | gray-1 |
| `bg-surface` | `#FFFFFF` | gray-3 |
| `bg-subtle` | gray-2 | gray-4 |
| `bg-hover` | gray-4 | gray-5 |
| `bg-selected` | accent-subtle | accent-subtle |
| `border-subtle` | gray-6 | gray-6 |
| `border-default` | gray-7 | gray-7 |
| `text-primary` | gray-12 | gray-12 |
| `text-secondary` | gray-11 | gray-11 |
| `text-placeholder` | gray-9 | gray-9 |
| `text-on-solid` | `#FFFFFF` | `#FFFFFF` |

> **为什么亮色画布取 gray-3 而不是 Radix 原模型的 gray-2**：我们的卡片是纯白，
> 画布必须坐到第 3 档才能过下面那条 ≥1.10 的硬指标（gray-2 对白只有 1.05）。
> **暗色同理，卡片整体上移一档到 gray-3** —— 不能因为"暗色本来就该靠描边"
> 就放过这条指标（实测 gray-1/gray-2 只有 1.05，卡片浮不起来）。

### 2.5 外壳两级色调

布局定案为**只用两级色调**（详见 [布局与外壳](设计规范-布局与外壳.md) §2）：

| token | Light | Dark | 用途 |
|---|---|---|---|
| `--surface` | `#FFFFFF` | gray-2 | 白面：一级菜单 / 内容区 / 卡片 |
| `--sunken` | gray-3 | gray-1 | **全局唯一的灰块**：二级面板 |

灰色的二级面板**自身即分隔物**，同时隔开一级菜单与内容区 ——
不用缝隙、不用线、不用第三个色阶。

**清爽风格（亮色）例外**（2026-09-28 用户定，对齐原型的明暗结构）：内容区画布为浅灰（`--canvas-clean`，每套主题一值），
卡片 / 表格 / 导航都是白面 —— 白面浮在浅灰上。二级面板不再用灰块，导航与画布之间**不画线**，靠白对浅灰的色差分界；
顶栏透明、融进画布。暗色与经典风格仍按本节。

**画布与卡片的明度差不得低于 1.10**（否则卡片浮不起来）；
**卡片与描边不得低于 1.25**（否则发丝边等于不存在）。这两条是硬指标，可自动化检查。

### 2.6 风格（与主题色正交的第二条轴）

2026-09-27 新增，同日按用户要求定稿：「重点不是墨青，而是整体的 UI 风格，同样要支持多种颜色」。

| 轴 | 属性 | 换什么 | 取值 | 默认 |
|---|---|---|---|---|
| 主题色 | `<html data-theme>` | **只换主色**（§2.2） | 黑白灰 · 墨青 · 藏青 · 靛蓝 · 墨绿 · 摩卡 · 简电青 · 时尚蓝 · 科幻紫 | 黑白灰 |
| **风格** | `<html data-style>` | **整体 UI 形态**：表格、tab、徽章、卡片、按钮、输入框、时间线、步骤条…… | **`clean` 清爽** · `classic` 经典 | 清爽 |

**风格不写死色相**：任何风格 × 任何主题色都必须成立。
风格改的颜色有两类，含义都不变：
- **语义色的色调**：降饱和，实心底压白字全部 ≥4.5（基线的绿 2.62、琥珀 2.35 不达标）。
- **中性色随主题色**（2026-09-28，仅清爽风格亮色）：每套主题一块 `[data-style="clean"][data-theme="…"]:not(.dark)`。
  **明度沿用 §2.1 基线每一档**，只换色相、给一点彩度（OKLCH；浅档 0.003–0.008、文字档 0.016–0.018，黑白灰减半）。
  色相取主题主色；两套青色主题取原型实测的 **222°**（主色本身 197° 会让灰偏绿）。
  为什么：原型的灰是带青的石板灰，与主色同一家族；基线灰偏蓝紫，配青色主色时整页发灰、发暗。
  （9-27 试过的是「一套固定青灰给所有主题」，只配墨青，已撤；每套主题各一套就不存在这个问题。）

| 语义 | solid（亮 / 暗） | subtle（亮 / 暗） | text（亮 / 暗） |
|---|---|---|---|
| success | `#2E7D4F` / `#4FBF82` | `#E7F3EC` / `#11261B` | `#1F5E3A` / `#86D9A9` |
| warning | `#A3690B` / `#E0A23D` | `#FDF3E0` / `#291E0B` | `#6F4A0C` / `#F0C374` |
| danger | `#B3403A` / `#EC7A70` | `#FBECEA` / `#2C1614` | `#8A2C27` / `#F5AAA2` |
| info | `#3F6AA8` / `#7FA1D8` | `#EEF2F8` / `#141C2B` | `#2B4E80` / `#ABC3EB` |

**组件形态**（对齐流程与工单原型 v4/16/13；只在 `clean` 下生效，`classic` 保持原样；实现在 `globals.css` 末尾的风格块）：

| # | 组件 | classic | clean（对齐原型） |
|:-:|---|---|---|
| 1 | 表格 | 表头色带 + 斑马纹，无行线，14px，行高 48 | **白表头**（12px / 600 / 次要色）+ **行间 1px 线**，无斑马纹，**13.5px**，行高 40，单元格 9px 10px |
| 2 | 主键列 | 加粗 | **等宽 12px 常规字重**（DataTable 的 `pk` 列，未指定时取前两列里表头以「号」结尾的） |
| 3 | tab（分段控件） | 灰槽 + 白色凸起块 | **下划线**：选中项主色字 + 2px 主色下划线；页面级 tab 底线通栏 |
| 4 | 徽章 | 药丸 + 600 | **小方角**（`--r-field`，原型 5px）+ 常规字重 |
| 5 | 卡片 · 统计卡 | 阴影 | **1px 细描边**；统计卡数字在上，将超时 / 已超时卡边框取语义色 |
| 6 | 按钮 | 14px / 600 | **13px 常规字重**；次按钮白底描边，悬停转主色；**危险按钮白底红字红边** |
| 7 | 输入框 · 下拉 · 多行文本 | 灰色填充，无边 | **白底 + 1px 描边**，聚焦描边转主色 |
| 8 | 提示条 | 灰块 | 浅灰块 + **1px 细描边**，13px |
| 9 | 抽屉头 | 浅灰底 | **白底 + 底线** |
| 10 | 时间线 | 每项左竖线 | **整条竖线 + 圆点**，首项主色 |
| 11 | 步骤条 | 8px 小圆点 | **22px 带编号圆 + 伸缩长连线**；完成 = 成功色，当前 = 主色 |
| 12 | SLA 剩余 | 纯文字 | **迷你色条 + 文字**（色条纯装饰，含义仍由文字表达，§11.4） |
| 13 | 外壳层次（亮色） | 一级白 / 二级灰 / 内容白 | **浅灰画布 + 白卡 / 白表格 / 白导航**，导航与画布间不画线，顶栏透明（§2.5 例外） |
| 14 | 线 | 行线 gray-6、控件描边 gray-7 两级 | **只有一种浅线**（`--border` = gray-5，行线 / 卡片 / 按钮 / 输入框共用，原型 1.24）；输入框悬停转 gray-8、聚焦转主色 |
| 15 | 表格勾选列 | 常驻 | **按需出现**：点「批量改派」进入选择模式才出现，改派完成或取消即退出（原型做法） |
| 16 | 少量选项的筛选 | 下拉 | **筛选标签**（`FilterChips`，`--r-chip`，单选、首项「全部」）；选项多仍用下拉 |

**「线条感」怎么量**（2026-09-28 与原型逐页对照）：线条感不来自线的**有无**，而来自**深线的数量**。
工单工作台原先有 76 条对比度 > 1.4 的「强线」（每行两个次按钮的描边 1.47、输入框、勾选框），原型只有 12 条；
改成一种浅线 + 勾选列按需后降到 8 条，线条对比度中位数 1.32 → 1.24（原型 1.24）。
改组件时若担心线又多起来，按这个口径量：可见边框中对比度 > 1.4 的条数、以及中位数。

**从原型没搬的**：深色侧栏（用户 9-28 定：导航保持浅色）；原型 11.5px 的徽章字号（低于 12px 下限，保持 12px）。
**9-28 起搬了的**：胶囊形筛选标签 —— 筛选标签本身就是「标签」，属于 §5「药丸只留给徽章 / 状态芯片」的范围。

**与否决清单的关系**：「表格行线」「卡片描边」正是 README 否决清单里「白底体系统一描边」否掉的做法。
清爽风格采用它们是**用户 2026-09-27 明确要求对齐原型**的结果，范围限定在该风格；经典风格下原结论不变。

**主题色的配套修正**（与风格无关，所有风格生效）——既然要求风格在每套颜色下都成立，就把每套颜色都验了一遍：

| 主题色 | 问题 | 修正 |
|---|---|---|
| 简电青 | 主色压白字 **2.19**：主按钮字、链接、选中文字都过不了 AA | 主按钮字改深色 `#0B1F24`（7.77）；主色文字用 `--primary-text` `#0F7B79`（白 5.09 / 浅灰 4.79） |
| 时尚蓝 | 主色压白字 **4.498**，差一点 | 主色 `#2F6BFF` → `#2E6AFF`（每通道 1/255，肉眼无差；C 端 SKINS 仍是原值）；主色文字 `#1F5FFF` |

新 token **`--primary-text`**：「主色写成的文字」（链接、选中 tab、菜单选中项、默认徽章）。默认等于主色，
只有主色压白底不到 4.5 的主题色单独给值。`text-primary` 工具类已全局改指它（其余三套主题色下零变化）。

**硬约束与实现坑**：
- 对比度由 `lib/style-contrast.test.ts` 锁住：清爽风格的语义色（亮 / 暗）+ **每一套主题色** + **清爽 × 每套主题的中性色阶**
  （正文 ≥7、次要 ≥4.5、次要压画布 ≥4.5、一种浅线 ≥1.2、浅线压画布 ≥1.08、控件悬停描边 ≥1.8、白卡/画布 ≥1.10）。
  清单直接取 `THEMES`，新增主题色自动纳入 —— 同时必须补它的清爽灰阶块，否则测试红。改值先跑它。
- 风格块**不放进任何 `@layer`**：`globals.css` 有条非 layer 的全局 `border-color` 规则，layer 里的规则压不过它（实测下划线、彩色边框被吃成灰）。
- **去阴影一律清 `--tw-shadow`，不写 `box-shadow: none`**：Tailwind 的焦点环、选中环也画在 box-shadow 上，直接清会把键盘焦点和统计卡选中态一起抹掉（当天实测踩过）。描边同理用真实 `border`。
- 组件上的钩子（`data-slot` / `data-surface` / `data-variant` / `data-tone` / `data-pk` / `data-state`，`segmented.ts` 的 `ui-seg` 类）是风格块的唯一入口，改组件时别删。

## 3. 排版

### 3.1 字族

| 用途 | 字族 |
|---|---|
| 拉丁 / 数字 | **IBM Plex Sans** |
| 阿拉伯语 | **IBM Plex Sans Arabic** |
| 中文 | **IBM Plex Sans SC**（CDN，见下）|

**清爽风格例外**（2026-09-28 用户定，对齐原型）：拉丁与中文用**系统字**（苹方 / SF / 雅黑），正文行高 **1.6**；
阿语仍用 IBM Plex Sans Arabic（系统阿语字形与界面不搭）；单号、金额等等宽内容不变。

**经典风格**（2026-09-28 用户定「大气一点、有呼吸感」，适度放松）：中文改系统字（苹方 / 雅黑）—— Plex SC 字形窄长、密排显挤；
拉丁与数字**保留 IBM Plex**（数字辨识度是当初选它的理由），阿语不变；正文行高 1.6。
同时放大层级与留白：页面标题 22px、卡片标题 16px；内容区边距 24 / 32 / 40，卡片内边距 24、间距 20；按钮 13px / 500。
表格行高（56）不动 —— 一屏行数基本不变。实现在 `globals.css` 末尾「经典风格」一块。

### 3.2 类型阶

密集型后台的基准字号应在 13–14px。本规范取 **14px**（13px 在长时间盯表格时偏吃力）。

| 名称 | 字号/行高 | 字重 | 用途 |
|---|---|:--:|---|
| `display` | 24 / 1.25 | 700 | 页面大标题（仅工作台）|
| `title` | 18 / 1.3 | 700 | 区块标题、抽屉标题 |
| `heading` | 15 / 1.4 | 600 | 卡片标题、表单分组 |
| `body` | 14 / 1.5 | 400 | 正文、表格单元格 |
| `body-strong` | 14 / 1.5 | 500 | 强调值、主键列 |
| `label` | 12 / 1.4 | 500 | 表单标签、列头 |
| `caption` | 11 / 1.4 | 400 | 辅助说明、时间戳 |

- 标题（`display`/`title`）加 **-0.2px 字距**；正文不加
- **所有数字列一律 `tabular-nums`**（金额、计数、ID、时间）——不等宽会让整列跳动
- 段落宽度上限 **72 字符**

### 3.3 字重使用

只用 400 / 500 / 600 / 700 四档。**不要用字重表达层级以外的东西**
（如"重要"用颜色或徽章表达，不是加粗）。

### 3.4 字族决策（已实施）

选 **IBM Plex 一族打通三种文字**，全部来自 Google Fonts。

- 换掉 Nunito 的理由：它是圆润的消费端字体，用在处理金额与设备号的密集台账上偏"软"；
  IBM Plex 为技术界面设计，数字辨识度高（0/O、1/l 分得开）
- **同一家族覆盖三种文字**是关键：三语混排时字重、字宽、基线一致，拼三个不同家族做不到

加载方式：
| 文字 | 方式 |
|---|---|
| 拉丁 / 阿语 | `next/font` 构建期自托管 |
| 中文 | Google Fonts CDN |

> ⚠️ **CJK 家族在 `next/font` 的字体数据里没有登记**（用 next 自带的 font-data.json
> 逐个探测确认：IBM Plex Sans / Arabic 都在，IBM Plex Sans SC 查无此项）。
> 自托管路径取不到汉字字形，用 latin 子集时 `document.fonts.check(...,'设备')`
> 实测为 `false` —— **字体加了等于没加，且肉眼完全看不出来**。
> 已知代价：受限网络/内网部署下中文会静默回退到 PingFang SC / 微软雅黑。

## 5. 形状

| Tailwind 类 | token | 值 | 用途 |
|---|---|:--:|---|
| `rounded-control` | `--r-control` | 3px | 复选框等 16px 级小控件 |
| `rounded-field` | `--r-field` | 6px | **控件**：按钮 / 输入 / 下拉 / 分段项 |
| `rounded-card` | `--r-card` | 10px | 卡片、表格容器 |
| `rounded-sheet` | `--r-sheet` | 14px | 抽屉、模态框 |
| `rounded-chip` | `--r-chip` | 9999px | **仅徽章/状态芯片** |

> ⚠️ **只有这五档。** `rounded-sm/md/lg/xl/2xl/full` 是 Tailwind 默认阶，
> 目前仍作为兼容层映射到五档（`lg → field`），但**新代码不许使用**——
> `lib/design-tokens.test.ts` 会让 `components/` 下的违规直接测试失败。
> `app/` 下尚有 37 处残留待清（见文末），清完即删兼容层。

**药丸只给徽章。** 徽章是"标签"隐喻，天然是药丸；按钮和输入用药丸是消费端语言，
在密集表格里吃横向空间、削弱扫描性。

## 6. 层次（Elevation）

密集界面**优先用描边分层，阴影只给真正的浮层**。滥用阴影会让界面显脏。

| 档 | 用途 | 值 |
|---|---|---|
| `elevation-0` | 卡片默认 | 无阴影，`border-subtle` 描边 |
| `elevation-1` | 需要浮起的卡片 | `0 1px 2px rgb(16 18 24 / .04), 0 1px 3px rgb(16 18 24 / .06)` |
| `elevation-2` | 下拉、气泡、提示 | `0 4px 8px rgb(16 18 24 / .06), 0 8px 16px rgb(16 18 24 / .08)` |
| `elevation-3` | 抽屉、模态框 | `0 8px 16px rgb(16 18 24 / .08), 0 24px 48px rgb(16 18 24 / .12)` |

暗色下阴影不可见，**改用 `border-default` 描边表达浮层边界**——直接加深阴影是无效的。

## 7. 动效

| 档 | 时长 | 用途 |
|---|:--:|---|
| `duration-instant` | 0ms | 必须立即响应的（复选框勾选）|
| `duration-fast` | 120ms | 颜色 / hover |
| `duration-base` | 180ms | 下拉、提示浮现 |
| `duration-slow` | 240ms | 抽屉、模态框 |

缓动：`standard = cubic-bezier(.2, 0, 0, 1)`（进出通用）

**必须响应 `prefers-reduced-motion: reduce`** —— 位移类动画全部关闭，保留透明度变化。

## 9. 密度

两档，**列表页默认紧凑，表单/抽屉默认舒适**。

| | 舒适 | 紧凑 |
|---|:--:|:--:|
| 控件高 | 36px | 30px |
| 表格行高 | 48px | 36px |
| 单元格横向内边距 | 16px | 12px |

## 10. 图标

- 控件内 **16px**，独立展示 **20px**，描边 **1.5px**
- 图标**不能是唯一的信息载体** —— 必须配文字或 `aria-label`
- 同一语义在全站用同一个图标（归档、导出、详情各自固定）

---

## 11. 状态与可访问性

### 11.1 每个交互元件必须定义的状态

`rest` · `hover` · `active` · `focus-visible` · `disabled` · `loading`（若可异步）·
`error`（若可校验）· `selected`（若可选中）· `read-only`（若可只读）

**缺任何一个 = 组件未完成。**

### 11.2 焦点

统一：`2px` 实心环，`2px` 偏移，颜色 `accent-solid`。
键盘可达是底线——所有可点元素必须能被 Tab 到并看得见焦点。

### 11.3 对比度底线

| 内容 | 要求 |
|---|---|
| 正文 / 次要文字 | ≥ 4.5:1 |
| 大字（≥18px 或 ≥14px 粗）| ≥ 3:1 |
| 元件描边 / 图标 | ≥ 3:1 |
| 焦点环 | ≥ 3:1（对相邻色）|

### 11.4 颜色不可单独承载语义

状态必须**同时**有颜色 + 文字/形状。红绿色盲占男性约 8%，
"红点=故障、绿点=正常"的界面对他们是不可用的。

---

## 12. 信息设计（密集台账特有）

后台是**被扫描和操作的**，不是被阅读的。

1. **摘要先于明细** —— 列表页顶部统计条是入口，点击应能筛选到对应子集
2. **状态用形态编码** —— 严重度除颜色外要有形状差异（芯片 / 左侧色条）
3. **主键列固定加强** —— 每张表的业务号列用 `body-strong`，扫描时有锚点
4. **数字右对齐 + 等宽**
5. **空态要说清为什么空** —— "暂无数据"是失败的空态，
   要写"当前筛选条件下没有记录"或"新到货的设备需先入库建档"
6. **破坏性操作**：红色 + 二次确认；不可逆的（作废/买断）要求输入确认文本

---

## 13. 文案

- 按钮写**动作本身**（"归档"而非"确定"），操作后的反馈用同一个词（"已归档"）
- 错误说**出了什么问题 + 怎么修**，不道歉、不含糊
- 用用户认得的词，不用系统内部词（说"通知"不说"webhook 配置"）
- 权限不足**不要静默隐藏**，要说清缺哪个权限码

---

## 14. 落地与治理

### 14.1 可自动化检查的硬指标

| 检查项 | 判据 |
|---|---|
| 组件内无颜色字面量 | 扫描 hex/rgb/oklch |
| 圆角只用五档 | 扫描计算样式 |
| 间距在 4px 网格上 | 扫描计算样式 |
| 可聚焦元素有焦点环 | DOM 扫描 |
| 画布/卡片 ≥1.10、卡片/描边 ≥1.25 | 计算对比度 |
| 文字对比度达标 | 计算对比度 |

`/dev/ui` 页已具备 DOM 扫描能力，按本规范扩展判据即可。

### 14.2 扩展规则

新增 token 前先回答：**它的岗位是什么？现有档位为什么表达不了？**
答不上来就不要加——这是"杂乱"的唯一来源。

| 项 | 现状 | 本规范 |
