# 库存系统对接 · 开发计划

> 2026-10-29。依据 [库存系统对接方案](库存系统对接方案.md)（下称「方案」）。
> 目标：ShareHub 运营端的库存账从本地设备表（LOCAL）切到 ai-shop 库存服务（SERVICE），并具备运维、对账与回滚能力；寻址方式兼容固定地址与服务发现（Nacos 等）。
>
> 估算单位：人天（1 人 1 天）。角色：**PB-后端**（powerbank 后端）· **PB-前端**（ops-web）· **库存**（ai-shop 库存服务）· **运维** · **测试**。

## 五、风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 库存服务不可用 | SERVICE 下入库、出库、处置、物料单据都失败（本地会回滚，不会出现半边账） | 告警（1.5）；必要时切回 LOCAL（2.5 runbook）；库存服务多实例部署 |
| 迁移后两边不一致 | 账实不符、运营误操作 | 两轮演练 + 对账清零才切（M2）；观察期日对账（3.3） |
| 库存服务侧有人直接改账 | powerbank 本地状态落后 | 事件投影补全（4.3）；对账日报兜底 |
| ai-shop 接口变更 | powerbank 调用失败 | 契约测试进 CI（4.6）；`InventoryApi` 版本化（路径 `/v1`） |
| 调拨半途失败 | 库存服务里「已出未入」 | 4.2 自动补偿；在此之前按方案 §九人工补 |
| 凭证泄露 | 他人可冒充 ShareHub 记账 | 只在后端、内网可达、可轮换（1.3）；库存服务按系统 + 操作人审计 |
