## 这不是「漏返回字段」，是一整块没建的功能

排查时先当成字段对齐去修，查到数据库才发现**存储根本不存在**：

```sql
-- mkt_push 实际列（V7__v2_trade_user.sql:501）
push_no  title  content  channel  audience(JSON)  sent_count  status  sent_at
         + tenant_id region_id created_at updated_at version deleted
```

前端 `PushMessage`（`ops-web/lib/types/marketing.ts:126`）还要：

| 字段 | 库里 | 界面上用在哪 |
|---|---|---|
| `scheduledAt` | ✗ | `marketing/page.tsx:383` 「已排期 {time} 发送」 |
| `targetCount` | ✗ | `:384` 「目标 {n} 人」 |
| `successCount` | ✗ | `:384` 「成功 {n} 人」 |
| `operatorName` | ✗ | `:505` 表格「操作人」列 |
| `idempotencyKey` | ✗ | `:379` 发送/重发入参 |
| `audienceType` / `audienceValue` | 只有 JSON `audience` | 编辑时回填人群下拉（`audienceKey` = `类型:值`） |

**状态机也对不上**：建表注释写 `DRAFT/SENT` 两态，前端是
`DRAFT → SCHEDULED → SENDING → SENT` 四态（`PUSH_TRANSITIONS`，SENT 为终态不可重发）。

**所以界面现在长这样**：「操作人」列全空，「目标 undefined 人 / 成功 undefined 人」。
不是显示 bug，是后端没有这些数据。

## 为什么会这样

前端按 mock 把定时推送整套做完了（排期、人群、触达统计、幂等），后端只建了「立即发一条」。
mock 模式下一切正常，切真实后端才露出来 —— 这类分叉**没有任何报错**，
只有把 `api-align.py` 接进卡口后才被盯住（2026-09-24 已接入 `check:drift`）。

## 要做什么

1. **迁移加列**（新的 `V<n>__mkt_push_schedule.sql`，别改已发布的 V7）
   `scheduled_at DATETIME(3) NULL` · `target_count INT NOT NULL DEFAULT 0` ·
   `success_count INT NOT NULL DEFAULT 0` · `operator_name VARCHAR(64) NULL` ·
   `idempotency_key VARCHAR(64) NULL` + **唯一索引**（幂等的意义全在这个索引上）
   ⚠️ 本仓踩过迁移版本号乱序的雷（V47/V48），**动手前先确认当前最大版本号**：
   2026-09-24 是 **V64**，但本仓多会话并行，别照抄这个数 ——
   `ls backend/sharehub-app/src/main/resources/db/migration/V*.sql | sed 's/.*\/V\([0-9]*\)__.*/\1/' | sort -n | tail -1`
2. **状态机扩到四态**：`DRAFT/SCHEDULED/SENDING/SENT`，非法迁移抛错而不是静默放行
   （与 ops-web 的 `PUSH_TRANSITIONS` 逐条对齐）。
3. **排期发送**：到点触发的调度（架构 v4 有独立调度器，别在 app 里起 `@Scheduled`）。
4. **人群拆列或拆 JSON**：`audienceType`/`audienceValue` 要能回填编辑表单。
   若保持 JSON，则 VO 里要展开成两个字段，不能让前端自己解。
5. **`PushMessageVO` 补字段**（`MarketingDtos.java:67`）+ `PushServiceImpl` 落数据。
6. **重跑** `python3 backend/scripts/api-extract.py`，然后从
   `known-api-align-gaps.txt` 删掉对应的 7 行（台账只准变短，卡口会提示你删）。
