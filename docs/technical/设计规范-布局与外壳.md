## 0. 为什么外壳一直调不好

现有规范覆盖了色彩 / 排版 / 间距 / 形状 / 层次 / 动效 / 层级 / 密度 / 图标 / 可访问性 /
信息设计——**唯独没有布局**。于是外壳的每次调整都是就事论事：

| 第几次 | 改法 | 结果 |
|:--:|---|---|
| 1 | 三栏灰块 | 三栏同色，等于没分 |
| 2 | 加竖发丝线 | 线多了界面碎 |
| 3 | 色调阶梯 + 内容浮起 | **导航整片变灰**，喧宾夺主 |

每次都在解决上一次的副作用。根因不是审美，是**布局从来没有被规定过**：
没有定义区域、没有定义各区域的表面归属、没有定义分隔手段的优先级。

## 1. 区域划分（Anatomy）

```
┌─────────────────────────────────────────────────────────┐
│ ░░ page ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ │  ← page：应用底
│ ░┌──────┬──────────┐ ┌────────────────────────────────┐░│
│ ░│ rail │  panel   │ │ header                         │░│
│ ░│      │          │ ├────────────────────────────────┤░│
│ ░│  L1  │  L2/L3   │ │ content                        │░│
│ ░│      │          │ │  ├ page-head                   │░│
│ ░│      │          │ │  ├ toolbar                     │░│
│ ░│      │          │ │  └ body（表格 / 表单 / 图表）   │░│
│ ░└──────┴──────────┘ └────────────────────────────────┘░│
└─────────────────────────────────────────────────────────┘
        nav 面                        content 面
```

| 区域 | 职责 | 是否滚动 |
|---|---|---|
| `page` | 应用底，**唯一的非白面** | 否 |
| `nav` | 导航面：rail(L1) + panel(L2/L3) | panel 内部滚动 |
| `content` | 内容面：header + 页体 | 页体滚动 |
| `header` | 面包屑 / 语言 / 主题 / 账户 | 否（吸顶） |

## 2. 表面与分隔（本章的核心决定）

### 2.1 三条原则

1. **导航与内容都是白面。** 导航不该是灰的——它是主功能入口，
   压成灰底等于把最常用的东西推到背景里。
2. **分隔靠「间隙」，不靠线、不靠给导航染色。**
   两个白面之间留 8px 的 `page` 底色缝隙，缝隙本身就是分隔。
3. **`page` 底是唯一的非白面**，只在缝隙与四周边距处露出来。

> 一句话：**两张白纸并排放在浅灰桌面上。**
> 分隔来自纸与纸之间的那道缝，而不是把其中一张纸涂灰。

这同时满足了此前几条互相冲突的要求：
去掉线条 ✓ / 用色块区分 ✓ / 适当阴影 ✓ / **导航不是灰的** ✓

### 2.2 表面分配

| 区域 | 底色 | 圆角 | 阴影 |
|---|---|---|---|
| `page` | `--canvas` | — | — |
| `nav` | `--surface`（白）| `--r-card` | `elevation-1` |
| `content` | `--surface`（白）| `--r-card` | `elevation-1` |
| 内容里的卡片 | `--surface` | `--r-card` | `elevation-1` |

> **rail 与 panel 同属一张纸**，之间**不再分色、不画线**——
> 它们是同一个导航面的两栏，用间距和字重区分层级即可。

## 3. 尺寸（Metrics）

| 量 | 值 | 说明 |
|---|:--:|---|
| 页面边距 | 8px | `page` 四周 |
| 面间缝隙 | 8px | nav 与 content 之间 |
| rail 宽（收起）| 56px | 图标 + 焦点环余量 |
| rail 宽（展开）| 168px | |
| panel 宽 | 208px | |
| header 高 | 56px | 与 rail 收起宽同值，视觉成方 |
| 内容内边距 | 24px | 常规密度；紧凑密度 16px |
| 内容最大宽 | 不限 | 表格需要横向空间；表单类页面单列限 720px |

**所有值必须落在 4px 网格上**（规范 §4）。

---

## 4. 导航状态

| 状态 | 表达 |
|---|---|
| 默认 | 文字 `--text-secondary`，无底 |
| hover | `--bg-hover` 填充 + `--r-field` 圆角 |
| **当前项** | `--accent-subtle` 填充 + `--text-primary` + 字重 600 |
| 分期锁定 | 文字降至 `--text-placeholder` + 尾部标记，不可点 |
| 分组标题 | `txt-label`，`--text-secondary`，不可点 |

- 当前项**只包住条目本身**（左右各 8px 内边距），不做整行通栏底色
- rail 收起时，当前项用 3px 竖条 + 图标着色（图标本身没有文字可包）

---

## 5. 滚动归属

- **`page` 永不滚动**（`h-screen overflow-hidden`）
- `panel` 与 `content` 各自独立滚动
- header 不随内容滚动
- 表格横向溢出**在表格容器内**滚动，页面本身永不横向滚动

---

## 6. 响应式

| 断点 | 行为 |
|---|---|
| ≥1280 | 完整三区 |
| 960–1279 | panel 可折叠（图标栏保留）|
| <960 | nav 收为抽屉，由 header 的按钮唤起 |

---

## 7. RTL

- 所有边距/圆角使用**逻辑属性**（`ms-/me-`、`padding-inline`、`border-start-*`）
- nav 在 RTL 下自动移到右侧，内容纸的圆角随之翻边
- 竖条指示器用 `border-inline-start`，不写死 left

---

## 8. 与既有实现的差距

| 项 | 现状 | 本规范 |
|---|---|---|
| 导航底色 | 灰色阶梯（rail 更深）| **白面，与内容同色** |
| 分隔手段 | 色调差 + 内容纸阴影 | **8px 缝隙 + 各自阴影** |
| rail / panel 关系 | 两个不同色块 | **同一张纸的两栏** |
| 页面边距 | 内容侧 8px、导航侧 0 | **四周统一 8px** |
| header 归属 | 在内容纸内 | 不变（仍在内容纸内）|

改动集中在 `app-shell.tsx` + `globals.css` 的外壳区块，
`rail.tsx` / `secondary-nav.tsx` 只需去掉自身底色（改由父面提供）。

## 9. 待确认

1. **导航与内容是「两张纸」还是「一张纸」？**
   - 两张纸（本规范）：缝隙分隔，各自独立滚动，结构清晰
   - 一张纸：nav 与 content 之间用一条极淡的分隔，整体更"整块"
2. 暗色下 `page` 与 `surface` 的明度关系是否照搬（暗色阴影不可见，
   靠明度差；建议 `page` 更深、`surface` 略浅）
