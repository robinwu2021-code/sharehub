## 0. 为什么外壳一直调不好

现有规范覆盖了色彩 / 排版 / 间距 / 形状 / 层次 / 动效 / 层级 / 密度 / 图标 / 可访问性 /
信息设计——**唯独没有布局**。于是外壳的每次调整都是就事论事：

| 第几次 | 改法 | 结果 |
|:--:|---|---|
| 1 | 三栏灰块 | 三栏同色，等于没分 |
| 2 | 加竖发丝线 | 线多了界面碎 |
| 3 | 色调阶梯 + 内容浮起 | **导航整片变灰**，喧宾夺主 |

每次都在解决上一次的副作用。根因不是审美，是**布局从来没有被规定过**：
没有定义区域、没有定义各区域的表面归属、没有定义分隔手段的优先级。

## 1. 区域划分（Anatomy）

```
┌─────────────────────────────────────────────────────────┐
│ ░░ page ░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ │  ← page：应用底
│ ░┌──────┬──────────┐ ┌────────────────────────────────┐░│
│ ░│ rail │  panel   │ │ header                         │░│
│ ░│      │          │ ├────────────────────────────────┤░│
│ ░│  L1  │  L2/L3   │ │ content                        │░│
│ ░│      │          │ │  ├ page-head                   │░│
│ ░│      │          │ │  ├ toolbar                     │░│
│ ░│      │          │ │  └ body（表格 / 表单 / 图表）   │░│
│ ░└──────┴──────────┘ └────────────────────────────────┘░│
└─────────────────────────────────────────────────────────┘
        nav 面                        content 面
```

| 区域 | 职责 | 是否滚动 |
|---|---|---|
| `page` | 应用底，**唯一的非白面** | 否 |
| `nav` | 导航面：rail(L1) + panel(L2/L3) | panel 内部滚动 |
| `content` | 内容面：header + 页体 | 页体滚动 |
| `header` | 面包屑 / 语言 / 主题 / 账户 | 否（吸顶） |

## 2. 表面与分隔（本章的核心决定）

### 2.1 只用两级色调

```
┌────┬──────────┬────────────────────┐
│rail│  panel   │  content           │
│ 白 │   灰     │   白               │
└────┴──────────┴────────────────────┘
```

**灰色的二级面板自己就是分隔物** —— 它同时隔开了 rail 与 content。
不需要缝隙、不需要线、不需要第三个色阶。

三条原则：

1. **一级菜单（rail）与内容同为白面。** 一级菜单是主功能入口，
   不该被压成灰底推到背景里。
2. **二级面板是唯一的灰块。** 它是"上下文"，比一级更临时、比内容更辅助，
   用一个下沉的色块表达刚好；同时它天然成为 rail 与 content 的分界。
3. **色块层级只有两级**：白（surface）与灰（sunken）。
   层级越少越不容易乱 —— 此前试过三级阶梯，结果是导航整片发灰、喧宾夺主。

> 一句话：**一整块白底，中间嵌一条灰带。**

参考：macOS Finder / Mail 的边栏（灰底 + 白色选中块）、
Notion（灰边栏 + 白内容）、Linear（下沉边栏）都是"白 + 单灰块"的两级结构；
它们都没有用三级以上的色阶去表达导航层级。

### 2.2 表面分配

| 区域 | 底色 | 说明 |
|---|---|---|
| `rail`（L1）| `--surface` 白 | 与内容同面 |
| `panel`（L2/L3）| `--sunken` 灰 | **全局唯一的灰块** |
| `content` | `--surface` 白 | |
| 内容里的卡片 | `--surface` 白 + `elevation-1` | 白上叠白，靠阴影分出 |

**不使用**页面缝隙、圆角纸、竖分隔线 —— 全部由这一个灰块承担分区职责。

### 2.3 二级面板的文字对比度（本次的具体缺陷）

灰底上的文字必须重新校准，不能沿用白底的值：

| 元素 | 颜色 | 对灰底(#F1F2F5)对比度 |
|---|---|---|
| 分组标题 | `--text-secondary` (gray-11) | ≥4.5:1 |
| 条目（默认）| `--text-secondary` | ≥4.5:1 |
| 条目（当前）| `--text-primary` (gray-12) | ≥12:1 |
| 分期锁定 | `--text-placeholder` (gray-9) | ≥3:1（非正文，允许 3:1）|

**当前项用白色填充块**（而非 accent 底）：白块与右侧内容面同色，
视觉上"这一项通向那片内容"，是 macOS 边栏用了二十年的手法。

## 3. 尺寸（Metrics）

| 量 | 值 | 说明 |
|---|:--:|---|
| 页面边距 | 0 | 全幅铺满，不留外边距 |
| 面间缝隙 | 0 | 由灰块边界分区，无缝隙 |
| rail 宽（收起）| 56px | 图标 + 焦点环余量 |
| rail 宽（展开）| 168px | |
| panel 宽 | 208px | |
| header 高 | 56px | 与 rail 收起宽同值，视觉成方 |
| 内容内边距 | 24px | 常规密度；紧凑密度 16px |
| 内容最大宽 | 不限 | 表格需要横向空间；表单类页面单列限 720px |

**所有值必须落在 4px 网格上**（规范 §4）。

## 4. 导航状态

| 状态 | 表达 |
|---|---|
| 默认 | 文字 `--text-secondary`，无底 |
| hover | `--bg-hover` 填充 + `--r-field` 圆角 |
| **当前项** | `--accent-subtle` 填充 + `--text-primary` + 字重 600 |
| 分期锁定 | 文字降至 `--text-placeholder` + 尾部标记，不可点 |
| 分组标题 | `txt-label`，`--text-secondary`，不可点 |

- 当前项**只包住条目本身**（左右各 8px 内边距），不做整行通栏底色
- rail 收起时，当前项用 3px 竖条 + 图标着色（图标本身没有文字可包）

---

## 5. 滚动归属

- **`page` 永不滚动**（`h-screen overflow-hidden`）
- `panel` 与 `content` 各自独立滚动
- header 不随内容滚动
- 表格横向溢出**在表格容器内**滚动，页面本身永不横向滚动

---

## 6. 响应式

| 断点 | 行为 |
|---|---|
| ≥1280 | 完整三区 |
| 960–1279 | panel 可折叠（图标栏保留）|
| <960 | nav 收为抽屉，由 header 的按钮唤起 |

---

## 7. RTL

- 所有边距/圆角使用**逻辑属性**（`ms-/me-`、`padding-inline`、`border-start-*`）
- nav 在 RTL 下自动移到右侧，内容纸的圆角随之翻边
- 竖条指示器用 `border-inline-start`，不写死 left

---

## 8. 与既有实现的差距

| 项 | 现状 | 本规范 |
|---|---|---|
| 导航底色 | 三级灰阶梯 | **rail 白 / panel 灰，只两级** |
| 分隔手段 | 缝隙 + 阴影 | **单个灰块自身即分隔** |
| rail / panel 关系 | 同色，混在一起 | **白 vs 灰，一眼分明** |
| 面板文字 | 沿用白底取值，与灰底融合 | **按灰底重新校准对比度** |
| header 归属 | 在内容纸内 | 不变（仍在内容纸内）|

改动集中在 `app-shell.tsx` + `globals.css` 的外壳区块，
`rail.tsx` / `secondary-nav.tsx` 只需去掉自身底色（改由父面提供）。

## 9. 修订记录

- v1.0 三栏灰块 → 三栏同色，等于没分
- v1.1 加竖发丝线 → 线多了界面碎
- v1.2 色调阶梯 + 内容浮起 → 导航整片变灰，喧宾夺主
- v1.3 两张白纸 + 8px 缝隙 → 主次菜单混在一起（都是白的，分不出一级二级）
- **v2.0（本版）两级色调：rail 白 / panel 灰 / content 白，灰块自身即分隔**

每一版都在解决上一版的副作用。v2.0 的关键是**减少色块层级**：
层级越少越不容易乱，且"一级白、二级灰"直接对应了导航的主次关系，
而不是靠深浅程度去暗示。
