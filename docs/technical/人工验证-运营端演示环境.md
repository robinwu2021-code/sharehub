| 1 | `E1005` 登录 → 设备台账 | 在线 **47** / 离线 1 / 故障 4；「最后心跳」是**当前分钟** |

## 二、两条完整业务链（要手点，各约 10 分钟）

### A 合同双人复核 —— 这条链昨天还走不通

在只有一个账号的时候，「不能审批自己提交的」和「会签人不能是审批人」
这两道闸把合同**锁死在流程里**，任何合同都到不了 ACTIVE。现在有 7 个账号了。

1. `E1006`（BD）→ 场所拓展 › 合同 › 新增。**站点必须选没有在途合同的**
   —— 目前空着的是 **ST308（Mall of Emirates）· ST309（DXB T3）· ST311（City Centre Deira）**，
   场地方要跟站点对上（分别是 VEN303 / VEN304 / VEN301），对不上会被拒。
   分成比例填 **0.35**、进场费 **2000** —— 超过阈值才会触发财务会签那一步。
2. `E1006` 提交审批 → 状态 `PENDING`。
3. **仍然用 `E1006`** 点审批 → 应被拒：「不能审批自己提交的合同」。
4. 换 **`E1005`** 审批通过 → 状态还是 `PENDING`，
   提示「待财务会签：分成比例 0.35 > 0.30」。
   （这里用 E1005 而不是 E1007，是因为下一步要让**同一个人**去会签，
   而只有超管同时握着审批与会签两个权限码。）
5. **仍然用 `E1005`** 点会签 → 应被拒：「财务会签人不能与运营审批人是同一人」。
6. 换 `E1004`（财务）会签通过 → `SIGNED`。
7. `E1006` 签署，**必须在这一步上传盖章扫描件**（已经 attach 过的不算，
   `sign` 只看本次请求带的文件）→ 生效日 ≤ 今天则直接 `ACTIVE`。

> 库里已经有一份走完全程的样本：**ST310 那份 ACTIVE 合同**（E1006 提交 / E1005 审批 / E1004 会签），
> 另有一份 ST307 的 `SIGNED`，生效日 10-01 —— 它**现在不该是 ACTIVE**，到日子才转。

### B 建登录号 → 强制改密

1. `E1005` → 员工与权限 › 员工 → 任一在职员工行上点**「登录口令」**。
2. 确认框说清楚了两件事：新口令只显示一次、原口令立刻失效。点「生成」。
3. 面板给出一次性口令。**关掉就查不回来了**（后端不落日志、没有第二个接口能查）。
4. 退出，用那个工号 + 一次性口令登录 → **进不去应用**，只有一屏改密表单。
5. 试着直接敲别的地址（如 `/devices/`）→ **还是那一屏**。这道门挡在外壳上，
   刷新和改地址都绕不过。
6. 改完密 → 立刻进入应用；旧的一次性口令**当场失效**。
7. 离职的员工行上**没有这个按钮**（后端也会拒，回 400）。

> 改完记得把口令改回 `ShareHub@<工号>`，否则上面那张账号表就对不上了。

## 三、看着对不对（机器判断不了，只能靠眼睛）

这几处我知道有问题或拿不准，**最需要你的判断**：

1. **员工列表的「部门」那一列被挤成了竖排单字**（「设 备 运 维 组」）。

   要不要把「因故障停借」和「因掉线停借」在列表上分开？

## 五、发现问题怎么记

请写清楚**三件事**，缺一件就很难定位：

1. **用哪个工号**（权限收敛是按角色的，同一个页面不同人看到的不一样）；
2. **点到哪一步**（到第几步、上一步返回了什么）；
3. **期望看到什么**（「不对」需要一个参照，否则只能猜）。

界面报错一般会带业务原话（不是「服务器错误」）。
如果看到的是**「服务器错误」或整页白屏**，那本身就是缺陷，请优先报 ——
这两种都意味着某个异常没有被正确归类。
