## 一、设计总纲

### 1.1 一句话

**库存不是一张数量表，是「每台设备现在在哪」的集合；所有位置变化走一个统一写口，写口同事务更新设备行并追加一行履历。** 余额由设备行现算，报表由履历推算。

### 1.2 设备的「库存位置」

不新增设备状态，库存位置由现有列派生（与 [出库与绑定技术设计](设备出库与绑定-技术设计.md) 一致）：

| 库存位置 | 判定 | 归谁管 |
|---|---|---|
| **在仓**（仓 X） | `status = IN_STOCK` ∧ `warehouse_no = X` | 本方案 |
| **在途**（调拨单 Y） | 柜 `status = IN_TRANSIT`；宝 `warehouse_no IS NULL` ∧ 在未完结调拨单 Y 上（D5） | 本方案 |
| **出库池**（商家 Z） | `status = IN_STOCK` ∧ `issued_agent_no = Z` ∧ `location_no IS NULL` | 已实现（V161） |
| **已绑定 / 已上线**（点位 L） | `location_no = L` | 生命周期其它环节 |
| **已离开**（报废 / 遗失 / 售出） | `status ∈ RETIRED, LOST, SOLD, SCRAP` | 本方案（入口） |

不变量（沿用并扩展）：

- **I1** 在仓与出库池互斥：`warehouse_no` 与 `issued_agent_no` 不同时非空。
- **I4** 一批一个事务。
- **I6（新）** 一台设备同一时刻至多在一张未完结的调拨单上。
- **I7（新）** 盘点中的仓不进不出。
- **I8（新）** 每次库存位置或归属变化，恰好对应一行履历。

### 1.3 模块落点

全部在 `sharehub-svc-core` 的 `inv` 包（与 `dev` 同模块、同库），不新开服务：

```
inv/
  entity · mapper            —— 表映射（下文 §二）
  movement/                  —— ★ 统一写口 DeviceStockMover + 履历（§三.1）
  warehouse/                 —— 仓库档案、冻结闸（§三.2）
  transfer/                  —— 调拨（既有 InventoryTransferService / TransferOpsService 迁入）
  intake/                    —— 收货、期初、建档登记 DeviceRegistrar（§三.4）
  stocktake/                 —— 盘点
  diff/                      —— 资产差异与处置审批
  report/                    —— 余额与库存报表（只读）
  procurement/               —— 供应商、采购单（D1）
```

控制器在 `sharehub-app` 的 `portal/platform`，路径都在 `/api/ops/` 下。

## 三、关键机制

### 3.1 统一写口 `DeviceStockMover`

所有改变库存位置或归属的代码**只经它**：

```java
List<Movement> move(MoveCmd cmd)
// cmd: items(类型+编号)、event、to(类型+引用)、reason、source(类型+单号)、expectFrom(可选)、idemKey
```

在调用方事务内依次：

1. **冻结闸**：涉及的每个仓（起点与终点）`SELECT … FOR UPDATE` 锁仓行，`counting_no` 非空则 409 `error.inv.warehouse_counting`（§3.2）。
2. **逐台条件更新**设备行（带原状态、原仓、原商家条件），影响行数 ≠ 1 则整批回滚 409，错误一次列全。
3. **写履历**：每台一行，`idem_key = 来源单号 + 事件 + 设备号`，重放时撞唯一键即视为已处理。
4. 返回本次履历，调用方据此回包。

**接入既有写入方**（W1 一次接完，否则履历不完整）：出库 `issue`、退回 `pool-return`、绑定 / 批量绑定 / 解绑、装机完工改绑、撤机 `undeploy`、调拨发货 / 签收、整站换商家、报废、宝的遗失确认 / 找回。

> ArchUnit 规则：`dev_cabinet` 的 `warehouse_no / issued_agent_no / location_no` 三列的写入只允许出现在 `inv.movement` 与 `dev` 的状态迁移内部；新写入点绕过写口时测试失败。

### 3.2 盘点冻结（I7）

借鉴 ai-shop `InventoryMutationGuard`：**仓行就是锁**。

- 开盘：`UPDATE inv_warehouse SET counting_no = ? WHERE warehouse_no = ? AND counting_no IS NULL`，影响 0 行 → 409（已有盘点进行中）。同事务把该仓当前在仓设备快照进 `inv_stocktake_item(book = 1)`。
- 写口第 1 步对同一行 `FOR UPDATE`，所以「开盘」与「进出」天然串行：开盘后进出全拒，进出事务中途开盘会等它提交，快照必然包含它的结果。
- 审批完成或作废：`counting_no` 置空，解冻。

### 3.3 余额与报表

- **余额**（C1）：一条 SQL 对 `dev_cabinet ∪ dev_powerbank` 按 `warehouse_no × item_type × model × 派生库存状态` 分组；在途按未完结调拨单明细汇总；出库池按 `issued_agent_no` 汇总。数据量在十万级以内，加 `(warehouse_no, status)` 索引即可，不做物化。
- **库存报表**（G1，期间 `[S, E]`）：
  - `期末(E) = 当前在库 − Σ(E 之后的净流入)`，`期初(S) = 期末(E) − Σ([S, E] 内的净流入)`；
  - 「净流入」按履历行的 `to` / `from` 是否属于某仓计 +1 / −1；分列按 `event` 归类（采购入库、期初、手工、调入、调出、出库给商家、退回、报废、遗失、调整）。
  - 前提：存量设备有 `BACKFILL` / `OPENING` 行（C4）；回填前的期间报表标注「回填前数据不完整」。

### 3.4 建档统一入口 `DeviceRegistrar`（B2、B5、B6、B7）

收货确认、期初确认、手工建档三条路都调它，一处规定：起始态 `IN_STOCK`、`qc_status = PENDING`（期初可选「存量免检」= `null`，S4 §五 #6）、`warehouse_no`、`origin / origin_ref`、SN 必填全库查重（一次列全）、服务端取号、写 `STOCK_IN / OPENING / MANUAL_IN` 履历。

- 收货确认事务：抢收货单状态（`DRAFT → CONFIRMED` 条件更新）→ 锁采购行 → 条件累加 `received_qty`（超收 409，D7）→ `DeviceRegistrar` 建档 → 推进采购单（全收齐 → `RECEIVED`）。
- 期初确认事务：抢批次状态 → 逐行校验（全部错误回写 `error` 列并整批拒绝）→ 建档 → 写 `inv_asset_cost`（有价值时）。

### 3.5 撤机回仓与复检（D7）

- 撤机完工去向 `RETURN_TO_WAREHOUSE`：生成回仓调拨草稿（起点站点、终点 = `inv.return_warehouse`，空则取第一个启用仓；**一个仓都没有 → 生成运维待办并告警**，不再静默跳过）；回收的宝按清点结果一并加入明细。
- 回仓签收：写口 `RETURN_IN`，柜 `IN_STOCK`、`qc_status = PENDING`（复检）；复检通过回到「可用」，不通过可报废。**不新增 `RETURNED` 状态**，「退回仓库」展示态由「最近一次入仓事件 = `RETURN_IN` 且待质检」派生。

### 3.6 差异处置审批（E4）

`OPEN →（提出处置）→ PROPOSED →（审批人 ≠ 提出人，通过）→ RESOLVED`；驳回回到 `OPEN`。审批通过在同一事务里经写口执行：

| 处置 | 设备变化 | 履历 |
|---|---|---|
| `FOUND` 找回 | 回到指定仓，`qc_status = PENDING` | `FOUND` |
| `CONFIRM_LOST` 确认遗失 | 柜 `RETIRED` + 原因 `LOST`（D6 过渡）；宝 `LOST` | `LOST` |
| `ACCOUNT_FIX` 账务调整（错仓 / 多件） | 改到实际所在仓 | `ADJUST` |
| `TO_RETIRE` 转报废 | `RETIRED` | `RETIRE` |

## 四、状态机

| 单据 | 状态与迁移 | 关键守卫 |
|---|---|---|
| 调拨单 | `DRAFT →(ship) IN_TRANSIT →(receive) DONE`；`DRAFT →(cancel) CANCELLED` | 发货：明细非空、每台在起点仓 / 站点、质检放行、两端仓未冻结；签收：终点仓未冻结 |
| 盘点单 | `COUNTING →(submit) SUBMITTED →(approve) APPROVED`；`SUBMITTED →(reject) COUNTING`；`COUNTING / SUBMITTED →(void) VOID` | 审批人 ≠ 提交人（D4 同口径可放宽）；`APPROVED / VOID` 时解冻 |
| 差异 | `OPEN →(propose) PROPOSED →(approve) RESOLVED`；`PROPOSED →(reject) OPEN` | 审批人 ≠ 提出人 |
| 期初批次 | `DRAFT →(confirm) CONFIRMED`；`DRAFT →(void) VOID` | 校验全过才可确认 |
| 采购单 | `DRAFT →(submit) SUBMITTED →(audit) APPROVED → RECEIVING → RECEIVED`；`APPROVED / RECEIVING →(close) CLOSED`；`SUBMITTED →(reject) DRAFT` | 审核人 ≠ 提交人；有收货后不可撤审 |
| 收货单 | `DRAFT →(confirm) CONFIRMED`；`DRAFT →(void) VOID` | 采购单须 `APPROVED / RECEIVING` |

机柜状态机**本方案不改**（`RETURNED / REPAIRING / LOST` 随 S5 裁决另做）。每个状态机一个 `XxxStateMachine` 类，前端 `lib/types` 同名同边，mock 层强制，非法迁移抛错。

### 6.2 交互要点

- **所有选仓的地方**（出库退回、调拨两端、撤机回仓、期初、收货、盘点）用同一个仓库选择器，只列启用的仓；冻结中的仓显示「盘点中」并禁选。
- **扫码优先**：期初、收货、调拨加明细、签收、盘点都支持连续扫 SN / 设备号，重复扫提示不报错。
- **错误一次列全**：批量动作的 409 / 400 返回逐行原因，表格内标红。
- **设备详情**：生命周期进度条下加「库存时间轴」（履历 + 状态日志合并）。

### 6.3 前端契约与 mock

- `lib/api/contracts/inventory.ts`（新）收拢仓库、余额、履历、盘点、期初、采购；调拨与差异从 `device.ts` 迁入（方法名不变，避免改调用方）。
- `contract.test.ts` 锚点与方法总数同步；后端端点落地前按 `featureReady` 501，`drift.test.ts` 的缺口棘轮保持 0。
- mock：`lib/mock/db/inventory/*`，**写口在 mock 里也只有一个**（`moveDevices()`），冻结、一件一单、履历同样强制；重开能读回。

## 八、测试

| 层 | 要点 |
|---|---|
| 后端场景（`sharehub-app` scenario） | 每批一个场景类：W1「出库 / 退回 / 绑定 / 撤机都恰好写一行履历」（I8）；W2「同一台设备加入第二张调拨单 409」（I6）；W5「开盘后发货 409、审批后放行」（I7）；收货「订 100 收 80 → 余额 +80、在途 20、重复确认不重复入库」（AC-07） |
| 并发 | 两人同时签收、同时开盘、开盘与发货交错：只一方成功，另一方 409 |
| 架构 | ArchUnit：位置列只经写口写；`dev_movement_log` Mapper 无 update / delete |
| 前端 | mock 层状态机与写口用例（`lib/mock/db/inventory/*.test.ts`）；`contract.test`、`drift.test`、`nav*.test`、`design-tokens.test` 全绿 |
| 报表 | 构造期间内 7 类事件，断言「期初 + 入 − 出 = 期末」且每个数可追到履历行 |

本地后端测试依赖本地 MySQL；时区为 UTC 时，写 `NOW(3)` 的测试数据会比 JVM 时间慢，涉及时间窗的断言改用程序时间写入。

## 九、风险与对策

| 风险 | 对策 |
|---|---|
| 漏接某个写入方，履历不完整、报表对不上 | W1 一次接完 + ArchUnit 守门；报表提供「履历与当前位置对账」自检接口 |
| 冻结导致仓库停摆 | 盘点可作废立即解冻；冻结提示带单号与发起人 |
| 存量数据没有履历，历史期间报表不准 | W7 回填；回填前的期间在报表上明示 |
| `inv_stock` 停用后仍有隐性读者 | 停用前全仓 grep + 一个版本的只读保留期 |
| 与并行会话冲突（`inv` / `dev` 是多人热区） | 每批开工前 `git status --porcelain` 目标文件；迁移号 `ls` 后通知 |
