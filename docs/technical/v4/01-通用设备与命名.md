# 01 · 通用设备抽象与命名规范

> 所属：[v4 详细规划](./README.md) · 决策：[ADR-021](../ADR/ADR-021-通用设备命名与使用形态.md)
> 延续：[ADR-018](../ADR/ADR-018-多设备类型与多供应商的抽象边界.md)（订单主表 + 扩展表、驱动分族）· [总纲 §一](../架构设计总纲-多设备共享平台.md)
>
> **一句话**：平台层一律用**通用名**；只有设备类型特有的东西（扩展表、类型模块、驱动族、类型专属接口）才用具体设备的名字；
> 实在通用不了的，**优先用充电宝的名字**，并登记在 §五「类型专属清单」里。

---

## 一、四类设备放在同一个模型里

首批按四类设计：**充电宝（主业务）· 充电桩 · 按摩椅 · 储物柜**。它们的差别不在「设备」这一层，而在**用户怎么用**：

| | 充电宝 | 充电桩 | 按摩椅 | 储物柜 |
|---|---|---|---|---|
| 类型码 `device_type` | `POWERBANK` | `EV_CHARGER` | `MASSAGE_CHAIR` | `LOCKER` |
| **使用形态** `usage_mode` | **RENTAL** 借还 | **SESSION** 就地使用 | **SESSION** | **SESSION** |
| 设备（容器） | 柜机 | 桩体 | 按摩椅 | 柜体 |
| 槽位 `slot_kind` | 仓位 `BAY` | 枪 `CONNECTOR` | 座位 `SEAT` | 格口 `CELL` |
| 物品（可移动资产） | **充电宝**（被带走） | — | — | — |
| 开始 = | 弹出成功 | 插枪并开始充电 | 椅子启动 | 开门存入 |
| 结束 = | 任意柜归还 | 停止充电 | 到时自动停 / 用户停 | 开门取件 |
| 计量 `metering` | `MINUTE` | `KWH` | `PACKAGE`（套餐）/ `MINUTE` | `MINUTE` |
| 付费模式 `pay_mode` | `PREAUTH` → 降级 `DEPOSIT` | `PREAUTH` | **`PREPAY`** 先付后用 | `PREPAY` / `PREAUTH` |
| 驱动指令族 | `POWERBANK` | `EV_CHARGER`（对齐 OCPP） | **`SESSION`** | `LOCKER` |
| 订单扩展表 | `ord_rent_ext` | `ord_charge_ext` | **`ord_session_ext`**（新） | `ord_locker_ext` |

**两个判据决定一种新设备怎么接**：

1. **物品会不会离开设备？** 会 → `RENTAL`（要归还、可能异地、可能丢失买断）；不会 → `SESSION`（在设备上用一段时间或一段电量）。
2. **怎么计量？** 时长 / 电量 / 套餐 / 次数 —— 交给计价引擎，不在订单里写死。

按摩椅是检验这套抽象的样本：它**没有物品、没有归还、先付后用、按套餐计时** —— 与充电宝几乎每一维都不同，
但**设备、槽位、订单主表、支付、分润、结算、工单、告警全部复用**，新增的只有一张扩展表、一个类型模块、一族指令。

## 二、物理层级（全部设备通用）

```
场地方 Venue ─┐
              ▼
站点 Site（网点）── 归属：代理 agent_no · 区域 region · 场地方 venue
   └─ 点位 Location（站内投放位）
        └─ 设备 Device（容器：柜机 / 桩 / 椅 / 柜）  device_type · vendor_code · sn
             └─ 槽位 Slot（仓位 / 枪 / 座位 / 格口）   slot_kind · slot_index
                  └─ 物品 Item（仅 RENTAL：充电宝）     类型专属台账（dev_powerbank）
```

- **每台设备至少有 1 个槽位**。按摩椅是「1 个座位」，这样订单永远能写 `slot_index`，不需要为「无槽位设备」开分支；
- **归属只挂站点**，点位、设备、槽位继承（ADR-013）；
- **物品台账是类型专属的**：充电宝有 `dev_powerbank`（电量、循环次数、在哪个仓 / 在谁手里），
  其他类型没有可移动物品，不建通用物品表 —— 等出现第二种借还型设备（如雨伞）再抽 `dev_item`。

## 三、订单：共性主表 + 形态扩展

### 3.1 共性主表 `ord_order`（资金侧只认它）

分润、账务、发票、结算**只 join `ord_order`**。新增设备类型时资金域一行不改 —— 这是判断共性列有没有抽对的唯一标准（ADR-018）。

共性列：`order_no` · `device_type` · `usage_mode` · `pay_mode` · `c_user_no` · `site_no` · `location_no` · `device_no` ·
`slot_index` · `status` · `sub_status` · `amount` · `currency` · `deposit_amount` · `auth_no` · `pay_no` ·
`price_plan_no` · `price_snapshot` · `coupon_no` · `agent_no` · `source_channel` · `partner_no` · `started_at` · `ended_at` · `tenant_id`

### 3.2 扩展表（按设备类型，1:1 挂主表）

| 扩展表 | 类型 | 专属列 |
|---|---|---|
| `ord_rent_ext` | POWERBANK | `powerbank_no` · `return_device_no` · `return_slot_index` · `buyout` · `duration_min` |
| `ord_charge_ext` | EV_CHARGER | `connector_no` · `energy_kwh` · `start_soc` · `end_soc` · `meter_start` · `meter_stop` · `peak_power_kw` · `stop_reason` · `idle_min` |
| **`ord_session_ext`**（新） | MASSAGE_CHAIR 及以后的计时型设备 | `package_code` · `planned_sec` · `actual_sec` · `program` · `extended_sec` · `stop_reason` |
| `ord_locker_ext` | LOCKER | `cell_index` · `access_code` · `overtime_min` · `item_note` |

**`ord_session_ext` 是通用的，不叫 `ord_massage_ext`**：「在设备上按时长使用」是一类形态（按摩椅、共享 KTV 仓、洗衣机……），
下一种计时型设备直接复用，不再建表。充电桩因为有电量与表底，单独一张。

### 3.3 状态机：通用主状态 + 类型子状态

```
CREATED ──► ACTIVE ──► ENDED ──► SETTLED ──► CLOSED
   │           │
   ├─► CANCELLED（授权失败 / 用户取消 / 超时未开始）
   └─► FAILED（启动失败：弹仓失败、桩拒绝、椅子无响应）        异常挂起：EXCEPTION（客服介入）
```

| 主状态 | 充电宝 | 充电桩 | 按摩椅 | 储物柜 |
|---|---|---|---|---|
| `CREATED` | 子状态 `AUTHORIZING` → `DISPENSING` | `AUTHORIZING` → `PREPARING`（等插枪） | `PAYING` → `STARTING` | `PAYING` → `OPENING` |
| `ACTIVE` | 已借出，用户持有 | 充电中 | 按摩中 | 存放中 |
| `ENDED` | 已归还（可能异地） | 已停止 | 已结束（到时 / 用户停 / 故障） | 已取件 |
| `SETTLED` | 请款完成 | 请款完成 | 先付已收，多退少不补 | 结清 |

- **资金侧只认 `SETTLED`**；子状态 `sub_status` 只给端上展示与运营排查，资金侧不读；
- **现状迁移**：今天 `OrdStateMachine` 用的是充电宝语义 `IN_USE` / `RETURNED` → 改为 `ACTIVE` / `ENDED`（数据 UPDATE 一次，见 [03 数据库 §五](./03-数据库.md)）。

### 3.4 付费模式 `pay_mode`

| 值 | 含义 | 典型 |
|---|---|---|
| `PREAUTH` | 先冻结，结束后请款，余额释放 | 充电宝、充电桩 |
| `DEPOSIT` | 先收押金，结束后从押金扣费，余额退回 | 充电宝（无免押资格时降级） |
| `PREPAY` | 先付全款，按套餐使用；中途故障按比例退 | 按摩椅、储物柜 |
| `CREDIT` | 免押白名单 / 信用分，先用后付 | 会员、白名单用户 |

资金来源（卡 / Apple Pay / Google Pay / 微信 / **钱包余额**）由支付服务处理，订单只记 `pay_no` / `auth_no`。

## 四、类型模块 SPI：新增一种设备写什么

订单服务按通用流程编排（建单 → 授权 / 收款 → 下发开始指令 → 等事件 → 计量 → 计价 → 结算），
**每一步里类型相关的决定委托给类型模块**：

```java
/** 设备类型模块：一种设备一个实现，放在 ai.neargo.sharehub.device.<type> 包。 */
public interface DeviceTypeModule {
    String deviceType();                                   // POWERBANK / EV_CHARGER / MASSAGE_CHAIR / LOCKER
    UsageMode usageMode();                                 // RENTAL / SESSION
    Set<PayMode> payModes();                               // 允许的付费模式，第一个为默认

    /** 建单前校验（可借数、枪空闲、椅子空闲、格口空闲），并决定用哪个槽位。 */
    SlotChoice chooseSlot(DeviceView device, StartRequest req);
    /** 扩展表的初始行（写 ord_<x>_ext）。 */
    OrderExt newExt(StartRequest req, SlotChoice slot);
    /** 开始指令：EJECT_SLOT / START_CHARGE / START_SESSION / OPEN_CELL。 */
    DeviceCommand startCommand(OrderView order);
    /** 用户主动结束（SESSION 型才有）：STOP_CHARGE / STOP_SESSION。 */
    Optional<DeviceCommand> stopCommand(OrderView order);
    /** 设备事件 → 订单迁移判定（「这算不算归还」只在这里判，网关只报物理事实）。 */
    Transition onDeviceEvent(OrderView order, DeviceEvent event);
    /** 计量读数，交给计价引擎：时长 / 电量 / 套餐 / 次数。 */
    Meter meter(OrderView order);
}
```

**新增一种设备 = 5 件事**（以按摩椅为例）：

| # | 做什么 | 按摩椅 |
|---|---|---|
| 1 | `md_device_type` 登记一行（纯数据） | `MASSAGE_CHAIR` · SESSION · PACKAGE · PREPAY · 指令族 SESSION · 扩展表 `ord_session_ext` |
| 2 | 类型模块实现 `DeviceTypeModule` | `device.massage.MassageChairModule` |
| 3 | 扩展表（能复用就复用） | 复用 `ord_session_ext`，**不建表** |
| 4 | 驱动族（能复用就复用） | 复用 `SESSION` 族；写厂商驱动 |
| 5 | 计价方案 | 在计价后台配套餐（5 分钟 / 10 分钟 / 15 分钟） |

**不动的**：设备台账、站点点位、订单主表、支付、分润、账务、结算、发票、工单、告警、客服、运营端的列表页（按 `deviceType` 筛）。

## 五、命名规范

### 5.1 三条规则

1. **平台层用通用名**：表、列、接口路径、字段、Port、事件、权限码、菜单 —— 一律按下方词典；
2. **类型层才出现设备名**：`device.<type>` 包、`ord_<x>_ext` 扩展表、驱动族、类型专属资产与动作（充电宝台账、买断）；
3. **通用不了，优先充电宝**：用充电宝的叫法，并登记进 §5.3 类型专属清单，review 时对照。

### 5.2 通用词典

| 概念 | 代码 / 字段 | 表 / 列 | 接口路径 | 中文（界面） | 不要再用 |
|---|---|---|---|---|---|
| 设备 | `Device` · `deviceNo` | `dev_device` · `device_no` | `/devices` | 设备（运营端可按类型显示「柜机 / 充电桩 / 按摩椅」） | ~~cabinet~~ ~~cabinetNo~~ |
| 槽位 | `Slot` · `slotIndex` · `slotKind` | `dev_slot` · `slot_index` · `slot_kind` | `/slots` | 槽位（仓位 / 枪 / 座位 / 格口） | ~~bay~~ ~~port~~ |
| 设备类型 | `deviceType` | `device_type` | `?deviceType=` | 设备类型 | ~~EV_PILE~~（→ `EV_CHARGER`） |
| 使用形态 | `usageMode` | `usage_mode` | — | — | — |
| 订单 | `Order` · `orderNo` | `ord_order` · `order_no` | `/orders` | 订单 | ~~rent~~ ~~RentOrder~~（仅充电宝语境可说「租借」） |
| 开始 / 结束 | `start` · `end` · `startedAt` · `endedAt` | `started_at` · `ended_at` | `/orders/{no}/stop`（用户主动结束） | 开始 / 结束 | ~~rent_start_at~~ ~~return~~（通用层） |
| 付费模式 | `payMode` | `pay_mode` | — | — | — |
| 计量 | `metering` | `metering` | — | 计费方式 | — |
| 套餐 | `package` · `packageCode` | `price_plan_item`（费用项）/ `package_code` | `/devices/{no}/price-plans` | 套餐 | — |
| 指令 / 事件 | `DeviceCommand` · `DeviceEvent` | `gw_command_log` · `gw_message_log` | `/commands` | 指令 / 事件 | ~~eject~~（通用层） |
| 厂商 | `vendorCode` | `gw_vendor` · `vendor_code` | `/vendors` | 设备厂商 | — |
| 设备序列号 | `sn` | `sn` | — | 序列号 | — |

**库名**也去掉 `pb_`：`sharehub_core` · `sharehub_auth` · `sharehub_pii` · `sharehub_gw` 四个（支付与任务的数据在共用服务里，本项目不建库，[ADR-025](../ADR/ADR-025-直接复用ai-shop在跑的支付与任务服务-多系统改造.md)；[03 数据库](./03-数据库.md)）。

### 5.3 类型专属清单（这些名字允许带设备语义）

| 名字 | 所属类型 | 为什么不通用 |
|---|---|---|
| `dev_powerbank` · `/api/ops/powerbanks` · `device:powerbank:*` | POWERBANK | 可移动物品台账，其他类型没有物品 |
| `ord_rent_ext` · `powerbank_no` · `return_device_no` | POWERBANK | 借还形态专属 |
| 买断 `buyout`：`/orders/{no}/buyout` · `/deposits/{no}/buyout` | POWERBANK（RENTAL） | 只有物品会丢 |
| 指令族 `POWERBANK`：`EJECT_SLOT` · `ITEM_INSERTED` | POWERBANK | 物理动作专属 |
| `ord_charge_ext` · 指令族 `EV_CHARGER`（OCPP 名） | EV_CHARGER | 行业标准名，不自创 |
| `ord_locker_ext` · 指令族 `LOCKER` | LOCKER | 格口、取件码 |
| `device.<type>` 包 | 各类型 | 类型模块 |

清单外的任何地方出现 `cabinet` / `powerbank` / `rent` / `eject` / `pile`，都按违规处理（卡口见 [08 落地路线 §三](./08-落地路线.md)）。
