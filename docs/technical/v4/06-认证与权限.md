## 一、模型：三件事正交

照 ai-shop「身份 / 功能权限 / 数据域」三分，各管一件，互不替代：

| 问题 | 回答者 | ShareHub 实现 |
|---|---|---|
| **你是谁**（身份） | 会话 + 身份解析器 | 令牌 → 会话表 → `subject_no` → 员工 / 代理 / 消费者档案（每次请求现算，带缓存） |
| **你能做什么**（功能权限） | 权限解析器 + `@perm.can` | 角色 → 功能点 → 权限码；`@PreAuthorize("@perm.can('码')")`（neargo rbac） |
| **你能看哪些数据**（数据范围） | 数据范围解析器 + SQL 拦截器 | `iam_data_scope`（ALL / REGION / SITE / LOCATION / VENUE / AGENT / SELF）→ `DataScopeHandler`（neargo scope）注入 WHERE |

C 端只有「身份」与「数据范围 = SELF」，**没有角色**；防越权靠 SQL 层强制带 `c_user_no = 我` + 服务层 `ConsumerContext.assertOwner`。

## 二、后端

### 2.1 Realm、令牌、过滤器链

| Realm | 前缀 | 过滤器链 | 会话表 | 谁 |
|---|---|---|---|---|
| `CONSUMER` | `ctk_` | `/mp/**` | `usr_session` | C 端用户 |
| `STAFF` | `stk_` | `/api/**` | `ops_session` | 运营员工 |
| `AGENT` | `atk_` | `/api/**` | `agt_session` | 代理商账号（ops-web 受限视图） |

- **前缀是 Realm 的唯一真源**（`Realm.tokenPrefix()`）：前缀与所在链不符 → 直接 `10401`，不查库；
- `RealmRoutingTokenStore` 按前缀分到对应池；**少配一个池启动即失败**；`revokeUser` 必须指明池；
- 过滤器链（Spring Security，无状态、关 CSRF）：

| 顺序 | 路径 | 放行 | 过滤器 |
|---|---|---|---|
| 1 | `/internal/**` | 全部走服务凭证 | `InternalTokenFilter`（`X-Internal-Token`，每个调用方一把）· 任务端点用 `X-Job-Token` |
| 2 | `/mp/**` | `/mp/auth/**` · `/mp/nearby/**` · `/mp/devices/**`（只读）· `/mp/sites/**` · `/mp/notice` · `/mp/faq` · `/mp/app/**` | `ConsumerTokenAuthFilter` |
| 3 | `/api/**` | `/api/auth/login` · `/api/auth/password/forgot` · `/api/auth/password/reset` | `StaffTokenAuthFilter`（STAFF + AGENT） |
| 4 | `/actuator/health` | 放行 | — |

令牌格式：**前缀 + 32 位随机串**（UUID 去横线），不是 JWT —— 必须能撤销、能踢人（ai-shop ADR-015 同一理由）。

### 2.2 会话

**存储**：`sharehub_auth` 的会话表只存「他是谁」（结构见 [03 §3.7](./03-数据库.md)）：`token_hash`（SHA-256）· `subject_no` ·
`issued_at` · `expires_at` · `last_seen_at` · `revoked_at` · `revoke_reason` · `client_type`。**不存权限、不存角色**。

**档位**（`SessionProfile`，照 ai-shop，按端装配同一套实现）：

| 参数 | CONSUMER | STAFF | AGENT | 说明 |
|---|---|---|---|---|
| 有效期（滑动） | 30 天 | **7 天** | 7 天 | ai-shop 运营端为 30 天；ShareHub 运营端有资金操作，缩短 |
| 会话缓存 `cacheTtl` | 5 分钟 | 60 秒 | 60 秒 | 堆内，不落盘，不做负缓存 |
| 身份缓存 `identityTtl` | 60 秒 | 30 秒 | 30 秒 | |
| 撤销轮询 `revokePoll` | 10 秒 | 5 秒 | 5 秒 | 其他实例最迟这么久踢下线 |
| `last_seen` 节流 | 24 小时 | 1 小时 | 1 小时 | 顺便顺延有效期 |
| 登录日志 | 异步 · 保留 90 天 | **同步** · 730 天 | 同步 · 365 天 | 失败一律同步写 |

**生命周期**：

| 动作 | 做法 |
|---|---|
| 签发 | 登录成功 → 生成令牌 → 存哈希 → 返回明文一次 |
| 续期 | 请求时按节流 `touch`，`expires_at` 顺延；**不需要 refresh token**（`/mp/auth/token/refresh` 仅作可选的令牌轮换） |
| 登出 | 撤销当前令牌，原因 `LOGOUT` |
| 踢人 | 停用账号（`DISABLED`）· 改密 / 重置密码（`PASSWORD_CHANGED`）· 角色强制重登（`FORCED_OUT`）→ `revokeUser`；**原因如实记录**（ai-shop 一律记成 DISABLED，是缺陷，不照抄） |
| 多设备 | 不限会话数；员工可在「我的会话」查看并逐个下线 |
| 清理 | 任务 `session-purge`（每天 04:15）清过期会话与超保留期的登录日志 |

**实现落位**：会话持久层用下沉后的 `neargo-auth-store`（原 ai-shop `shop-auth-store`，JDBC + Ehcache，只依赖 spring-jdbc）；
现有 `TokenStore` SPI 保留，`token-store=db` 为生产值，`memory` 只给测试。

### 2.3 身份与权限：每次请求现算

```
请求 → 前缀路由 → 会话缓存（token_hash → 会话）
     → LiveIdentityResolver：subject_no → {realm, name, roles[], agentNo, dataScope}       缓存 identityTtl
     → LivePermResolver：roles[] → 权限码集合（角色 → 功能点 → perm_code；wildcard 角色短路为 *）  整表快照缓存
     → SecurityContext（LoginUser）+ DataScopeContext
```

- **改权限不踢人**：改角色的功能点、改人员的角色、改数据范围 → 写库后 `invalidate()` 本机快照，
  并把 `sys_param` 的 `iam.perm_version` 加一；各实例的撤销轮询顺带比对版本号，变了就清快照 ——
  **多实例下最迟 5 秒生效**（替代今天进程内的 `PermVersion` 原子计数器，它在多实例下不同步）；
- 解析失败（库暂时不可用）回落到上一份快照，不回落到「无权限」也不回落到「全权限」。

### 2.4 功能点权限模型（照 ai-shop）

```
功能 iam_function（菜单分区，两级）
  └─ 功能点 iam_function_point（MENU = 一个页面；ACTION = 一个按钮 / 操作）── perm_code（后端码）
        ▲
角色 iam_role ── iam_role_point（勾选功能点）
        ▲
成员 iam_role_member（realm × subject_no × role_no，一人多角色）
```

- **一套码走到底**：功能点的 `perm_code` 就是后端 `@perm.can` 的码，也是前端 `can()` 的码 ——
  **不做** ai-shop 的「UI 码 → 后端码」双层映射（ai-shop 自己的复核结论：从一开始统一就可以删掉那层）；
- **权限码命名**：`模块:资源:动作`，读写分开、高危动作单独发码（如 `finance:payout:execute`）；通配 `*` / `模块:*`；
  设备相关用通用码 `device:asset:*`（[01 §5.4](./01-通用设备与命名.md)）；
- **`backend_status`**：`NOT_IMPLEMENTED` 的功能点前端置灰（替代今天前端写死的 `backend-ready.ts`）；
- **超管**：`iam_role.wildcard = 1`，解析短路为 `*`，数据范围恒为全量；API 新建的角色不能是通配；
- **规则**（照 ai-shop 错误码语义）：内置角色的功能点只读 · 有成员的角色不能删（`archive`）· 角色码 `^[A-Z][A-Z0-9_]{1,31}$` · 不能停用自己或改自己的角色；
- **代理菜单单独一棵**：`iam_function.realm = 'AGENT'`，代理角色只能勾代理树里的功能点（「我的看板 / 我的设备 / 我的订单 / 我的收益 / 我的结算 / 设备报修」）。

### 2.5 数据范围

沿用 ShareHub 已实现的 neargo `DataScopeHandler` + `DataScopeRegistration`（表 → 锚点列，[03 §四](./03-数据库.md)）。
ai-shop 的维度（社区 / 自提点）是它的产品特有，不照搬。两条规矩：
AGENT realm **强制** `agent_no = 自己`（不可被角色配置放宽）；系统任务用 `DataScopeContext.executeWithoutScope` 显式豁免，**豁免点要可数**（进卡口计数，只降不升）。

### 2.6 员工与代理账号

| 项 | 规则 |
|---|---|
| 登录名 | 员工：邮箱（新建必须是邮箱）；代理：`agt_account.username` |
| 登录接口 | `POST /api/auth/login {realm: STAFF｜AGENT, username, password}` —— `realm` 只选账号池，**不是权限**；缺省 STAFF |
| 凭据 | `sharehub_auth.cred_credential`，bcrypt（cost 10），旧哈希登录成功时自动升级 |
| 建号 | 管理员建号 → 生成 12 位随机密码一次性显示（或邮件）→ `must_change = 1` → 首次登录强制改密 |
| 密码策略 | 至少 8 位；不能与用户名相同；改密 / 重置后踢掉该账号所有会话 |
| 防爆破 | **账号维度**：连续失败 5 次锁 15 分钟（`10458`）；**IP 维度**：nginx 限流 + 应用内每 IP 每分钟 20 次 —— ai-shop 运营端没有这层，是缺陷，不照抄 |
| 找回密码 | `/api/auth/password/forgot` 无论账号是否存在都回成功；每账号每小时 5 次；重置码 15 分钟、一次性（`auth_reset_code`） |
| 自助改密 | `PUT /api/auth/password {old, new}` |
| 登录日志 | 成功与失败**成对**记录（`LOGIN` / `LOGIN_FAILED`，账号打码）；有卡口测试（§五） |

### 2.7 消费者登录

`POST /mp/auth/login {grantType, principal, credential, agreed}` 按 `grantType` 分发到 `ConsumerLoginStrategy`（已有 5 个，补 1 个）：

| grantType | 端 | 服务端校验（今天是占位的要做实） | 解析出 |
|---|---|---|---|
| `PHONE_OTP` | 全部 | 验证码校验（§2.8） | phone |
| `PASSWORD` | App / H5 | 凭据校验；**只认人不建户** | phone / email |
| `WX_MINI` | 微信小程序 | `code2Session`（服务商或直连 appid/secret） | openid · unionid |
| `WX_OPEN` | App 内微信登录（海外中国用户，可选） | 开放平台 `oauth2/access_token` | openid · unionid |
| `APPLE` | iOS | 校验 identityToken 的 JWT 签名（Apple 公钥）、`aud` = bundleId、`nonce` | sub（Apple 用户 ID）· email |
| `GOOGLE` | Android | 校验 id_token 签名（Google 公钥）、`aud` = clientId | sub · email |

- **找人顺序**（照 ai-shop `RESOLVE_ORDER`）：`usr_identity` 按 PHONE → UNIONID → OPENID / APPLE / GOOGLE 查；找不到则建户（`PASSWORD` 除外）；
- **绑手机号**：`POST /mp/user/phone/bind`（验证码）· `POST /mp/user/phone/wx`（小程序 getPhoneNumber）；手机号已属他人 → `10409`，**不自动合并**（避免账号劫持）；
- **可用登录方式按国家配**：已有表 `sys_login_setting`（今天没用上）→ 新增 `GET /mp/auth/methods?platform=&country=`，端上按它渲染按钮；
- 登录请求带 `agreed`（隐私政策同意），落 `usr_consent`（PDPL）。

### 2.8 验证码

| 项 | 值（照 ai-shop） |
|---|---|
| 格式 / 有效期 | 6 位数字 / 5 分钟；只存哈希；一次性 |
| 输错 | 同一目标 5 次 → 锁 15 分钟（`10454`） |
| 发送频控 | 同一目标 60 秒 1 次、每天 10 次；同一 IP 每小时 20 次（`10450` / `10451`） |
| 存储 | **落库 `auth_otp`**（ai-shop 放内存只能单实例，这里改掉） |
| 开发便利 | 固定码只在 `dev` profile 且 `sharehub.auth.otp.dev-fixed-code` 显式配置时生效；启动日志打印告警 |
| 发送 | 经通知模块（短信 / 邮件）；发送失败不泄露账号是否存在 |

### 2.9 服务间凭证

| 调用 | 头 | 规则 |
|---|---|---|
| gateway / pay-svc → app（事件回推）；app → gateway / pay-svc | `X-Internal-Token` | 每个调用方一把，可轮换（新旧两把并存期）；常量时间比较；没配一律 401；只走内网直连 |
| sharehub-job → 各任务目标 | `X-Job-Token` | 共享模块约定；每个目标一把 |
| 将来拆分后的业务服务之间 | 透传用户 Bearer | [设计v3-工程骨架](../设计v3-工程骨架.md) 已定 |

### 2.10 401 / 403

| 场景 | HTTP | `code` |
|---|---|---|
| 没带令牌 / 前缀不符 | 401 | `10401` |
| 令牌过期 / 登出 / 被踢 / 改密 | 401 | `10402` |
| `@perm.can` 拒绝 | 403 | `10403` |
| 数据范围外 / 非本人资源 | 404 | `10404`（与「不存在」同码，不暴露资源是否存在；同 ai-shop） |

**HTTP 状态与业务码同时给**（ai-shop 只给业务码，它的运营端因此从没触发过 403 处理）；
方法级 `@PreAuthorize` 抛出的拒绝要在全局异常处理里映射（已有，保留）。

## 三、ops-web

### 3.1 登录态

`lib/auth.ts`（zustand persist），localStorage 键 `sharehub-ops-auth`（原 `pb-ops-auth`）：

```ts
type AuthState = { token: string | null; me: Me | null };            // 不再有单值 role
type Me = { subjectNo; realm: "STAFF" | "AGENT"; name; username; roles: string[]; perms: string[];
            dataScope; agentNo?: string; mustChangePassword: boolean };
```

### 3.2 登录页

- 字段：账号池切换（员工 / 代理商）· 用户名 · 密码；**删掉 role**；不支持 URL 带密码自动登录（ai-shop 的 `?u=&p=` 是缺陷）；
- 成功 → 存 `{token, me}` → `mustChangePassword` 为真则弹**不可关闭**的改密框 → 进首页；
- 失败提示区分：账号或密码错误（`10456`，不透露哪个错）/ 已锁定（`10458`，显示剩余分钟）/ 频率超限（`10429`）；
- 「忘记密码」抽屉：输邮箱发重置码 → 输码 + 新密码。

### 3.3 请求层 `lib/api/http-client.ts`

```ts
if (res.status === 401 || body.code === 10401 || body.code === 10402) {
  onceGuard(() => { auth.clear(); toast(t("auth.expired")); router.replace(`/login?redirect=${encodeURIComponent(path)}`); });
} else if (res.status === 403 || body.code === 10403) {
  toast(body.message ?? t("error.forbidden")); void auth.refreshMe();      // 权限可能刚被改，重新拉
} else if (res.status === 404 || body.code === 10404) {
  toast(body.message ?? t("error.notFound"));
}
```

- 并发的多个 401 只处理一次（`onceGuard`）；
- 只读 `message` 字段（后端 401/403 今天写的是 `msg`，统一改成 `message`）；
- **不再发** `X-Roles` / `X-User-Id` / `X-Merchant-Id`（后端本来就忽略，边缘也会清掉）。

### 3.4 权限从哪来

| 时机 | 动作 |
|---|---|
| 登录成功 | 用登录响应里的 `me` |
| 应用挂载 / 标签页重新可见 | `GET /api/auth/me` + `GET /api/auth/menus` |
| 收到 403 | 重新拉 `me` |

**删除** `lib/permissions.ts` 里写死的 `ROLE_PERMS`；mock 模式的权限夹具由脚本从后端种子生成（`scripts/gen-perm-fixture.mjs`），不手写。

### 3.5 判权 API

```ts
can(code: string): boolean          // 语义与后端 neargo Permissions.matches 一致：完全相等，或 "*"，或 "模块:*" 前缀
canAny(...codes: string[]): boolean
useCan(): (code: string) => boolean // hook
<Can perm="device:asset:create" fallback={<ReadOnlyNotice …/>}>…</Can>   // 🆕 按钮级组件
```

`<ReadOnlyNotice>` 继续用（CLAUDE.md 棘轮：手写「仅可查看」≤17，只降不升）。

### 3.6 菜单

- **以服务端 `/api/auth/menus` 为准**；`lib/nav.ts` 降为**路由登记表**（`href → 图标 / 页面 / 所需功能点`），并在 mock 模式下兜底；
- 渲染 = 服务端树 ∩ 登记表：服务端有、前端没登记的页面不显示（避免 404）；`backendStatus = NOT_IMPLEMENTED` 置灰；`phase` 出徽章；
- 代理登录时服务端返回代理树，前端不再靠 `portalFor:["AGENT"]` 判断。

### 3.7 路由守卫（🆕，ai-shop 没有）

`components/layout/app-shell.tsx`：未登录 → `/login?redirect=`；已登录但当前路由的功能点不在可见集合里 → 渲染 `<Forbidden/>`（而不是让页面打开后满屏 403）。
`phase-guard.tsx` 保留（产品分期）。

### 3.8 身份与权限管理页（`/employees` 扩展，照 ai-shop `app/iam`）

|---|---|---|
| 员工 | 建号（一次性显示密码）、启停、多角色、数据范围、重置密码、查看在线会话并下线 | `org:employee:*` |
| 角色 | 功能点勾选树（按功能分组，ACTION 挂在 MENU 下）、新建 / 改名 / 归档、内置只读、**强制重新登录**（二次确认，高危审计） | `org:role:*` |

### 4.3 请求层 `src/api/http-client.ts`（照 ai-shop 共享请求层）

```ts
if (statusCode === 401 || [10401, 10402].includes(body.code)) {
  user.clearSession();
  // #ifdef MP-WEIXIN
  if (!retried && await user.silentLogin()) return retry(req);          // 小程序：静默登录后重试一次
```

`redirect` 只接受 `/pages/` 开头（防开放重定向，照 ai-shop）。

### 4.4 页面守卫（🆕，ai-shop 只在各页 `onLoad` 里各自判断）

用 `uni.addInterceptor` 拦 `navigateTo` / `redirectTo` / `reLaunch` / `switchTab`，按登记表判断：

| 公开（无需登录） | 需登录 |

| 启动页、首页（地图 / 列表）、站点详情、扫码结果与价格展示、公告、帮助、关于 / 协议、登录 / 注册 / 找回密码 | 下单确认、订单列表 / 详情、钱包 / 充值、券（领取）、会员（购买）、我的设置、报障、发票、消息 |

## 七、与 ai-shop 的差异（有意为之）

| 点 | ai-shop | ShareHub | 理由 |
|---|---|---|---|
| 403 | HTTP 200 + `10403` | HTTP 403 + `10403` | ai-shop 运营端判 HTTP 状态，拒绝路径从未触发 |
| 验证码 / 限流存储 | 进程内存 | 落库 | 多实例 |
| 运营端防爆破 | 无 | 账号锁定 + IP 限流 | ai-shop 自评缺陷 |
| 撤销原因 | 一律 `DISABLED` | 如实记录 | 审计可用 |
| 路由守卫 | 只判登录 | 按功能点拦 | 避免打开页面后满屏 403 |
| UI 码 / 后端码 | 双层映射 | 一套码 | ai-shop 自评可删 |
| 密码存放 | 员工表列 | 独立凭据库 `sharehub_auth` | ADR-010 凭据隔离（PDPL） |
| 权限变更跨实例 | 快照 TTL 60 秒 | 版本号 + 轮询，5 秒 | ShareHub 已承诺「改权限即时生效」 |
| 运营端会话时长 | 30 天 | 7 天 | 含资金操作 |
