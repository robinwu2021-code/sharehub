## 一、分层

**先分清库和服务**：库嵌在调用方进程里、随调用方升级生效；服务有自己的进程和库、部署即生效。两者的版本语义不同，不放在同一类里。

| 类 | 是什么 | 放在哪 | 谁用 | 发布 |
|---|---|---|---|---|
| **框架** | 纯技术底座，五级（L0 基础 → L1 抽象与策略 → L2 适配器 → L3 自带表的基础设施 → L4 starter） | `neargo-framework`（✅ 已建） | neargo 全家 | `ai.neargo:*`，框架版本线 |
| **组件** | 嵌入产品进程的可复用能力**库**，可自带表：通知通道、媒体存储 | `neargo-framework` 的 `components/` | 至少两个产品 | 与框架同一版本线、同一个 BOM |
| **共用服务** | 独立进程 + 自有库；**代码与实例都共用一套**，按 `system` 维度隔离（[ADR-025](../ADR/ADR-025-直接复用ai-shop在跑的支付与任务服务-多系统改造.md)）：支付（含全部通道与微信能力）、任务调度 | **暂由 ai-shop 托管并部署**（ADR-024 · ADR-025） | 两个产品 | `ai.neargo.shop:*`，随 ai-shop 发布；产品只依赖服务的客户端与契约 |
| **产品私有** | 各产品的业务域与产品层配置 | 各产品仓库 | 仅本产品 | 不发布 |

| 规则 | 内容 |
|---|---|
| 依赖方向 | 产品 → 共用服务的客户端 / 契约 · 组件 · 框架；组件 → 框架；**框架不依赖组件；框架与组件都不依赖任何 `ai.neargo.shop:*`**（§3.4） |
| 入选判据（组件，缺一不可） | ① 至少两个产品在用，或一个在用、另一个已排期；② 不含任何产品的业务名词；③ 自带测试；④ 接口稳定、有维护人 |
| 共用服务的改动 | 本项目需要的改动**提给 ai-shop，由 ai-shop 统一改**；本项目不 fork、不复制 |
| 产品差异 | 一律经 SPI 由产品注册：表的隔离归属、响应信封、用户池集合、权限码、错误码分段、业务号前缀、业务端口实现 |
| 不猜测性抽取 | 只有一个产品需要的能力留在产品，按中性命名写，等第二个产品需要时再上移（例：本项目的 CRUD 模板） |
| 贡献回流 | 本项目写出的通用能力回到对应位置：Google / Apple 验签 → `neargo-security`；S3 存储 → `neargo-media`；MENA 短信 → `neargo-notify`；预授权、AE 支付通道 → 提给 ai-shop 的支付服务 |

| `neargo-audit`（审计日志） | 两边表结构与写法不同（ai-shop 显式记录 · 本项目横切拦截） | 统一表结构后 |
| `neargo-setting`（类型化系统参数） | 两边参数表语义不同 | 再观察 |
| `neargo-iot`（协议对接内核） | 只有本项目需要 | 第二个产品需要设备接入时 |
| 通知升级为服务 | 现在只是通道库 | 多个产品要共用同一发送出口（统一配额、签名、通道账号），或要集中发送日志与重试、跨产品退订时，另建服务，`neargo-notify` 作为它的通道层 |

| 前端包 | 来源 | 归属 |
|---|---|---|
| `@neargo/ops-ui` | ai-shop `ops-web/components`（React） | 前端会话细化；发布到 Nexus npm |
| `@neargo/uni-ui` · `@neargo/uni-shared` | ai-shop `packages/ui` · `packages/shared`（uni-app） | 同上 |
| `@sharehub/contract` | 本项目接口契约生成的类型 | 本项目私有 |

## 七、实施顺序（与 [10 §七](./10-共享构件与Nexus.md) 一致）

| 步 | 内容 | 谁改 | 本项目收益 |

## 八、治理

| 项 | 规则 |
|---|---|
| 维护人 | 框架与组件的每个构件在 README 首行登记维护人；共用服务的维护人在 ai-shop |
| 改动流程 | 框架 / 组件：在 `neargo-framework` 提改动 → 两项目兼容矩阵 → 发版 → 产品升 BOM。共用服务：**本项目提需求给 ai-shop**，ai-shop 统一改、发版，本项目升客户端版本并更新实例 |
| 禁止 | 在产品里 fork 或复制框架、组件、共用服务的代码 |
| 边界卡口 | 框架构建：enforcer 按级禁依赖 + 禁 `ai.neargo.shop:*` + ArchUnit 禁产品包；产品侧：enforcer 白名单只放行三个 ai-shop 构件，`neargo-archrules` 复查 |
| 文档 | 每个构件 README 写职责、SPI、配置项、表结构、装配示例；产品侧只写「怎么装配」 |
| 弃用 | 框架 1.x 冻结只修缺陷；2.x 内被替换的类 `@Deprecated` 保留一个次版本 |
