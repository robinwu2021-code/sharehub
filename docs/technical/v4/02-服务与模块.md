## 一、部署单元（4 个进程）

| 进程 | 来源 | 端口 | 库 | 副本 | 做什么 |
|---|---|---|---|---|---|
| **`sharehub-app`** | 本仓库 | 8082 | `sharehub_core` · `sharehub_auth` · `sharehub_pii` | N | 全部业务 + 认证 + 对外接口（`/api` `/mp`） |
| **`sharehub-gateway`** | 本仓库 | 8091 | `sharehub_gw` | 1 起 | 协议对接：第三方充电宝 / 充电桩平台与设备 |
| `ai-shop-pay`<br>（**共用实例**，不是本项目的进程） | ai-shop `backend/pay/` | 8083（已在跑） | 支付服务自己的库，按 `system` 隔离 | 2 | 支付：通道、流水、预授权、退款、回调、对账、打款；含全部微信能力 |
| `ai-shop-job`<br>（**共用实例**，不是本项目的进程） | ai-shop `backend/job/` | 无端口（已在跑） | 任务服务自己的库，按 `system` 隔离 | 1 | 定时任务调度：到点回调各系统各目标的任务端点 |

- **ShareHub 只有上面两个自有进程**。支付与任务**直接用 ai-shop 已在跑的两个服务实例**（同一台腾讯云机器，内网直通），两个服务改造为多系统后按 `system=SHAREHUB` 隔离（[ADR-025](../ADR/ADR-025-直接复用ai-shop在跑的支付与任务服务-多系统改造.md) · [15 改造需求](./15-多系统多平台改造需求.md)）；实例拆分随时可做，届时只改地址；
- 调度器不执行业务，只按时回调：`sharehub-app`、`sharehub-gateway`、`pay-svc` 三个进程都是它的**任务目标**（[07 定时任务](./07-定时任务.md)）；
- **开发形态**：`sharehub-app` 一个进程即可跑通 —— 网关用本地实现 + Demo 驱动、支付用 Stub、任务用进程内调度。

## 二、Maven 模块

### 2.1 本仓库 `backend/`（groupId `ai.neargo.sharehub`）

```
sharehub-parent
├─ sharehub-common             内核（≈ ai-shop shop-base）：BizException / ErrorCode · 业务号 · 事件接口 · AfterCommit · 内部调用 · 工具；不依赖 MyBatis
├─ sharehub-auth               🆕 认证（≈ shop-base-auth）：Realm · 会话 · 过滤器 · Perms · 响应包裹 · 全局异常 · 登录策略 · OTP
├─ sharehub-store              🆕 持久（≈ shop-store-mybatis）：BaseEntity · 审计填充 · CRUD 基类 · 分页 · 幂等 · 事件去重 · Outbox 投递
├─ sharehub-api                跨进程契约：Port 接口 · 事件类 · DTO · 远程实现（@ConditionalOnMissingBean）
├─ sharehub-svc-platform       业务：底座与运营配置面
├─ sharehub-svc-core           业务：订单主链路 + 设备资产 + 用户营销 + 设备类型模块
├─ sharehub-svc-ops            业务：告警 · 工单 · 客服
├─ sharehub-svc-finance        业务：账务 · 分润 · 结算 · 发票 · 对账
├─ sharehub-app                启动器：业务单体 = 4 个 svc + auth + store；只含配置、跨域编排（报表 / 看板）与任务目标装配
├─ sharehub-gateway-kernel     🔁 由 sharehub-svc-gateway 改名：接入内核 + 驱动 SPI
├─ sharehub-gateway-transport-http    🆕 厂商云 API / Webhook
├─ sharehub-gateway-transport-mqtt    🆕 MQTT（经 EMQX）
├─ sharehub-gateway-transport-tcp     🆕 TCP 私有协议（Netty）
├─ sharehub-gateway-transport-ocpp    🆕 OCPP 1.6J / 2.0.1（WebSocket）
├─ sharehub-gateway-driver-*          🆕 每家厂商一个
└─ sharehub-app-gateway        启动器：协议对接服务 = kernel + 各 transport + 各 driver + 任务目标
```

- `sharehub-svc-gateway` → `sharehub-gateway-kernel`：它从来不是「业务服务」，改名让依赖规则一眼可读；
- transport 与 driver 按需出现：**首个是 `transport-http` + 首家厂商驱动**，其余随厂商签约逐个加。

### 2.3 依赖规则（进卡口，违反即构建失败）

| 规则 | 说明 |
|---|---|
| `svc-*` 只依赖 `common` · `auth` · `store` · `api` | 业务模块之间**不互相依赖**，跨模块只经 `api` 的 Port |
| `api` 不依赖任何 `svc-*` | 契约层不含实现 |
| `gateway-transport-*` · `gateway-driver-*` 只依赖 `gateway-kernel` | 内核不知道有哪些协议和厂商；driver 之间互不依赖 |
| `sharehub-app` 不依赖 `gateway-*` | 业务单体只经 `DeviceCommandPort` 调网关 |
| 任何 ShareHub 模块不依赖支付服务的实现包（`pay-channel` / `pay-domain` / `pay-svc`） | 只经 `PaymentPort` 远程调用 |
| 业务模块不依赖 `shop-job-core` / `shop-job` | 业务只实现 `shop-job-api` 的 `JobHandler` |
| `sharehub-auth` 只依赖 `common` + neargo 认证件 | 业务不直接碰会话，只经 `SecurityUtils` / `StaffContext` / `ConsumerContext` |

## 三、业务模块与包

### 3.1 包约定

```
ai.neargo.sharehub.<domain>
   ├─ api/{ops,mp,internal}/      本域控制器（照 ai-shop；拆服务时随域走）
   ├─ service/  service/impl/     业务（接口 + 实现；状态机放 service）
   ├─ entity/  mapper/            数据（一实体一文件；每域一个 XxxMappers）
   ├─ dto/                        出参 VO（入参 Req 嵌在控制器、Command 嵌在服务接口）
   ├─ port/                       本域实现的 api Port
   ├─ event/                      Outbox 消费者
   └─ job/                        定时任务（JobHandler + JobDeclaration）
```

控制器放在各域的 `api` 子包；只有跨域编排（报表、看板）放 `sharehub-app` 的 `portal`。完整约定见 [09 后端代码架构 §四](./09-后端代码架构.md)。

### 3.2 模块清单与归属

| 主数据 | `md` | 设备类型注册、区域、国家、银行、问题库 | `md_*` |
| 系统 | `sys` | 参数、业务规则、版本、税、登录配置 | `sys_*` |
| 通知 | `notify` | 模板、发送、退订 | `notify_*` |
| 开放平台 | `openapi` | 对外 AppKey | `openapi_*` |
| 代理商 | `agent` | 档案、账号、区域、划拨（合并 `agent.ext`） | `agt_*` |
| 场地 | `loc` | 场地方、站点、点位、合同、拓展线索、站点生命周期（合并 `loc.ext`） | `loc_*` |

**core**（`sharehub-svc-core`）

| 模块 | 包 | 职责 | 表前缀 |
|---|---|---|---|
| 设备资产 | `device` | 设备、槽位、影子、码批次（**设备无关**）；`device.spi` 放 `DeviceTypeModule` | `dev_device` `dev_slot` `dev_shadow` `dev_code_batch` |
| 设备类型模块 | `device.powerbank` · `device.evcharger` · `device.massage` · `device.locker` | 实现 `DeviceTypeModule`；类型专属资产 | `dev_powerbank`（仅充电宝） |
| 库存 | `inv` | 仓库、调拨 | `inv_*` |
| 订单 | `order` | 通用订单编排、状态机、预约、押金、异常、投诉、退款申请 | `ord_*` |

| 支付编排 | `payment` | 何时冻结 / 收款 / 请款 / 撤销；`RemotePaymentPort` 适配 | 无表（流水在 pay-svc） |

**ops**（`sharehub-svc-ops`）：告警 `alarm`（`dev_alarm*` `dev_alert`）· 工单 `wo`（`wo_*`）· 客服 `cs`（`cs_*`）

**gateway**（`sharehub-gateway-kernel`，包 `ai.neargo.sharehub.gw.*`）：厂商 `gw_vendor*` · 绑定 `gw_device_binding` ·
指令 `gw_command_log` · 报文 `gw_message_log` · 心跳 `gw_heartbeat` · 固件 `gw_ota_*`（原 `dev_heartbeat` / `dev_ota_*` 改前缀，随库迁到 `sharehub_gw`）

**auth**（`sharehub-auth`，包 `ai.neargo.sharehub.auth.*`）：会话、登录日志、凭据、OTP 的表在 `sharehub_auth`（[06 认证与权限](./06-认证与权限.md)）

### 3.3 跨模块 / 跨进程契约（`sharehub-api`）

| Port / 事件 | 提供方 | 消费方 | 本地 / 远程 |
|---|---|---|---|
| `DeviceQueryPort`（原 `CabinetQueryPort`） | device | ops、finance、platform | 单体内本地 |
| `DeviceOwnershipPort` | device | agent | 本地 |
| `SiteQueryPort` | loc | core、ops | 本地 |
| `TicketRefundPort` · `TicketWorkOrderPort` | order / wo | cs | 本地 |
| **`DeviceCommandPort`**（新） | gateway | order、wo | **远程** `/internal/gw/commands` |
| **`TelemetryQueryPort`** | gateway | core、ops | **远程** `/internal/gw/telemetry/**` |
| **`VendorPort`**（新） | gateway | sys（运营端厂商页） | **远程** `/internal/gw/vendors/**` |
| **`PaymentPort`**（从 svc-core 移入） | pay-svc | order、wallet、settlement | **远程** `/internal/pay/**` |
| **`PayoutPort`**（新） | pay-svc | settlement | **远程** |
| `DeviceEvent` · `CommandResult` | gateway | core、ops | **Outbox 推送** `/internal/events/device` |
| `PaymentEvent` | pay-svc | core、finance | **Outbox 推送** `/internal/events/payment` |
| `OrderSettled` · `AssetAssigned` 等 | 单体内模块 | 单体内模块 | 进程内事件 |

### 3.4 横切件放在哪

| 能力 | 位置 |
|---|---|
| 服务凭证：客户端 `InternalClient` + `ServiceLocator` / 服务端 `InternalTokenFilter` | 客户端在 `sharehub-common`（移植 ai-shop，待下沉 `neargo-common-internal`）；过滤器在 `sharehub-auth` |
| 幂等 · 事件去重 · Outbox 投递 | `sharehub-store`（移植 ai-shop `shop-store-mybatis`，待下沉 `neargo-common-store`；`OutboxDispatcher` 由任务 `outbox-dispatch` 驱动） |
| 链路追踪透传 | `sharehub-common`（RestClient 拦截器 + 事件头） |
| 任务目标端点 | `shop-job-target`（app、gateway、pay-svc 各自装配） |
| 审计 | `iam`（写操作审计拦截器，已有）+ 高危操作显式 `AuditLogPort.record`（照 ai-shop） |
