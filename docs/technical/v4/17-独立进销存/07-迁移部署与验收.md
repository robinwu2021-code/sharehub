# 独立进销存：迁移部署与验收

> 状态：开发设计草案（未实施） · 2026-10-29
> 已确认边界：仓内库存、进出库、盘点；出库后不跟踪业务库存；通过出库池交接；独立部署并提供 API。其余具体规则为本轮建议设计。

## 1. 部署与运行

独立 inventory-server、独立数据库/账号、独立迁移历史和库存作业端。健康检查分启动/存活/就绪：迁移未完成、数据库不可写、关键任务未注册则不得标就绪。服务凭证由密钥配置注入，文件中不写真实 key。API 使用内网 TLS/网关白名单，浏览器经 BFF。

任务：Outbox 发布、领取/命令异常查询、质检过期/检测超时提醒、库存余额与 SN 对账、事件保留、任务重试。可复用已有独立 job 服务，但 inventory 必须声明并注册自己的任务，首发用真实任务心跳和积压验证；Bean 已创建不代表任务已执行。所有任务重入幂等，不能与在线过账争用不受控的全表锁。

监控：API 错误/延迟、失败命令、池领取冲突、未完成关联、退仓业务冻结时长、待检/过期、outbox 最老待投时长、对账差异、盘点锁时长。告警到负责系统的处理人，池未领取不等于库存丢失。

## 2. powerbank 迁移清单

1. 执行前固定两个仓库 HEAD、数据库版本与目标服务版本，备份旧库存、设备、质检、单据/明细、映射及业务关联。
2. 盘点旧表含义：仓内设备、已投放设备、已出库待安装、运输中、缺件、重复 SN、无仓号、历史质检、业务差异。逐类映射并输出 dry-run 报告。
3. 建物料、仓库、业主和外部对象映射。仅已证实在仓的 SN 创建 OPEN 周期；存量运营设备不灌成库存，不补造 AVAILABLE 池。
4. 已出库待安装且有明确凭证的设备导入历史出库池，注明 migrationBatch/sourceProof；已有业务关联标 CLAIMED，不能让其重领。
5. 完成单据按历史事实导入，不重跑过账。未知质检导入 PENDING；授权历史免检导入 EXEMPT，保留审批批次。
6. 未完成旧调拨不能直接当全部已出库：仓间在途迁库存扩展，业务已交出迁交接池，缺件人工对清后迁；无证据的记录进入异常清单。
7. 旧余额只作核对，不和 SN 开放周期同时累加。导入流水使用唯一迁移批次和原始键，重复执行不重复加数。

## 3. 切换与单一写权

迁移模式分 READ_ONLY_SHADOW（仅比较）、CUTOVER_FROZEN（冻结旧写，等待在途任务清理）、REMOTE_AUTHORITATIVE（新服务唯一写）。新旧模式不能同时对同一库存做真实扣减。

切流步骤：冻结旧库存写入口及调度→清理/冻结在途操作→最后增量导入→实存/SN/池/质检逐项核对→切 BFF 和后台任务→检查旧写已拒绝→受控真实入库/质检/出库/领取/退仓→开放正常写。

旧业务页面保留只读历史入口。旧 API 不可继续接受 status 更新绕过新服务；不能仅改前端而漏掉老定时任务、测试工具和内部入口。

## 4. 回滚

尚未在新服务发生写入：关闭新入口，验证旧数据无差异后切回。

已发生新服务写入：默认保持新服务为权威，先回滚应用/BFF 到兼容版本或修复故障；不能直接开旧表写。若必须退回旧系统，冻结双方写，导出新系统全部增量单据、SN 周期、池关联和质检，按反向迁移映射回填并对账；池领取等旧系统不能表达的状态须补充兼容存储，否则不得回切。恢复数据库备份不能抹掉真实出入库事实。

## 5. ai-shop 独立切流

沿用原商品/库存对账思路，但新服务双写观测期间禁止两个库存同时承诺库存。先完成库存接口故障注入和非零订单演练，才允许权威切换。

必测：reserve 成功回包丢失、支付回调先于本地库存结果、预留到期竞争、commit 重复、退货重复、服务不可用、事件重投、跨门店发货源。统计零订单上的零差异不能作为成功依据。商家端、运营端、批处理同时收口；必要时按业主分批迁移。

## 6. 验收矩阵

| 编号 | 场景 | 必须成立 |
|---|---|---|
| AC-01 | 同一 SN 两张入库单并发 | 一个 OPEN 周期，失败单不增加余额 |
| AC-02 | 同一 SN 两张出库单并发 | 一次扣减、一个池、另一单冲突 |
| AC-03 | 出库过账中途失败 | 单据/SN/余额/池/流水/事件/命令结果全部回滚 |
| AC-04 | 仓 A 单选到仓 B 设备 | 拒绝过账，不能靠总体数量足够绕过 |
| AC-05 | 质检待检、失败、过期、复检中 | 实存保留，普通 ISSUE 全部拒绝 |
| AC-06 | 退仓后收到上轮质检回调 | 不影响新周期合格与冻结 |
| AC-07 | 两个工单同时领取一个池 | 只有一个关联生效，无二次库存扣减 |
| AC-08 | 请求超时/同键异参/重试 | 能查原结果，异参冲突，无重复写 |
| AC-09 | 已领取后本地崩溃 | 持久化任务恢复本地关联或受控补偿 |
| AC-10 | 实物退仓与领取并发 | 锁顺序一致；无已回仓仍可领取记录 |
| AC-11 | 业务撤机但实物未到仓 | 库存不增加 |
| AC-12 | 实物回仓业务未确认 | 库存计实存但冻结，不能再次出库 |
| AC-13 | 回仓再出库 | 稳定 SN/业务设备身份，新周期、新池，旧池终态 |
| AC-14 | 盘点数量相等 SN 不同 | 缺失/多出分别可见，不能只判数量相等 |
| AC-15 | 开盘有活跃预留；冻结后各写入口 | 开盘拒绝/冻结写拒绝，取消后恢复 |
| AC-16 | 作废/已过账盘点再 post | 拒绝或幂等，绝无二次调整 |
| AC-17 | 盘盈扫描已出库或别仓 SN | 不自动新增库存，进入核验/纠正 |
| AC-18 | 其它系统/业主/站点越权 | 列表与命令均拒绝，BFF 不信任任意 ref |
| AC-19 | ISSUE 误过账纠正、已领取、已回仓 | 按前置规则拒绝或一次纠正，不能通用 void 加数 |
| AC-20 | 模板变更、证据跨业主、必检失败 | 历史冻结、非法证据拒绝、不能手改通过 |
| AC-21 | outbox 提交乱序、重投、重启 | 订阅不漏事件，旧版本不覆盖新投影 |
| AC-22 | 完整备份恢复/重复迁移 | 无重复余额/池/领取/质检任务，冻结可恢复 |
| AC-23 | 商城数量 SKU 与销售预留/售后 | 无 SN 强制，无虚假 SALE，无预留侵占 |
| AC-24 | 柜与宝同批出库/部分回仓 | 每件有明细，仅实收回库，仓外缺件业务追查 |
| AC-25 | 同设备待检/退仓冻结/人工冻结并存 | 不可用只计一件；质检通过不能解除其它冻结 |
| AC-26 | 实盘复核后改内容或未批准直接 post | 无批准版本拒绝过账，修改使旧批准失效 |
| AC-27 | 检测执行器过期、重领、旧回调 | 旧 fenceToken 拒绝写；超重试不误放行 |
| AC-28 | 误出库批准纠正 | 原周期保持 CLOSED、新周期 PENDING、原池 REVOKED、库存只恢复一次 |
| AC-29 | 数量仓间调拨差异与重复收货 | 未清余量留在途，累计收货/损失不超发出量，无重复搬账 |

QC-01…QC-10 见 02，覆盖 INV/PB 要求。验收报告逐项记录命令、环境、数据、真实输出和 traceId；设计文档不预填“全绿”。

## 7. 发布退出条件

- OpenAPI/生成客户端/前后端字段与权限目录一致。
- 全部 AC/QC 必验场景通过，含真实数据库并发与故障注入，不只 mock。
- 三方数量核对：开放 SN 周期、余额、流水回放一致；池数量单独核对。
- 独立部署不启动商城上下文，旧写已被禁止，关键任务有实际运行证据。
- 有可执行恢复方案和试运行记录；未处理迁移异常不得自动豁免。
