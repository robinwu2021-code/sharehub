# 独立进销存：前端作业与权限

> 状态：开发设计草案（未实施） · 2026-10-29
> 已确认边界：仓内库存、进出库、盘点；出库后不跟踪业务库存；通过出库池交接；独立部署并提供 API。其余具体规则为本轮建议设计。

## 1. 界面分类

| 库存作业端 | 内容 |
|---|---|
| 总览/余额 | 仓内实存、可用、占用、待检/不合格/冻结；池数量独立展示 |
| 仓内 SN | 仓、物料、SN、当前周期、质检、冻结原因与历史单据 |
| 入库/退仓 | 草稿、SN 扫码、重复/未知提示、实际接收确认、自动质检任务 |
| 出库 | 来源仓→用途→目标站点/人员→SN 明细→预览→实物出库确认 |
| 质检 | 待检队列、逐项采集、检测进度、证据、失败原因、复检、模板版本 |
| 出库池 | AVAILABLE/CLAIMED/RETURNED/REVOKED，来源单/目标/领取业务引用；不提供修改实时位置按钮 |
| 盘点 | 冻结提示、账面快照、连续扫码、差异、复核、过账及取消 |
| 配置/审计 | 仓库、物料、外部对象、质检模板、凭证与命令异常 |

业务端另有：按已授权站点/接收人筛设备的选择器；业务领取进度与重试入口；安装/撤机/退仓关联；已出库待安装列表。列表查询成功不代表领取成功，提交后必须显示服务确认结果。独立库存页面可作为链接跳转，业务操作经各宿主 BFF，不暴露服务密钥。

## 2. 交互要求

- 过账、领取、复检、豁免、纠正必须是明确动作，不能把状态下拉塞入编辑表单。
- 出库池名称使用“待业务领取/已关联”，不称“可用库存/安装完成”。
- SN 签收/扫描默认空集合，从真实扫描逐件加入，不默认全部已收；重复扫描不加数。
- 展示待检仍计实存的原因；总览可用量与发货规则一致。
- 出库确认展示来源、用途、目的地、接收人、SN 数、质检/冻结提示。
- 盘点范围冻结前展示待处理预留等阻塞项；不静默取消其它业务预留。
- 错误显示冲突件、原因、可执行下一步；网络超时显示“处理中，可查询结果”，不鼓励换请求重复提交。
- 新前端继承宿主设计规范、三语及 RTL 约定；不在本方案另起颜色/排版体系。

## 3. 新权限（拟议，实施时登记）

| 权限 | 能力 |
|---|---|
| inventory:stock:read | 仓内查询 |
| inventory:inbound:write / :post | 入库制单/确认实收 |
| inventory:outbound:write / :post | 出库制单/确认出库 |
| inventory:dispatch:read / :claim / :release | 池查询/业务领取/受控补偿 |
| inventory:qc:inspect / :execute / :review | 人工检测/机器结果提交/质检复核 |
| inventory:qc:template / :exempt | 模板管理/例外豁免 |
| inventory:count:write / :review / :post | 盘点录入/复核/调整过账 |
| inventory:correction:approve | 已过账纠正 |
| inventory:return:clear | 仅原业务系统确认回仓业务关联已解除 |
| inventory:reservation:write / inventory:sale:commit / inventory:sale:return | 商城预留/销售确认/实物退货；人工仓管不可任意制造 SALE |
| inventory:transfer:write / :post / :review | 数量仓间调拨制单/确认搬运/差异复核 |
| inventory:master:write / inventory:audit:read | 主数据管理/审计查询 |

以上是独立库存服务权限提案，不宣称已存在于 powerbank 权限真源。宿主现有 `device:inventory:*` 到独立 scopes 的映射必须先更新功能权限清单、后端目录、前端契约；不能给 OPS 笼统全权限以便接通。

## 4. 权限与人员

服务端每次校验功能权限、业主、仓库、目标系统和调用来源。盘点录入者不能复核自己；豁免/重大损失审批人与操作人分离。机器执行器只能写授予自己的任务结果，不能授予自己豁免。人员离职停用影响新操作，不删历史姓名快照。

审计记录 traceId、clientId、实际操作者、资源、请求号、前后状态和原因；记录中的机密凭证与个人信息需脱敏。终端不能靠隐藏按钮代替后端鉴权。
