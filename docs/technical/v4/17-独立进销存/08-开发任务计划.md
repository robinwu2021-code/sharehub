# 独立进销存改造 Implementation Plan

> 状态：开发设计草案（未实施） · 2026-10-29
> 已确认边界：仓内库存、进出库、盘点；出库后不跟踪业务库存；通过出库池交接；独立部署并提供 API。其余具体规则为本轮建议设计。

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 从 ai-shop 提取独立库存服务，交付仓内 SN/质检/出入库/盘点/交接池及两个宿主对接。

**Architecture:** 独立库存库与服务承接库存写权，宿主 BFF/适配层提供业务主数据、设备检测执行和业务关联恢复。Outbox/inbox、幂等命令与单件锁保证跨服务重试可恢复；不承诺跨库原子事务。

**Tech Stack:** Java、Spring、MyBatis、Flyway、现有 neargo 构件、OpenAPI；准确版本由任务 T0 固定；前端沿用现有 React/TypeScript 作业技术体系。

**Spec:** [需求与边界](./00-需求边界与决策.md)、[架构模型](./01-服务架构与数据模型.md)、[质检](./02-质检方案.md)、[API](./03-API与事件契约.md)、[验收](./07-迁移部署与验收.md)。

## Global Constraints

- 出库池是交接凭证，不是虚拟库存。
- 领取不再次扣库存；实物未入仓不增加库存。
- 每 SN 最多一个 OPEN 周期，每池最多一个有效业务关联。
- quantity 与 SERIAL 并存；不得强制商城 SKU 录入 SN。
- 质检最终放行在库存，现场验收在业务；所有修改可审计。
- API 前缀 `/api/inventory/v1`，单次命令最多 200 SN，批量领取全成全败。
- 新权限先登记；旧表不得与新服务并行成为库存权威；迁移号不预占。
- 下述新文件为建议目标；执行前核对重名、在途改动与父 POM，不覆盖其它会话代码。

## Review Focus

- 请求已成功但回包丢失：重试原键返回原结果。
- 退仓新周期被旧质检/旧事件污染：周期与版本绑定拒绝旧结果。
- 已领取设备被原单作废加回库存：用途分流和纠正前置必须拦住。
- 冻结盘点遗漏预留或旧写路径：所有命令统一冻结守卫，活跃预留拒绝开盘。
- 多系统同编号与人员越权：目标命名空间、凭证范围、BFF 权限同时检查。
