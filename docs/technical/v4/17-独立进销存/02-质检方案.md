# 独立进销存：质检归属与实现方案

> 状态：开发设计草案（未实施） · 2026-10-29
> 已确认边界：仓内库存、进出库、盘点；出库后不跟踪业务库存；通过出库池交接；独立部署并提供 API。其余具体规则为本轮建议设计。

## 1. 决策

仓内质检放库存：库存决定某个仓内设备能否出库，就必须拥有可审计的最终放行依据。业务系统负责设备检测执行和出库后的安装验收。不能只让库存调用“业务设备正常”布尔值，更不能让浏览器直接上传一个 PASSED 放行。

| 职责 | 库存服务 | 业务/设备系统 |
|---|---|---|
| 质检模板版本、必检项、阈值 | 保存并冻结执行版本 | 提供设备专项模板建议，授权人员发布 |
| 收货外观、配件、人工项 | 仓管执行并记录 | 可提供参考信息 |
| 开机、槽位、通信、电量、循环检测 | 创建任务、校验结果、保存证据、计算结论 | 检测适配器执行，回传测量结果和原始证据 |
| 仓内最终 PASSED/FAILED | 唯一权威，控制可用性 | 查询、同步展示 |
| 安装试借还、现场联网、计费门禁 | 不参与 | 独立任务、独立结论 |

业务专属检测项不写死在通用库存核心：使用版本化检查项（BOOLEAN/NUMBER/ENUM/TEXT/EVIDENCE）＋受限规则（必填、上下限、枚举允许值）。不引入任意脚本执行引擎。

## 2. 入库与库存关系

实物核验入库后 onHand+1；待检 unavailable+1；PASSED 或经授权 EXEMPT 后，只有不存在其它 hold 才退出 unavailable。每件最多计一次不可用，多种冻结原因不重复加数。FAILED 仍在仓，不能出库；退供应商/报损是专用处置出库，允许不合格但需原因及相应权限，不得生成正常领用池。

初次建档、退仓、仓内维修后默认要求新质检；普通数量 SKU 默认不要求。物料配置 `qcPolicy=REQUIRED/NONE`，SN 设备新建默认 REQUIRED。存量未知质检不能自动转 PASSED；迁移可创建有批次、操作者和原因的 EXEMPT，页面必须显示“豁免”而不是“合格”。

## 3. 模型

| 对象 | 字段与规则 |
|---|---|
| 模板 | templateId,version,status(DRAFT/PUBLISHED/RETIRED),适用物料,检查项,单位,阈值,有效期策略 |
| 任务 | taskNo,episodeId,templateId/version,roundNo,state(OPEN/RUNNING/COMPLETED/CANCELLED),executorSystem |
| 结果项 | taskNo,checkCode,value,unit,evidenceRefs,measuredAt,receivedAt,executor,sourceEventId |
| 最终结论 | taskNo,result(PASSED/FAILED),ruleEvaluation,reviewer,completedAt |
| 当前放行引用 | episodeId,qcStatus,qcRevision,currentTaskNo,validUntil,holdReason |
| 审计 | 创建、采集、重试、复核、撤销放行、豁免及修订历史 |

模板发布后不可修改；新阈值发布新版本。任务开出时冻结模板与版本。新政策是否使旧合格失效必须走显式批量重检，不隐式改历史结论。

## 4. 执行流程

1. 入库提交后同事务创建 OPEN 质检任务，SN 为 PENDING。
2. 仓管录人工检查；需要设备检测的任务通过持久化检测命令交给授权 executorSystem。
3. 业务适配器根据 SN 触发真实检测，回传任务号、检查码、测量值、单位、时间、证据引用及来源事件 ID。
4. 库存验证任务绑定、当前周期、模板版本、授权执行器、采样有效期；检查项缺失则任务不能完成。
5. 库存按冻结规则计算结论；任何必检项失败不可通过。人工可附理由判失败，不可覆盖机器必检失败为通过。
6. 更新 qcRevision 和不可用数量，写结论/事件；发货事务必须再次验证当前 revision、有效期和冻结状态。

示例设备模板：机柜开机/槽位/配件，充电宝电量/循环。powerbank 现有实现默认电量至少 60、循环最多 500，仅作为迁移基线；生产阈值需从当前配置读取后生成模板，不能在新代码复制常量。

## 5. 复检、过期与例外

- FAILED→重新送检创建新 round，不覆盖旧结果；新一轮开始立刻使旧放行失效并回 PENDING。
- 已出库设备的迟到结果仅保留审计，不得更改 CLOSED 周期或新回仓周期。
- 同 task/check/sourceEventId 重投幂等，内容不同返回冲突；同检查项重测保留版本和最新有效采样引用。
- validUntil 到期后立即不可出库，即使定时器未更新汇总，发货仍以时间强校验；过期任务对汇总不可用量做幂等修正。汇总读也按有效期计算，防出现“显示可用但实际过期”。
- 豁免权限与常规质检分离，必须填原因、适用期限、批准人。涉及安全必检的模板默认禁止豁免；迁移免检必须单独授权并可追溯。
- 仓内发现故障：先冻结设备并清理预留冲突，再维修/复检。库存仅记录处置，不建设维修工单引擎。

## 6. 与现有 powerbank 质检迁移

现有 `QcServiceImpl` 的在库限制、检查规则和 `dev_qc_record` 是迁移来源。切换后旧写接口改为 BFF 转发或返回迁移提示，不能一边写 dev_qc_record 一边写库存独立质检。

`qcStatus` 在业务库只作为带库存版本号/时间的只读投影，放行决策查询库存；已有现场上线门禁仍可读取历史出库质检证据，但现场试借还不能被仓内 PASS 替代。无需把 powerbank 全部质检删除，迁移的是仓内部分。

## 7. 必验用例

QC-01 入库待检计实存不可出；QC-02 缺任一必检项拒绝完成；QC-03 阈值失败不能手改通过；QC-04 模板发布新版本不改变旧结论；QC-05 重新送检使旧合格失效；QC-06 发货与撤销合格并发最多一个顺序成立；QC-07 回仓后旧任务回调不放行新周期；QC-08 过期即拦出库；QC-09 普通 quantity SKU 不受 SN 模板影响；QC-10 退不合格设备给供应商有独立权限且无领用池。

## 8. 检测命令交付与超时

首版执行器拉取并领取任务：查询分配给自身 executorSystem 的 OPEN/到期可重试任务，调用 acquire 获得 executionId、单调递增 fenceToken 和 leaseUntil。默认租约 5 分钟，每分钟 heartbeat，最长检测 30 分钟，均可按模板配置。提交 results/complete 必须带当前 fenceToken；租约过期或旧 token 不能写新结果。设备指令也使用 taskNo＋checkCode＋attempt 的幂等引用，避免执行器重试重复触发有副作用指令。

最多自动重试 3 次；超限进入人工处理，任务保持未完成、设备 PENDING，不伪造 FAILED 或 PASSED。仓管可取消并新建 round，保留旧记录。任务创建写 QcTaskReady 事件作提示，但拉取队列为恢复依据；事件丢失不丢检测任务。没有业务执行器的人工模板直接由仓管执行，不要求机器 acquire。
