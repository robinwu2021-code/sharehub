## 一、状态机（`neargo-statemachine`）

### 1.1 定义

```java
enum WoStatus { CREATED, DISPATCHED, ACCEPTED, PROCESSING, DONE, AUDITED, CLOSED }
enum WoEvent  { DISPATCH, ACCEPT, PROCESS, COMPLETE, AUDIT, CLOSE, REJECT, REWORK, WITHDRAW, MERGE }

static final StateMachine<WoStatus, WoEvent> WO = StateMachine.builder(WoStatus.class, WoEvent.class)
    .edge(DISPATCH, CREATED, DISPATCHED)
    .edge(ACCEPT,   DISPATCHED, ACCEPTED)
    .edge(PROCESS,  ACCEPTED, PROCESSING)
    .edge(COMPLETE, PROCESSING, DONE)
    .edge(AUDIT,    DONE, AUDITED)
    .edge(CLOSE,    AUDITED, CLOSED)
    .edge(REJECT,   Set.of(DISPATCHED, ACCEPTED, PROCESSING), CREATED)
    .edge(REWORK,   DONE, PROCESSING)
    .edge(WITHDRAW, Set.of(CREATED, DISPATCHED), CLOSED)
    .edge(MERGE,    Set.of(CREATED, DISPATCHED, ACCEPTED, PROCESSING), CLOSED)
    .role(CREATED, StateRole.INITIAL)
    .role(Set.of(DISPATCHED, ACCEPTED, PROCESSING), StateRole.ACTIVE)
    .role(DONE, StateRole.AWAITING_VERIFY)
    .build();   // 构建期完成全部校验（§1.3）
```

### 1.2 接口

| 方法 | 语义 | 失败 |
|---|---|---|
| `S next(S from, E event)` | 推进 | `IllegalTransitionException(from, event)`，错误键 `workflow.transition.illegal` |
| `S next(S from, E event, GuardContext ctx)` | 推进并跑守卫 | 守卫拒绝 → `GuardRejectedException(errorKey, args)` |
| `Set<E> events(S from)` | 可走事件 | — |
| `Optional<E> eventFor(S from, S to)` | 反查事件 | 多个事件都能走 → `AmbiguousEventException`（**不随便挑一个**） |
| `boolean isTerminal(S s)` · `Set<S> terminals()` | 无出边即终态 | — |
| `StateRole roleOf(S s)` | 角色；终态自动为 `TERMINAL` | — |
| `Map<S, Set<S>> projection()` | 投影成「起 → 止集合」，兼容 ai-shop / ai-erp 旧调用点 | — |
| `Graph graph()` | 可序列化为 JSON：`{states, events, edges:[{event, from, to, guarded}], roles, terminals}` | — |

守卫：

```java
.edge(APPROVE, PENDING, APPROVED).guard(ctx ->
    ctx.actor().equals(ctx.attr("submittedBy")) ? Guard.reject("workflow.approval.self_review") : Guard.pass())
```

### 1.3 构建期校验（启动即失败，SM-08）

| 校验 | 例 |
|---|---|
| 有且只有一个 `INITIAL` | 没标或标了两个 |
| 每个状态都从 `INITIAL` 可达 | 孤立状态 |
| 每个事件至少一条边 | 定义了没用的事件 |
| 同一 `(event, from)` 不得指向两个 `to` | 歧义 |
| 手工把非终态标成 `TERMINAL`、或给有出边的状态标 `TERMINAL` | ai-shop 售后 `REJECTED` 就会在这里被拦下 |

### 1.4 条件更新与流转日志（`neargo-workflow-store`）

只用状态机时，对**业务表自己的状态列**做条件更新：

```java
S to = transitions.fire(
    WO,                                          // 状态机
    Target.of("wo_order", "wo_no", woNo, "status"),   // 表、键列、键值、状态列（标识符按白名单正则校验）
    expectedFrom,                                // 调用方读到的原状态
    WoEvent.DISPATCH,
    Meta.of(reason).payload(Map.of("assignee", a)));
// 执行：UPDATE wo_order SET status=?, updated_at=? WHERE wo_no=? AND status=?   → 0 行抛 StateChangedException（409）
// 同一事务内写 wf_transition_log 一行
```

| 规则 | 说明 |
|---|---|
| 表名 / 列名只能来自代码 | 用 `^[a-z_][a-z0-9_]{0,63}$` 校验，不接受请求参数 |
| 附加条件 | `Target.and("step", "OPS")` → `AND step = ?`（合同「按原状态 + 原环节」即此） |
| 同时改别的列 | `Meta.set("dispatched_at", now)`；**不接受**状态列、租户列、审计列 |

## 二、审批（`neargo-approval`）

### 2.1 流程定义

```java
@Bean
ApprovalFlow locContractFlow() {
    return ApprovalFlow.code("LOC_CONTRACT")
        .step("OPS")
            .approvers(Approvers.byPermission("location:contract:approve"))
            .mode(Mode.ANY)
        .step("FINANCE")
            .when(subject -> subject.attr("needsCosign", Boolean.class))   // 条件步（AP-02）
            .approvers(Approvers.byPermission("finance:contract:cosign"))
            .mode(Mode.ANY)
        .rules(Rules.defaults())      // 四条内建规则（AP-06），可逐条关
        .build();
}

@Bean
ApprovalFlow merchantQualificationFlow() {          // ichain 队列形态
    return ApprovalFlow.code("MERCHANT_QUALIFICATION")
        .step("REVIEW").approvers(Approvers.queue("audit-queue-qualified")).claimTimeout(Duration.ofMinutes(30))
        .build();
}
```

### 2.2 接口

| 方法 | 语义 | 规则 |
|---|---|---|
| `submit(flowCode, subject, evidence, note)` | 提交；按条件算出本轮步骤；建第一步的任务 | 同一对象已有 `PENDING` 审批 → 冲突 |
| `decide(approvalNo, APPROVE / REJECT, reason)` | 当前步决定 | 驳回必填原因；提交人不能审自己；队列任务必须先领取且只能领取人决定 |
| `withdraw(approvalNo, reason)` | 撤回 | 只有提交人、只在 `PENDING` |
| `resubmit(approvalNo, note)` | 驳回 / 撤回后再提交 | 轮次 +1；**旧轮次的任务与决定原样保留** |
| `claim(taskNo)` · `release(taskNo)` | 队列领取 / 放回 | 已被他人领取 → 冲突 |
| `myTasks(query)` | 待我审批 | 按审批人解析 + 队列成员 + 数据范围 |
| `detail(approvalNo)` | 含全部轮次、每步每人的决定 | — |
| `current(subjectType, subjectNo)` | 对象当前审批 | — |

### 2.3 与业务域的衔接（**同一事务**）

```java
@Component
class ContractApprovalOutcome implements ApprovalOutcomeHandler {
    public String flowCode() { return "LOC_CONTRACT"; }

    // 在审批最后一步决定的**同一事务内**同步调用 —— 抛异常则审批决定一起回滚
    public void onCompleted(ApprovalOutcome o) {
        switch (o.result()) {
            case APPROVED  -> contracts.markSigned(o.subjectNo());
            case REJECTED  -> contracts.markRejected(o.subjectNo(), o.reason());
            case WITHDRAWN -> contracts.markDraft(o.subjectNo());
        }
    }
}
```

| 时机 | 机制 | 用途 |
|---|---|---|
| 事务内 | `ApprovalOutcomeHandler.onCompleted` | **推进业务状态**。放在事务外会出现「审批已通过、合同还在待审」 |
| 提交后 | `ApprovalCompletedEvent`（Spring 事件 + `AfterCommit`） | 通知、统计、跨域联动 |

### 2.4 审批人解析

| 解析器 | 返回 | 用在 |
|---|---|---|
| `Approvers.byPermission(code)` | 由项目 SPI `PermissionDirectory` 反查持有该权限的人；**待办查询时按当前用户是否持有该权限过滤**，不预先展开成人 | powerbank |
| `Approvers.byRole(roleCode)` | 同上，按角色 | ai-shop 平台运营 |
| `Approvers.users(Function<Subject, Set<String>>)` | 指定人 | 对象负责人 |
| `Approvers.queue(queueCode)` | 队列；成员由 SPI `QueueMembership` 判定 | ichain、ai-shop 商品审核 |

按权限 / 角色的任务**不写入具体人**：人员变动（离职、调岗）无需迁移任务；「待我审批」在查询时实时判定。

## 三、工单（`neargo-case`）

### 3.1 类型登记

```java
@Bean
CaseType powerbankMaintenance() {
    return CaseType.code("PB_MAINTENANCE")
        .machine(WO)                                     // 1.1 的状态机
        .noPrefix("WO")
        .assigneeTypes("EMPLOYEE", "AGENT")
        .dispatch(DispatchStrategy.MANUAL)               // 或 POOL，或项目 Bean
        .slaGroup("PB_WO")                               // wf_sla_rule 里的规则组
        .scope(anchors -> anchors                        // 数据范围锚点：开单时由对象算出（快照语义）
            .slot(1, "SITE",  subject -> sites.siteOf(subject))
            .slot(2, "AGENT", subject -> sites.agentOf(subject)))
        .build();
}
```

### 3.2 接口

| 方法 | 语义 |
|---|---|
| `open(OpenCommand)` | 开单：`typeCode · source · sourceRef · subject · priority · title · description · ext · assignee?` |
| `openOrAttach(OpenCommand)` | 带 `dedupeKey`：同键已有未结单则附加一条时间线并返回该单 |
| `fire(caseNo, eventCode, ActionCommand)` | **所有状态动作的唯一入口**；`eventCode` 按该类型状态机解析 |
| `assign(caseNo, assignee, reason)` · `pool(caseNo)` · `grab(caseNo)` | 派单 / 放池 / 抢单 |
| `escalate(caseNo, assignee, reason)` | 升级 / 接管 |
| `merge(fromCaseNo, intoCaseNo, reason)` | 合并；被并单以 `MERGED` 关闭原因关 |
| `note(caseNo, text, mediaIds)` | 备注与附件 |
| `setPriority(caseNo, priority, reason)` | 改优先级，SLA 重算 |
| `reassignFrom(assignee, reason)` | 受理方不可用时批量改派；返回改派数 |
| `sweepSla(batchSize)` | SLA 扫描一批；返回处理数（给项目的定时任务调用） |
| `page(CaseQuery)` · `detail(caseNo)` · `summary(query)` | 查询；**全部按数据范围过滤** |

### 3.3 SLA 计算

| 项 | 规则 |
|---|---|
| 时限来源 | `wf_sla_rule(group, type_code, priority)`：`respond_minutes` · `resolve_minutes` · `business_hours_only` |
| 起算 | 首次进入 `ACTIVE` 角色 |
| 暂停 | 进入 `WAITING_EXTERNAL` 记暂停起点；离开时把暂停时长累加到 `sla_paused_ms`，顺延 `sla_due_at` |
| 营业时间 | `business_hours_only = 1` 时由 SPI `BusinessCalendar` 算；时区取 `neargo.workflow.business-zone` |
| 超时 | 扫描把 `sla_state` 从 `ON_TRACK` 置 `BREACHED`，写时间线，提交后发 `CaseSlaBreachedEvent` |
| 停表 | 进入 `TERMINAL` |
| 改优先级 | 按新规则从起算点重算（已暂停时长照扣） |

## 四、SPI 汇总

| SPI | 谁实现 | 必需 | 缺省 | 说明 |
|---|---|:-:|---|---|
| `ActorProvider` | 项目 | ✓ | — | 当前操作人 `(type, no, name)`；定时任务里返回 `SYSTEM` |
| `TenantProvider` | 项目 | — | 无租户 | 当前租户键 |
| `PermissionChecker` | 项目 | — | 放行 | 此人能否对此对象发此事件 |
| `PermissionDirectory` | 项目 | 用 `byPermission` 时 ✓ | — | 当前用户是否持有某权限 / 角色 |
| `QueueMembership` | 项目 | 用队列时 ✓ | — | 当前用户属于哪些队列 |
| `ScopeFilter` | 项目 | 配了数据范围时 ✓ | 不过滤 | 把当前用户的数据范围翻成对锚点列的条件；**未命中即不可见** |
| `AssigneeDirectory` | 项目 | 用工单时 ✓ | — | 受理方名字、是否可用 |
| `DispatchStrategy` | 项目（可选） | — | `MANUAL` | 自定义派单规则 |
| `BusinessCalendar` | 项目（可选） | — | 7×24 | 营业时间 |
| `BizNoGenerator` | 项目（可选） | — | 前缀 + 雪花 | 业务号 |
| `ApprovalOutcomeHandler` | 项目 | 用审批时 ✓ | — | 事务内推进业务状态（§2.3） |
| `CaseTransitionHandler` | 项目（可选） | — | — | 工单迁移时事务内联动（如完工回写设备状态） |
| `MediaReferenceSink` | 项目（可选） | — | — | 装了 `neargo-media` 时登记附件引用 |

每个 SPI 在 `neargo-workflow-test` 里有对应 TCK，项目实现后跑一遍即知是否合约。

## 五、数据模型

### 5.1 约定

| 项 | 约定 | 理由 |
|---|---|---|
| 时间 | **`BIGINT` 毫秒（UTC）** | 不受 JDBC 连接时区影响；MySQL / PostgreSQL / H2 同一类型。ai-shop `ord_status_log.at` 已是这种写法；powerbank 已为「三个时区」付过代价 |
| 租户列 | 列名取 Flyway 占位 `${tenantColumn}`（缺省 `tenant_id`），**建表前**可改；始终存在、可空 | powerbank 等项目有「每张表都要有租户列」的卡口；没有租户的项目留空即可 |
| JSON | MySQL `JSON` / PostgreSQL `JSONB` | — |
| 主键 | 自增 `id` + 业务号唯一键 | — |
| 乐观锁 | `version INT` | — |
| 软删除 | 不做 | 流程数据不删；关闭即终态 |

### 5.3 PostgreSQL 差异

| MySQL | PostgreSQL |
|---|---|
| `BIGINT AUTO_INCREMENT PRIMARY KEY` | `BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY` |
| `JSON` | `JSONB` |
| `TINYINT` | `SMALLINT` |
| `TEXT` | `TEXT` |
| 表内 `KEY idx (…)` / `UNIQUE KEY uk (…)` | 表外 `CREATE INDEX` / `CREATE UNIQUE INDEX` |
| `case` 是保留字 | 同样是保留字 —— 两边都靠缺省前缀 `wf_` 变成 `wf_case`，所以**前缀不允许配成空**（启动时校验） |

脚本位置：`classpath:db/neargo/workflow/{vendor}/`（`mysql` · `postgresql` · `h2`），由 Flyway 按数据源自动选择。

## 七、错误键

| 键 | HTTP | 含义 |
|---|:-:|---|
| `workflow.transition.illegal` | 409 | 当前状态不能走这个事件 |
