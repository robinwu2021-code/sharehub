## 一、一页结论

| 问题 | 结论 |
|---|---|
| 形态 | **同域、按路径分区**：运营台在 `/`，流程与工单平台（`flow-console`）在 `/flow/`；各自仓库、各自构建、各自发布；nginx 按前缀分流 |
| 为什么是这个 | 用户定的目标是「各自开发、集成到一起」，不要求同屏组合与跨栈嵌入；在这个目标下它最简单，且不引入任何运行时框架（对比见 [19](../19-前端模块化-业界方案调研.md)） |
| 看起来是一个产品 | 靠两个共享包：**`@neargo/ops-shell`**（外壳、会话、主题、语言）与 **`@neargo/ops-ui`**（设计 token + 基础组件），都从 ops-web 抽出 |
| 登录 | 只在运营台；同源，登录一次两区通用；无需跨域 SSO |
| 技术栈 | 与 ops-web 同模板：Next 16 静态导出 · React 19 · Tailwind 4 · Radix · TanStack Query/Table · zustand |
| 视觉 | 布局与组件照 ops-web；原型的可取之处落为 `teal` 皮肤 + 六个通用组件 |

## 二、与后端的边界

前端**不定义**接口、权限判定与数据范围；这些在 21。前端对后端只有下面这些**要求**，由 21 落实：

| # | 前端需要 | 21 中的对应 | 状态 |
|:-:|---|---|---|
| R1 | 页面接口走**界面面** `/api/flow/ui/v1/**`，同源经 nginx 反代 | 21/02「界面面」 | ✅ 已在 21 |
| R2 | 服务从**宿主令牌**解析操作人与权限，不要前端传操作人、数据范围 | 21 README K4 | ✅ 已在 21（JWT 或内省二选一；ShareHub 令牌是不透明的 `stk_`+UUID，只能内省） |
| R3 | 带业务前置校验的动作由页面直接调**宿主后端**（同源 `/api/**`） | 21 README C5 | ✅ 已在 21 |
| R4 | 列表的每个筛选控件都有对应的查询参数（不做「取一页再页内过滤」） | 14 §一 | 需 21/06 继承 |
| R5 | 统计卡的数字附带可回填的查询参数；工单详情出参带 `actions` | 14 §2.3 | 需 21/06 继承 |
| R6 | 出 `openapi.yaml` 并入库，前端类型从它生成 | 21 README 技术栈（springdoc） | 需 21/06 明确路径 |
| R7 | 宿主登出后，下一次请求即返回 401 | 内省缓存时长决定 | 需 21 给出缓存上限 |
