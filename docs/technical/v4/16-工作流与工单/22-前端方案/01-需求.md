# 01 · 前端需求

> 所属：[22 前端方案](./README.md)。产品功能（用户故事与验收）以 [12 PRD](../12-产品需求.md) 为准，本篇只写**前端工程**要满足的需求。

## 一、目标

| # | 目标 | 来源 |
|:-:|---|---|
| G1 | **各自开发、各自发布**：流程与工单平台的前端与运营台互不阻塞，一方发版不需要另一方重新构建 | 用户定 |
| G2 | **集成到一起**：用户在同一个域名、同一个外壳里使用，感觉是一个产品 | 用户定 |
| G3 | 布局照 ops-web，原型的配色与组件取其可取之处 | 用户定（15 §〇） |
| G4 | 权限统一：菜单、按钮与服务端判定用同一套权限码 | 用户定 |

不做：同屏组合（一个页面里拼两个系统的块）、跨技术栈嵌入、iframe、运行时微前端框架。需要时按 [19](../19-前端模块化-业界方案调研.md) 再引入，与本方案不冲突。

## 二、区与页面

| 区 | 前缀 | 页面 |
|---|---|---|
| 运营台（宿主） | `/` | 既有 33 个页面；登录、首页、个人设置；菜单（含指向 `/flow/` 的叶子） |
| 流程与工单 | `/flow/` | PRD 九页：P1 待办中心 · P2a 审批列表 · P2 审批详情 · P3 审核队列 · P4 工单工作台 · P5 工单详情 · P5a 流程配置 · P6 运营配置 · P7 接入管理 |

页面与接口、表的对应以 [14](../14-数据库与API定稿.md) §一为准；接口的最终形态以 21/06 为准。

## 三、功能性需求（工程侧）

| # | 需求 | 验收 |
|:-:|---|---|
| FE-1 | 两区外壳（顶栏、Rail、二级菜单、主题、语言、操作人切换）**逐像素一致** | 同一视口下两区截图的外壳区域零差异 |
| FE-2 | 菜单是同一棵：在 flow 区看到的菜单与在运营台看到的完全相同，并按同一份 `perms` 过滤 | 自动比对 |
| FE-3 | 跨区跳转不丢上下文：深链可复制、刷新、分享；浏览器前进后退正常 | 用例覆盖 |
| FE-4 | 登录一次两区通用；任一区遇到 401 跳运营台登录页，**登录后回到原页** | 用例覆盖（现状缺 `next` 参数，见 07 Z5） |
| FE-5 | 主题与语言在任一区切换，另一区打开即生效 | 用例覆盖 |
| FE-6 | 每个列表筛选控件都对应一个查询参数；统计卡可点，点后列表口径与卡片数字一致 | 与 14 §一、§2.3 对照 |
| FE-7 | 按钮按权限码显示；无权限时给解释性提示（`<ReadOnlyNotice>`），不是静默隐藏整页 | 棘轮基线不上升 |
| FE-8 | flow 区可以脱离后端用 mock 独立开发，mock 强制状态机、非法迁移抛错 | 与 ops-web 既有 mock 纪律一致 |

## 四、非功能需求

| # | 需求 | 指标 |
|:-:|---|---|
| NF-1 | 三语（zh / en / ar）与 RTL | 与 ops-web 同一套 i18n；阿语下布局镜像正确 |
| NF-2 | 设计规范硬约束 | `design-tokens.test.ts` 同样跑在 flow-console 与两个共享包上：五档圆角、不写死颜色、类型阶不与 `font-*`/`leading-*` 共存 |
| NF-3 | 跨区切换耗时 | 跨区整页加载，入口资源预取后首屏 ≤ 1.5s（本机生产构建测量） |
| NF-4 | 浏览器 | 与 ops-web 相同 |
| NF-5 | 发布独立 | 两区流水线、产物目录互不覆盖；共享包版本不一致时发布前卡口拦截 |
| NF-6 | 可访问性 | 与设计规范 §可访问性一致（焦点、对比度、键盘） |

## 五、验收总表

| 场景 | 通过标准 |
|---|---|
| 各自开发 | 只改 flow-console 并发布，运营台零构建、零部署，线上即生效 |
| 集成 | 从运营台菜单进入 `/flow/` 任一页，外壳不变、登录态不丢、主题语言一致 |
| 权限 | 同一员工在两区看到的菜单一致；去掉某权限码后，两区的对应菜单与按钮同时消失，服务端同时拒绝 |
| 登出 | 在运营台登出后，flow 区下一次请求即跳登录页 |
