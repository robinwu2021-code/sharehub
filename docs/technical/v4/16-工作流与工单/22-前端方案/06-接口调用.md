# 06 · 前端接口调用

> 所属：[22 前端方案](./README.md)。接口本身（路径、报文、错误键）以 **21/06 接口设计** 为准；本篇只讲前端**怎么调**。

## 一、调谁

| 目标 | 路径 | 什么时候 |
|---|---|---|
| flow 服务 · **界面面** | 同源 `/api/flow/ui/v1/**` | 页面的查询与不带业务前置校验的动作 |
| 宿主后端 | 同源 `/api/**` | 带业务前置校验的动作（21 C5）、菜单 `/api/auth/menus` |

两者都同源，没有 CORS；都带宿主令牌（`ops-shell` 提供）。**请求体里不带操作人、不带数据范围**（21 K4）。

## 二、客户端

| 项 | 做法 |
|---|---|
| 唯一入口 | `lib/api/client.ts`：拼路径、带令牌与 `Accept-Language`、统一错误处理；页面不直接 `fetch` |
| 类型 | 由 flow-svc 入库的 `openapi.yaml` 生成到 `lib/api/generated/`，不手改；生成工具在 C1 任务时选定并核版本 |
| 响应格式 | 以 21/06 的通用约定为准。ops-web 现在按 `Result{code,message,data}` 拆包；若 flow 界面面的约定不同，差异只收在 `client.ts` 一处 |
| 查询 | 列表用 TanStack Query；每个筛选控件对应一个查询参数，参数进 URL（深链可复现） |
| 统计卡 | 点击时把出参里的 `queryParams` 原样回填给列表查询，前端不自己拼 |
| 动作条 | 渲染出参 `actions`，不在前端维护状态迁移表 |

## 三、错误与会话

| 响应 | 前端处理 |
|---|---|
| 401 | `ops-shell` 统一处理：跳 `/login?next=<当前完整路径>` |
| 403 | 页面显示 `<ReadOnlyNotice>` 并说明缺哪个权限，不是空白 |
| 409（并发冲突 / 状态已变） | 提示「内容已被他人更新」，提供一键刷新；不自动重试 |
| 422（流程定义校验失败） | 按 `errors[].path` 把错误挂到对应表单字段（14 §2.2 的形态） |
| 错误键 | 按 21/06 的错误键表映射三语文案；服务端已本地化的 `message` 优先 |
| 网络失败 | 统一「网络异常」提示，列表保留上次数据 |

## 四、mock

| 项 | 做法 |
|---|---|
| 位置 | `lib/api/mock/`，实现与生成类型相同的接口 |
| 切换 | `lib/api-mode.ts`，同 ops-web 写法 |
| 纪律 | mock 必须真改内存库（重开能读回）；**状态机在 mock 层强制、非法迁移抛错** —— 与 ops-web 既有约定一致 |
| 一致性 | CI 校验 mock 与生成类型的方法签名一致 |
