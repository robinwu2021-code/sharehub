# 05 · 前端依赖关系

> 所属：[22 前端方案](./README.md)。版本为 2026-09-27 从 ops-web `node_modules` 实测的已安装版本；flow-console 与之对齐。

## 一、包之间

| ↓ 依赖 → | ops-ui | ops-shell | ops-web | flow-console |
|---|:-:|:-:|:-:|:-:|
| **ops-ui** | — | ❌ | ❌ | ❌ |
| **ops-shell** | ✅ | — | ❌ | ❌ |
| **ops-web** | ✅ | ✅ | — | ❌ |
| **flow-console** | ✅ | ✅ | ❌ | — |

两个区之间**没有代码依赖**，只经三样运行时契约交互：URL（`zoneHref`）、同源会话（`ops-shell`）、菜单数据（`/api/auth/menus` 或 `/shell/nav.json`）。

## 三、禁止依赖

| 规则 | 为什么 | 实测现状 |
|---|---|---|
| `ops-ui` 不得 import `next/*` | 让基础组件不绑 Next，Vite 系 React 19 运营台也能用 | `components/ui/` 现有 **0 处** `next/*`，无需改造 |
| `ops-ui` 不得 import 任何宿主模块（`@/lib/api` 等） | 包不能反向依赖宿主 | 现有 1 处：`file-field.tsx` import `@/lib/api`，抽包时改为传入 `upload` |
| `ops-shell` 不得 import 宿主业务模块 | 同上 | 外壳现用 `next/link` 3 处、`next/navigation` 5 处，属允许范围 |
| 区之间不得互相 import | 保证各自发布 | —— |
| 区内不得直接读写会话 / 主题 / 语言的存储 key | 区契约 #3 | —— |
| 区内不得自写外壳 | 区契约 #2 | —— |
