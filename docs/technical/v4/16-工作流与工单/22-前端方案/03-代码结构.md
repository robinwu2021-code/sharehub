# 03 · 前端代码结构

> 所属：[22 前端方案](./README.md)。结构照 ops-web 现有写法（`app/` · `components/` · `lib/`），让两个区的开发者不用重新学一套。

## 一、仓库与包的位置

| 物件 | 放哪 | 为什么 |
|---|---|---|
| `@neargo/ops-ui` · `@neargo/ops-shell` | **powerbank 仓库** `packages/` 下 | 源头就在 ops-web；ops-web 用 pnpm workspace 直接链接，改动即时可见；发私仓给其他区用 |
| `flow-console` | 平台独立仓库 | 与 flow-svc 同版本线，独立发布 |
| ops-web | 不动位置 | 改为依赖两个包 |

## 二、`packages/`

```
packages/
├── ops-ui/                       # 设计 token + 基础组件（不依赖 Next）
│   ├── package.json              # peer: react ^19 · react-dom ^19
│   ├── src/
│   │   ├── tokens.css            # 从 ops-web globals.css 抽出的 token 部分（色阶 · 皮肤 · 类型阶 · 圆角 · 层级）
│   │   ├── components/           # ops-web components/ui 的 41 个组件
│   │   ├── flow/                 # 六个新组件：SlaBar · Timeline · StepFlow · StatCard · RuleToggleGroup · VersionHistory
│   │   ├── i18n/                 # 组件自带文案（zh / en / ar），可被调用方覆盖
│   │   └── index.ts
│   └── test/design-tokens.test.ts   # 与 ops-web 同一套规范卡口
└── ops-shell/                    # 外壳（依赖 Next）
    ├── package.json              # peer: next ^16 · react ^19；deps: @neargo/ops-ui · zustand
    └── src/
        ├── OpsShell.tsx          # 顶栏 · Rail · 二级菜单 · 内容区（来自 components/layout）
        ├── session.ts            # 会话读写 · 401 → /login?next=（来自 lib/auth.ts · lib/api/session.ts）
        ├── menu-source.ts        # 服务端菜单 / nav.json 兜底（来自 lib/menu-source.ts）
        ├── stores/               # theme · locale · nav-prefs（来自 lib/stores）
        ├── zone.ts               # zoneHref() · 判断链接是否在本区
        └── index.ts
```

## 三、`flow-console`

```
flow-console/
├── next.config.ts                # output: "export" · trailingSlash · basePath "/flow"（同 ops-web 写法）
├── app/
│   ├── globals.css               # @import "tailwindcss" · @import ops-ui tokens · 两个包的 @source
│   ├── layout.tsx                # <OpsShell zone="/flow">
│   ├── todo/                     # P1 待办中心
│   ├── approvals/                # P2a 审批列表 · P2 审批详情
│   ├── queues/                   # P3 审核队列
│   ├── work-orders/              # P4 工单工作台 · P5 工单详情
│   ├── definitions/              # P5a 流程配置
│   ├── settings/                 # P6 运营配置
│   └── access/                   # P7 接入管理
├── components/                   # 只放本区业务组件；通用组件一律进 ops-ui
├── lib/
│   ├── api/
│   │   ├── client.ts             # 调界面面的唯一入口（06）
│   │   ├── generated/            # 由 openapi.yaml 生成的类型（不手改）
│   │   └── mock/                 # mock 实现，强制状态机
│   ├── api-mode.ts               # mock / 真接口切换（同 ops-web）
│   └── perms.ts                  # flow:* 权限码常量（码必须先在真源表存在）
└── test/
    ├── zone-contract.test.ts     # 区契约五条的架构测试（02 §四）
    └── design-tokens.test.ts
```

页面路径是**区内路径**（`/todo/`），发布后的完整路径是 `/flow/todo/`。深链格式如 `/flow/work-orders/detail/?no=WO26092701` —— 静态导出下动态段需要枚举，详情页一律用查询参数带编号。

## 四、ops-web 要改的地方

| 处 | 改法 |
|---|---|
| `components/layout/` | 换成 `@neargo/ops-shell` 的 `<OpsShell zone="/">`；原文件删除 |
| `components/ui/` | 换成 `@neargo/ops-ui`；`file-field` 的上传改为传入 `upload` |
| `lib/auth.ts` · `lib/api/session.ts` · `lib/stores/*` · `lib/menu-source.ts` | 改为从 `ops-shell` 导入；`session.ts` 的 401 跳转补 `next` 参数 |
| `app/globals.css` | token 部分改为 import `ops-ui/tokens.css`；为两个包加 `@source` |
| `lib/nav.ts` | 加 `/flow/...` 叶子（放组末尾）；构建脚本额外输出 `out/shell/nav.json` |
| 现有工单界面 `components/workorder/`（9 个文件）· `app/work-orders/` | **暂不动**。flow 的工单上线后按 16 的 P 系列迁移：菜单叶指向 `/flow/work-orders/`，旧页下线 |
