# 04 · UI 与皮肤

> 所属：[22 前端方案](./README.md)。承接 [15](../15-前端方案-独立可嵌入与皮肤.md) §〇 · §二 · §三，此处为准。
> 用户要求：「工单原型的页面颜色风格有可取之处，但整体布局要基于 ops-web，用平台右侧主界面部分的 UI 形成一套皮肤，赋能到 ops-web」。

## 一、做法：主题色 + 风格两条轴（已落地，2026-09-27）

用户定：「重点不是墨青，而是整体的 UI 风格，同样要支持多种颜色」「重点是亮色，以及 table、tab 等相关 UI 的样式」。

| 轴 | 换什么 | 取值 | 默认 |
|---|---|---|---|
| 主题色 `data-theme` | 只换主色 | 墨青 · 黑白灰 · 简电青 · 时尚蓝 · 科幻紫 | 墨青 |
| **风格 `data-style`** | 整体 UI 形态（对齐原型的 12 项组件形态） | **清爽 `clean`** · 经典 `classic` | 清爽 |

风格不带色相，任何风格 × 任何主题色都成立；12 项组件形态、语义色取值、主题色的 AA 修正与实现坑，
全部见 [设计规范 §2.6](../../../设计规范-ShareHub运营台.md)（唯一真源，此处不重复）。

## 二、验证（亮色）

- 逐组件对照原型：表格、tab、统计卡、步骤条、SLA 色条、抽屉、按钮、输入框均对齐。
- 五套主题色各截一张工单列表：形态一致，只有主色变。
- 对比度卡口覆盖每一套主题色；`/dev/ui` 全状态矩阵在清爽风格下正常。
- 已知仍与原型不同：深色侧栏（布局照 ops-web，用户定）、胶囊筛选 chip（否决清单）、徽章字号 12px（下限）。

## 三、六个新组件

全部用 ops-web 现有 token 实现（语义色、12 档灰、五档圆角、七档类型阶），放在 `ops-ui/src/flow/`，两个区都能用：

| 组件 | 来自原型 | 两区之外还能用在 |
|---|---|---|
| `<SlaBar value state>` | 工作台 SLA 四色条（绿 / 黄 / 红 / 灰暂停） | 提现审批时效、合同到期；可替代现有 `components/workorder/sla-remain.tsx` |
| `<Timeline items>` | 工单详情时间线 | 订单事件、合同审批历史、设备生命周期 |
| `<StepFlow steps current>` | 审批进度条（含条件步标记） | 站点五态、合同状态、入驻流程 |
| `<StatCard clickable queryParams>` | 可点统计卡 | 统一「卡片数字 ↔ 列表筛选」口径 |
| `<RuleToggleGroup>` | 流程配置的规则开关（含「不可关」态） | 任何「规则开关 + 说明」配置块 |
| `<VersionHistory>` | 流程配置版本历史 | 价格方案版本等 |

验收：进 `/dev/ui` 组件总览页的全状态矩阵；设计规范卡口全绿。它们也是降低 ops-web 棘轮基线（内联 `Badge tone={}` ≤58、手写「仅可查看」≤17）的载体。

## 四、布局与权限表现

| 项 | 照谁 |
|---|---|
| 外壳 | `ops-shell`，flow 区不自带 |
| 页面骨架 | 列表 `PagedTable`、筛选 chips / 下拉、抽屉 `FormDrawer`（均来自 `ops-ui`） |
| 类型阶 | **不与 `font-*` / `leading-*` 共存**（非 layer 区的 `.txt-*` 永远胜出） |
| 空态 · 只读 · 状态徽章 | 一律 `<ReadOnlyNotice>` · `<StatusBadge>` · 解释性空态文案（棘轮只许降） |

按钮权限码：**已登记进真源表**（[功能权限清单 §16](../../../../requirements/功能权限清单.md)，2026-09-28），
强制方是 OpsKit，ShareHub 只管「谁持有」。角色归属以真源表为准，这里只列码：

| 权限码 | 含义 | 页面 |
|---|---|---|
| `flow:todo:read` | 待办中心 | P1 |
| `flow:approval:read` | 审批 查 | P2a · P2 |
| `flow:approval:decide` | 审批 决定 | P2 |
| `flow:queue:claim` | 审核队列 领取 / 决定 / 放回 | P3 |
| `flow:ticket:read` | 工单 查 | P4 · P5 |
| `flow:ticket:handle` | 工单 办理（接单 / 处理 / 备注 / 撤单 / 抢单） | P1 · P5 |
| `flow:ticket:dispatch` | 派单 / 改派 / 退回抢单池 / 升级 / 批量改派 | P4 · P5 |
| `flow:process:manage` | 流程配置 | P5a |
| `flow:config:manage` | 运营配置 | P6 |
| `flow:access:manage` | 接入管理 | P7 |

命名用 `flow:ticket:*`：ShareHub 旧的 `workorder:*` 模块在迁移期与新工单并存（21/07 P6 双写），名字分开免得混。

工单详情的动作条**不按权限码自行拼**：以服务端出参 `actions` 为准（14 §2.3），前端只负责渲染。
