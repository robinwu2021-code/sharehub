# 04 · UI 与皮肤

> 所属：[22 前端方案](./README.md)。承接 [15](../15-前端方案-独立可嵌入与皮肤.md) §〇 · §二 · §三，此处为准。
> 用户要求：「工单原型的页面颜色风格有可取之处，但整体布局要基于 ops-web，用平台右侧主界面部分的 UI 形成一套皮肤，赋能到 ops-web」。

## 一、做法：皮肤 + 风格两条轴（已落地，2026-09-27）

用户要求「ops-web 基于原型的风格，基于组件库抽出一个对应的风格」。规范原本只有一条轴「皮肤」，而且只换主色；
原型的观感却主要来自带青调的中性色与降饱和的语义色。所以新增第二条轴「风格」，两条轴正交组合：

| 轴 | 换什么 | 原型对应 | 取值 | 默认 |
|---|---|---|---|---|
| 皮肤 `data-theme` | 只换主色 | 墨青 `#0f7173` | 墨青 · 黑白灰 · 简电青 · 时尚蓝 · 科幻紫 | **墨青** |
| **风格 `data-style`** | 整套 Tier 1：12 档中性 + 语义色三档 | 右侧主界面的底色与状态色 | **ink** · classic | **ink** |

规范依据与完整色值见 [设计规范 §2.6](../../../设计规范-ShareHub运营台.md)。组件只消费 Tier 2，所以**组件库一行都不用改**就换了风格。

| 原型要素 | 处理 |
|---|---|
| 墨青主色 | ✅ 皮肤 `teal`，设为默认 |
| 带青调的中性色、降饱和的语义色 | ✅ 风格 `ink`，设为默认 |
| 原型里 3 处过不了 AA 的取值（次要文字 3.00、绿字 4.43、琥珀字 4.16） | ✅ 各压深到达标，锁进 `lib/style-contrast.test.ts` |
| 深色侧栏、卡片描边、胶囊 chip | ❌ 与布局规范或被否决清单冲突，不搬 |
| SLA 条 · 时间线 · 步骤条 · 可点统计卡 · 规则开关组 · 版本历史 | ⏳ 六个组件，见 §三（U2） |

| 文件 | 改动 |

| `lib/stores/style.ts`（新） | 风格 store，持久化 key `ops-style` |
| `lib/stores/theme.ts` | 加 teal，默认改为 teal |

| `app/layout.tsx` | 首帧脚本读 `ops-style`；`<html>` 带默认 `data-theme` / `data-style`，没有存储时首帧也不闪 |

## 三、六个新组件

全部用 ops-web 现有 token 实现（语义色、12 档灰、五档圆角、七档类型阶），放在 `ops-ui/src/flow/`，两个区都能用：

| 组件 | 来自原型 | 两区之外还能用在 |
|---|---|---|
| `<SlaBar value state>` | 工作台 SLA 四色条（绿 / 黄 / 红 / 灰暂停） | 提现审批时效、合同到期；可替代现有 `components/workorder/sla-remain.tsx` |
| `<Timeline items>` | 工单详情时间线 | 订单事件、合同审批历史、设备生命周期 |
| `<StepFlow steps current>` | 审批进度条（含条件步标记） | 站点五态、合同状态、入驻流程 |
| `<StatCard clickable queryParams>` | 可点统计卡 | 统一「卡片数字 ↔ 列表筛选」口径 |
| `<RuleToggleGroup>` | 流程配置的规则开关（含「不可关」态） | 任何「规则开关 + 说明」配置块 |
| `<VersionHistory>` | 流程配置版本历史 | 价格方案版本等 |

验收：进 `/dev/ui` 组件总览页的全状态矩阵；设计规范卡口全绿。它们也是降低 ops-web 棘轮基线（内联 `Badge tone={}` ≤58、手写「仅可查看」≤17）的载体。

## 四、布局与权限表现

| 项 | 照谁 |
|---|---|
| 外壳 | `ops-shell`，flow 区不自带 |
| 页面骨架 | 列表 `PagedTable`、筛选 chips / 下拉、抽屉 `FormDrawer`（均来自 `ops-ui`） |
| 类型阶 | **不与 `font-*` / `leading-*` 共存**（非 layer 区的 `.txt-*` 永远胜出） |
| 空态 · 只读 · 状态徽章 | 一律 `<ReadOnlyNotice>` · `<StatusBadge>` · 解释性空态文案（棘轮只许降） |

按钮权限码（**提案**，须先进 `docs/requirements/功能权限清单.md` 并过 `perm-ssot-align`，才能写进代码）：

| 权限码 | 含义 | 页面 |
|---|---|---|
| `flow:todo:read` | 看自己的待办 | P1 |
| `flow:approval:read` | 查审批单 | P2a · P2 |
| `flow:approval:decide` | 做审批决定 | P2 |
| `flow:queue:claim` | 队列领取与决定 | P3 |
| `flow:workorder:read` | 查工单 | P4 · P5 |
| `flow:workorder:handle` | 办理工单 | P5 |
| `flow:workorder:dispatch` | 派单 / 改派 / 升级 / 合并 / 改优先级 | P4 · P5 |
| `flow:definition:manage` | 流程配置 | P5a |
| `flow:config:manage` | SLA / 日历 / 队列配置 | P6 |
| `flow:access:manage` | 接入管理 | P7 |

工单详情的动作条**不按权限码自行拼**：以服务端出参 `actions` 为准（14 §2.3），前端只负责渲染。
