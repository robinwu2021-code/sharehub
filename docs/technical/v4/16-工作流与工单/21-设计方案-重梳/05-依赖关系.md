## 一、模块间依赖

### 1.1 能力模块之间

| 依赖方 ＼ 被依赖 | commons | platform-api/client | platform-core/store | process-api/client | process-core/store | ticket-* |
|---|:-:|:-:|:-:|:-:|:-:|:-:|
| `commons` | —— | ❌ | ❌ | ❌ | ❌ | ❌ |
| `platform-*` | ✅ | —— | —— | ❌ | ❌ | ❌ |
| `process-*` | ✅ | ✅ | ❌ | —— | —— | ❌ |
| `ticket-*` | ✅ | ✅ | ❌ | ✅ | ❌ | —— |
| `opskit-svc` | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |

| 要点 | 说明 |
|---|---|
| 只经客户端接口 | 上层只见下层的 `*-api` 与 `*-client`；进程内实现类（`Embedded*Client`）在下层 core 里，由 `opskit-svc` 注入 |
| 下层对上层无知 | 平台不知道流程、工单；流程不知道工单 |
| 共享库 | `commons` 只放类型与算法，无表、无 Spring 组件扫描 |

### 1.2 模块内（每个能力模块相同）

| 子模块 | 可依赖 | 禁止 |
|---|---|---|
| `*-api` | `commons`；下层 `*-api` | Spring · Jackson · 任何框架 |
| `*-client` | 本模块 api · `spring-web` | 本模块 core / store |
| `*-core` | 本模块 api / store；下层 api / client · Spring Boot | 下层 core / store |
| `*-store` | 本模块 api（定义类）· `commons.jdbc` · Spring JDBC · Flyway | core；任何 ORM |

## 二、外部依赖（服务端）

### 2.1 基线

| 项 | 版本 | 来源 |
|---|---|---|
| Java | 21 | `neargo-parent`（enforcer 锁死） |
| Spring Boot | 4.0.7 | `neargo-parent` 的 parent |
| Spring Framework | 7.0.x | 随 Boot |
| Jackson | 3.x（`tools.jackson`） | 随 Boot |

### 2.2 按子模块

| 子模块 | 依赖 | 版本 | 用途 |
|---|---|---|---|
| `commons` · `*-api` | **无**（仅 JDK） | —— | —— |
| `*-client` | `spring-web`（`RestClient` · `@HttpExchange`）· `spring-boot-autoconfigure` | 随 Boot | HTTP 客户端 · 自动装配 |
| `*-store` | `spring-jdbc`（`JdbcClient`）· `flyway-core` · `flyway-mysql` · `flyway-database-postgresql` | Flyway **11.14.1**（Boot BOM） | 持久化 · 迁移 |
| `platform-core` | `spring-boot-starter` · `spring-tx` · **`db-scheduler-spring-boot-starter`** · `spring-boot-starter-oauth2-resource-server` · `micrometer-core` | db-scheduler **16.12.0** | 定时 · 令牌校验（JWT 多签发方按 `iss` 分派；不透明令牌内省） |
| `process-core` · `ticket-core` | `spring-boot-starter` · `spring-tx` · `micrometer-core` | 随 Boot | —— |
| `opskit-svc` | `spring-boot-starter-web` · `-actuator` · `-security` · `spring-boot-flyway` · 驱动（`mariadb-java-client` · `mysql-connector-j` · `postgresql`）· `micrometer-registry-prometheus` | 随 Boot | 进程 |
| | `springdoc-openapi-starter-webmvc-api` | **3.0.3** | 构建期生成 `openapi/*.yaml` |
| 测试 | JUnit 5 · AssertJ · `spring-boot-starter-test` · Testcontainers（`testcontainers-mariadb` · `-mysql` · `-postgresql`，2.x 新包名 `org.testcontainers.{mariadb,mysql,postgresql}`）· H2 · ArchUnit | Testcontainers **2.0.5** · ArchUnit **1.3.0** | —— |

> ⚠️ **不用** Boot 的 Flyway 自动配置（`spring-boot-flyway`）：它只管一个实例、一张历史表，且 `{vendor}` 占位是 Boot 的特性。三个模块各自用 `flyway-core` 显式建实例（如 `PlatformMigrations`：独立历史表 + 按方言选目录）。反过来也要记住：Boot 4 下只加 `flyway-core` 是**不会**自动迁移的 —— 迁移必须由模块代码显式调用。

### 2.3 明确不引入

| 不引入 | 为什么 |
|---|---|
| Flowable · Camunda · Activiti 等 BPMN 引擎 | 绑 MyBatis；D8 |
| MyBatis · MyBatis-Plus · jOOQ · JPA / Hibernate | 统一 `JdbcClient` |
| ShedLock · Quartz | db-scheduler 已覆盖 |
| Redis | 幂等、发件箱、定时全部落库；将来只做可丢缓存 |
| 表达式引擎（SpEL 求值租户输入 · JUEL · Groovy · Nashorn） | 服务不执行租户脚本 |
| Jackson 2（`com.fasterxml.jackson.databind`） | 与 Boot 4 的 Jackson 3 并存会让注解行为难查 |
| GraalVM `native-maven-plugin` | 本期不做 AOT |
| 任何业务构件：`ai.neargo.sharehub:*` · `ai.neargo.shop:*` · `top.ichain:*` | 产品不依赖任何客户 |

## 三、构建约束（`opskit-parent` 的 enforcer）

| 规则 | 说明 |
|---|---|
| `dependencyConvergence` | 同构件两版本即失败；db-scheduler starter 按 Boot 4.0.6 编译，其传递的 Boot 构件由 4.0.7 BOM 统一 |
| `banDuplicatePomDependencyVersions` | —— |
| `bannedDependencies` | §2.3 全部坐标：`org.flowable:*` · `org.camunda*:*` · `org.activiti:*` · `org.mybatis:*` · `com.baomidou:*` · `org.jooq:*` · `org.hibernate*:*` · `net.javacrumbs.shedlock:*` · `org.quartz-scheduler:*` · `com.fasterxml.jackson.core:jackson-databind` · `ai.neargo.sharehub:*` · `ai.neargo.shop:*` · `top.ichain:*` |

## 四、接入方怎么依赖

| 接入方 | 依赖 | 说明 |
|---|---|---|
| 只要进程内状态校验 | `ai.neargo.opskit:process-api` | 纯 Java 状态机库；不需要服务在线 |
| Java 接入方（API） | `process-client` / `ticket-client`（各自带上 api 与 `platform-client`） | HTTP 客户端 + webhook 接收骨架（验签 · 幂等分发） |
| 非 Java | 无 | 按 `openapi/*.yaml` 调 HTTP |
| 前端 | 由 `openapi/*.yaml` 生成的 TS 客户端 + 嵌入组件包 | 见前端方案 |

### 4.1 以 ShareHub 为例

| 项 | 做法 |
|---|---|
| enforcer | `sharehub-parent` 只禁 `ai.neargo.shop:*`，`ai.neargo.opskit:*` 无需放行 |
| 位置 | 新增适配模块（如 `sharehub-opskit-adapter`）依赖客户端；业务 svc 只依赖 `sharehub-api` 里的端口接口（守住 ADR-017 的模块边界） |
| 与 MyBatis-Plus | 无冲突：客户端不带持久化依赖 |

## 五、运行时依赖

| 依赖 | 谁需要 | 不可用时 |
|---|---|---|
| 数据库 `opskit` | `opskit-svc` | 服务不可用 |
| 接入方 webhook 端点 | 事件投递 | 退避重试，不阻塞任何写操作 |
| 接入方 / 客户的 JWKS 或内省端点 | 成员令牌认证 | 该账户的成员登录不可用（缓存期内仍可用）；应用凭证调用不受影响 |
| 服务 → 接入方的同步业务调用 | **无**（R1） | —— |

## 六、架构测试（ArchUnit）

| # | 规则 | 负对照 |
|:-:|---|---|
| A1 | 上层不得依赖下层的 `..core..` / `..store..`（`ticket` → `process` / `platform`；`process` → `platform`） | 在工单里 import 流程 core 的类 → 红 |
| A2 | 下层不得依赖上层 | —— |
| A3 | `commons..` 与 `..api..` 只依赖 JDK | api 里用 Spring 注解 → 红 |
| A4 | `..core.domain..` 不得依赖 Spring、`java.sql`、`..store..` | —— |
| A5 | 只有 `..store..` 使用 `JdbcClient` / 含 SQL 字面量 | —— |
| A6 | `..store.dao..` 的公开方法第一个参数是 `WorkspaceId` 或 `AccountId` | 新增一个不带空间的查询 → 红 |
| A7 | SQL 字面量不得同时出现两个模块的表前缀（禁止跨前缀 JOIN） | —— |
| A8 | 出站 HTTP 只出现在 `platform.core.outbox..` 与 `platform.core.auth..` | 在 app 层用 `RestClient` → 红 |
| A9 | 不得出现任何客户名：`sharehub` · `shop` · `ichain` · `tradeagent` · `powerbank`（类名 · 包名 · 字符串常量） | —— |
| A10 | 不得引用 `com.fasterxml.jackson..` | —— |
| A11 | 不得使用 `BeanPropertyRowMapper` / `DataClassRowMapper` | —— |
| A12 | `..app..` 的每个公开用例方法声明所需产品权限（注解）或显式标注「系统动作」 | 新增一个未声明的用例 → 红 |
