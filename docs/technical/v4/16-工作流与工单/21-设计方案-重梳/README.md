## 一、定位

| 项 | 定 |
|---|---|
| 是什么 | **OpsKit（运营套件）**：给任何运营系统用的基础能力平台 —— 把「事情找人、按流程办完、超时有人管、全程可追溯」做成一个可独立售卖的 SaaS 产品 |
| 代号 | `opskit`（用户定，2026-09-27；进包名 `ai.neargo.opskit` · 坐标 · 库名 · 接口；对外品牌可另起）。先后否掉 `flow`（太窄）与 `OpsCore`（它不是核心能力，是给运营系统用的一套积木） |
| 首批能力 | **流程**（Process：状态流转 · 人工任务 · 审批 · 时限）· **工单**（Ticket：租户自定义类型 · 字段 · 派单 · 统计） |
| 平台层 | 租户（账户 / 空间）· 身份与目录 · 接入应用 · 事件投递 —— 所有能力共用，后续能力（表单、通知、自动化）直接复用 |
| 谁用 | ① **平台伙伴**：把 OpsKit 嵌进自己的 SaaS，给它的每个客户开一个空间（ShareHub 即此类）② **直接客户**：没有自有平台的企业，用 OpsKit 自己的控制台 ③ **内部系统**：以 API 接入 |
| 部署 | 多租户 SaaS（主形态）· 私有化单租户部署（同一镜像） |
| 设计原则 | **产品先于客户**：概念、角色、流程、字段全部是租户可配置的数据；**不为任何一个现有系统写特例，现有系统按附录映射来适配** |

## 二、通用化：把什么从「现有业务」改成了「租户数据」

| 维度 | 上一版（贴着现有系统） | 本版（通用） |
|---|---|---|
| 隔离单位 | `system_code`（接入的是哪个产品） | **账户 → 空间**；数据按空间隔离，定义可在账户级共享为模板 |
| 人 | `actorType` 枚举 STAFF · AGENT · MERCHANT · USER | **主体**：成员 · 组 · 应用 · 外部联系人；员工 / 代理 / 商家只是成员的**属性或所在组** |
| 权限 | 直接用业务权限码当资格 | 产品**固定权限目录** + 租户自定义**角色**；宿主权限经声明映射进角色 |
| 流程里的角色 | 状态角色 6 个（含「已升级」「待复核」等业务味） | **状态类别** 5 个（新建 · 处理中 · 等待 · 已完成 · 已取消，同业界做法）+ **参与者角色**（发起人 · 负责人 · 办理人 · 审批人 · 关注人 + 自定义） |
| 流程 | 状态图与审批流分成两种定义 | **一种流程定义**：状态 + 迁移（谁能走 · 条件 · 必填 · 后置动作）；审批、外部确认、定时是**状态上挂的门** |
| 业务前置校验 | 界面动作交给宿主后端（`uiActionMode`） | **外部确认门**：进入某状态时发事件，外部系统异步回复确认 / 驳回 —— 任何平台都能用 |
| 工单字段 | 固定列 + `ext` 展示用 JSON | 租户为每个类型定义**字段**（文本 · 数字 · 日期 · 选项 · 成员 · 组 · 附件 · 外部引用），可筛选 |
| 优先级 / 关闭原因 / 来源 | 写死 P1–P4、枚举 | 租户定义的**选项集** |
| 派单 | MANUAL · POOL · RULE（规则由业务实现） | **派单策略**：手工 · 队列领取 · 轮询 · 最少负载 · 按字段 · 外部指定 |
| 数据范围 | 三个锚点列（按 powerbank 的站点 / 代理设计） | **范围标签**：多值、维度不限（`site:ST0311` · `region:east`）；可见 = 全部可见权限 ∪ 参与者 ∪ 标签相交 |
| SLA | 按（类型 × 优先级）一个时限 | **SLA 策略**：多个指标（首次响应 · 解决 · 自定义），起算 / 暂停 / 停止条件按状态类别与迁移配置，目标按条件矩阵 |

## 三、相对上一版（同目录首版）的其他变化

| 变化 | 说明 |
|---|---|
| 名称 | `flow` → `opskit`；模块 `workflow` / `workorder` → `process` / `ticket`，另增 `platform` 与共享库 `commons` |
| 托管 | 先在 powerbank 根目录 `opskit/` 孵化，成熟后拆为独立仓库（K2） |
| 表前缀 | `wf_` / `wo_` → `plat_` / `proc_` / `tkt_`（按能力模块） |
| 接口 | 按空间寻址：`/v1/workspaces/{ws}/…`；三类调用方（应用 · 成员 · 运维） |
| 审批 | 从独立聚合的「对外主入口」降为流程状态上的门；只要审批的接入方用「审批类流程」即可 |
| 目录 | 新增轻量成员目录（令牌即时开通 + 同步 API），因为「派给某人」「组内会签」「轮询派单」都需要知道组里有谁 |
| 保留不变 | 自研引擎 + `JdbcClient` · db-scheduler · 条件更新并发控制 · 唯一键防重 · epoch 防旧定时 · 发件箱 + 至少一次 webhook · 不跑表达式 · 本期不做 AOT |
