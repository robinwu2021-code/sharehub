# 06 · 接口设计

> 所属：[21 OpsKit 设计方案](./README.md) · 状态：**已定**（2026-09-27）
> 契约真源：`opskit-svc` 构建期生成的 `openapi/{platform,process,ticket}.yaml`。

---

## 一、调用方与认证

| 调用方 | 认证 | 操作人 | 典型使用者 |
|---|---|---|---|
| **应用** | `Authorization: Bearer <应用凭证>` | 请求体 `onBehalfOf: {externalRef}`（代成员，不存在即开通）或不带（应用自身） | 伙伴平台后端、内部系统 |
| **成员** | `Authorization: Bearer <成员令牌>`（宿主令牌或客户 IdP 令牌）。JWT 按 `iss` 找到账户；**不透明令牌**（无 `iss`，如 `stk_…`）按账户登记的**令牌前缀**找到 IdP，再调其内省端点 | 服务从令牌解析，**请求体中的操作人字段与数据范围一律忽略** | 控制台、嵌入组件 |
| **运维** | 运维凭证 | 运维身份 | 我们 |

一套接口，三类调用方共用；差别只在「操作人从哪来」与权限判定。

## 二、通用约定

| 项 | 约定 |
|---|---|
| 基址 | SaaS：`https://api.{品牌域名}/v1`；经宿主同源反代时：`/api/opskit/v1` |
| 寻址 | 运行时资源一律在空间下：`/v1/workspaces/{workspaceId}/…`；应用可用 `ext:{外部租户号}` 代替空间 ID。**下文表格里的 `/tickets/{no}/…`、`/instances/{no}/…`、`/tasks/{no}/…`、`/approvals/{no}/…` 都是简写，完整路径一律带 `/workspaces/{ws}` 前缀** |
| 只有一套路径 | 应用、成员、运维共用同一套路径，差别只在认证与操作人来源（§一）。早期稿里单独的「界面面」前缀 `/api/flow/ui/v1` **已废止** |
| 账户级 | 模板定义、应用、IdP、订阅：`/v1/accounts/{accountId}/…` |
| 版本 | 大版本进路径；`/v1` 内只加字段 |
| 幂等 | 写请求带 `Idempotency-Key`（≤ 128）；同键同内容返回首次结果（响应头 `Idempotent-Replayed: true`），同键不同内容 409 `opskit.idempotency.mismatch`，同键仍在处理 409 `opskit.idempotency.in_progress`。键按调用方隔离（应用 / 成员）；「同内容」= 方法 + 路径 + 请求体逐字节相同。只记确定的结果（2xx 与业务性 4xx），401 / 409 / 429 / 5xx 不记、可同键重试 |
| 分页 | `page`（从 1）· `size`（≤ 200）→ `{list, total, page, size}` |
| 查询 | 列表一律 `POST …/query`；每个筛选控件对应一个参数 |
| 时间 | epoch 毫秒 |
| 多语言 | 定义中的名称为 `{zh, en, ar, …}`；读接口按 `Accept-Language` 同时返回 `name`（已选语种）与 `names`（全部） |
| 错误 | `{ "error": "opskit.process.illegal_transition", "message", "args", "traceId", "errors": [{path, error}]? }` |
| HTTP 码 | 400 格式 · 401 未认证 · 403 无权限 / 规则拒绝 · 404 不存在 / 跨空间 / 不可见 · 409 冲突 · 422 校验不过 · 429 超配额 |
| 追踪 | 接受 `traceparent`；响应带 `traceId` |

### 2.1 共用结构

```json
// 主体引用
"member:mb_01J8…" | "group:field-ops" | "role:contract-approver" | "perm:location:contract:audit" | "contact:ct_…"

// 代成员（应用调用时）
"onBehalfOf": { "externalRef": "E107", "displayName": "Ali", "groups": ["field-ops"], "scopes": ["site:ST0311"] }

// 外部引用（业务对象）
"subject": { "type": "contract", "ref": "CT0042", "display": { "title": "万达广场进场合同" } }
```

## 三、平台

| 资源 | 方法 · 路径 | 说明 |
|---|---|---|
| 空间 | `POST /accounts/{a}/workspaces` · `GET …` · `PATCH /workspaces/{ws}` | 伙伴开户时调用；`externalRef` 唯一 |
| 应用 | `POST /accounts/{a}/apps` · `POST /apps/{id}/rotate-credential` · `PUT /apps/{id}/workspaces` | 凭证只返回一次 |

| 成员属性定义 | `GET /workspaces/{ws}/member-attributes` · `PUT /workspaces/{ws}/member-attributes/{key}`（`{name, valueLabels}`，需 `directory:manage`；账户级模板待做） | `[{key, name, names, values[{value, name, names}]}]`；供 `assignee.attrs.{key}.name` 与属性筛选的选项（O1-12） |
| 目录同步 | `POST /workspaces/{ws}/directory/sync` | 批量 upsert 成员 · 组 · 组成员 · 角色绑定；`mode: MERGE \| REPLACE`。请求体 `{mode, members[{externalRef, displayName, attrs, scopes}], groups[{code, name, kind, claimTimeoutSec?, orderBy?}], memberships{组代号: [外部编号]}, roleBindings[{roleCode, principal}]}` → `{members, groups, memberships, roleBindings}`；**只认应用凭证**（成员令牌即使持 `directory:manage` 也 403）；整批一个事务；请求体上限 16 MiB（其他写接口 1 MiB）。REPLACE 只对本批出现的组 / 成员以本批为准 —— 分批时同一个组的成员名单要在同一批给全（已实现）|

| 投递 | `POST /accounts/{a}/webhook-deliveries/query` · `POST /webhook-deliveries/{id}/redeliver` | —— |
| 审计 | `POST /accounts/{a}/audit/query` | —— |
| 定义版本总览 | `GET /accounts/{a}/definitions?workspace=` | 流程 · 审批模板 · 工单类型 · SLA 策略的当前版本 `{kind, code, version, publishedAtMs, publishedBy, channel}`（接入管理页） |
| 我是谁 | `GET /workspaces/{ws}/me` | 成员调用：解析后的身份 · 组 · 角色 · 权限 · 标签（前端据此亮按钮） |

## 四、流程

| 资源 | 方法 · 路径 | 说明 |
|---|---|---|
| 定义 | `PUT /accounts/{a}/processes/{code}`（模板）· `PUT /workspaces/{ws}/processes/{code}` | 幂等发布；请求体 = 流程的规范化 JSON（与启动引导的定义文件同形，可加 `note`），代号须与路径一致；返回 `{version, created}`（空间级已实现；`runningOnOlderVersions` 与账户模板级待做）；校验失败 422 逐条 |
| | `GET …/processes` · `GET …/processes/{code}` · `GET …/processes/{code}/versions` · `POST …/processes/{code}/disable` · `/enable` | 列表含在途数；停用 = 不接受新实例。已实现（空间级，需 `process:manage`）：列表 `[{code, name, version, enabled, inherited, fromTemplate, publishedAtMs}]`（在途数待做）· versions · disable / enable；单个定义用 `…/definition` |
| | `GET /workspaces/{ws}/processes/{code}/definition` | 当前生效的原始定义，形状 = PUT 请求体（取回改完原样提交）；需 `process:manage`；头 `X-Definition-Version`（已实现）|
| SLA 策略 | `PUT …/sla-policies/{code}` · `GET …` | 同上 |
| 实例 | `POST /workspaces/{ws}/instances` | `{processCode, subject?, fields, participants, scopes, slaPolicies?, onBehalfOf?}` → `{instanceNo, processCode, processVersion, status, statusCategory, open, seq, approvalNo?, createdAtMs}`（停在审批门时带 `approvalNo`）；`onBehalfOf` 只认应用凭证，成员令牌带它 → 403。**成员令牌**只能发起审批模板，需 `approval:submit`，`fields` 按模板发起表单校验（错误路径 `fields.<代号>`）；审批模板的流程发起后在同一请求内走 `submit` 进入审批 |
| | `POST /instances/{no}/transitions/{code}` | `{fields?, comment?, onBehalfOf?}` → 与发起同形 `{instanceNo, status, statusCategory, open, seq, approvalNo?, …}`；who 由流程定义判，`requires` 缺项 422（已实现）|
| | `PATCH /instances/{no}/fields` · `PUT /instances/{no}/participants`（已实现，`{role, principals[]}`，仅应用） · `PUT /instances/{no}/scopes`（已实现，`{tags[]}`，仅应用） | 字段变化可能触发 SLA 重算 |
| | `GET /instances/{no}` | 含**当前操作人可走的迁移**（名称 · 必填项）· 参与者 · 门状态 · SLA 计时器 |
| | `GET /instances/{no}/history` · `POST /instances/query` | —— |
| 外部确认 | `POST /workspaces/{ws}/confirmations/{token}` | **仅应用凭证**：`{result: CONFIRM\|REJECT, reason?}`（REJECT 须写 reason）→ `{instanceNo, result, first}`；重复回复返回首次结果（`first=false`），不再迁移；令牌过期 / 已离开该状态 → 409 `opskit.confirmation.expired`（已实现，Java 侧见 `opskit-connector`）|
| 任务 | `POST /tasks/{no}/claim` · `/release` · `/assign` · `/reassign` · `/complete` | `reassign` 必填 `reason` |
| | `POST /workspaces/{ws}/tasks/query` | `{queueGroup?, status?[], claimed?, assignee?: "me" \| memberId, page, size}`；`"me"` 由服务端按令牌解析（2026-09-28 与前端对齐的参数名） |
| 审批模板 | `PUT /accounts/{a}/approval-templates/{code}`（模板）· `PUT /workspaces/{ws}/approval-templates/{code}` · `GET …` · `…/versions` · `/disable` | 控制台「流程配置」页编辑的形态（02 §6.4a）；服务端编译为审批类流程；422 的 `errors[].path` 按模板字段给 |
| 审批 | `GET /approvals/{no}` | 全部轮次 × 每步任务与决定 |
| | `POST /approvals/{no}/decide` | `{taskNo, decision: APPROVE\|REJECT, reason?}`；五条规则固定顺序校验 |
| | `POST /approvals/{no}/withdraw` | 仅发起人、仅待审 |
| | `POST /workspaces/{ws}/approvals/query` | `status[] · processCode · requestedBy · from/to · keyword · subject` |
| | `POST /workspaces/{ws}/approvals/count` | 按状态分组计数（审批列表页签角标），参数同 query（不含 status） |
| 队列 | `POST /workspaces/{ws}/tasks/queue-counts` | 每个队列组 `{queue{code,name}, unclaimed, claimedByMe}`（审核队列页签「待领 12」） |
| 待办 | `POST /workspaces/{ws}/todos/query` · `/count` | query：`{origin: ALL\|PROCESS\|TICKET, claimable?, page, size}` → `{list, total, page, size}`；count 一次回全部角标 `{all, process, ticket, claimable}`，与 query 同口径；候选匹配 ∩ 可见 |
| 对账 | `GET /workspaces/{ws}/subjects/{type}/{ref}/history` | 该业务对象的全部实例、审批、工单流转 |

### 4.1 示例：用审批类流程审一份合同

```json
POST /v1/workspaces/ext:T0001/instances
Authorization: Bearer <应用凭证>
Idempotency-Key: contract-CT0042-submit-1

{ "processCode": "contract-approval",
  "subject": { "type": "contract", "ref": "CT0042", "display": { "title": "万达广场进场合同" } },
  "fields": { "needsCosign": true, "shareRate": 0.35 },
  "participants": { "REQUESTER": ["member:@E107"] },
  "scopes": ["site:ST0311", "agent:AG0007"],
  "onBehalfOf": { "externalRef": "E107" } }
```

流程定义里：`草稿 →(submit) 运营审批[审批门：role:contract-approver] →(approved) 财务会签[审批门，when needsCosign] → 生效确认[外部确认门] → 已生效`；ShareHub 收到 `instance.awaiting_confirmation` 后查时间段不重叠，再回复确认或驳回。

## 六、事件（webhook）

| 项 | 约定 |
|---|---|
| 载荷 | `{ "eventId", "eventType", "accountId", "workspaceId", "workspaceExternalRef", "occurredAt", "idemKey", "traceparent", "data" }` |
| 签名 | `X-OpsKit-Signature: t=<ms>,v1=<hex>`；`v1 = HMAC-SHA256(secret, t + "." + body)`；时间窗 ±5 分钟 |
| 成功 | 2xx；其余重试：1m · 5m · 30m · 2h · 12h · 24h × 3；耗尽标记失败、可重投 |
| 投递运维（已实现，空间级，需 `integration:manage`）| `POST /workspaces/{ws}/webhook-deliveries/query` `{state: FAILED\|PENDING\|DONE, eventType?, page, size}` · `GET …/webhook-deliveries/{id}`（信封原文 + 每次尝试：url · 状态码 · 耗时 · 错误）· `POST …/webhook-deliveries/{id}/redeliver`（清失败、立即到期；已送达 409）。账户级 `…/accounts/{a}/webhook-deliveries/*` 待运维面凭证一起做 |
| 顺序 | 不保证跨事件；同一实例 / 工单内按 `seq` 判序 |
| 接收方义务 | 验签 · 按 `idemKey` 去重 · 只推进自己的状态 · 处理中不同步回调服务 |
| 操作人字段 | `instance.*` 的 `actor`、`approval.completed` 的 `decidedBy`、`task.*` 的 `assignee` 一律是 `{ref, externalRef?, displayName?}`：`ref` 为 `member:…` / `app:…` / `system`，成员另带宿主编号与显示名（M5-0，2026-09-28）|
| `approval.completed.data` | `approvalNo` · `instanceNo` · `subject{type, ref}`（实例有业务对象时）· `roundNo` · `result`（APPROVED / REJECTED / WITHDRAWN）· `reason?` · `decidedBy` |
| 已实现 / 未实现 | 载荷里 `traceparent` 尚未输出；其余字段均已实现 |
| 订阅与凭证 | 单宿主部署走启动引导 `apps` / `webhooks` 段（凭证由部署方生成经 env 注入，按代号幂等、改值即轮换；订阅以声明为准整体替换）|

## 七、列表与详情出参（前后端对齐，2026-09-27）

名称类字段一律同时给 `name`（按 `Accept-Language` 选好的）与原值代号，前端不自己查字典。

| 视图 | 字段 |
|---|---|
| **TodoItem**（待办行） | `taskNo` · `kind`（WORK / APPROVAL）· `origin`（PROCESS / TICKET）· `title` · `subject{type, ref, display{title, summary}}` · `priority{code, name, ordinal}` · `createdAtMs` · `dueAtMs?` · `sla?{state, startedAtMs, dueAtMs, pausedMs}`（剩余比例 = 按这三项算，前端不猜起点）· `claimable`（**必须先领取才能办**：池里的办理任务与队列组任务；普通审批的候选可直接决定，为 false —— 2026-09-28 与前端对齐；`todos/count.claimable` 同口径）· `ticketNo?` · `ticketType?{code, name}` · `approvalNo?` |
| **TicketRow**（工单行） | `ticketNo` · `type{code, name}` · `title` · `subject?{type, ref, display}` · `priority{code, name, ordinal}` · `status{code, name}` · `statusCategory` · `assignee?{ref, displayName, attrs}` · `requester?{ref, displayName}` · `slaState` · `slaNextDueAtMs?` · `sla?{state, startedAtMs, dueAtMs, pausedMs}`（取到期最近的那个运行中指标，与 TodoItem 同形）· `escalated` · `createdAtMs` · `updatedAtMs` · `fields`（仅列表配置里要显示的可筛选字段）· `actions[]`（同 TicketView，列表行也给，免得逐行调详情）|
| **TicketView**（详情）| TicketRow 全部 + `description` · `fields`（全部）· `fieldList[{code, label, value}]`（按工单类型的字段配置排好序、带显示标签）· `participants[]` · `slaMetrics[{code, name, state, startedAtMs, dueAtMs, pausedMs}]`（每个指标一项；**不叫 `sla`**：继承自 TicketRow 的 `sla` 是到期最近那个指标的摘要对象，同一个键不能既是对象又是数组）· `dedupe?{key, attachedCount}` · `resolution?` · `mergedInto?` |
| **ApprovalRow**（审批行） | `approvalNo` · `process{code, name}` · `subject{type, ref, display}` · `status` · `currentStep?{code, name}` · `round` · `requestedBy{ref, displayName}` · `requestedAtMs` · `stepStartedAtMs?` · `stepDueAtMs?`（「已等待」与超时标记用）· `finishedAtMs?`（通过 / 驳回 / 撤回时的办结时刻；列表「耗时」= `finishedAtMs − requestedAtMs`）|
| **ApprovalView**（审批详情） | ApprovalRow 全部 + `facts[{label, value, hint?}]`（业务提交时给的展示字段）· `steps[{code, name, approverText, conditionText?, state: DONE\|CURRENT\|TODO\|SKIPPED, decidedBy?, decidedAtMs?}]` · `rounds[{round, status, atMs, by, comment?}]` · `evidence[]` · `mine{taskNo?, canDecide, whyNot?, canWithdraw}`（**`whyNot` 由服务按规则给出**，前端不自己判断）· `rules{crossStepExclusive}` |
| **QueueTask**（队列行） | `taskNo` · `queue{code, name}` · `subject` · `priority{code, name, ordinal}` · `createdAtMs` · `evidenceSummary?` · `claimedBy?{ref, displayName}` · `claimExpiresAtMs?`（领取倒计时）|
| **TimelineEntry**（时间线） | `seq` · `atMs` · `kind: CREATED\|ASSIGNED\|TRANSITION\|SLA\|DEDUPE\|COMMENT\|ESCALATED\|APPROVAL\|MERGE` · `title`（服务按语言给好）· `actor?{ref, displayName}` · `detail?` · `hot`（需要突出显示，如超时、驳回）|
| **Action**（动作） | `code` · `name` · `toCategory`（迁移后的状态大类；前端据此决定主 / 次按钮，不按代号写死）· `requires{fields[], comment}` —— 只含**当前操作人可走**的迁移 |

| 值的形状（统一）| 说明 |
|---|---|
| `fields.{code}` | 一律 `{value, name?}`：选项 / 成员 / 组字段带 `name`（按语言选好的显示名）；文本、数字只有 `value`；日期时间 `value` 为毫秒；外部引用 `value` 为 `{type, ref, display}`。**字段代号由租户在工单类型里定义**（ShareHub 的类型会定义 `source`（选项集）与 `sourceRef`（文本），见 21/07 P6），前端按类型的字段配置渲染，不假定代号 |
| `assignee.attrs.{key}` | 一律 `{value, name?}`；`name` 来自空间的「成员属性定义」（属性值 → 多语种显示名，见 21/07 O1-12）；未定义显示名时只有 `value` |

| 查询参数补充 | 说明 |
|---|---|
| `tickets/query` 的 `assigneeAttr{key, values[]}` | 按受理方的成员属性筛（如 `{key:"partyType", values:["AGENT"]}`）。实现：先向平台取匹配成员，再按 IN 过滤（不跨模块 JOIN）；匹配成员超过 5000 返回 422 `opskit.ticket.filter_too_broad`，此时应改用 `group` 筛选 |

| 容易写死、但**不许写死**的 | 正确来源 |
|---|---|
| 办理人是「代理 / 员工 / 客服」 | 成员属性（`assignee.attrs`，如 `partyType`），由租户定义；前端按属性值显示，不内置这几个词 |
| 工单来源「告警 / 巡检 / C 端 / 手工」 | 工单类型里的一个选项集字段（通常叫 `source`），在 `fields` 里带显示名 |
| 优先级颜色 | 按 `priority.ordinal` 与语义 token 映射，不按代号写死 |

## 八、宿主内省端点契约（接入方实现，OpsKit 调用）

不透明令牌（如 ShareHub 的 `stk_…`）的宿主要提供一个内省端点，OpsKit 按登记的令牌前缀路由过去（21/02 §8.2）。形状同 RFC 7662：

| 项 | 约定 |
|---|---|
| 请求 | `POST {introspectUrl}`，`Content-Type: application/x-www-form-urlencoded`，体 `token={令牌}`；登记了 clientId 时带 `Authorization: Basic base64(clientId:clientSecret)` |
| 成功应答 | `200` + JSON：`{"active": true, "sub": "E107", "name": "Ali", "tenant": "T0001", "groups": ["field-ops"], "roles": ["agent"], "perms": ["location:contract:audit"], "scopes": ["site:ST0311", "agent:AG0007"], "exp": 1790499600}` —— 声明名可自定，由 IdP 登记里的**声明映射**对上；数组也可写成空格分隔字符串 |
| 无效令牌 | `200` + `{"active": false}`（过期、登出、伪造一律如此，不区分） |
| 必须有的 | `active` · 成员编号（映射的 `member`）· 伙伴租户号（映射的 `workspace`，缺了则令牌不能访问任何空间）· 建议给 `exp`（OpsKit 缓存不会超过它） |
| 全量范围 | 数据范围为「全部」的人发 `scopes:["*"]`（不发 = 没有范围）；`*` 只放开范围条件，见 02 §7.2 |
| OpsKit 这边 | 超时 5 秒；结果按「令牌剩余有效期」与 5 分钟取小缓存；`active:false` 不缓存；非 200 视为无效令牌（对终端用户即 401） |
| 安全 | 端点只对 OpsKit 开放（内网或 Basic 凭据）；应答里不放手机号等敏感信息 |
