# 02 · 架构设计

> 所属：[21 OpsKit 设计方案](./README.md) · 状态：**已定**（2026-09-27）· 依据：[01 需求](./01-需求.md)

## 一、边界

| 归 OpsKit | 归接入方（伙伴平台 / 业务系统） |
|---|---|
| 谁来办、办到哪、超没超时、谁能看见、全程留痕 | 业务对象本身（合同、订单、设备）及其状态 |
| 流程执行、任务、审批规则、SLA、工单记录与字段 | 业务前置校验 —— 以**外部确认门**的回复参与流程 |
| 成员目录（开通自令牌或同步） | 人员与组织的真源 |
| 发事件 | 收事件、推进自己的状态（幂等） |

### 1.1 解耦规则

| # | 规则 | 落法 |
|:-:|---|---|
| R1 | 服务**从不同步调用**接入方、从不读接入方的库 | 出站 HTTP 只有 webhook 投递与令牌校验（架构测试白名单） |
| R2 | 接入方的数据只以「外部引用 + 字段 + 快照」进服务 | 外部引用字段类型；实例的 `subject` |
| R3 | 结果只经事件回推；接收方必须幂等 | 发件箱 + 至少一次；每个事件带幂等键 |
| R4 | 需要接入方判断的，一律异步：外部确认门、外部指定派单 | 发事件 → 等回复 → 超时有兜底迁移 |

## 二、能力分层

| 层 | 模块 | 内容 | 表前缀 |
|---|---|---|---|
| 能力 | **`ticket`** 工单 | 工单类型 · 字段 · 选项集 · 工单 · 派单策略 · 去重合并 · 评论 · 统计 | `tkt_` |
| 能力 | **`process`** 流程 | 流程定义 · 实例 · 迁移 · 参与者 · 任务 · 审批门 · 外部确认门 · 定时门 · SLA 策略与计时 · 待办 | `proc_` |
| 平台 | **`platform`** 平台 | 账户 · 空间 · 应用与凭证 · 令牌联邦 · 成员 / 组 / 角色 · 日历 · 事件订阅与投递 · 幂等 · 审计 | `plat_` |
| 共享库 | **`commons`** | 空间上下文类型 · 编号生成 · 方言 · 条件模型与求值 · 定时适配 · 错误模型 —— **库，不是服务，无表** | —— |

| 依赖方向 | 规则 |
|---|---|
| `ticket → process → platform` | 上层只经下层的**客户端接口**调用（`ProcessClient` · `PlatformClient`），不碰下层的表与内部类 |
| 平台对能力无知 | `platform` 代码里不出现流程、工单 |
| 后续能力（表单、通知、自动化） | 作为新的能力模块挂在 `platform` 之上，同样只经客户端接口 |

每个模块内部仍是 `*-api · *-client · *-core · *-store` 四个子模块（03）。

## 三、部署

| 形态 | 说明 |
|---|---|
| **多租户 SaaS**（主） | 一个进程 `opskit-svc` 装全部模块；共享库，按空间行级隔离；多实例无状态 |
| **私有化** | 同一镜像，单账户；可指定只装部分模块（profile） |
| 模块间 | 同进程注入进程内客户端，**共用同一事务**；将来拆进程时切 HTTP 客户端，模块间改为最终一致（发件箱 + 幂等），代码不改 |
| 扩展 | 先按账户分库（路由键 = 账户）再谈分片；所有表带 `account_id` 为此预留 |

## 五、身份与参与者

### 5.1 主体

| 主体 | 引用写法 | 说明 |
|---|---|---|
| 成员 | `member:{memberId}` | 带外部引用号与属性；令牌首次出现即开通，或经同步 API 批量写入 |
| 组 | `group:{code}` | 类型：`TEAM` · `QUEUE`（可领取，带领取超时）；成员关系可由令牌声明或同步 API 维护 |
| 角色 | `role:{code}` | 产品权限的组合（01 §九） |
| 外部权限 | `perm:{code}` | 令牌里带来的宿主权限，原样可用作候选条件（不进角色也能用），**不可枚举** |
| 应用 | `app:{appId}` | 系统操作；日志里区分「应用代成员」与「应用自身」 |
| 外部联系人 | `contact:{id}` | 不登录；可作发起人 / 关注人 |

### 5.2 操作人上下文 `Actor`

| 调用方 | 怎么得到 |
|---|---|
| 成员（控制台 / 嵌入组件） | 令牌 → 按声明映射得到 `memberId` · 组 · 角色 · 权限 · 范围标签；目录里的组 / 角色与令牌声明**取并集** |
| 应用代成员 | 应用凭证认证；请求体给 `onBehalfOf: {externalRef}` → 查 / 开通成员 → 读目录中的组与角色 |
| 应用自身 | 应用凭证；只能做应用被授权的系统动作（如外部确认门回复） |

### 5.3 参与者角色（流程与工单共用）

| 角色 | 基数 | 行为 |
|---|---|---|
| `REQUESTER` 发起人 | 1 | 可撤回（待审时）· 可见 |
| `OWNER` 负责人 | 0..1 | 可改派、升级 |
| `ASSIGNEE` 办理人 | 0..1 | 当前任务办理人；由任务同步 |
| `WATCHER` 关注人 | N | 可见、收事件 |
| 自定义（类型或流程里声明） | N | 可在迁移「谁能走」、审批候选里引用 |

## 六、通用流程模型

### 6.1 流程定义（数据）

| 部分 | 字段 | 说明 |
|---|---|---|
| 状态 | `code` · `name{i18n}` · `category`（NEW · IN_PROGRESS · WAITING · DONE · CANCELLED）· `gate?` | 恰一个初始状态；`DONE` / `CANCELLED` 必须无出边 |
| 迁移 | `code` · `name{i18n}` · `from[]`（或 `*`）· `to` · `who` · `when` · `requires` · `actions[]` · `system` | `system=true` 的迁移只能由门触发，界面不出按钮 |
| `who` 谁能走 | 参与者角色 · 角色 · 组 · 外部权限（任一匹配即可） | 缺省 = 当前办理人 |
| `when` 条件 | `{field, op, value}`，至多两层 `all` / `any` | 只比较实例字段；无表达式 |
| `requires` 必填 | 字段列表 · 是否必须评论 | 如「驳回必须写原因」 |
| `actions` 后置动作 | `assign(策略)` · `setField` · `addParticipant` · `clearAssignee` | 固定集合，同事务执行 |

### 6.2 状态上的门

| 门 | 进入状态时 | 结束时 |
|---|---|---|
| **审批门** `APPROVAL` | 按门里的步骤建审批单与第一步任务（§6.4） | 通过 → 触发 `onApproved` 迁移；驳回 → `onRejected`；撤回 → `onWithdrawn` |
| **外部确认门** `EXTERNAL` | 生成确认令牌，发事件 `instance.awaiting_confirmation{topic, token}` | 外部回复 `confirm` / `reject`（带原因）→ 对应迁移；超时 → `onTimeout` 迁移 |
| **定时门** `TIMER` | 调度到期 | 到期仍在该状态 → `onElapsed` 迁移 |

一个状态至多一个门；门触发的迁移必须是 `system=true` 且从该状态出发（定义校验）。

### 6.3 定义校验（发布时，全部错误一次返回）

| 校验 | 例 |
|---|---|
| 结构 | 恰一个初始状态 · 全部可达 · `(from, code)` 唯一 · 终态类别无出边 |
| 门 | 门引用的迁移存在、为 `system`、从本状态出发；审批会签的候选可枚举 |
| 引用 | `who` / 候选引用的角色、组、参与者角色存在；条件字段在字段集里（工单）|
| 版本 | 规范化 JSON 的 SHA-256 前 16 位；内容不变不产生新版本 |

### 6.4 审批门里的审批

| 部分 | 说明 |
|---|---|
| 步骤 | `code` · `when?` · `approvers` · `mode`（ANY · ALL）· `dueIn?` |
| 候选 `approvers` | `member` · `group` · `role` · `perm` · `field`（取实例字段里的成员）· `participant`（如负责人） |
| 会签可枚举性 | `ALL` 只允许 `member` 列表 · `group`（进入该步时**快照**组成员）· `field`；`role` / `perm` 不可枚举，只能 `ANY` |
| 规则 | `selfApproval`（缺省禁止）· `crossStepExclusive`（缺省开启）· 驳回必填原因（不可关） |
| 轮次 | 驳回 / 撤回后回到门前状态；再次进入门 = 新一轮；每轮每步决定只增不改 |

**只要审批的接入方**：用一个「审批类流程」（`草稿 → 审批中[审批门] → 已通过 / 已驳回`）起实例即可，不需要工单。

### 6.4a 审批模板（控制台编辑的形态，2026-09-28 定）

运营在控制台看到的是**线性审批步骤**，不是状态机。所以另设一种定义「审批模板」，由服务端**编译**成标准的审批类流程：

| 项 | 说明 |
|---|---|
| 模板形状 | `name{i18n}` · `steps[{code, name{i18n}, approver{kind, value}, mode: ANY\|ALL, when?{field, op, value}, dueHours?}]` · `rules{selfApproval, crossStepExclusive}` |
| 审批人种类 | `MEMBER`（指定成员）· `GROUP`（组，含队列组）· `ROLE` · `PERM`（宿主权限）· `FIELD`（提交时由业务在字段里给出人选，即原型里的「提交时指定」） |
| 编译产物 | 一个 `PROCESS` 定义：`草稿 →(submit) 审批中[审批门：steps 原样] →(approved) 已通过 / →(rejected) 已驳回 / →(withdrawn) 草稿`；模板与产物各自带版本，产物记下来源模板的版本 |
| 校验 | 在**模板层**做，错误路径按模板字段给（如 `steps[1].approver.value`），前端直接挂到对应字段；会签（ALL）只允许 MEMBER / GROUP / FIELD（ROLE / PERM 不可枚举），违反时路径为 `steps[i].mode` |
| 字段口径 | `approver.value` 必填：MEMBER 为成员 ID 列表、GROUP / ROLE / PERM 为代号、FIELD 为**字段代号**（提交时业务在该字段里给出人选）· `name` 至少一种语言非空，不规定必须是哪种（显示时按请求语言 → en → 任意一种回退）· `dueHours` 可空 |
| 为什么不让控制台直接编辑状态机 | 引擎只保留一种流程模型，不为页面开特例；运营不需要理解状态、迁移和门；12 F8a 要的就是表单化、无画布 |
| 高级需求 | 需要工单式多状态流转的，仍用完整流程定义（API 登记）；两者产物同形，引擎不区分 |

### 6.5 SLA 策略

| 部分 | 说明 |
|---|---|
| 指标 | `code`（`FIRST_RESPONSE` · `RESOLUTION` · 自定义）· `start` · `pause` · `stop` |
| 条件写法 | `start`：实例创建 / 进入某类别 / 某迁移；`pause`：处于某些类别或状态（缺省 `WAITING`）；`stop`：进入某类别（缺省 `DONE` · `CANCELLED`）/ 某迁移 / 首次公开评论 |
| 目标矩阵 | `[{when, targets{metric: 时长}, calendar?}]`，**自上而下第一条匹配** |
| 预警 | `warnAt`（如 80%） |
| 绑定 | 工单类型或流程引用一个或多个策略 |

## 七、工单模型

| 对象 | 关键字段 | 规则 |
|---|---|---|
| **TicketType** 工单类型 | `code` · `name{i18n}` · `processCode` · `fields[]` · `priorityOptions` · `resolutionOptions` · `numberPrefix` · `assignment` · `slaPolicies[]` · `scopeFrom[]` · `dedupe?` | 定义是数据；账户级模板 + 空间级覆盖 |
| **FieldDef** 字段 | `code` · `name{i18n}` · `type` · `required` · `onCreate` · `filterable` · `options?` · `refType?` | `filterable` 的字段值写入索引表 |
| **Ticket** 工单 | `ticketNo` · 类型与版本 · `instanceNo` · 标题 · 描述 · 优先级 · 解决结果 · 字段值 · 参与者 · 范围标签 · 状态快照 · SLA 快照 · 去重键 · 合并去向 | **没有自己的状态机**：状态只经流程实例迁移，工单表存只读快照 |
| **Comment** 评论 | 公开 / 内部 · 附件 | 首次公开评论可作 SLA 停止条件 |

### 7.1 派单策略

| 策略 | 行为 |
|---|---|
| `MANUAL` | 建单不派，等有 `ticket:assign` 的人派 |
| `QUEUE` | 候选 = 组（`QUEUE` 类型），组员领取 |
| `ROUND_ROBIN` | 在组内按游标轮转（游标行条件更新，防并发重复） |
| `LEAST_LOADED` | 组内未结任务最少者（同分按轮转） |
| `FIELD` | 取工单字段里的成员 |
| `EXTERNAL` | 发事件 `ticket.assignment_requested`，等外部调用派单接口；超时回退到配置的兜底策略 |

### 7.2 范围标签与可见性

| 项 | 规则 |
|---|---|
| 工单的标签 | 由类型的 `scopeFrom` 从字段值派生（如字段 `site` → `site:{值}`），外加建单时显式给出的标签 |
| 成员的标签 | 令牌声明 ∪ 目录里的成员属性；无标签即只能看「自己参与的」 |
| 可见 | `ticket:view:all` ∪（`ticket:view:scoped` 且标签相交）∪ 是参与者（`ticket:view:own`） |
| 待办 | 候选匹配 **且** 可见（两者都满足才出现） |
| 流程层的「可见」（O2-9 落地口径） | 实例：未打范围标签 ∨ 标签相交 ∨ 是参与者（范围是业务选择加的，不打标签即不设限）· 审批单**更严**：提交人 ∨ 参与者 ∨ 审批任务的候选 / 处理人，持 `approval:view:all` 不限 —— 不因实例没打标签就对全空间公开 · 应用自身不限，但没有「我的」待办。工单层在此之上叠加 `ticket:view:*` |
| 计数口径 | 每个计数与对应列表共用同一段 WHERE（`QueryDao`），不另写 |

## 八、核心流程

所有写操作：**一个应用服务方法 = 一个事务**；发事件 = 同事务写发件箱。

### 8.1 迁移 `transition(instanceNo, code, actor, input)`

| 步 | 做什么 | 失败 |
|:-:|---|---|
| 1 | 读实例（带版本）；按定义行 + 版本取编译后的流程（本地缓存，版本不可变） | 404 |
| 2 | 找迁移：`from` 含当前状态；非 `system`（界面 / 应用调用时） | 422 `opskit.process.illegal_transition` |
| 3 | `who` 校验 · `when` 求值 · `requires` 校验 | 403 / 422（逐条） |
| 4 | 条件更新 `… SET status=?, version=version+1, event_seq=event_seq+1 WHERE id=? AND status=? AND version=?` | 0 行 → 409 `opskit.state_changed` |
| 5 | 日志；离开状态的门收尾（取消审批 / 作废确认令牌 / 定时 epoch+1）；进入状态的门启动 | —— |
| 6 | 后置动作；SLA 各指标按新状态类别起算 / 暂停 / 恢复 / 停止 | —— |
| 7 | 终态类别：关闭未完成任务，`is_open=0` | —— |
| 8 | 领域事件同事务分发（工单快照同步）；写发件箱 `instance.transitioned` | —— |

### 8.2 任务

| 动作 | 条件更新（0 行即 409） | 附带 |
|---|---|---|
| 建 | 插任务 + 候选行 | 到期 → 调度 |
| 领取 | `WHERE status='OPEN'` 且 actor 匹配候选 | 组有领取超时 → 调度（`claim_epoch+1`） |
| 放回 | `WHERE status='CLAIMED' AND assignee=?` | `claim_epoch+1`，旧超时作废 |
| 指派 / 转派 | `WHERE status IN ('OPEN','CLAIMED','ASSIGNED')`；转派必填原因 | 候选换为 `member:受理人` |
| 完成 | `WHERE status IN ('CLAIMED','ASSIGNED') AND assignee=?` | 候选 `is_open=0` |

**我的待办**：把 actor 展开为候选键集合（`member:x` ∪ 各 `group:*` ∪ 各 `role:*` ∪ 各 `perm:*` ∪ 参与者键）→ 在候选表 `IN` 匹配、`is_open=1` → 再按可见性过滤 → 按到期排序。

### 8.3 审批门

| 阶段 | 做什么 |
|---|---|
| 进入 | 用实例字段求每步 `when` → 本轮 plan；建审批单（首次）或新一轮；为第一步建任务：或签 1 个任务多条候选；会签按可枚举的审批人每人 1 个任务 |
| 决定 | 校验顺序（2026-09-28 与前端对齐）：**先 409**（任务已被处理 / 已被他人领取 —— 页面过期时先提示「请刷新」，不先报规则错）→ **再 403**（① 自审 ⑤ 跨步互斥 · 非领取人 · 不在候选）→ **最后 422**（② 驳回缺原因）；最终以条件更新落库，并发的第二人仍得 409。驳回 → 取消本轮其余任务 → 触发 `onRejected`；通过 → 或签即步完成 / 会签等齐 → 下一步或触发 `onApproved` |
| 撤回 | ③ 只有发起人、只在待审；取消本轮任务 → 触发 `onWithdrawn` |
| 事件 | `approval.task_created` · `approval.completed{roundNo, result}`（幂等键 `approvalNo:roundNo`） |

### 8.4 外部确认门

| 步 | 做什么 |
|:-:|---|
| 1 | 进入状态：生成 `confirmToken`（随机、一次性），存实例；发 `instance.awaiting_confirmation{instanceNo, topic, token, subject, fields}`；调度超时 |
| 2 | 外部系统校验后调 `POST …/confirmations/{token}` `{result: CONFIRM\|REJECT, reason?}`（应用凭证） |
| 3 | 令牌仍有效且实例仍在该状态 → 条件更新作废令牌 → 触发对应 `system` 迁移；重复回复返回首次结果 |
| 4 | 超时仍未回复 → 触发 `onTimeout` |

这是**业务前置校验的通用落法**：如「合同生效前查时间段不重叠」「代理入驻通过后激活成功才算生效」。

### 8.5 SLA 计时

| 时机 | 做什么 |
|---|---|
| 指标起算 | 按目标矩阵取时长与日历；算 `due`（自然时间或逐段累加工作时段、跳节假日）；`epoch+1` 调度 `sla-due`，另调度 `sla-warn` |
| 暂停 / 恢复 | 暂停：记 `pausedSince`，`epoch+1`；恢复：累计暂停时长，按剩余时长重算 `due`，`epoch+1` 重新调度 |
| 条件变化 | 重新匹配矩阵，从原起算点扣除已暂停时长重算 |
| 停止 | 按时 → `MET`，逾期 → 保持 `BREACHED` 并记实际时长 |
| 到期 / 预警触发 | 比对 `epoch`，不符即无操作；否则标记并发 `sla.breached` / `sla.warning` |
| 兜底 | 每 10 分钟扫「未暂停且已过期仍 `RUNNING`」的指标补触发 |

### 8.6 工单

| 动作 | 工单模块 | 调流程模块（同进程同事务） |
|---|---|---|
| 建单 | 字段校验 → 去重（唯一键占位，撞键即附加到既有单）→ 写工单与字段索引 → 派生范围标签 | `instances.start(process, fields, participants, scopes, slaPolicies)` → 按派单策略建办理任务 |
| 流转 | —— | `instances.transition(...)` |
| 派单 / 领取 / 转派 / 升级 | 升级打标记 | `tasks.*` · 参与者变更 |
| 改字段 | 更新值与索引；标签来源字段变了则重算标签 | `instances.updateFields`（可能触发 SLA 条件重算） |
| 合并 | 被并单记去向 | 被并单走类型里配置的合并迁移 |
| 快照同步 | 订阅 `InstanceTransitioned` / `SlaChanged` → 更新状态快照、是否未结、SLA 快照；关单清去重占位 | —— |

### 8.7 事件投递

| 步 | 做什么 |
|:-:|---|
| 1 | 业务写操作同事务写 `plat_outbox` |
| 2 | 周期任务（5 秒；db-scheduler 保证单实例执行）取到期行 → 按空间 / 账户的订阅展开 → HMAC 签名投递 → 每次写投递记录 |
| 3 | 2xx 完成；否则退避（1m · 5m · 30m · 2h · 12h · 24h × 3）；耗尽标记失败、告警、可重投 |

## 九、定时（db-scheduler）

| 任务 | 类型 | 任务 ID | 触发后 |
|---|---|---|---|
| `sla-due` · `sla-warn` | 一次性 | `ws:clockId:epoch` | §8.5 |
| `task-due` | 一次性 | `ws:taskNo:epoch` | 标记到期、发事件 |
| `claim-timeout` | 一次性 | `ws:taskNo:claimEpoch` | 仍相符则放回 |
| `gate-timer` · `confirm-timeout` | 一次性 | `ws:instanceNo:gateEpoch` | 仍在该状态则触发门的迁移 |
| `assign-timeout` | 一次性 | `ws:ticketNo:epoch` | 外部指定超时 → 兜底策略 |
| `outbox-relay` | 周期 5 秒 | —— | §8.7 |
| `sla-reconcile` · `claim-reconcile` | 周期 10 分钟 | —— | 兜底 |
| `idempotency-purge` · `confirm-token-purge` | 每日 | —— | 清理 |

| 要点 | 说明 |
|---|---|
| 任务不带数据 | 信息全编进任务 ID（≤ 100 字符），不用 db-scheduler 的序列化 |
| epoch 防旧 | 重排不依赖取消成功，旧任务触发后比对 epoch 无操作 |
| 与事务的关系 | 回滚 → 触发时 epoch 不符；调度丢失 → 兜底扫描补上；两种情况都正确 |

## 十、一致性与并发

| 场景 | 保证 | 手段 |
|---|---|---|
| 一次写操作 | 强一致 | 单事务 |
| 模块之间（同进程） | 强一致 | 共用事务 |
| 服务 → 接入方 | 至少一次，同对象可判序 | 发件箱 + `seq` / `roundNo` |
| 接入方 → 服务 | 恰一次效果 | 幂等键 |
| 并发迁移 / 领取 / 决定 / 确认回复 | 只一人成功 | 条件更新 |
| 同对象重复发起、同键重复建单、轮转游标 | 至多一个 | 唯一键 / 条件更新（04 §五） |

## 十一、安全

| 层 | 做法 |
|---|---|
| 空间隔离 | 仓储方法第一个参数是类型化的 `WorkspaceId`；SQL 必带空间条件（架构测试）；跨空间 → 404 |
| 应用 | 凭证 → 应用 → 可访问空间集合；请求的空间不在集合内 → 404 |
| 成员 | 令牌校验（JWKS / 内省，结果按有效期缓存）→ 声明映射；缺声明 = 无权限（fail-closed） |
| 产品权限 | 角色 → 权限目录；每个用例声明所需权限 |
| 可见性 | §7.2；数据范围外按不存在处理 |
| 请求体 | DTO 白名单；状态、办理人、审计字段不可经请求体改 |
| 凭证与密钥 | 凭证只存哈希；签名密钥加密存储；日志不打令牌 |
| 审计 | 定义发布、权限与角色变更、凭证操作、联邦配置变更写审计 |

## 十二、关键决定

| # | 决定 | 放弃 | 为什么 |
|:-:|---|---|---|
| D1 | 产品化：概念、角色、流程、字段全为租户数据；现有系统按映射适配 | 为现有系统定制 | 用户定；附录 A 已验证覆盖 |
| D2 | 平台层独立（租户 · 身份 · 接入 · 投递） | 塞在流程模块里 | 后续能力复用；流程模块只管流程 |
| D3 | 账户 → 空间两级 + 定义继承 | 单层租户 | 平台伙伴模式（一次定义、多客户隔离） |
| D4 | 轻量成员目录（令牌即时开通 + 同步） | 无目录 / 完整 IAM | 派给某人、组内会签、轮转派单都需要知道组里有谁；IAM 不是本产品 |
| D5 | 状态类别驱动通用行为 | 按状态名 / 业务角色 | 各客户状态名不可能统一 |
| D6 | 一种流程定义 + 状态上的门（审批 · 外部确认 · 定时） | 状态机与审批流分两种定义 | 概念更少；审批与工单天然组合 |
| D7 | 业务前置校验走外部确认门（异步） | 同步回调 / 界面交给宿主 | 服务不同步调用接入方；任何平台都能接 |
| D8 | 自研引擎 + `JdbcClient` | Flowable 等 | [20](../20-去MyBatis-引擎重评.md) |
| D9 | 条件只做字段比较 | 表达式语言 | 服务不执行租户脚本 |
| D10 | 可筛选字段写索引表（类型化值列） | 全放 JSON 查 | 两库都能走索引 |
| D11 | 范围标签多值不限维度 | 固定锚点列 | 通用；不为某客户的「站点 / 代理」建列 |
| D12 | db-scheduler + 任务不带数据 + epoch | 扫表 / Quartz | 精确、多实例安全、结果不依赖取消 |
| D13 | 本期不做 AOT | —— | 用户定 |
