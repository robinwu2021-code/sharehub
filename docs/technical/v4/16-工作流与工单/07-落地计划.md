## 一、阶段

| 阶段 | 做什么 | 在哪 | 验收 | 依赖 |
|:-:|---|---|---|---|
| **W1** | 建 `workflow/` 聚合：`workflow-api`（状态机 + 审批契约）· `workflow-store` · `workflow-core`（形态 A）；契约测试与架构规则 | powerbank `backend/workflow/` | 模块自测在 H2 · MySQL · PostgreSQL 各绿；`mvn -pl workflow -am verify` 不依赖任何 `sharehub-*` | 无 |
| **W2** | powerbank 14 个状态机迁到 `workflow-api`；两条前后端一致卡口改读 `graph()` | powerbank | 全量测试**一条不改**仍绿；每个状态机一条负对照 | W1 |
| **W3** | powerbank 合同审批接入（最复杂：条件会签），再接代理入驻、提现 | powerbank | 既有用例全绿；四条内建规则、轮次保留、回调幂等各一条负对照 | W1 |
| **W4** | 建 `workorder/` 聚合（形态 A）；powerbank 运维工单接入，并掉 `WorkOrderService` 与 `WoOpsService` | powerbank `backend/workorder/` | 既有用例全绿；SLA 暂停 / 超时 / 改派 / 去重开单各有用例 | W1 · 待定 #2 |
| **W5** | ichain、tradeagent 的 `AuditTask` 迁到审批队列模式 | 各自 | 既有测试不改仍绿 | W3 |
| **W6** | ai-shop：状态机（25 条边补事件名）→ 商品审核 → 售后 | ai-shop | 同上 | W2 ~ W4 · ai-shop 排期 |
| **W7** | ai-erp、ai-neargo 只接状态机 | 各自 | 同上 | W2 |
| **W8** | `workflow-svc` / `workorder-svc` + 形态 B 客户端、发件箱、回调、对账 | 两个模块内 | 同一套 powerbank 用例在 `mode=remote` 下全绿；回调重复 / 丢失 / 乱序各一条用例 | W3 · W4 · **出现服务化信号时再做**（03 §三） |

W5、W6、W7 互不依赖，可以并行。W8 不在关键路径上：形态 A 跑通即可交付，服务化等信号。

## 二、Nexus 就绪前怎么共用

| 项 | 做法 |
|---|---|
| 源码 | 只在 powerbank 的 `backend/workflow/`、`backend/workorder/` 里改 |
| 其他项目 | 逐字复制两个目录 |
| 防漂移 | 每个副本带一条测试：计算模块源码的校验和，与 `MODULE_SOURCE.sha256` 比对；不一致即红 |
| 登记 | 各项目 `known-pending-shared.txt` 记一行 |
| Nexus 就绪后 | 各项目删副本、改依赖构件；包名不变，调用方零改动 |

## 四、风险

| 风险 | 概率 | 影响 | 应对 |
|---|:-:|:-:|---|
| 迁移中无意改变行为 | 中 | 高 | 硬约束「既有测试一条不改仍绿」+ 逐项负对照 |
| 形态 B 暴露出业务回调不幂等 | 中 | 高 | 从 W3 起契约测试就强制幂等（R3），不等 W8 |
| ai-shop 25 条边命名拖延 | 高 | 中 | 先用 `projection()` 保持旧调用点，命名随后补 |
| 副本漂移 | 中 | 中 | 校验和测试 |
| 工单锚点落法有争议 | 中 | 高 | 待定 #2 先拍板再开 W4 |
| 模块被某个项目的特例带偏 | 中 | 中 | 特例一律走数据或产品侧接口；模块代码里出现产品名词由架构测试拦 |
| 维护人不到位 | 高 | 高 | 两个模块各一名维护人 |
