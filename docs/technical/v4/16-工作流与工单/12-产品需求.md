## 一、产品定位

**一个给所有业务系统共用的「事情找人」平台**：审批要人批、工单要人办、超时要人管。业务系统负责「事情本身」（合同、售后、设备），平台负责「谁来办、办到哪、超没超时、全过程记录」。

| 目标 | 度量 |
|---|---|
| 一处待办：一个人所有要办的事在一张列表 | powerbank 运营台与 ai-shop 商家端各自的「待办」入口都指向平台数据 |
| 流程有据可查：任何一单能回答「谁、何时、为什么」 | 详情页时间线覆盖 100% 动作 |
| 超时看得见：SLA 超时在发生前预警、发生后可追责 | 看板超时数 · 达标率按受理方可查 |
| 新业务接入不改平台 | 新增一个工单类型 / 审批流程 = 业务登记定义，平台零发版 |

## 二、角色

| 角色 | 是谁 | 用哪些页面 |
|---|---|---|
| **办理人** | powerbank 运维员工 / 代理；ai-shop 商家 | 待办中心 · 工单详情 · 抢单池 |
| **审批人** | powerbank 运营 / 财务；ai-shop 平台运营 | 待办中心 · 审批详情 |
| **审核员** | ichain / ai-shop 商品审核员（队列形态） | 审核队列 |
| **运营管理员** | 各业务的运营负责人 | 工单工作台 · 看板 · 统计 · 运营配置 |
| **平台管理员** | 维护平台本身的人 | 接入管理 |
| **接入研发** | 各业务后端 | 不用界面，走 API（10 §五） |

登录与权限**由各业务系统提供**：平台页面嵌在各业务运营台里（powerbank 先行，页面进 ops-web 菜单），操作人信息与数据范围由宿主传入。平台首版**不做**自己的登录页。

## 三、功能需求

### F1 待办中心

| 项 | 内容 |
|---|---|
| 用户故事 | 作为办理人 / 审批人，我打开一个页面就能看到所有等我办的事，不用分别去审批页和工单页翻 |
| 内容 | 审批任务与工单**混排**一张列表；每行：类型徽章（审批 / 工单 / 可抢）、标题、业务对象摘要、优先级、剩余时限（超时红色）、来源系统 |
| 交互 | 筛选：全部 / 审批 / 工单 / 可抢单；排序默认按到期时间；点行进详情；顶部数量角标 = 未办数 |
| 验收 | ① 只显示「我够资格办」且在我数据范围内的（fail-closed）② 别人抢走 / 办完的行即时消失 ③ 空态文案说明「没有待办 ≠ 没有工单」并给去处 |

### F2 审批处理

| 项 | 内容 |
|---|---|
| 用户故事 | 作为审批人，我要看清这单是什么、谁提交的、前面几轮为什么被驳回，再做决定 |
| 内容 | 业务对象卡（标题 · 摘要 · 关键属性，如分成比例 / 金额）· 步骤进度条（当前步高亮，条件步标「按条件触发」）· **全部轮次**的历史（每轮每步谁、何时、决定、原因，永不覆盖）· 证据附件 |
| 交互 | 通过 / 驳回两个动作；**驳回必须填原因**（不填不能提交）；提交人打开自己提交的单：动作区显示「不能审批自己提交的单」并给撤回入口；财务会签步对运营审批人显示「跨步互斥：您已审批过上一步」 |
| 验收 | 五条内建规则（08）各有一条界面表现：自审拦截 · 驳回必填原因 · 撤回仅提交人且仅待审 · 并发第二人提交提示「已被他人处理，请刷新」 · 跨步互斥提示 |

### F3 审核队列

| 项 | 内容 |
|---|---|
| 用户故事 | 作为审核员，我从队列领一条、审完再领下一条；领了没审完的超时自动回队列，不会压在我手里 |
| 内容 | 队列切换（如资质 / 商品 / 验厂）· 每队列未领取数 · 列表：优先级、等待时长、证据缩略 |
| 交互 | 「领取」→ 行进入「我在审」区、显示领取倒计时；「放回」；决定后自动带出下一条（可关） |
| 验收 | ① 已被他人领取的行灰掉并显示领取人 ② 领取超时（默认 30 分钟，可配）自动回队列并留痕 ③ 只有领取人能决定 |

### F4 工单工作台

| 项 | 内容 |
|---|---|
| 用户故事 | 作为运营管理员，我要看到所有工单的状态分布、超时情况，能筛能派能催 |
| 内容 | 顶部统计卡：未结 · 处理中 · 即将超时 · 已超时 · 今日关闭；列表：单号、类型、标题、对象、优先级、状态、受理方、SLA 剩余（色条：绿 / 黄 / 红 / 灰=暂停）、来源 |
| 交互 | 筛选：类型 / 状态 / 优先级 / 受理方 / 来源 / 锚点（站点、商户…）；行内动作按当前状态出（派单 / 催办 / 升级）；批量改派入口 |
| 验收 | ① SLA 色条与剩余时间一致，暂停态明确标出 ② 列表按数据范围过滤 ③ 「即将超时」卡可点进筛好的列表（**卡必须可点** —— powerbank 曾有两张死卡的教训） |

### F5 工单详情

| 项 | 内容 |
|---|---|
| 用户故事 | 作为办理人，我在一页里看到这单的全部：对象、时间线、SLA、附件，并完成我这一步 |
| 内容 | 头部：状态 + SLA 计时（含已暂停时长）；对象卡（快照 + 跳业务系统的链接）；**时间线**：迁移 / 派单 / 升级 / 备注 / 附件 / SLA 事件 / 内嵌审批，一条流水；关联：来源（告警号）、被并单、内嵌审批单 |
| 交互 | 动作条**只显示当前状态可走的事件**（按钮集合来自平台，前端不自己维护）；备注 + 传图；升级 / 接管需填原因；合并选目标单 |
| 验收 | ① 非当前受理方看不到办理动作 ② 等审批 / 等外部时 SLA 显示「已暂停」③ 复核不过回到处理中且时间线可见原因 |

### F6 抢单池

| 项 | 内容 |
|---|---|
| 用户故事 | 作为运维，池里有单我先到先得；抢到就是我的，别人同时抢只有一个成功 |
| 验收 | 两人同时抢：一人成功、另一人得到「已被抢」提示且行消失 |

### F7 统计与看板

| 项 | 内容 |
|---|---|
| 内容 | 按受理方 / 时间段：完成数 · SLA 达标率 · 平均处理时长 · 被接管数（powerbank 代理月度考核、清退门禁「未结单数」都从这里取数）；按类型 / 锚点的趋势 |
| 验收 | 口径与 10 §五 的统计接口一致，两个产品读同一套数 |

### F8 运营配置

| 项 | 内容 |
|---|---|
| 内容 | **SLA 规则**：按（类型 / 流程 × 优先级）配响应 / 解决时限、是否只算营业时间、用哪个日历；**工作日历**：时区 + 每周时段 + 节假日；**队列**：名称、排序、领取超时 |
| 交互 | 改规则只影响新单；界面明示这一点 |
| 验收 | 规则冲突（同组同对象同优先级重复）保存被拒并说明 |

### F9 接入管理（平台管理员）

| 项 | 内容 |
|---|---|
| 内容 | 接入系统列表（代号、回调地址、凭证轮换）；webhook 订阅（事件类型 × URL）；**投递记录**：每次投递的状态码 / 耗时 / 重试次数，失败可一键重投；定义版本列表（图 / 流程 / 类型，含内容哈希） |
| 验收 | ① 投递失败有告警入口 ② 重投幂等 ③ 凭证只显示一次、界面只留提示位 |

## 五、非功能

| 项 | 要求 |
|---|---|
| 权限与身份 | 全部来自宿主业务系统；平台页面不出现登录 |
| 数据范围 | fail-closed：条件给了就只显示范围内的 |
| 多语言 | 界面文案 zh / en / ar 三语；ar 需 RTL（沿用各业务 i18n 方案） |
| 时间显示 | 按接入系统配置的业务时区显示；存储 UTC |
| 空态 / 错误态 | 每张列表都有解释性空态；409 冲突统一提示「已被他人处理，请刷新」 |

## 六、边界（本版不做）

| 不做 | 原因 / 去处 |
|---|---|
| 审批 / 工单的**提交发起页** | 提交入口在各业务系统（08 R1：人的动作经业务接口进入） |
| 流程图形化设计器 | 定义由研发登记（01 §六） |
| 通知发送 | 平台只发事件；发送归通知组件 |
| 跨系统合并待办门户（单点登录） | 首版页面嵌各业务运营台；门户是将来的独立命题 |
| 独立报表页 | 二期；先保证统计接口口径 |
