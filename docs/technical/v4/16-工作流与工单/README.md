## 一页结论

| 问题 | 结论 |
|---|---|
| 做成什么 | **两个独立模块**：工作流 `workflow/`（状态机 + 审批）· 工单 `workorder/`；各含 `api · store · core · svc` 四个子模块，照 ai-shop 的任务与支付模块 |
| 两个模块的关系 | 工单只依赖 `workflow-api`（为了状态机），不依赖审批引擎；两个都能各自单独部署 |
| 部署形态 | 同一套 core 两种形态：**嵌入**（缺省，强一致）与**独立服务**（出现信号再切，最终一致）；切换只改配置 |
| 让切换只改配置的关键 | 产品侧做完所有判断，引擎只收数据（状态图、流程、类型、操作人上下文、数据范围条件都是数据）；业务回调从第一天起幂等、且不回头调引擎 |
| 谁用 | powerbank · ai-shop（全部）· ichain · tradeagent（审批）· ai-erp · ai-neargo（状态机） |
| 快速集成 | 只要状态机：一个依赖一个定义，≤ 30 分钟；审批 / 工单：一个依赖 + 定义 + 两个 Provider + 回调，自动建表且不占项目迁移版本号 |
| 兼容各项目差异 | `JdbcClient`（MyBatis-Plus / jOOQ / JDBC 都能用）· MySQL 与 PostgreSQL 两套 DDL · 租户列名可配 · 不强加响应信封 · 表带 `system_code` |
| 托管 | 暂由 powerbank 托管（同支付与任务暂由 ai-shop 托管）；groupId、包名中性 |
| 不做 | BPMN 引擎、流程设计器、跨服务 Saga |
| 技术栈 | 以 [21/05 依赖关系](./21-设计方案-重梳/05-依赖关系.md) 为准：Java 21 · Spring Boot 4.0.7 · **自研引擎 + `JdbcClient`**（不用 Flowable / MyBatis，见 [20](./20-去MyBatis-引擎重评.md)）· db-scheduler · Flyway · Testcontainers · ArchUnit；本期不做 AOT |
| 需要你拍板 | 07 §五，最关键：#1 各项目是否排期 · #2 工单数据范围锚点落法 · #3 服务化触发信号；另 [18 §八](./18-技术栈.md) 六项（引擎放行 · 表前缀不一致 · 是否共用数据源 · 前端 Tailwind 分叉 · native 范围 · 形态顺序） |
