| 规则 | 说明 |
|---|---|
| 依赖方向 | `svc → core → store/api`；`client → api`；**业务系统只依赖 `flow-api` 与 `flow-client`** |
| 分包按领域 | `access · definition · approval · workorder · todo · integration`，跨领域只经 `shared/Events`；架构测试守住 |
| 没有业务名词 | 架构测试：`ai.neargo.flow..*` 不得出现 `sharehub` / `shop` / `ichain` 等标识，不得依赖任何产品构件 |
| 定时任务 | 服务自己调度（Spring Scheduling + 库锁），不依赖共用任务服务 —— 它是独立微服务，不能反过来依赖某个产品托管的服务 |

## 二、领域对象模型

### 2.1 聚合与实体总表

| 领域 | 聚合根 | 内部实体 / 值对象 | 引用（跨聚合只用编号） |
|---|---|---|---|
| 接入 | **System** 接入系统 | Credential · WebhookEndpoint | —— |
| 定义 | **Definition** 定义（按 kind 分：Graph / Flow / WorkOrderType） | Graph{State, Event, Edge, Role} · FlowDef{StepDef, Condition, ApproverRule} · WorkOrderTypeDef | System |
| 定义 | **Queue** 队列 · **SlaRule** · **Calendar** | —— | System |
| 审批 | **Approval** 审批单 | Round 轮次 · ApprovalTask 任务 · Decision 决定 | System · Definition(Flow) · Subject |
| 工单 | **WorkOrder** 工单 | SlaClock · TimelineEntry · Assignee · AttachmentRef | System · Definition(WorkOrderType) · Subject · Approval（内嵌审批时） |
| 待办 | **TodoItem**（读模型） | —— | ApprovalTask 或 WorkOrder |
| 集成 | **OutboxMessage** · **IdempotencyRecord** · **WebhookDelivery** | —— | System |

### 2.2 共用值对象

| 值对象 | 字段 | 约束 |
|---|---|---|
| `Subject` | `subjectType` · `subjectNo` · `attrs: map<string, scalar\|list>` · `anchors: [a1, a2, a3]` · `display: {title, summary}` | 不透明引用；`attrs` 只允许标量与标量列表；`display` 是展示快照 |
| `ActorContext` | `actorType`(STAFF·AGENT·MERCHANT·USER·SYSTEM) · `actorNo` · `actorName` · `permissions: set` · `roles: set` · `queues: set` · `tenant` | 每次请求随请求体带；服务不持久化人员目录 |
| `ScopeCondition` | `slots: {1: ALL \| [values], 2: …, 3: …}` | 缺省不过滤；给了即 fail-closed |
| `Assignee` | `assigneeType` · `assigneeNo` · `assigneeName`（快照） | 类型来自工单类型登记 |
| `AttachmentRef` | `mediaId` · `name` · `contentType` · `size` | 只存引用 |
| `Money`（可选属性） | `amount`(minor, long) · `currency` | 只用于 SLA / 条件判断中的金额阈值 |

### 2.3 定义领域

| 对象 | 字段 | 不变式 |
|---|---|---|
| **Graph** | `code` · `version`(内容哈希) · `states[]{name, role}` · `events[]` · `edges[]{event, from, to}` | 恰一个 `INITIAL`；全部状态可达；`(event, from)` 唯一；`TERMINAL` 只能推导不能手标 |
| **FlowDef** | `code` · `version` · `steps[]` · `rules{selfReview, crossStepExclusive, reasonRequiredOnReject}` · `slaGroup?` | ≥ 1 步；步骤代号唯一 |
| **StepDef** | `code` · `when?: Condition` · `approvers: ApproverRule` · `mode`(ANY·ALL) · `allowSelf`(缺省 false) · `dueMinutes?` | —— |
| **Condition** | `{attr, op: EQ\|TRUE\|IN\|GTE\|LTE, value}`，可 `all[]` / `any[]` 一层组合 | 只对 `Subject.attrs` 求值；不含表达式语言 |
| **ApproverRule** | `{kind: PERMISSION\|ROLE\|ATTR\|QUEUE, ref}` | `ATTR` 的 `ref` 指向 `attrs` 里的人员编号列表 |
| **WorkOrderTypeDef** | `code` · `version` · `graphCode` · `noPrefix` · `assigneeTypes[]` · `dispatch`(MANUAL·POOL·RULE) · `slaGroup` · `anchorSlots[3]{name}` · `embeddedFlows[]{event, flowCode}` · `closeReasons[]` | 图里每个状态都有角色；`embeddedFlows` 的事件必须把工单推入 `WAITING_EXTERNAL` |
| **Queue** | `code` · `name` · `orderBy`(PRIORITY·DUE·CREATED) · `claimTimeout` | 成员不在服务里 |
| **SlaRule** | `group` · `target`(类型代号或流程代号，`*` 通配) · `priority`(`*` 通配) · `respondMinutes?` · `resolveMinutes` · `businessHoursOnly` · `calendarCode?` | `(system, group, target, priority)` 唯一 |
| **Calendar** | `code` · `zone` · `weekly[]{dow, from, to}` · `holidays[]` | —— |

### 2.4 审批领域

| 对象 | 字段 | 状态 / 不变式 |
|---|---|---|
| **Approval** | `approvalNo` · `flowCode` · `flowVersion` · `subject` · `currentRound` · `currentStep?` · `status` · `submittedBy` · `submittedAt` · `finishedAt?` · `dueAt?` · `anchors` · `version` | `PENDING → APPROVED \| REJECTED \| WITHDRAWN`；`REJECTED/WITHDRAWN → PENDING`（新轮）；同一 subject 至多一张 `PENDING` |
| **Round** | `roundNo` · `plan[]`(步骤代号) · `attrsSnapshot` · `evidence[]` · `note` · `submittedBy/At` · `result?` · `finishedAt?` | 只增不改 |
| **ApprovalTask** | `taskNo` · `roundNo` · `stepCode` · `rule` · `status` · `claimedBy?` · `claimedAt?` · `decision?` · `reason?` · `decidedBy?` · `decidedAt?` · `dueAt?` · `version` | `OPEN → CLAIMED → DONE`；`OPEN/CLAIMED → CANCELLED`；队列任务只能由 `claimedBy` 决定 |
| **Decision**（值对象） | `APPROVE \| REJECT` · `reason` · `by` · `at` | `REJECT` 必有 `reason` |
| **ApprovalOutcome**（事件） | `approvalNo` · `subject` · `flowCode` · `roundNo` · `result` · `reason?` · `decidedBy` · `at` | webhook 载荷；可重复交付 |

### 2.5 工单领域

| 对象 | 字段 | 状态 / 不变式 |
|---|---|---|
| **WorkOrder** | `orderNo` · `typeCode` · `typeVersion` · `source{kind, ref}` · `subject` · `title` · `description` · `priority` · `status` · `open` · `assignee?` · `inPool` · `escalated` · `closeReason?` · `mergedInto?` · `dedupeKey?` · `anchors` · `ext`(展示用 JSON) · `eventSeq` · `sla: SlaClock` · `createdBy/At` · `closedAt?` · `version` | 每次迁移是图上的边；同 `dedupeKey` 至多一张 `open`；`TERMINAL` 后不可变 |
| **SlaClock** | `ruleId?` · `startedAt?` · `dueAt?` · `pausedMs` · `pausedSince?` · `state`(ON_TRACK·PAUSED·BREACHED·MET) | 暂停不计时；终态停表 |
| **TimelineEntry** | `seq` · `kind`(TRANSITION·ASSIGN·ESCALATE·NOTE·ATTACH·SLA·MERGE·APPROVAL) · `event?` · `from?` · `to?` · `actor` · `content?` · `attachments[]` · `at` | `seq` 单调；只增不改；也是回调幂等键 |
| **WorkOrderTransition**（事件） | `orderNo` · `typeCode` · `event` · `from` · `to` · `seq` · `actor` · `at` · `subject` | webhook 载荷 |

### 2.6 待办与集成

| 对象 | 字段 | 说明 |
|---|---|---|
| **TodoItem** | `todoNo` · `source`(APPROVAL_TASK·WORK_ORDER·POOL) · `sourceNo` · `title` · `subject` · `priority` · `dueAt?` · `eligibility{kind, ref}[]`（谁能办：USER·PERMISSION·ROLE·QUEUE·ASSIGNEE·POOL_TYPE）· `anchors` · `status` | 投影；`myTodos` = 用 `ActorContext` 匹配 `eligibility` ∩ `ScopeCondition` |
| **OutboxMessage** | `id` · `direction`(CALLBACK) · `eventType` · `idemKey` · `targetSystem` · `payload` · `attempts` · `nextAt` · `doneAt?` · `lastError?` | 服务侧只有回调方向 |
| **IdempotencyRecord** | `(systemCode, idemKey)` · `requestHash` · `responseBody` · `status` · `at` | 同键不同内容 → 409 |
| **WebhookDelivery** | `deliveryId` · `outboxId` · `attempt` · `httpStatus?` · `latencyMs` · `at` | 每次投递一行，便于排障 |

### 2.7 关系

| 关系 | 基数 |
|---|---|
| System — 一切 | 1 : N |
| Definition(Flow) — Approval | 1 : N（按版本绑定） |
| Approval — Round — ApprovalTask | 1 : N : N |
| Definition(WorkOrderType) — WorkOrder | 1 : N |
| WorkOrder — TimelineEntry | 1 : N |
| WorkOrder — Approval（内嵌） | 1 : N |
| ApprovalTask / WorkOrder — TodoItem | 1 : 0..1 |
| Approval / WorkOrder — OutboxMessage | 1 : N |

## 三、数据库设计

### 3.1 约定

| 项 | 约定 |
|---|---|
| 库 | 独立库 `neargo_flow`；MySQL 8 / MariaDB 10.6+ 与 PostgreSQL 14+ 两套脚本；H2（MySQL 模式）跑测试 |
| 前缀 | `flw_` |
| 公共列 | `system_code VARCHAR(32) NOT NULL` 在**每张表**；业务表可空 `tenant_code`；时间一律 `BIGINT` 毫秒 UTC |
| 主键 | 自增 `id` + 业务号唯一键 `(system_code, xxx_no)` |
| JSON | MySQL `JSON` / PostgreSQL `JSONB` |
| 不做 | 物理删除、外键约束（应用层保证）、跨库 JOIN |
| 迁移 | 服务自己的 Flyway；历史表 `flyway_schema_history_flow` |

### 3.2 表清单

| 表 | 领域 | 说明 |
|---|---|---|
| `flw_system` | 接入 | 接入系统、凭证哈希、回调地址、时区 |
| `flw_webhook_subscription` | 接入 | 系统订阅哪些事件类型、回调 URL、签名密钥 |
| `flw_definition` | 定义 | 状态图 / 流程 / 工单类型，按版本只增 |
| `flw_queue` · `flw_sla_rule` · `flw_calendar` | 定义 | 运营可维护 |
| `flw_approval` · `flw_approval_round` · `flw_approval_task` | 审批 | —— |
| `flw_work_order` · `flw_work_order_event` | 工单 | 时间线含 SLA 事件 |
| `flw_todo` | 待办 | 投影表 |
| `flw_transition_log` | 共用 | 审批单 / 任务 / 工单每次状态变化 |
| `flw_outbox` · `flw_webhook_delivery` · `flw_idempotency` | 集成 | —— |

### 3.3 DDL（MySQL；PostgreSQL 差异见 3.4）

```sql
CREATE TABLE flw_system (
  id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  system_code VARCHAR(32) NOT NULL, name VARCHAR(128) NOT NULL,
  credential_hash VARCHAR(128) NOT NULL, credential_hint VARCHAR(8) NULL,
  callback_base_url VARCHAR(512) NOT NULL, signing_secret_enc VARCHAR(256) NOT NULL,
  default_zone VARCHAR(64) NOT NULL DEFAULT 'UTC', enabled TINYINT NOT NULL DEFAULT 1,
  created_at_ms BIGINT NOT NULL, updated_at_ms BIGINT NOT NULL,
  UNIQUE KEY uk_system (system_code)
);

CREATE TABLE flw_webhook_subscription (
  id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  system_code VARCHAR(32) NOT NULL, event_type VARCHAR(64) NOT NULL,   -- '*' 全部
  url VARCHAR(512) NOT NULL, enabled TINYINT NOT NULL DEFAULT 1,
  UNIQUE KEY uk_sub (system_code, event_type, url)
);

CREATE TABLE flw_definition (
  id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  system_code VARCHAR(32) NOT NULL,
  kind VARCHAR(16) NOT NULL,                         -- GRAPH / FLOW / WO_TYPE
  code VARCHAR(64) NOT NULL, version VARCHAR(64) NOT NULL,   -- version = 内容 SHA-256 前 16 位
  body JSON NOT NULL, latest TINYINT NOT NULL DEFAULT 1,
  registered_by VARCHAR(64) NOT NULL, registered_at_ms BIGINT NOT NULL,
  UNIQUE KEY uk_def (system_code, kind, code, version),
  KEY idx_latest (system_code, kind, code, latest)
);

CREATE TABLE flw_queue (
  id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  system_code VARCHAR(32) NOT NULL, tenant_code VARCHAR(64) NOT NULL DEFAULT '',
  queue_code VARCHAR(64) NOT NULL, name VARCHAR(128) NOT NULL,
  order_by VARCHAR(16) NOT NULL DEFAULT 'PRIORITY', claim_timeout_sec INT NOT NULL DEFAULT 1800,
  enabled TINYINT NOT NULL DEFAULT 1,
  UNIQUE KEY uk_queue (system_code, tenant_code, queue_code)
);

CREATE TABLE flw_sla_rule (
  id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  system_code VARCHAR(32) NOT NULL, tenant_code VARCHAR(64) NOT NULL DEFAULT '',
  rule_group VARCHAR(64) NOT NULL, target_code VARCHAR(64) NOT NULL, priority VARCHAR(16) NOT NULL,   -- '*' 通配
  respond_minutes INT NULL, resolve_minutes INT NOT NULL,
  business_hours_only TINYINT NOT NULL DEFAULT 0, calendar_code VARCHAR(64) NULL,
  enabled TINYINT NOT NULL DEFAULT 1,
  UNIQUE KEY uk_rule (system_code, tenant_code, rule_group, target_code, priority)
);

CREATE TABLE flw_calendar (
  id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  system_code VARCHAR(32) NOT NULL, tenant_code VARCHAR(64) NOT NULL DEFAULT '',
  calendar_code VARCHAR(64) NOT NULL, zone VARCHAR(64) NOT NULL,
  weekly JSON NOT NULL, holidays JSON NULL,
  UNIQUE KEY uk_cal (system_code, tenant_code, calendar_code)
);

CREATE TABLE flw_approval (
  id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  system_code VARCHAR(32) NOT NULL, tenant_code VARCHAR(64) NULL,
  approval_no VARCHAR(40) NOT NULL,
  flow_code VARCHAR(64) NOT NULL, flow_version VARCHAR(64) NOT NULL,
  subject_type VARCHAR(64) NOT NULL, subject_no VARCHAR(64) NOT NULL,
  subject_display JSON NULL,
  current_round INT NOT NULL DEFAULT 1, current_step VARCHAR(64) NULL,
  status VARCHAR(16) NOT NULL,                       -- PENDING / APPROVED / REJECTED / WITHDRAWN
  submitted_by VARCHAR(64) NOT NULL, submitted_at_ms BIGINT NOT NULL,
  finished_at_ms BIGINT NULL, due_at_ms BIGINT NULL,
  work_order_no VARCHAR(40) NULL,                    -- 内嵌审批时指向工单
  scope_anchor_1 VARCHAR(64) NULL, scope_anchor_2 VARCHAR(64) NULL, scope_anchor_3 VARCHAR(64) NULL,
  version INT NOT NULL DEFAULT 0,
  UNIQUE KEY uk_no (system_code, approval_no),
  KEY idx_subject (system_code, subject_type, subject_no, status),
  KEY idx_pending_due (system_code, status, due_at_ms)
);

CREATE TABLE flw_approval_round (
  id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  system_code VARCHAR(32) NOT NULL, approval_no VARCHAR(40) NOT NULL, round_no INT NOT NULL,
  plan JSON NOT NULL, attrs_snapshot JSON NULL, evidence JSON NULL, note VARCHAR(1000) NULL,
  submitted_by VARCHAR(64) NOT NULL, submitted_at_ms BIGINT NOT NULL,
  result VARCHAR(16) NULL, finished_at_ms BIGINT NULL,
  UNIQUE KEY uk_round (system_code, approval_no, round_no)
);

CREATE TABLE flw_approval_task (
  id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  system_code VARCHAR(32) NOT NULL, tenant_code VARCHAR(64) NULL,
  task_no VARCHAR(40) NOT NULL, approval_no VARCHAR(40) NOT NULL,
  round_no INT NOT NULL, step_code VARCHAR(64) NOT NULL,
  rule_kind VARCHAR(16) NOT NULL, rule_ref VARCHAR(512) NOT NULL,
  status VARCHAR(16) NOT NULL,                       -- OPEN / CLAIMED / DONE / CANCELLED
  claimed_by VARCHAR(64) NULL, claimed_at_ms BIGINT NULL,
  decision VARCHAR(16) NULL, reason VARCHAR(1000) NULL, decided_by VARCHAR(64) NULL, decided_at_ms BIGINT NULL,
  due_at_ms BIGINT NULL, version INT NOT NULL DEFAULT 0,
  UNIQUE KEY uk_no (system_code, task_no),
  KEY idx_todo (system_code, status, rule_kind, rule_ref(128)),
  KEY idx_approval (system_code, approval_no, round_no),
  KEY idx_claim_timeout (status, claimed_at_ms)
);

CREATE TABLE flw_work_order (
  id BIGINT NOT NULL AUTO_INCREMENT PRIMARY KEY,
  system_code VARCHAR(32) NOT NULL, tenant_code VARCHAR(64) NULL,
  order_no VARCHAR(40) NOT NULL, type_code VARCHAR(64) NOT NULL, type_version VARCHAR(64) NOT NULL,
  source_kind VARCHAR(32) NULL, source_ref VARCHAR(64) NULL,
  subject_type VARCHAR(64) NULL, subject_no VARCHAR(64) NULL, subject_display JSON NULL,
  title VARCHAR(256) NULL, description TEXT NULL,
```

## 四、工作流引擎：开源方案评估

### 4.1 我们需要什么

| 需求 | 来源 |
|---|---|
| 定义是**数据**，由业务系统经 API 登记；非 Java 业务也要能登记 | 08 R2、S22 |
| 状态图 + ≤ 3 步审批链 + 工单生命周期；**不需要**网关、并行分支、子流程、补偿、人工建模 | 01 §2.2 六个项目实测 |
| 多系统隔离、数据范围锚点、领取 / 或签 / 会签 / 轮次保留 | 00 |
| Java 21 · Spring Boot 4.0.x（`neargo-parent`）· MySQL 与 PostgreSQL | 01 §2.1 |
| 没有运维流程引擎集群的人 | 现状 |

### 4.2 候选

| 方案 | 形态 | 许可 | 能力 | 对我们的问题 |
|---|---|---|---|---|
| **Flowable** 7.x | 嵌入式库 + Spring Boot starter；BPMN / CMMN / DMN | Apache 2.0 | 完整 BPMN 引擎、任务 / 候选组 / 认领、历史 | 流程要写成 BPMN XML（要么业务写 XML，要么我们把数据定义翻译成 BPMN 再喂它）；自带 ACT_* 二十余张表且不带 `system` 维度；候选人模型是「用户 / 组」需要同步身份目录；**Boot 4.0.x 兼容需实测**（官方 starter 面向 Boot 3.x 线） |
| **Camunda 7** | 嵌入式；BPMN / DMN | Apache 2.0；**社区版已宣布终止维护**（2025-10） | 同上 | 不该新建依赖 |
| **Camunda 8** (Zeebe) | 独立集群（broker + Elasticsearch / OpenSearch）+ 客户端 | 8.6 起 Camunda License 1.0（源代码可得、非 OSI 开源） | 大规模编排 | 运维一个集群；许可不是开源；我们的流程规模用不上 |
| **Temporal** | 独立集群（Go）+ Java SDK | MIT（服务端）| 持久化工作流、重试、定时器极强 | 面向**代码即工作流**：流程是 Java 代码，不是可由外部系统登记的数据；需要运维集群；审批 / 待办 / 认领这些人机模型要自己做 |
| **Netflix Conductor / Orkes Conductor OSS** | 独立服务 + JSON 定义 | Apache 2.0（Netflix 仓库 2023-12 归档，社区在 conductor-oss 延续） | JSON 定义、HTTP 任务 | 面向服务编排而非人工审批；自带 Elasticsearch / Redis 依赖 |
| **Activiti 7 / 8** | 嵌入式 | Apache 2.0 | BPMN | 社区活跃度低于 Flowable |
| **jBPM / Kogito** | 嵌入式（Quarkus 优先） | Apache 2.0 | BPMN | 与 Spring Boot 4 线不匹配 |
| **Spring Statemachine** | 库 | Apache 2.0 | 状态机（含区域、层次） | 只覆盖状态机；配置是代码 / 枚举，不是可登记的数据；比我们的需求重 |
| **COLA Statemachine / Squirrel** | 库 | Apache 2.0 / MIT | 轻量状态机 DSL | 同上；`Squirrel` 已多年不更新 |
| **自研**（状态图 + 审批链 + 工单内核） | 本服务 | —— | 恰好覆盖 §四 4.1 | 要自己写、自己测；但模型本来就要为多系统、锚点、领取、轮次定制 |

### 4.3 结论

| 决定 | 理由 |
|---|---|
| **核心自研**，不引 BPMN 引擎 | 六个项目的流程都 ≤ 3 步、无网关无并行；引擎带来的表、建模语言、身份同步，每一样都和「定义是数据、多系统隔离、非 Java 业务可接」冲突。自研部分是有界的：状态图执行（≈ 300 行）、审批链（计划求值 + 任务 + 五条规则）、工单内核 |
| **不引 Spring Statemachine 等状态机库** | 我们的图是数据（JSON）、要能导出给前端和其他系统；这些库的配置在代码里，反而多一层翻译 |
| **可选后备**：若将来出现并行会签树、子流程、动态流程编排等真需求 | 选 **Flowable**（许可干净、可嵌入、有 Spring 生态），以「我们的数据定义 → 生成 BPMN」的方式接入，对外 API 不变。前提：在 Boot 4.0.x 上实测通过 |
| 复用的开源件（非引擎） | Spring Boot 4 · Spring JDBC `JdbcClient` · Flyway · Micrometer · Jackson · springdoc-openapi（生成 OpenAPI）· Testcontainers（MySQL / PostgreSQL 双库测试）· ArchUnit（架构规则）· ShedLock 或库锁（多实例定时任务互斥） |

## 五、对外接口

### 5.1 通用约定

| 项 | 约定 |
|---|---|
| 基路径 | `/api/flow/v1`；大版本进路径，小改动向后兼容 |
| 认证 | `Authorization: Bearer <系统凭证>`；服务由凭证解析出 `system_code` 并**覆盖**请求里任何自称的系统代号 |
| 幂等 | 所有写请求带 `Idempotency-Key`（≤ 128 字符，调用方保证唯一）；同键同内容返回首次结果；同键不同内容 → 409 |
| 操作人 | 写请求体的 `actor` 字段（`ActorContext`）；读请求用 `X-Actor`（Base64 JSON）或查询体 |
| 数据范围 | 读请求体 / 查询体的 `scope` 字段（`ScopeCondition`）；缺省不过滤 |
| 分页 | `page`（从 1）· `size`（≤ 200）；返回 `{list, total, page, size}` |
| 时间 | 一律 epoch 毫秒 |
| 错误 | `{ "error": "flow.approval.self_review", "message": "…", "args": {…}, "traceId": "…" }`；HTTP 400 / 403 / 404 / 409 / 422 |
| 并发冲突 | 409 + `flow.state_changed`，调用方重读后重试 |
| 契约真源 | `flow-svc` 生成的 `openapi.yaml` 入库；Java 客户端与其他语言 SDK 都从它生成或对照 |

### 5.4 Webhook

| 项 | 约定 |
|---|---|
| 方向 | 服务 → 业务系统的 `callback_base_url` + 订阅 URL |
| 事件类型 | `approval.completed` · `approval.task.created` · `approval.task.due` · `work_order.transitioned` · `work_order.assigned` · `work_order.escalated` · `work_order.sla.breached` · `work_order.closed` |
| 载荷 | `{ "eventId", "eventType", "systemCode", "occurredAt", "idemKey", "data": {…} }`；`data` 为 `ApprovalOutcome` 或 `WorkOrderTransition` 等 |
| 签名 | 头 `X-Flow-Signature: t=<ms>,v1=<hex>`；`v1 = HMAC-SHA256(secret, t + "." + body)`；接收方校验时间窗 ±5 分钟 |
| 幂等键 | `approval.completed`：`approvalNo:roundNo`；`work_order.*`：`orderNo:seq`；接收方按键去重 |
| 成功判定 | HTTP 2xx；其他一律重试 |
| 重试 | 指数退避：1m · 5m · 30m · 2h · 12h · 24h，共 8 次；耗尽 → 告警并留在投递记录，可手工重投 |
| 顺序 | 不保证跨事件顺序；同一对象内按 `seq` / `roundNo` 由接收方判序 |
| 对账 | 业务系统对本地「审批中 / 处理中」超阈值的对象调 `GET /subjects/{type}/{no}/history` 补推 |

### 5.5 权限与隔离

| 层 | 做法 |
|---|---|
| 系统级 | 凭证 → `system_code`；所有 DAO 强制带 `system_code`；跨系统查询 → 404（沿用 ADR-025 验收） |
| 人级 | 服务只校验「这个 `actor` 是否为该任务 / 工单的合法办理人」（资格匹配 + 领取人 + 受理方）；业务级权限由业务系统在调用前用自己的权限码拦 |
| 数据范围 | 读接口按 `scope` 过滤锚点列；给了即 fail-closed |
| 管理接口 | `/systems/*`（登记系统、轮换凭证）只对运维凭证开放，独立于业务凭证 |

### 5.6 版本与兼容

| 项 | 约定 |
|---|---|
| 接口 | `/v1` 内只加字段、不删不改；破坏性变更起 `/v2` 并行至少一个季度 |
| 定义 | 进行中的审批按提交时的 `flowVersion` 走完；新版本只影响新提交 |
| Webhook | 事件类型只增；载荷只加字段 |
| 客户端 | `flow-client` 版本 = 服务 API 版本 + 补丁号；其他语言按 `openapi.yaml` 生成 |
