### 1.2 规则

| 项 | 规则 |
|---|---|
| 共享代码放哪 | 技术底座与嵌入式能力库 → `neargo-framework`（框架 + `components/`）；**共用服务**（支付、任务）→ 暂在 ai-shop；产品之间除「本项目依赖 ai-shop 发布的三个服务客户端 / 契约构件」外**互不依赖** |
| 依赖方式 | 只经 Nexus 坐标（Nexus 就绪前经本机 `mvn install`）；不用 git submodule、不跨仓库相对路径引用 |
| 跨仓改动 | 框架 / 组件：先在 `neargo-framework` 提改动 → 跑两个产品的兼容矩阵 → 打标签发版 → 产品升 BOM 版本。共用服务：**需求提给 ai-shop，由 ai-shop 统一改**、发版，本项目升客户端版本并更新实例 |
| 版本与标签 | 框架（含组件）一条语义化版本线（仓库内标签 `v2.1.0`）· 共用服务随 ai-shop 发版 · 本项目 `sharehub-v0.3.0` · 产品版本与框架版本无关 |
| 本地联调框架改动 | 在框架仓库改完 `mvn install`（2.x 起；1.x 阶段只 verify，见 13 §二），产品临时把 `neargo.version` 指到本地 `-SNAPSHOT`；**提交前改回 release 版本**（发布 profile 的 enforcer 会拦） |
| 部署产物 | 产品自己的进程（`sharehub-app` · `sharehub-app-gateway`）由产品仓库构建；**共用服务的进程由 ai-shop 部署**（`ai-shop-pay` · `ai-shop-job`），本项目不再另起实例，只在它们的配置里登记 `system=SHAREHUB` 与目标地址（[ADR-025](../ADR/ADR-025-直接复用ai-shop在跑的支付与任务服务-多系统改造.md)） |

### 4.2 `backend/`：目录即层级

与框架同一个思路：**顶层目录就是层级**，只许依赖更低的层；目录只做分组，不是 Maven 父 POM（根 `pom.xml` 直接列 `foundation/sharehub-common` 这样的路径）。

| 目录 | 层 | 放什么 | 可依赖 |
|---|---|---|---|
| `foundation/` | 产品底座 | 错误码、业务号前缀、实体基类、隔离登记骨架、认证产品层 | 框架 |
| `contracts/` | 契约 | 跨模块 / 跨进程的 Port、DTO、事件 | foundation 中的 `sharehub-common` · 框架 L0–L1 |
| `domains/` | 业务域 | 四组业务域（jar，不可独立启动） | foundation · contracts · 组件 · 共用服务的客户端 / 契约 |
| `gateway/` | 协议对接 | 内核 · 传输 · 厂商驱动 | foundation（不含 auth）· contracts |
| `apps/` | 进程 | 两个可执行 jar：只有这里配 `spring-boot-maven-plugin` | 以上全部（`sharehub-app` 不依赖 gateway，反之亦然） |
| `support/` | 非生产 | 演示种子 · 测试支撑 | 按需；不进生产构建 |

### 4.3 持久化怎么选（落在哪个目录）

| 场景 | 访问方式 | 位置 | 隔离 |
|---|---|---|---|
| 业务表的增删改查 | MyBatis-Plus `BaseRepository` / Wrapper | `domains/*/<domain>/mapper/` | 自动（MP 拦截器） |
| 域内复杂查询 | MP XML Mapper | 同上 | 自动 |
| 跨域报表、看板 | JdbcClient 只读 | `apps/sharehub-app/…/portal/{report,dashboard}/` | 自动（`neargo-data-jdbc` 改写器） |
| 报文、遥测、设备日志的高频追加 | JdbcClient 批量 | `gateway/sharehub-gateway-kernel/…/gw/store/` | 自动；网关库的表按平台级登记 |
| 幂等、Outbox、会话、凭据 | 框架 L3 组件 | 不写代码 | 全局表 |
| 平台级任务（跨租户统计、清理） | JdbcClient + `Isolation.bypass("原因", …)` | `<domain>/job/` | 豁免，登记到 `known-isolation-bypass.txt` |

### 4.4 隔离登记：每个域登记自己的表

```java
// domains/sharehub-svc-core/src/main/java/ai/neargo/sharehub/order/OrderIsolation.java
@Component
class OrderIsolation implements IsolationRegistrar {
    @Override
    public void register(IsolationRegistry r) {
        r.table("ord_order").tenant("tenant_id").scope("AGENT", "agent_no").scope("SITE", "site_no").softDelete("deleted");
        r.table("ord_session_ext").tenant("tenant_id");
        r.table("ord_price_snapshot").global();          // 只随订单读取、无租户列
    }
}
```

三处必须一致，由 `sharehub-app` 的一条架构测试校验：`package-info.java` 声明的表 = 该域 `@TableName` 实体的表 = 该域 `XxxIsolation` 登记的表。任何实体的表没有登记，测试失败；运行期「未登记表拒绝」再兜一层。

| 2 | `ai.neargo:neargo-bom`（**已建**） | MyBatis-Plus · Nacos · ArchUnit 等框架用到的第三方钉版 + 全部框架构件版本 |
| 3 | `ai.neargo:neargo-build-parent`（**已建**，继承 2） | Java 21（enforcer `[21,22)`）· 编码 · 插件 · 发布 profile 的 `requireReleaseDeps` · `distributionManagement`（Nexus，N1 起） |
| 4 | `ai.neargo.sharehub:sharehub-parent` | 本项目模块版本 + **ai-shop 共用服务的三个构件版本**（`shop.services.version`）+ **本项目私有**的第三方钉版 |
| 5 | 各模块 POM | **不写任何版本** |

**判据**：第三方依赖被框架或组件用 → 钉在 `neargo-bom`；随共用服务客户端传入的 → 由 ai-shop 的构件决定；只有本项目用 → 钉在 `sharehub-parent`；Boot 已管理的 → 哪里都不写。

### 5.6 校验

| 规则 | 工具 | 放在哪 |
|---|---|---|
| Java 21 | enforcer `requireJavaVersion [21,22)` | `neargo-build-parent`（已建） |
| 依赖版本收敛 | enforcer `dependencyConvergence` | `neargo-build-parent` |
| 生产构建不许 SNAPSHOT | enforcer `requireReleaseDeps`（发布 profile） | `neargo-build-parent` |
| §5.2 的 ✗ 与 §5.3 的禁止项 | enforcer `bannedDependencies`（每个模块一条规则） | 各模块 POM |
| 包级边界（控制器位置、Port 位置、公共层隔离…） | ArchUnit（`neargo-archrules`） | `sharehub-app` 测试 |
| 表归属三处一致（§4.4） | 架构测试 | `sharehub-app` 测试 |
| `Isolation.bypass` 只减不增 | `known-isolation-bypass.txt` + ArchUnit | `sharehub-app` 测试 |
| 模块 POM 不写版本 | 小脚本检查 `<version>` 只出现在 `sharehub-parent` | CI |

`bannedDependencies` 写法（以业务模块为例）：

```xml
<!-- domains/sharehub-svc-core/pom.xml：业务域之间互不依赖，不依赖进程模块与网关；ai-shop 只放行三个服务客户端 / 契约；不用框架 1.x -->
<plugin>
  <groupId>org.apache.maven.plugins</groupId>
  <artifactId>maven-enforcer-plugin</artifactId>
  <executions>
    <execution>
      <id>module-boundary</id>
      <goals><goal>enforce</goal></goals>
      <configuration>
        <rules>
          <bannedDependencies>
            <excludes>
              <exclude>ai.neargo.sharehub:sharehub-svc-*</exclude>
              <exclude>ai.neargo.sharehub:sharehub-app*</exclude>
              <exclude>ai.neargo.sharehub:sharehub-gateway-*</exclude>
              <exclude>ai.neargo:neargo-common-*</exclude>
              <exclude>ai.neargo.shop:*</exclude>
            </excludes>
            <includes>
              <!-- 白名单：共用服务对产品开放的客户端与契约 -->
              <include>ai.neargo.shop:pay-client</include>
              <include>ai.neargo.shop:shop-job-api</include>
              <include>ai.neargo.shop:shop-job-target</include>
            </includes>
          </bannedDependencies>
        </rules>
      </configuration>
    </execution>
  </executions>
</plugin>
```
