# 05 · 网关

> 所属：[v4 详细规划](./README.md) · 图：[`11-gateway-service.svg`](../diagrams/11-gateway-service.svg)
>
> 本项目有**两种网关，职责完全不同**，别混为一谈：
>
> | | 边缘网关 | 设备网关 |
> |---|---|---|
> | 是什么 | nginx | `sharehub-gateway`（协议对接服务） |
> | 管谁的流量 | 人（运营端、C 端）+ 外部回调 | 设备与厂商平台 |
> | 做什么 | TLS、静态托管、按前缀分流、限流、请求头清洗 | 协议适配、指令下发、事件归一化 |
> | 懂业务吗 | 不懂 | 不懂（只报物理事实） |

# A. 边缘网关（nginx）

## A1. 为什么不上应用层 API 网关

只有 4 个进程、路由是静态前缀表、认证在业务单体里完成 —— Spring Cloud Gateway 之类只会多一跳和一套配置。
**信号**：开放平台 / 互联互通伙伴变多、需要按伙伴计量限流与 API 产品化时再引入。

## A2. 路由表

| 路径 | 上游 | 超时 / 特殊处理 |
|---|---|---|
| `/` | ops-web 静态（`/data/app/sharehub/web/ops-web`） | `try_files` 回落 `index.html` |
| `/c/` | c-app H5 静态 | 同上 |
| `/api/` · `/mp/` | `app.svc.internal:8082` | 读超时 30 秒 |
| `/pay/callback/` | `pay.svc.internal:8092` | 按通道 IP 白名单（通道提供时） |
| `/gw/` | `gw.svc.internal:8091` | 按厂商 IP 白名单（厂商提供时） |
| `/ocpp/` | `gw.svc.internal:8091` | WebSocket 升级；读超时 3600 秒；关缓冲 |
| `/actuator/health` | app | 只放健康检查 |
| `/actuator/` 其余 · `/internal/` | **拒绝（404）** | 进程间调用直连内网，不经 nginx |
| TCP 私有协议 | nginx `stream` → `gw.svc.internal:<端口>` | 每个厂商协议一个端口；也可由网关直接监听 |
| MQTT | EMQX `8883`（TLS，对外）· `1883`（仅内网，网关订阅） | 不经 nginx |

服务寻址统一用 `/etc/hosts` 名（`app.svc.internal` · `pay.svc.internal` · `gw.svc.internal` · `db.svc.internal`），换机器只改一处。

## A3. 安全与清洗

| 项 | 做法 |
|---|---|
| 受信头清洗 | 入站**一律清空** `X-User-Id` `X-Roles` `X-Merchant-Id` `X-Internal-Token` `X-Job-Token`；后端只认令牌反查的身份 |
| 追踪 | 没有 `traceparent` 就生成一个；`X-Request-Id` 同步写入访问日志 |
| 限流（`limit_req`，按 IP） | `/api/auth/login` 5 次/分 · `/api/auth/password/*` 3 次/分 · `/mp/auth/login` 10 次/分 · `/mp/auth/otp` 3 次/分 —— 与应用内按账号 / 手机号的限流**两层叠加** |
| 请求体 | 默认 1 MB；上传类（`/api/**/import` · 报障图片）10 MB |
| CORS | 生产同源不需要；原生 App 壳的来源（`capacitor://localhost` · `https://localhost`）经环境变量 `SHAREHUB_CORS_ALLOWED_ORIGINS` 下发（现网踩过：默认只放 `localhost:3000`，同源 POST 带 Origin 也被拒） |
| TLS | 泛域证书；HSTS；TLS 1.2+ |
| 安全头 | `X-Content-Type-Options` · `Referrer-Policy` · ops-web 加 `Content-Security-Policy` |

## A4. 配置骨架

```nginx
limit_req_zone $binary_remote_addr zone=login:10m rate=5r/m;
limit_req_zone $binary_remote_addr zone=otp:10m   rate=3r/m;

server {
  listen 443 ssl http2;  server_name sharehub.example.com;
  proxy_set_header X-User-Id "";  proxy_set_header X-Roles "";  proxy_set_header X-Merchant-Id "";
  proxy_set_header X-Internal-Token "";  proxy_set_header X-Job-Token "";

  location = /api/auth/login  { limit_req zone=login burst=5 nodelay; proxy_pass http://app.svc.internal:8082; }
  location = /mp/auth/otp     { limit_req zone=otp   burst=2 nodelay; proxy_pass http://app.svc.internal:8082; }
  location /api/              { proxy_pass http://app.svc.internal:8082; }
  location /mp/               { proxy_pass http://app.svc.internal:8082; }
  location /pay/callback/     { proxy_pass http://pay.svc.internal:8092; }
  location /gw/               { proxy_pass http://gw.svc.internal:8091; }
  location /ocpp/             { proxy_pass http://gw.svc.internal:8091;
                                proxy_http_version 1.1; proxy_set_header Upgrade $http_upgrade;
                                proxy_set_header Connection "upgrade"; proxy_read_timeout 3600s; proxy_buffering off; }
  location = /actuator/health { proxy_pass http://app.svc.internal:8082; }
  location /internal/         { return 404; }
  location /actuator/         { return 404; }
  location /c/                { alias /data/app/sharehub/web/c-app/; try_files $uri $uri/ /c/index.html; }
  location /                  { root  /data/app/sharehub/web/ops-web; try_files $uri $uri.html $uri/ /index.html; }
}
```

| 环境 | 边缘 | 说明 |

# B. 设备网关（`sharehub-gateway`）

## B1. 定位与红线

把第三方充电宝 / 充电桩 / 按摩椅等**平台与设备**的各种协议，统一成平台内的**指令**与**事件**。

- **只报物理事实**：`EJECT_OK`（弹出成功）、`ITEM_INSERTED`（有宝插入）、`SESSION_ENDED`（椅子停了），「这是不是归还 / 订单是否结束」由订单的类型模块判定；
- **不碰订单与资金**：厂商云自带的下单 / 代收款接口一律不用，manifest 白名单之外的能力在驱动层不存在；
- **不带个人信息**：指令里只有 `deviceNo` / `slotIndex` / 参数，没有用户身份（PDPL）。

## B2. 三种接入形态

| 形态 | 对端 | 传输模块 | 入口 | 典型 |
|---|---|---|---|---|
| **A 厂商云** | 厂商开放平台 | `transport-http` | 出站：调厂商 API；入站：`POST /gw/callback/{vendorCode}` | 充电宝主流、按摩椅厂商云 |
| **B 设备直连** | 设备本体 | `transport-tcp`（Netty）· `transport-mqtt`（EMQX） | TCP 端口 · MQTT 主题 | 部分柜机、带 4G 模块的按摩椅 |
| **C 行业标准** | 桩本体或桩企云 | `transport-ocpp` | `wss://…/ocpp/{chargePointId}` | 充电桩（OCPP 1.6J / 2.0.1） |

**首个落地**：`transport-http` + 第一家充电宝厂商驱动（覆盖面最大、无长连接运维负担）。

## B3. 驱动与指令 / 事件目录

### B3.1 驱动 SPI（已有，扩展 manifest）

```java
public interface DeviceDriver {
    DriverManifest manifest();                                   // 声明：厂商、设备类型、形态、指令 / 事件白名单
    SendResult send(DeviceRef device, DeviceCommand command);    // 下发（A 调 API；B / C 编码后交传输层）
    List<NormalizedEvent> parse(RawMessage raw);                 // 上行解析（Webhook 体 / 帧 / MQTT 负载）
    default boolean verify(RawMessage raw) { return true; }     // Webhook 验签
}

record DriverManifest(String vendorCode, Set<String> deviceTypes, AccessForm form,       // A / B / C
                      Set<CommandFamily> families, Set<String> commands, Set<String> events,
                      Map<String, Integer> commandTimeoutSec) {}                          // 越出族的指令启动即失败
```

**路由**：按设备的 `(vendor_code, device_type)` 找驱动；一个厂商可以同时供多种设备（`gw_vendor_device_type`）。

### B3.2 指令族（`CommandFamily`：`GENERIC` `POWERBANK` `EV_CHARGER` `SESSION` `LOCKER`）

| 族 | 指令 | 事件 | 用于 |
|---|---|---|---|
| **通用** `GENERIC` | `REBOOT` · `LOCATE` · `QUERY_STATUS` · `SET_CONFIG` · `OTA_PUSH` | `ONLINE` · `OFFLINE` · `HEARTBEAT` · `STATUS_REPORT` · `FAULT` · `FAULT_CLEARED` · `OTA_RESULT` · `COMMAND_ACK` | 所有设备 |
| **充电宝** `POWERBANK` | `EJECT_SLOT` · `EJECT_ANY` · `LOCK_SLOT` · `UNLOCK_SLOT` · `QUERY_SLOTS` | `EJECT_OK` · `EJECT_FAIL` · `ITEM_INSERTED` · `ITEM_REMOVED` · `SLOT_REPORT`（每仓：有无宝、宝号、电量） | 柜机 |
| **充电桩** `EV_CHARGER` | `START_CHARGE` · `STOP_CHARGE` · `UNLOCK_CONNECTOR` · `SET_CHARGING_PROFILE` | `CONNECTOR_STATUS` · `TX_START` · `METER_VALUE` · `TX_STOP`（含表底） | 充电桩（对齐 OCPP，不自创） |
| **计时会话** `SESSION` 🆕 | `START_SESSION{durationSec, program}` · `STOP_SESSION` · `EXTEND_SESSION{addSec}` | `SESSION_STARTED` · `SESSION_PROGRESS`（可选）· `SESSION_ENDED{reason, actualSec}` | **按摩椅**及以后的计时型设备 |
| **储物柜** `LOCKER` | `OPEN_CELL` · `QUERY_CELLS` | `CELL_OPENED` · `CELL_CLOSED` · `CELL_OVERTIME` | 储物柜 |

`SESSION` 族与 `ord_session_ext` 一样**按形态命名而非按按摩椅命名** —— 下一种计时型设备直接复用。
`SESSION_ENDED.reason`：`TIME_UP`（到时自停）/ `USER`（设备端按停）/ `REMOTE`（平台下发停止）/ `FAULT`。

### B3.3 OCPP 映射（充电桩）

| OCPP 消息 | 方向 | 归一化 |
|---|---|---|
| `BootNotification` / `Heartbeat` | 桩 → 平台 | `ONLINE` / `HEARTBEAT` |
| `StatusNotification` | 桩 → 平台 | `CONNECTOR_STATUS` |
| `RemoteStartTransaction` / `RemoteStopTransaction` | 平台 → 桩 | `START_CHARGE` / `STOP_CHARGE` |
| `StartTransaction`（1.6）/ `TransactionEvent Started`（2.0.1） | 桩 → 平台 | `TX_START` |
| `MeterValues` | 桩 → 平台 | `METER_VALUE`（过程只展示） |
| `StopTransaction` / `TransactionEvent Ended` | 桩 → 平台 | `TX_STOP`（带表底，**结算只认它**） |
| `UnlockConnector` · `SetChargingProfile` · `UpdateFirmware` | 平台 → 桩 | 同名指令 · `OTA_PUSH` |

## B4. 指令生命周期

```
ACCEPTED ──► SENT ──► ACKED ──► SUCCEEDED
   │           │         └────► FAILED
   │           └─(超时，重试 N 次)─► TIMEOUT
   └──► CANCELLED（下发前被撤销）
```

| 规则 | 说明 |
|---|---|
| 幂等 | `commandId` 由调用方生成、全局唯一；重复受理返回已有记录 |
| 超时 | 按驱动 manifest 的 `commandTimeoutSec`；缺省：弹出 15 秒 · 启动会话 10 秒 · OCPP 远程启动 60 秒 · 开格口 10 秒 |
| 重试 | 只对「未送达」重试（最多 2 次，退避 2 秒 / 5 秒）；**已送达未回执不重试**（弹两次宝是事故）→ 记 `TIMEOUT` 交业务补偿 |
| 结果回推 | 终态以 `CommandResult` 事件推给业务单体；业务按 `bizType + bizRef` 找到订单 / 工单 |
| 兜底 | 进程内按指令计时；另有任务 `gw-command-timeout-sweep`（每分钟）扫漏网的 |

## B5. 归一化事件格式

```jsonc
{
  "eventId": "EV2609231200050001",            // 全局唯一，消费方按它去重
  "type": "SESSION_ENDED",
  "family": "SESSION",
  "deviceNo": "DV2609010000321", "deviceType": "MASSAGE_CHAIR", "slotIndex": 1,
  "sn": "MC-8F21-0042", "vendorCode": "acme-chair",
  "commandId": "CMD…",                         // 由指令引起时填
  "occurredAt": "2026-09-23 12:10:05",          // 设备时间（有则用）
  "receivedAt": "2026-09-23 12:10:06",
  "payload": { "reason": "TIME_UP", "actualSec": 600 }
}
```

投递：写 `sharehub_gw` 的 outbox → 投递器批量 `POST /internal/events/device`（至少一次，失败退避重试，超限进死信 + 告警）。

## B6. MQTT 主题（直连型设备）

```
sh/{region}/{tenant}/dev/{sn}/up/{event}      设备上行（心跳 / 状态 / 事件）          QoS 1
sh/{region}/{tenant}/dev/{sn}/cmd/{command}   平台下行指令                           QoS 1
sh/{region}/{tenant}/dev/{sn}/ack             指令回执
sh/{region}/{tenant}/dev/{sn}/status          在线态（retain + 遗嘱 LWT）
```

- 客户端 ID = `sn`；每台设备独立凭据；EMQX ACL 限定只能收发自己的主题；
- 网关以共享订阅（`$share/gw/sh/+/+/dev/+/up/#`）消费，多节点自动分摊；
- 前缀由 `pb/` 改为 `sh/`（[01 §5.4](./01-通用设备与命名.md)）。

## B7. 各形态的安全

| 形态 | 凭据 | 校验 |
|---|---|---|
| 厂商云出站 | 厂商给的 AppKey / 证书，存 `gw_vendor_config`（KMS 加密） | — |
| 厂商 Webhook | 每个厂商的签名密钥 | `DeviceDriver.verify`；失败 401 且落报文 |
| MQTT | 每台设备的用户名 / 密码或证书 | EMQX 认证 + ACL |
| TCP 私有协议 | 设备注册包里的 SN + 厂商密钥签名 | 驱动在握手时校验，失败断连 |
| OCPP | 每个 `chargePointId` 的 Basic Auth（安全等级 1/2）或客户端证书（等级 3） | `transport-ocpp` 握手时校验 |

## B8. 伸缩与连接路由

- HTTP 回调无状态，任意扩；
- 长连接（TCP / OCPP）分布在多节点时，`gw_connection`（或 Redis）记 `sn → 节点`；下发指令落到非持有节点时，转发给持有节点；
- 节点宕机：设备自动重连到其他节点，路由表随上线事件更新；
- 按传输拆进程（[技术架构方案 §4.5](../技术架构方案-v4.md)）时，每组节点前面仍是同一个 `/internal/gw` 地址。

## B9. 网关自己的定时任务（经 `sharehub-job` 回调网关）

| 任务 | 周期 | 做什么 |
|---|---|---|
| `device-offline-scan` | 每分钟 | 心跳超时的设备记 `OFFLINE` 事件 |
| `gw-command-timeout-sweep` | 每分钟 | 兜底扫描超时未决的指令 |
| `gw-outbox-dispatch` | 每 5 秒 | 投递设备事件 |
| `gw-log-purge` | 每天 03:20 | 报文 / 心跳按保留期清理（分区直接 DROP） |

## B10. 可观测

按厂商与设备类型出指标：在线率、指令成功率、指令时延 P95、事件积压、Webhook 验签失败数。
某厂商成功率跌破阈值 → 告警（经业务单体的告警模块开单）。
