**核心问题**：后端端点全开放，`X-Roles` 被忽略——前端 `can()` 是唯一"防线"但可绕过。红线未闭合。

## 二、本次继续（运营端后端鉴权 MVP）
1. `spring-boot-starter-security` + `SecurityConfig`（@EnableMethodSecurity；permitAll: 登录/actuator/OPTIONS；其余 authenticated；401/403→Result JSON；CORS/CSRF）。
2. `StaffTokenAuthFilter`（Bearer→内存会话→写 authorities=角色权限码到 SecurityContext；**忽略客户端 X-Roles**）。
3. `PermChecker(@perm)` 通配判定（`*`/`device:*`），语义同前端 `can()`。
4. `AuthController` `POST /api/auth/login`（发 token）+ `RolePerms`（服务端角色→权限码，镜像 ops-web）。
5. 写接口挂 `@PreAuthorize("@perm.can('...')")`（干预/退款审核/派单/指令/保存/拉黑/供应商/代理）。
6. ops-web：登录改调后端换真 token；`http-client` 已带 Bearer。
7. 验证：无 token→401；VIEWER token POST 退款→403；ADMIN→200；ops-web 联调不破。

## 二·验收（已完成，实测）
- 无 token→401；login→token；authed 读→200；ops-web 登录换真 token、Bearer 携带、dashboard 200（浏览器实测）。
- RBAC 矩阵（curl）：VIEWER 退款审核/订单干预/建站点→**403「无权限」**；FINANCE 退款审核→200；CS 订单干预→200；ADMIN/BD 建站点→200；**OPS 建站点→403**（有 poi:read 无 poi:create，与前端 can() 精确一致）。
- 红线闭合：后端据 **token 反查**的权限鉴权，忽略客户端 X-Roles。
- 实现：`auth/{RolePerms,PermChecker(@perm),StaffTokenStore,StaffTokenAuthFilter,AuthController}` + `config/SecurityConfig`(@EnableMethodSecurity,无状态,CORS,401/403 JSON) + 9 写接口 `@PreAuthorize("@perm.can('码')")` + GlobalExceptionHandler 补 AccessDenied→403 + ops-web 登录改调 `/api/auth/login`。
