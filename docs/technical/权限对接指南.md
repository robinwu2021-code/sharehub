# 权限对接指南（业务模块集成）

> 状态：对接手册 · 创建 2026-07-12 · 面向**写业务模块的开发**：如何基于权限核心正确接入功能鉴权/数据权限/属主鉴权，而不碰底层。
> 上位：[权限体系设计.md](./权限体系设计.md)（架构）· [运营端权限方案.md](./运营端权限方案.md)（运营端 as-built）· [功能权限清单.md](../requirements/功能权限清单.md)（权限码 SSOT）。
> 铁律：**业务代码只经 `SecurityUtils`/`StaffContext`/`ConsumerContext` 取身份，绝不 import `SecurityContextHolder`；功能鉴权只在 Controller 层 `@PreAuthorize`，Service 不判权限。**

---

## 0. 一分钟上手

| 你要做的 | 运营端（`/api`、`/internal`）| C 端（`/mp`）|
|---------|------------------------------|-------------|
| 认证 | 自动（`StaffTokenAuthFilter`），无需写 | 自动（`ConsumerTokenAuthFilter`）|
| 一个写接口要鉴权 | 方法挂 `@PreAuthorize("@perm.can('模块:资源:动作')")` | 无 RBAC，见"属主鉴权" |
| 取当前登录人 | `SecurityUtils.userNo()` / `StaffContext.agentNo()` | `ConsumerContext.userNo()` |
| 只让看自己的数据 | 注册表锚点（数据权限自动注入）| service 强制 `where c_user_no=当前` + `ConsumerContext.assertOwner()` |
| 会话存哪 | 无感（`TokenStore` 由配置切 memory/redis/mysql/ehcache）| 同 |

## 1. 运营端模块对接（B 端）

### 1.1 端点放置与认证
- 对外走 `/api/**`，域间走 `/internal/**`。落这两个前缀即被 `opsChain` 认证（`anyRequest().authenticated()`），**无需自己写认证**。
- 公开端点（无需登录）才加进 `SecurityConfig.opsChain` 的 `permitAll`（谨慎）。

### 1.2 功能鉴权（每个写接口必挂）
```java
@PostMapping("/api/ops/cabinets/{no}/commands")
@PreAuthorize("@perm.can('device:command:send')")     // ← 唯一要做的
public CommandResult send(@PathVariable String no, @RequestBody Cmd body) { ... }
```
- 权限码格式 `<模块>:<资源>:<动作>`，从 [功能权限清单.md](../requirements/功能权限清单.md) 选；没有就**先在清单里加**再用。
- `@perm.can` 自带通配（`*` / `device:*` / `device:cabinet:*`），语义与前端 `can()` 完全一致。
- **只挂 Controller 方法**；Service 不写鉴权（职责分离）。读接口通常不挂（数据权限兜底），高敏读可挂。

### 1.3 取当前登录人（禁碰 SecurityContextHolder）
```java
String me       = SecurityUtils.userNo();     // 当前员工号
String tenant   = SecurityUtils.tenantId();   // MAIN
String agentNo  = StaffContext.agentNo();      // 代理号(AGENT 才有)
boolean canX    = StaffContext.hasPerm("finance:withdrawal:audit");  // 需要在代码里判权限时
```

### 1.4 数据权限（让查询只返回该员工能看的范围）
数据权限**自动注入 SQL**，你只需让你的表"可被识别"：
1. 表要有归属锚点列（`agent_no`/`region_id`/`site_no`/…）。
2. 在 `auth/DataScopeTableRegistry` 注册该表的锚点：
   ```java
   register("ord_rent", Map.of(ScopeDim.AGENT, "agent_no", ScopeDim.REGION, "region_id"));
   ```
3. 之后 AGENT 查该表自动加 `WHERE agent_no IN(...)`，**你的 Service/Mapper 代码不用改**。
- **未注册的表 = 全局放行**（不过滤）——适合字典/全局配置表。
- **AGENT 是红线**：注册了 AGENT 锚点的表，代理只能看自己 `agent_no` 的数据，前端传参无效。
- **后台任务/事件消费**（无登录人）查这些表，必须豁免：
  ```java
  DataScopeContext.executeWithoutScope(() -> mapper.selectList(...));  // 否则查空
  ```

### 1.5 新增权限码 / 菜单（运行时可配，也可种子）
- **权限码**：加进 [功能权限清单.md](../requirements/功能权限清单.md) → 前端 `lib/permissions.ts` → 后端角色映射（当前 `auth/RolePerms` 种子，或后台 `PUT /api/platform/iam/roles/{no}/permissions` 配到自定义角色）。
- **菜单**：`iam_menu` 加一条（`path`+`perm` 绑查看码）；员工有该 `perm` 即在 `GET /api/auth/menus` 出现。
- **改完即时生效**：后台改角色权限 → 系统 `bump` 版本 → **在线员工下一请求自动刷新**（口径 B），无需重登。

## 2. C 端模块对接（消费者）

### 2.1 端点与认证
- 落 `/mp/**` 即被 `consumerChain` 认证。登录/发码等公开端点在 `permitAll`（`/mp/auth/**` 等）。
- **C 端无 RBAC**，不要挂 `@PreAuthorize`。

### 2.2 属主鉴权（核心：只能碰自己的数据）
```java
// (1) 列表/我的：服务端强制属主条件，忽略前端传的任何 userNo
query.setCUserNo(ConsumerContext.userNo());
mapper.selectPage(page, query);

// (2) 单资源：属主断言，防横向越权(IDOR)
@GetMapping("/mp/trade/orders/{orderNo}")
public OrderVO detail(@PathVariable String orderNo) {
  var o = orderService.get(orderNo);
  ConsumerContext.assertOwner(o.cUserNo());   // 非本人 → 403
  return vo(o);
}
```
- `ConsumerContext.userNo()` 是**唯一可信来源**；**绝不信请求体/参数里的 c_user_no**。
- 敏感字段（手机/证件）返回前脱敏。

## 3. 会话 / TokenStore（对业务无感）

- 你**不直接碰会话**；发/校验 token 由过滤器与 `AuthController`/`ConsumerAuthService` 处理。
- 存储后端由配置切换，**代码零改**：
  ```yaml
  powerbank:
    auth:
      token-store: memory   # memory(默认) | ehcache | redis(多实例推荐) | mysql(sys_token 强持久)
      token-ttl: 2h
  ```
- 需要主动登出/踢人时用 `TokenStore.revoke(token)`（一般在 auth 层，不在业务）。

## 4. 对接检查清单

**运营端**
- [ ] 端点在 `/api` 或 `/internal`。
- [ ] 每个写接口挂 `@PreAuthorize("@perm.can('码')")`，码在功能权限清单里。
- [ ] Service 取身份只用 `SecurityUtils`/`StaffContext`，**无 `SecurityContextHolder` import**。
- [ ] 需按归属收敛的表：加锚点列 + 注册 `DataScopeTableRegistry`。
- [ ] 无登录人的任务/消费用 `DataScopeContext.executeWithoutScope`。
- [ ] 新权限码/菜单已同步清单 + 前端 + 角色映射。

**C 端**
- [ ] 端点在 `/mp`，不挂 `@PreAuthorize`。
- [ ] 所有查询按 `ConsumerContext.userNo()` 过滤；单资源 `assertOwner()`。
- [ ] 不信任前端传的 `c_user_no`；敏感字段脱敏。

## 5. 完整示例

### 5.1 运营端：新增"分润规则删除"接口
```java
// 1) 功能权限清单加码：finance:share_rule:delete
// 2) Controller
@DeleteMapping("/api/trade/share-rules/{ruleNo}")
@PreAuthorize("@perm.can('finance:share_rule:delete')")
public OkResult delete(@PathVariable String ruleNo) {
  return shareRuleService.delete(ruleNo);        // Service 不判权限
}
// 3) 若 share_rule 要按代理收敛：DataScopeTableRegistry 注册 {AGENT:"agent_no"}（表需有列）
// 4) 角色分配：后台给需要的角色勾上 finance:share_rule:delete（内置角色改种子/自定义角色后台配）
```

### 5.2 C 端：新增"我的钱包流水"接口
```java
@GetMapping("/mp/user/wallet/txns")
public PageData<WalletTxn> myTxns(PageReq p) {
  // 强制属主，忽略任何前端传参
  return walletService.pageByUser(ConsumerContext.userNo(), p);
}
```

## 6. 常见坑（都已在核心处置，你需知道）

1. **`@PreAuthorize` 在参数反序列化之后执行**：坏 body（primitive 字段传 null）会先 400/500，到不了鉴权——不是安全漏洞（方法体没跑），但排查 403 时注意先给合法 body。
2. **方法级 `@PreAuthorize` 抛的 `AccessDeniedException` 不走 Security 的 deniedHandler**，由 `GlobalExceptionHandler` 兜成 403 Result——已处理，别再各自 catch。
3. **不要信客户端可信头**：ops-web 是 SPA 会自填 `X-Roles`，后端**只认 token 反查的权限**。你的接口别读 `X-Roles`/`X-User-Id` 做鉴权。
4. **数据权限拦截器只对已注册表生效**：新持久化的域记得注册锚点，否则 AGENT 会看到全量（越权）。
5. **无登录人上下文的查询要豁免**（`executeWithoutScope`），否则数据权限按空范围查空。
6. **C 端别挂 `@PreAuthorize`**（C 端无角色权限），用 `assertOwner`。

## 7. FAQ

- **Q：读接口要不要挂 @PreAuthorize？** 一般不用（数据权限兜底 + 前端 canModule 控入口）；高敏读（如全量导出）可挂。
- **Q：我要在 Service 里判"是不是财务"？** 用 `StaffContext.hasPerm('finance:...')`，不要读角色字符串硬比。
- **Q：AGENT 怎么只看自己设备？** 表加 `agent_no` + 注册锚点即可，登录时会话已强制 `agent_no`，无需你写过滤。
- **Q：切 Redis 要改我的代码吗？** 不用，改配置 `token-store: redis` + 起 Redis 即可。
- **Q：改了角色权限，在线的人要重登吗？** 不用，下一请求自动生效（口径 B）。
