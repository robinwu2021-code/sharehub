## 零、一句话诊断

**页面齐了，流程是断的。** 每个页面都能增改查，但：

1. **状态是手填的**。合同状态、线索阶段、调拨状态、站点生命周期都在编辑表单里用下拉框改。系统不知道「下一步能去哪」，用户也看不到。
2. **对象之间不能跳转**。告警上的工单号是纯文本，工单上的来源告警不是链接，站点详情里的合同看不到详情。
3. **详情只是字段清单**。合同没有详情页；工单详情是一列 `Field`；设备详情没有告警、工单、指令历史。「这件事走到哪一步了、卡在哪、下一步谁做」一个都答不上。
4. **动作缺闭环**。告警关不掉；调拨没有「发出」「收货」按钮；逐件核对无处勾选；工单完工不能传照片。

所以本方案的主线不是加页面，而是三件事：**状态机驱动的动作**、**对象之间可跳转**、**详情页回答「现在到哪了」**。
**一级菜单一个不加**，与功能清单 §11.3 一致。

## 一、共享层：先补 6 个部件，全站复用

现有组件库已有 `PagedTable` · `FormDrawer` · `Drawer` + `Field` · `StatusBadge` · `Timeline` · `ConfirmDialog` · `SiteMap` · `SummaryCard` · `RowActions` · `ReadOnlyNotice` · `EmptyState`。
缺的都是「流程」类部件：

| # | 部件 | 放在 | 做什么 | 用在 |
|---|---|---|---|---|
| C1 | **`transitions` 通用助手** | `lib/types/transitions.ts` | 把现有的 `WO_TRANSITIONS` + `nextActions` 模式泛化：`defineTransitions(table)` → `{ can(status, action), actions(status) }`。每个域只写一张表 | 合同 / 站点 / 机柜 / 调拨 / 告警 / 工单 / 充电宝 |
| C2 | **`StateActions`** | `components/state-actions.tsx` | 输入：状态、迁移表、`action → {label, tone, perm, confirm, drawer}` 描述；输出：主按钮 + `RowActions`。**动作缺权限时显示禁用 + 提示缺哪个码**（规范 §13），不静默隐藏 | 所有详情头、列表行 |
| C3 | **`StatusStepper`** | `components/ui/status-stepper.tsx` | 横向步骤条：已过 / 当前 / 未到三态 + 分支终态（驳回、终止、撤场）。当前步用**文字 + 形状**（实心点 + 粗体）而不只用颜色（规范 §11.4）；窄屏折叠为「第 3 / 5 步 · 待生效」 | 合同 / 站点 / 工单 / 调拨详情头 |
| C4 | **`DetailHeader`** | `components/ui/detail-header.tsx` | 详情抽屉与详情页统一的头：业务号（`body-strong`）+ 名称 + `StatusBadge` + `StatusStepper` + `StateActions`。只负责排版，不含业务 | 所有详情 |
| C5 | **`RefLink`** | `components/ref-link.tsx` | 业务号 → 该对象详情的链接：`<RefLink kind="alarm" no="ALM…" />`。统一路由规则（抽屉用 `?no=`，页面用路径）；对象已归档时加删除线 + tooltip；无权限时显示纯文本 + tooltip 说明缺哪个码 | 全站的 `woNo` / `alarmNo` / `contractNo` / `siteNo` / `cabinetNo` |
| C6 | **`GateChecklist`** | `components/gate-checklist.tsx` | 门禁清单：每项 `✓ / ✗ / —` + 说明 + 「去处理」链接。**全部通过才启用主动作** | 设备上线门禁 · 站点关闭前置校验 · 合同生效 · 代理清退 |

另有两项**表单能力**要补进 `FormDrawer`：

| # | 能力 | 说明 |
|---|---|---|
| C7 | `type: "file"` 字段 | 多文件、进度、失败重试、图片缩略图；按用途（`category`）提示类型与大小。**存储定为 COS、统一经应用服务器上传**（2026-09-25），接口与策略见 [方案-文件上传与COS存储](./方案-文件上传与COS存储.md)；mock 期用对象 URL 并在 mock db 写文件记录 |
| C8 | `type: "entity"` 字段 | 选站点 / 设备 / 员工 / 告警码的带搜索选择器，替换现在的自由文本（调拨的调出 / 调入、通知规则的告警码、巡检的下次执行时间） |

**设计约束**（每个部件都要满足，`/dev/ui` 组件总览页补全状态矩阵）：
颜色只用语义 token；圆角只用五档（抽屉 `rounded-sheet`，徽章 `rounded-chip`，按钮 `rounded-field`）；
抽屉层级 `--z-drawer`；动效 240ms 并尊重 `prefers-reduced-motion`；
类型阶不与 `font-*` / `leading-*` 共存；RTL 用逻辑属性（`ms-` / `me-`），步骤条方向随 `dir` 翻转。

## 二、全站统一的四条页面规则

| # | 规则 | 依据 | 现状反例 |
|---|---|---|---|
| R1 | **状态不进编辑表单。** 状态只能由 `StateActions` 的动作改；编辑表单只改属性 | 流程文档 §五 状态机 | 合同状态下拉、线索阶段下拉、调拨状态下拉 |
| R2 | **列表顶部摘要条可点击筛选**，一张卡 = 一个待办子集 | 规范 §12.1 | 站点概览卡片不可点；告警、工单、合同没有摘要条 |
| R3 | **业务号都用 `RefLink`** | — | 告警的关联工单、工单的来源、站点详情的合同都是纯文本 |
| R4 | **有副作用的动作都要确认**：可逆的走 `ConfirmDialog`，不可逆的（终止合同、退役设备、关闭站点、报废）走 `requireText` | 规范 §12.6 | 恢复营业、撤销合作伙伴、设备重启 / 弹出、告警转工单都没有确认 |

新页面和改到的页面同时满足棘轮：状态用 `<StatusBadge>`（不用内联 `Badge tone={}`）、只读用 `<ReadOnlyNotice>`、空态写清为什么空和下一步做什么。

### 4.1 列表

| 改动 | 说明 |
|---|---|

| 摘要条 | **待我审批** · 60 天内到期 · 已到期未续 · 缺签署件（点击筛选） |
| 筛选 | 状态 · 场地方 · 到期区间 |
| 行动作 | 主按钮按状态：草稿 → 提交；待审批 → 审批（有权限时）；生效中且 60 天内到期 → 续签。其余进 `RowActions` |

### 4.2 表单（新建 / 编辑草稿）

仅草稿可编辑（R1）；待生效之后的条款变更走「补充协议」（L1）。分组：

| 分组 | 字段 |
|---|---|
| 基本 | 合同号（系统生成，只读）· 场地方 · 站点（按场地方收窄；未建站点时允许「签约后建站」）· 签约方联系人 |
| 分成 | **分成模式**（纯分成 / 进场费 / 保底 + 分成 / 免费）→ 按模式 `disabledWhen` 显示：比例 · 保底金额 · 进场费 · 币种；分成基数（实收 / 应收）· 结算周期 |
| 期限 | 生效日 · 到期日 · 自动续约 |

### 4.3 合同详情抽屉（新增，560px）

```
┌ DetailHeader ─────────────────────────────────────────────────────────┐
│ CT2026-0012  · 迪拜购物中心 · [待审批]                  [通过] [驳回] ⋯ │
│ ● 草稿 ── ● 待审批 ── ○ 待生效 ── ○ 生效中 ── ○ 到期                     │
└───────────────────────────────────────────────────────────────────────┘
 条款 │ 签署件 │ 审批记录 │ 版本
```

| 页签 | 内容 |
|---|---|
| 条款 | 按表单分组展示；关联站点、场地方、来源商机都是 `RefLink` |
| 签署件 | 盖章扫描件（C7，可预览 / 下载）+ 签署日期。**「生效」门禁**：待生效 → 生效中需要签署件与签署日期（C6 两项） |
| 审批记录 | `Timeline`：提交、驳回（意见）、撤回、通过、生效、到期、终止，每条带操作人与意见 |
| 版本 | L1：补充协议链，标出每版生效日；L0 只显示「当前版本 v1」 |

| 动作 | 状态 | 交互 | 权限码 |
|---|---|---|---|
| 提交 | 草稿 | 确认 | 候选 `location:contract:submit` |
| 撤回 | 待审批（提交人） | 确认 | 同上 |
| 通过 | 待审批 | 抽屉：意见（选填）；条件加签时显示「需财务加签」（L1） | 候选 `location:contract:audit` |
| 驳回 | 待审批 | 抽屉：意见**必填**，destructive 按钮 | 同上 |
| 上传签署件 | 待生效 | FormDrawer（C7 + 签署日期） | `location:contract:update` |
| 续签 | 生效中 / 已到期 | 新建草稿并预填，旧合同详情显示「已有续签草稿 →」 | `location:contract:create` |
| 终止 | 生效中 | `requireText`（输入合同号）+ 原因 + 终止生效日（L1 走审批） | 候选 `location:contract:terminate` |

> **权限码**：三个候选码未在真源表登记。按惯例，**前端动作与后端端点、真源表登记在同一提交里落**；
> 在那之前这三个动作渲染为禁用，并用 `ReadOnlyNotice` 说明缺哪个码。
> 另注意：新码必须同时登记进 `UI_PERM_MAP`，否则 `can()` 对任何人都返回 false（包括超管的 `*`）——
> 提现「登记打款」按钮不渲染就是这么来的。
