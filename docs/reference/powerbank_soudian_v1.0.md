## 1. 项目概况

### 1.1 背景

君盛科技有限公司在餐厅、酒店、购物中心、健身房等商业场所部署共享充电宝机器，向客户提供充电宝租赁服务。目前已经有共享充电宝租赁 App 和管理后台，但现有报告功能主要以月度交易报表为主，尚不能充分满足以下需求：

- 查看和导出每一笔租赁、扣款、支付及发票的完整明细。
- 自动生成符合适用要求的发票、税务发票或收据。
- 追踪商户收入分成、代理佣金、已付款及未结应付款。
- 管理现有机器、充电宝以及未来新增采购、收货、调拨、维修、损坏或报废的设备。
- 同步 Zoho Books 中的会计、发票及付款数据，执行对账。
- 为运营、销售、财务及管理层提供实时运营和财务看板。

开发商应首先评估现有 App、后台、数据库、支付网关及硬件接口，确定是**升级现有系统**，还是对部分功能进行重新开发。[A §1；B p.10]

### 1.2 项目目标

1. 升级现有用户应用及管理后台，形成统一的共享充电宝“超级应用”。
2. 实时记录、查询、筛选并导出完整租赁交易明细。
3. 自动进行租赁计费、支付状态跟踪及发票/收据处理。
4. 到达设定最长租赁时限时，即使设备尚未归还，也自动**发起**适用的最高租赁金额扣款。
5. 统计商户分成、代理佣金、应得金额、已付金额、调整及未结应付款。
6. 与 Zoho Books 对接，完成会计数据及付款同步和对账。
7. 建立覆盖既有资产与新增采购的完整设备/充电宝库存记录。
8. 按商户、设备、交易、发票及期间生成财务和运营报表。
9. 减少手工操作，提高财务准确性、运营控制能力、对账效率和管理报告质量。[A §2、§15]

### 1.3 系统组成与用户群

[B p.2] 将方案分成**一个系统、两个部分**：

| 部分 | 主要用户 | 范围 |
|---|---|---|
| Part 1：用户超级 App（Super App for users） | 租赁客户 | 扫码租借、租赁前查看价格及封顶规则、计费与收费提示、收据/税务发票 |
| Part 2：管理看板（Management Dashboard） | 运营、销售、财务、管理层及其他授权人员 | 交易和付款实时视图、商户分成、合同到期、库存、发票、报表及 Zoho 数据 |

[A] 同时要求建立统一的**商户、合同、代理、机器及安装地点数据库**，并为管理员、财务、运营和其他授权人员配置不同权限。材料没有要求必须把不同岗位做成彼此独立的 App。

### 1.4 项目业务边界

- **运营系统**：负责客户租赁、机器/充电宝跟踪、订单及支付明细、商户/合同、库存和管理报表。
- **支付网关**：负责实际授权、扣款、退款、处理状态及相关结算信息。是否支持后续扣款须由开发商验证。
- **Zoho Books**：作为会计分录和已记录付款的会计记录来源；商户与代理的实际付款在 Zoho Books 录入，运营系统同步其结果，而非重复手工录入。
- **设备/制造商接口**：如硬件及厂商接口支持，可提供在线/离线、故障、可用充电宝数量等能力。
- **税务与财务规则**：适用阿联酋法规；开票时点、VAT、科目和更正流程需经公司财务人员/税务顾问审核。[A §4—§9]

## 2. 端到端业务流程

### 2.1 从扫码到发票

[B p.3] 展示的用户旅程可整理如下：

```text
客户扫码 / 租出充电宝
          ↓
建立租赁记录（客户、商户、机器、位置、开始时间）
          ↓
按计费规则累计租赁时长及费用
          ↓
    ┌───────────────┴────────────────┐
    ↓                                ↓
充电宝归还                         到达最长租赁时限仍未归还
    ↓                                ↓
按实际使用及适用封顶规则结算         自动发起最高适用收费
    ↓                                ↓
记录支付结果                       记录支付结果、失败/重试/提醒
    └───────────────┬────────────────┘
                    ↓
       按适用法定时点生成发票/收据
                    ↓
           运营管理、财务同步与报表
```

说明：原图主要表达“扫码 → 建立记录 → 时限触发 → 自动扣款 → 开票”。[A] 进一步明确，**实际归还不应成为最高收费发票/收据的唯一触发条件**，且**自动发起扣款不等于扣款成功**。

### 2.2 关键场景

| 场景 | 合并后的原文要求 |
|---|---|
| 正常借还 | 出租时建立记录；归还时记录归还时间、租赁时长、适用费率、应收金额、付款和发票 |
| 进行中 | 持续记录租赁时长、当前费用、商户、机器、用户参考编号及支付/归还情况 |
| 到达最长时限未还 | 发起最高适用租赁金额扣款，记录时间、金额、支付参考号及支付状态 |
| 超时扣款后归还 | 更新归还状态；不得仅因归还自动取消、冲销此前收费 |
| 扣款失败 | 标明失败并支持可配置重试或跟进提醒；同一事件不得重复扣款 |
| 付款后出具单据 | 按适用开票时点生成发票或收据；支持后续关联退款、更正及贷项通知单 |
| 设备变更商户 | 保留交易发生时的商户/设备关联，不重新归属既有历史报表 |

## 3. 用户超级 App 需求

本章结合 [B p.2—p.4] 的客户端描述与 [A §3—§5] 的交易、计费、发票要求。

### 3.1 租赁前

- 用户可以**扫码租赁充电宝**。[B]
- 在开始租赁前向用户清楚展示租赁价格、计费周期、每日或其他适用封顶金额、最长租赁时限和未归还后的收费条件。[A][B]
- 明确展示可能发生的最高租赁收费，用户条款应包含适用收费条件。[A]
- 设备遗失费用如要实施，应作为**独立于最高租赁收费的规则**，须经公司批准并符合法律要求。[A]

### 3.2 租赁过程中

- 客户取出充电宝后自动创建唯一租赁记录，初始状态为“租赁中”。[A]
- 记录租赁开始时间、客户参考编号、商户和机器/位置。[A][B]
- 按已配置计费规则持续计算时间与费用。[A]
- 当达到封顶或最高收费触发条件时，通知功能可用的情况下向客户发送提醒；[B] 特别提到“达到 AED 30 封顶时通知”。
- 客户尚未归还但到达最长时限时，仍应触发最高适用金额扣款流程。[A][B]

### 3.3 归还、收费及凭证

- 记录实际归还时间及设备归还状态，计算租赁时长及适用费用。[A]
- 对于正常归还，[B] 演示“归还后扣费并自动生成税务发票”。
- 对于达到最长时限的未归还租赁，[A] 要求在适用时点自动收费并生成所需单据，无需等到归还。
- 用户可获得相应发票、税务发票或付款收据；发票包含租赁、支付和税务明细。[A][B]
- 已执行最高收费的租赁，后续归还不自动冲销该收费。[A][B]

> **注意**：两份文件没有详细列出客户端注册/登录、历史订单页、支付方式选择、客服或地图查找等界面规格；本合并稿不将这些内容列为已确认的原始要求。

## 4. 租赁交易与计费管理

### 4.1 逐笔租赁记录字段

[A §3] 明确要求每笔租赁至少包含：

| 分类 | 数据字段 |
|---|---|
| 租赁标识 | 唯一租赁交易编号 |
| 客户 | 客户参考编号或客户 ID，满足适用隐私要求 |
| 商户 | 商户名称及唯一编号 |
| 设备 | 设备/机器编号及租赁发生时所在位置 |
| 时间 | 租赁开始日期时间、归还日期时间（如适用）、租赁时长 |
| 价格 | 适用租赁费率、最高租赁收费金额、计算后的租赁金额 |
| 支付 | 支付方式、支付参考编号、支付状态 |
| 发票 | 发票或收据编号及状态 |
| 税务 | 适用 VAT 信息 |
| 分成 | 适用的商户分成及代理佣金 |

管理后台支持按**日期范围、商户、设备、客户参考编号、支付状态、租赁状态**查询、筛选、查看和导出。设备迁移商户后，交易历史的商户和设备归属不得被覆盖。[A §3]

### 4.2 可配置计费参数

[A §4] 要求支持：

1. 租赁费率；
2. 租赁计费周期；
3. 最长租赁时限；
4. 最高租赁收费金额。

[B] 提供了 AED 5 / 30 分钟、每日 AED 30 封顶、48 小时未还自动扣 AED 69 等演示数字，详见第 13 章。**这些参数与其组合适用规则需要最终确认**。

### 4.3 达到最长租赁时限的自动扣款

- 到达设定时限自动**发起**最高适用租赁收费，即使充电宝没有归还。
- 保存触发扣款时间、金额、支付参考编号、支付状态及对应租赁记录。
- 封顶扣款发生后，如客户归还设备，更新归还状态但不自动撤销收费。
- 失败时明确失败状态；支持可配置的重试和跟进提醒，避免同一事件重复扣款。
- 支付状态与充电宝**实际归还状态分开展示**。
- 事先验证支付服务商对客户授权、保存支付凭证、预授权及后续银行卡扣款的支持。
- 首次预授权成功不保证最终实际扣款成功。[A §4]

### 4.4 进行中与逾期租赁看板

应显示：

- 当前进行中的租赁及持续时间。
- 客户参考编号、商户及设备编号。
- 已累计费用及最高收费金额。
- 即将到时限或已经超时的租赁。
- 已触发最高收费的订单及其支付状态。
- 失败、待处理的扣款。
- 已归还和未归还的充电宝。
- 发票生成与支付状态。
- 可筛选、导出逾期租赁和扣款失败记录。[A §4]

## 5. 支付、退款与支付对账

### 5.1 支付管理要求

- 关联租赁订单的支付方式和网关交易参考号。
- 跟踪支付状态：**成功、待处理、失败、已退款**。
- 最高租赁收费自动触发后记录扣款发起时间及状态。
- 对失败扣款提供重试/跟进提醒；同一租赁事件不得重复收费。
- 保持租赁、支付和物理归还状态可分别查看。
- 记录相关退款、冲回及财务调整。[A §3—§6]

### 5.2 支付网关费用和结算

- 报告支付网关手续费、结算信息及其他相关费用。[A §7、§10]
- 在 Zoho Books 所支持的范围内同步/记录相关手续费及结算信息。[A]
- 对账应用内交易金额、支付网关金额与 Zoho Books 会计数据。[A]

### 5.3 支付合规及限制

公司和开发商应确认：网关是否可进行预授权、保存支付凭证、后续扣款及必要授权；最高收费及收费条件必须提前向客户披露。金额触发、支付成功、实际到账/结算是不同事件，不得仅凭“发起扣款”推定支付成功。[A §4、§7]

## 6. 自动发票、税务发票与收据

### 6.1 自动生成规则

- 根据交易及阿联酋适用规定，生成发票、税务发票或付款收据。
- 在**法律规定的适用时点**生成单据；包括最高租赁收费触发时可能须开具的单据，不能只等待设备归还。
- [B] 采用“正常归还后自动生成税务发票；未归还而扣款时同步生成发票”的业务演示。
- 发票编号、开票时点、VAT 及更正过程，应经公司财务/税务顾问审核。[A §5；B p.4]

### 6.2 发票/收据字段

| 分类 | 要求字段 |
|---|---|
| 开票主体 | 公司法定名称、地址、适用税务登记号 TRN |
| 单据标识 | 唯一发票/单据编号、开具日期及时间 |
| 客户 | 法规要求的客户信息 |
| 业务信息 | 租赁交易编号、商户名称、设备/机器编号、租赁开始和归还信息 |
| 计价 | 服务描述、租赁费用、折扣、退款或调整信息 |
| 税务金额 | 适用 VAT 税率、税额、应付总金额 |
| 支付 | 支付方式、支付参考编号、支付状态 |

[B p.5] 还展示了一个具体的发票版式及金额示例，见第 13.2 节。

### 6.3 发票管理与导出

1. 按发票编号、租赁/交易编号、客户、商户、设备和日期查询。
2. 查看发票详情及支付状态。
3. 下载单张 PDF 发票。
4. 对选定交易或期间批量下载 PDF。
5. 导出 Excel 发票登记表。
6. 重发已有发票而不重复生成新的发票记录。
7. 通过关联记录处理退款、取消、贷项通知单及更正。
8. 保留发票创建及变更审计记录。[A §5]

### 6.4 按商户、设备提取发票

- **按商户**：选择商户及期间，查看所有关联交易/发票、单据数量、金额、VAT、退款和状态；可下载单张或选定的 PDF，技术可行时支持打包下载，支持 Excel。
- **按机器**：按设备编号及期间查看所有关联租赁、交易、扣款、付款和发票；下载对应 PDF 并导出 Excel 交易明细。
- **历史一致性**：以交易发生时的商户及设备关联关系为准，不能用设备当前商户覆盖过去的记录。[A §5]

## 7. 商户、代理、安装地点与合同

### 7.1 统一基础档案

[A §9] 要求统一维护：

- 商户名称、唯一商户编号、联系方式和业务信息。
- 商户分支机构、安装地点及关联设备。
- 合同编号、协议内容、分成比例或其他约定商业条款。
- 合同开始时间、到期时间（适用时）。
- 合同与分成条款的历史变更。
- 代理对象及关联佣金规则。
- 设备与商户之间的安装、调拨、撤出及维修历史。

### 7.2 合同到期提醒

[B p.2、p.7、p.9] 明确增加：

- **合同到期提前 2 个月自动提醒**。
- 管理看板展示合同到期告警。
- 演示：Hotel A 合同于 **2026-12-26** 到期，**2026-10-26** 显示“两个月后到期”的提示。
- 运营及销售人员能够查看合同期限和关联商户数据。

### 7.3 商业协议规则

[A §6] 要求依据**商户协议、代理、合同、分支机构和生效日期**配置分成与佣金；支持不同的百分比或固定金额，并保留规则及已计算结果的历史记录。

[B p.2、p.6] 使用 **15%—50% 的商户分成比例**作为业务范围/演示，实际比例以各商户合同为准。不能直接把一个统一比例应用到所有商户。

## 8. 商户分成、代理佣金与未结应付款

### 8.1 计算及台账

- 按商业协议计算每个商户的收入分成。
- 在适用情况下计算代理佣金。
- 显示**应得金额、已付金额、调整金额、未结余额**。
- 按商户和期间出具应付款报表。
- 保留历史计算结果及协议变动记录。
- 支持部分付款、多次付款、冲回和经过批准的调整。
- 比较运营系统计算额与会计记录，识别差异。[A §6]

### 8.2 Zoho Books 付款回写

- **商户和代理的实际付款在 Zoho Books 录入，不在超级应用中重复手工录入。**
- 超级应用从 Zoho Books 获取相关付款记录，自动更新应付款余额。
- 同步字段包括付款参考编号、日期、商户账户、所属期间、部分付款与批准的调整。
- 支持重复记录防控、同步日志，以及同步失败或无法匹配的提醒。[A §6]

### 8.3 商户应付款示例（来源 A）

| 项目 | 金额 |
|---|---:|
| 商户应得分成 | AED 5,000 |
| Zoho Books 中记录的已付款 | AED 3,000 |
| 应付未结余额 | **AED 2,000** |

同步 AED 3,000 的付款后，应用自动将未结应付款更新为 AED 2,000。[A §6]

## 9. Zoho Books 会计系统集成

### 9.1 功能范围

[A §7] 要求通过 Zoho Books 允许的 API / 集成方式处理：

1. 销售、发票、付款、退款及贷项通知单的相关同步。
2. 商户及代理付款记录同步，更新/核对应付款。
3. 适用 VAT 数据和税务分类。
4. 在系统支持时记录网关手续费、结算和其他相关费用。
5. 商户分成、代理佣金的会计处理。
6. 运营应用、支付网关、Zoho Books 三方交易总额对账。
7. 同步状态、错误日志及重试流程。
8. 防止重复会计分录与重复付款记录。

### 9.2 数据归属与同步原则

- Zoho Books 是**会计分录与已记录付款**的会计系统记录来源。
- 共享充电宝运营应用保留**逐笔运营交易明细、设备跟踪和运营报表**。
- 若经批准的会计流程允许部分销售在 Zoho Books 中汇总入账，运营应用也不得丢失逐笔交易。
- 实施前必须由开发商与财务人员确认会计科目及数据映射。[A §7]

### 9.3 采购与库存的会计核对

在 Zoho Books 选用的配置和接口支持的前提下，应将采购记录用于核对**供应商发票、供应商余额、VAT 和相关库存会计记录**；实物库存、运营库存与会计记录必须可以相互核对。设备级资产追踪与会计库存计价可能是不同的处理方式，需在技术评估阶段确认。[A §8.5]

## 10. 设备资产、采购、库存与调拨

### 10.1 管理范围与资产档案

平台管理**公司全部既有机器、充电宝及未来所有新采购设备**。既有设备即使缺少原采购发票，也应允许登记，并标记依据和保留支持文件。[A §8.1]

| 数据类型 | 要求字段 |
|---|---|
| 唯一识别 | 机器编号、充电宝编号（适用时）、序列号 |
| 基本信息 | 设备类型、型号、数量 |
| 位置归属 | 当前存放位置、所分配商户 |
| 运行信息 | 安装日期、运行状态 |
| 采购凭据 | 采购信息、相关证明文件（如有） |
| 期初记录 | 有可靠依据时记录期初数量及价值；无票据设备可标记来源 |

### 10.2 新设备采购与收货

授权用户可以建立采购或入库记录，记录：

- 供应商名称、供应商编号。
- 采购日期、供应商发票编号。
- 设备类型、型号、序列号、唯一设备编号。
- 订购数量、实际收货数量。
- 单位成本、采购总金额、适用 VAT 金额。
- 采购订单及供应商发票附件。
- 交货/收货日期、当前库存位置。
- 采购状态、收货状态。[A §8.2]

**库存增加规则**：只有**确认实际收货**后才增加对应库存；从 Zoho Books 导入或同步相同采购记录时不得重复增加。[A §8.2；B p.8]

### 10.3 设备生命周期和状态

[A §8.2—§8.3] 列明的状态或动作：

1. 已订购；
2. 已收货；
3. 库存可用；
4. 已安装；
5. 维修中；
6. 损坏；
7. 遗失；
8. 已撤出；
9. 报废（作为处理动作）；
10. 从商户退回仓库或存放地点。

完整业务链路为**采购或初始登记 → 收货入库 → 安装至商户 → 商户之间调拨/退库 → 维修/损坏/遗失/报废/撤出**。[A §8.3；B p.8]

### 10.4 设备移动历史

每次安装、调拨、撤出或相关移动应记录：

- 移动日期；
- 原始位置；
- 新位置；
- 负责员工；
- 移动原因。

必须保留商户与设备的**历史关联**，确保历史交易及财务报表仍然归属租赁发生时的商户。[A §8.3、§9]

### 10.5 设备在线状态（有条件）

在硬件及制造商接口支持下，提供：

- 在线/离线状态。
- 故障检测。
- 设备内可租借充电宝的库存/可用数量。[A §9]

原文未指定设备通信协议、远程控制指令格式或厂商 API，属于技术评估中必须确认的依赖。

### 10.6 库存管理报表

[A §8.4] 要求至少统计：

1. 所有登记的机器及充电宝总数。
2. 期初、采购、收货、安装、调拨、退回、撤出、遗失及期末库存。
3. 按编号、序列号、型号、位置和商户分类的库存。
4. 新增设备及按供应商分类的采购历史。
5. 采购数量、单位成本、采购金额和 VAT。
6. 已采购尚未收货的设备。
7. 已收货尚未安装的设备。
8. 当前已安装在商户现场的设备。
9. 维修中、损坏、遗失或撤出的设备。
10. 当前库存余额和变动历史。
11. 实物盘点与系统记录的差异。

支持按**日期范围、供应商、设备类型、机器编号、商户、状态**筛选。

### 10.7 库存演示案例

**采购/收货**（[B p.8]）：订购 100 台，实际收到 80 台，则库存 **+80**，剩余 **20** 台仍为在途/未到货，不纳入当前实物库存；同一采购不能重复入库。

**设备历史迁移**（[B p.8]）：机器 **M-12** 在 **1 月至 6 月**归属 **Hotel A**，从 **7 月**开始归属 **Mall B**。历史租赁和报表仍按发生时的 Hotel A 归属保留，不能改写。
