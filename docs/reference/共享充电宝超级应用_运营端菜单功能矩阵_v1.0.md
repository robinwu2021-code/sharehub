> **适用范围**：运营端 Dashboard；不包含 C 端客户 App 页面。此处菜单组织属于产品与研发建议，最终应在现有系统评估和业务评审后确认。

## 1. 运营端菜单设计原则

1. **业务主链路优先**：工作台、租赁、设备、商户、支付、发票、结算、报表。
2. **库存为独立一级菜单、独立业务模块 M08**：采购、验收入库、资产账、仓储、调拨、盘点、维修报废和库存报表，不与设备运营混用。
3. **第三方硬件平台对接为独立一级菜单、独立业务模块 M10**：厂商连接配置、协议能力、设备映射、指令、事件、异常及调用日志。
4. **设备运营 M09 只负责营业可用性**：机器运营开关、安装点运营、设备故障与可借量；不直接变更资产结存，也不实现厂商专用协议。
5. **规则集中动态配置**：计费、封顶、超时费用、支付重试、税务/票据、分成、佣金、结算、库存审批、合同提醒等由规则中心维护；原文金额比例作为候选初值。
6. **角色与按钮级权限**：菜单可见性只是第一层权限，关键操作按创建、编辑、审批、执行、导出、重试、发布分开授权。
7. **资金、发票和库存事实不可无痕修改**：历史通过版本、补偿交易、冲回流水或正式调整单处理。
8. **对外系统权威来源**：收款及退款结果以支付网关实际状态为准；已登记的商户/代理付款以 Zoho Books 为来源；厂商设备遥测不覆盖实物库存账。

**标记**：P0 = 首期关键交付；P1 = 增强功能；`P1-条件` = 厂商/支付/Zoho数据或能力经验证后交付。`角色`为建议默认访问角色，管理员不自动拥有所有高风险操作权限。

## 5. 角色与操作权限矩阵（原则性）

| 建议角色 | 主要职责 / 常用页面 | 关键限制 |
|---|---|---|
| 管理 | 总体经营、商户分成摘要、关键审批 | 不默认拥有财务明细编辑和密钥读取权 |
| 运营 | 租赁监控、商户运营、设备经营、异常工单 | 不能手动把失败支付改为成功 |
| 客服 | 租赁查询、客户授权查询、退款发起与票据重发 | 个人信息最小化，不能审批自己提交的退款 |
| 设备运营 | 机器运行、在线/故障、安装协同、硬件事件查询 | 不直接修改库存余额或厂商密钥 |
| 仓储 | 采购、收货、资产、调拨、盘点和报废 | 盘亏与报废审批适当职责分离 |
| 商务 | 商户、合同、代理、分成查询、到期提醒 | 合同/分成规则修改需经审批生效 |
| 财务 | 支付、发票、分成、Zoho同步和对账 | 真实商户/代理付款在Zoho登记，不在本系统重复入账 |
| 技术 | 硬件接口、集成配置、同步任务、系统日志 | 不可直接伪造支付、发票、付款或修改业务流水 |
| 管理员 | 用户权限、规则流程配置和第三方凭证元数据 | 高风险操作仍应审批并留痕 |
| 审计 | 历史流水、审计记录、风险追溯 | 原则上只读与受控导出 |

### 5.1 高风险操作必须独立授权

| 操作 | 权限控制 | 审批/审计要求 |
|---|---|---|
| 人工退款及退款执行 | 发起、审批、执行拆分权限；关联原支付流水 | 按动态审批规则流转，记录真实网关结果 |
| 计费/封顶/超时收费规则发布 | 编辑、试算、审批、发布拆分权限 | 批准后按生效时间与作用范围发布；订单保留历史快照 |
| 税率、发票规则及会计映射变更 | 由财务授权角色审批 | 应由公司财税人员确认符合法定要求 |
| 商户分成、佣金和合同变更 | 商务录入、财务复核、授权发布 | 生效日期、合同版本与历史结算不回写 |
| 库存盘盈盘亏、报损和报废 | 盘点登记与差异审批分离 | 生成调整单、库存流水及附件，不直接改余额 |
| Zoho人工匹配与付款核销 | 仅授权财务可调整匹配 | 不能在本平台伪造Zoho真实付款记录 |
| 设备指令人工重发或事件重放 | 仅授权设备运营或技术人员 | 必须核实外部执行状态并保证业务幂等 |
| 第三方凭证维护与轮换 | 独立密钥管理权限 | 密文存储、访问留痕，不应导出明文 |
| 批量财务/客户数据导出 | 数据范围与导出按钮分别授权 | 记录导出人、筛选范围、导出时间和用途 |

### 5.2 推荐的权限点命名规则

建议采用 `ops.<module>.<resource>.<action>` 的方式，例如 `ops.rental.order.view`、`ops.inventory.goods-receipt.confirm`、`ops.hardware.command.retry`、`ops.billing.rule.publish`、`ops.payment.refund.approve`。后台同时校验商户/组织数据范围。

## 6. 三个设备相关菜单的责任边界

| 业务事实或操作 | 设备运营 M09 | 库存管理 M08 | 硬件对接 M10 |
|---|---|---|---|
| 采购及供应商发票 | 查询参考 | **拥有/维护** | 不负责 |
| 资产主数据和序列号 | 引用 | **拥有/维护** | 保存外部映射ID |
| 设备所属商户及历史安装地点 | 读取当前/历史 | **资产流转权威来源** | 仅映射厂商设备ID |
| 借出/还宝物理事件 | 运营异常协同 | 消费事件形成资产位置追踪（适用时） | **接收、校验、标准化** |
| 机器可经营/停用状态 | **拥有/维护** | 引用维修/资产状态 | 提供最近设备状态 |
| 厂商实时可借数量 | 展示和预警 | 只作核对，不覆盖资产总量 | **采集并提供** |
| 入库、调拨、报废和盘点 | 提出申请/查看 | **唯一执行业务流水** | 不修改库存 |
| 设备指令及厂商接口 | 发起授权业务请求 | 不直接发硬件指令 | **实现厂商适配/指令日志** |
| 设备故障/维护工单 | **工单及运营处理** | 资产维修状态/位置流水 | 故障事件输入 |

## 7. 动态规则与初始模板的落地约束

所有数值或策略均支持版本化配置。**原始提案中的示例值不作为代码常量**；初始化配置按候选草稿导入，由业务与财务审核后激活：

| 规则类别 | 原始资料中的初始化候选 | 运营端菜单 | 关键注意 |
|---|---|---|---|
| 计费周期和费率 | AED 5 / 30分钟 | 动态规则中心 → 租赁定价 | 含5分钟免费示例，时间取整必须确认 |
| 租赁封顶 | AED 30 / 日 | 动态规则中心 → 封顶与超时 | 日窗口与其他收费的关系按规则配置 |
| 最长时限收费 | 48小时 / AED 69 | 动态规则中心 → 封顶与超时 | 固定总额或追加金额、已支付金额抵扣需确认 |
| 商户分成 | 15%、30%、50% 示例 | 动态规则中心 → 商户分成 | 按合同、税基、手续费处理配置 |
| 税率 | VAT 5% 示例 | 动态规则中心 → 发票与税务 | 实际应符合公司适用税务要求 |
| 合同到期提醒 | 提前2个月 | 动态规则中心 → 合同提醒策略 | 提醒范围与接收人可配置 |
| 支付失败重试 | 次数及间隔待业务确认 | 动态规则中心 → 支付重试 | 先核验未知交易结果并控制幂等 |

## 8. 页面统一组件和交互要求

1. **标准列表页**：搜索、日期区间、商户/机器/状态筛选、表格分页、详情抽屉、导出（受权限控制）。
2. **标准详情页**：基础属性、关联业务对象、状态变化时间线、外部引用ID、规则版本/快照、操作审计和附件。
3. **权限**：菜单可见、数据可见、字段脱敏、按钮可操作四级控制；不可只由前端隐藏按钮实现授权。
4. **全局检索**：统一按租赁单号、机器号、充电宝号、商户号、支付流水号和发票号跳转至对应详情。
5. **标准导出**：敏感数据权限、时间/筛选口径、生成时间、操作人、导出任务状态及审计。
6. **数据新鲜度**：运营实时指标展示最近更新时间；厂商状态无法获取时展示“未知/未接入”，不伪装实时。
7. **异常状态**：第三方返回失败/未知时允许关联核验，不提供直接“改为支付成功/设备已出宝”的无审计按钮。

## 9. 交付范围与实施优先级

**P0 目标**：围绕租赁→计费→支付→开票→分成应付→Zoho付款核销的核心链路，以及完整的采购→收货→仓储→安装/调拨→盘点的库存链路，交付可验证的管理页面和跨模块追溯。

**P1/条件能力**：多厂商扩展、设备实时在线率/槽位数据、部分清算手续费详情、Zoho采购库存会计字段以及运营增强分析，先以厂商API/账套实际能力核实为前提。

**开发拆解建议**：每个二级菜单先形成 `列表接口 + 详情接口 + 操作接口 + 权限点 + 审计事件 + 验收用例` 六项交付物；跨域页面仅调用归属模块公开API，不跨模块直接更新数据表。

> **功能矩阵统计**：14 个一级菜单，125 个二级菜单/功能页。功能页为产品信息架构划分，不等同于 125 个独立后端服务。
