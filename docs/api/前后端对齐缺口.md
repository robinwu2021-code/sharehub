## C. 后端有、前端没调（24）

**已排除 `/internal/*`**（11 条）：那是服务间调用，设计上就没有前端调用者，算进来只会让这个数字永远清不掉。

仍需**逐条区分**：前端还没接（待办），或后端端点已废弃（该删）。混在一起会让「未接线」永远显得像「待办」。按受众分开看 —— `/api/*` 归运营端 ops-web，`/mp/*` 归 C 端 c-app。

## D. 后端出参无对应前端类型（27）

**已排除三类**（合计 8 条），它们不是缺口：

- `/internal/*` 的出参 6 条 —— 服务间调用，设计上就没有前端类型；
- **另一个投影** 2 条 —— `CabinetDetail` / `InvoiceView` 这类，前端有对应的裸类型但形状本就不同，硬当同名去逐字段比只会造出假的字段差异；
- **分层后缀**（`VO` / `Entry` / `Row`）—— 后端 `RoleRowVO`、前端 `RoleRow`，同一概念两层命名习惯不同，已自动对齐后按字段比（结果进 B 类）。
