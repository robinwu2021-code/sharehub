### 1.1 进程与接入面

```
                        ┌────────────── nginx（公网入口；/internal/** 对外封死）──────────────┐

  支付通道 ────────────┼── /pay/callback/{ch} ─┐   │   │                                     │
                        └──────────────────────┼───┼───┼─────────────────────────────────────┘
                                               │   │   ▼
                                               │   │ ┌─────────────────────── sharehub-app（业务单体 :8082）───────────────────────┐
                                               │   │ │ platform（loc · agent · iam · notify · file）  core（dev · trade · price）      │
                                               │   │ │ ops（alarm · wo · cs）                         finance（share · settlement）   │

                                               │   │        │ /internal/     │ /internal/gw/        │ /internal/job/   │ /internal/pay/
                                               │   │        │ events/device  │ commands · telemetry │ {handler}/run    │ …

                                               │ ┌──────────┴──────────────────────┐   ┌────────────┴─────┐  ┌─────────┴──────────┐
```

| 接入面 | 前缀 | 提供进程 | 调用方 | 鉴权 | 本流程涉及 |
|---|---|---|---|---|---|
| 运营端 | `/api/{auth,ops,trade,user,agent,platform}/**`（**6 个，不得新增**） | sharehub-app | ops-web（员工 / 代理两种会话） | 令牌 + `@perm.can` + 数据范围 | ✓ 主体 |
| C 端 | `/mp/**` | sharehub-app | c-app | 消费者令牌 + 属主校验 | ✓ 借还、找柜、报障 |
| 进程间 | `/internal/**` | 各进程 | 进程之间；**浏览器不得直接调** | `X-Internal-Token` · `X-Job-Token` · 过渡期定时端点只认回环地址 | ✓ 设备事件、指令、任务、支付 |
| 南向回调 | `/gw/**` | sharehub-gateway | 厂商云 | 厂商签名 | 间接（产生设备事件） |
| 支付回调 | `/pay/callback/**` | pay-svc | 支付通道 | 通道签名 | 间接（产生支付事件） |

## 二、按架构约束的裁决（7 处，已回写 TDD）

| # | 设计原文 | 违反的约束 | 裁决 |
|---|---|---|---|
| 1 | `POST /api/files` | 运营端只有 6 个前缀，**不得新增**（api/README §1.2、v4/04 §一） | 改为 **`/api/platform/files`**；C 端 `/mp/files` 不变 |
| 2 | 合同审批 `…/approve` + `…/reject` 两个端点 | 审批类统一用 **`/audit`** 动作，驳回原因必填，审批人由服务端回填（api/README §1.5；入驻、退款、提现均如此） | 合并为 **`POST /api/ops/contracts/{no}/audit`**，`{result: APPROVE\|REJECT, reason}`；`REJECT` 时 `reason` 必填 |
| 3 | 设备动作挂在 `/api/ops/cabinets/{no}/…` | v4/04 §三：设备资源改为通用名 `devices`，**一次切换、不留别名** | 新端点**直接用目标名** `/api/ops/devices/{deviceNo}/…`（避免上线后再改一次）；现有 `cabinets` 端点随 D1 批量改名。过渡期 `deviceNo` 即 `cabinetNo`，权限码仍用 `device:cabinet:*`，与 D1 同批改 `device:asset:*` |
| 4 | `POST /internal/events/device` 单条 `SignalIngestReq` | v4/04 §6.1：**批量**、至少一次、按 **`eventId`** 去重 | 改为 `{events: [DeviceEventDto]}`，每条带 `eventId`；消费侧 `EventIdempotency.once(eventId, …)` |
| 5 | 定时入口 `/internal/<域>/…/tick`（系统 cron + 回环） | v4/07：任务由调度器回调 `/internal/job/{handler}/run`（`X-Job-Token`），任务名进统一目录 | **过渡期保留 tick**（与调价先例一致），但 tick 的名字与 service 方法**按目标任务名命名**，接通调度器时只换入口：见 §3.4 |
| 6 | 试借还「复用现有指令通道」 | 指令归网关：app 经 `POST /internal/gw/commands` 下发，`commandId` 幂等，结果以设备事件回推（v4/04 §6.2） | 试借还下发 `{command: EJECT, bizType: TRIAL_RENT, bizRef: trialNo}`；弹出结果从 `COMMAND_RESULT` 设备事件回来，不同步等待 |
| 7 | 交易自愈「撤单释放 / 退款」 | 资金动作归 pay-svc（`/internal/pay/pre-auths/{authNo}/release` · `/internal/pay/refunds`），业务侧经 `PaymentPort` | `TradeRemedyPort` 的实现只改订单状态并调 `PaymentPort`；自愈结果以支付事件确认，不以接口返回为准 |

另有两条沿用现状、不在本期改：
- **错误码**：目标是 `10xxx` 分段（v4/04 §2.3），现状为 400 / 403 / 409 / 500；本期新端点按现状，随 v4/09 的 `BizException` 统一切换；
- **控制器位置**：目标是各域 `api.{ops,mp,internal}` 子包（v4/09 §四），现状在 `sharehub-app/portal`；本期新控制器仍放 `portal`（与相邻端点同处），随 v4/09 重构整体迁移。

列：**状态**（✓ 保留 · ✏️ 改 · 🆕 新增 · ❌ 删除 · 🔁 D1 改名）· **幂等**（写接口：K = 接受 `Idempotency-Key` · S = 状态条件天然幂等 · — 不需要）· **范围** = 数据范围维度（A = AGENT · S = SITE · R = REGION）· **功能** = 矩阵编号。
请求 / 响应 DTO 名与 TDD 各章一致；分页一律 `page/size` → `PageResult{list,total}`；动作端点一律 `POST`，无 `DELETE`。

## 四、跨进程调用链

### 4.1 设备上线（门禁 → 试借还 → 上线 → 站点营业）

```
ops-web            sharehub-app                                   sharehub-gateway        设备
  │ GET  /api/ops/devices/{no}/go-live-gate
  │───────────────▶ 门禁：站点(Port) · 合同(ContractQueryPort) · 在线 · 试借 · 计费(PricingProbe)
  │ POST /api/ops/devices/{no}/trial-rents
  │───────────────▶ 建试借 EJECTING ── POST /internal/gw/commands {EJECT, TRIAL_RENT, trialNo} ─▶ 下发 ─▶ 弹出
  │                  ◀──────────── POST /internal/events/device {COMMAND_RESULT ok} ◀──────────────────
  │                  试借 WAIT_RETURN
  │                  ◀──────────── POST /internal/events/device {RETURN_SN_SEEN} ◀─────────── 运维放回
  │                  试借 PASSED · trial_passed_at
  │ POST /api/ops/devices/{no}/go-live
  │───────────────▶ 重跑门禁 → DEPLOYED → 发 CabinetWentLiveEvent ─▶ 站点 PREPARING→ACTIVE
```

### 4.2 设备故障 → 业务告警 → 工单 → 复核

```
设备 ─▶ gateway ─ /internal/events/device ─▶ app：信号入库 · 保护动作（禁仓）· 发 DeviceSignalEvent
调度器 / cron ─ alarm-rule-eval ─▶ app：判定器读可借状态（CabinetQueryPort）→ 「站点借不到」成立
                                        → 影响评估 → 到开单时刻 → WoOpsService.openOrAttach → 派给运维责任人（NotifyPort）
ops-web / 代理门户 ─ POST /work-orders/{no}/complete（照片 fileNos）─▶ 发 WorkOrderCompletedEvent
                                        → 告警域复核：已恢复 → 告警 RESOLVED、工单自动验收；未恢复 → 复核未通过
```

### 4.3 付了款没拿到宝 → 交易自愈

```
C 端 ─ POST /mp/trade/orders/rent ─▶ app：RentabilityGuard 通过 → 建单 → /internal/gw/commands {EJECT}
gateway ─ COMMAND_RESULT 失败 ─▶ app：订单撤单（信号层保护）；撤单失败 5 分钟
alarm-rule-eval ─▶ RENT_NOT_DELIVERED → AUTO_FIX → TradeRemedyPort.cancelUndelivered
                    → PaymentPort ─ /internal/pay/pre-auths/{authNo}/release ─▶ pay-svc
pay-svc ─ /internal/events/payment ─▶ app：确认释放 → 告警 AUTO_FIXED；三次失败 → CsTicketService 建客服单
```

### 4.4 合同生效

```
cron / 调度器 ─ contract-lifecycle ─▶ app：SIGNED 且开始日到 → ACTIVE → 发 ContractSignedEvent（→ finance 介绍费）
                                        同站点旧合同 → EXPIRED
alarm-rule-eval ─▶ 站点无生效合同 → SITE_WITHOUT_CONTRACT → 待办（BD）
```

## 五、通用约定在本流程中的落地

| 约定（出处） | 本流程的具体做法 |
|---|---|
| 出参 `Result{code,message,data}` · 分页 `PageResult{list,total}`（README §1.1 / §1.4） | 新端点无例外；`/internal/job/**` 目标入口不套信封（v4/07） |
| Upsert：`POST /x` 新建 · `POST /x/{no}` 更新；无 `DELETE`（README §1.5） | 合同、站点、设备编辑沿用；删除语义一律 `archive` 或业务动作（`terminate`、`retire`、`close`） |
| 动作端点用动词后缀（README §1.5） | `submit` `withdraw` `audit` `sign` `terminate` `renew` `pause` `resume` `withdraw` `close` `go-live` `mark-fault` `repair` `undeploy` `retire` `release` `ack` `dispose` `close` `done` `complete` |
| 审批类：`/audit`，驳回原因必填，审批人服务端回填（README §1.5） | 合同审批（裁决 #2）；另「不能自己审批自己」 |
| 幂等：创建类接受 `Idempotency-Key`，重复返回首次结果（README §1.5 · v4/04 §2.2） | 标 K 的端点；动作类靠状态条件天然幂等（标 S），重复调用返回当前结果而非报错 |
| 数据范围外返回「不存在」（v4/04 §2.3） | 所有 `{no}` 端点：范围外与不存在同一文案 |
| 服务端出参脱敏（README §1.6） | 文件下载地址不进日志；代理门户看告警时不出现 C 端手机号 |
| `Accept-Language` 决定错误文案 | 门禁清单的 `detail` 文案同样按语言返回 |
| 权限码先登记后使用（CLAUDE.md） | 新增 3 码（合同）随端点同一提交登记；告警细码由在途工作提供 |
