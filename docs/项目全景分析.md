## 一、项目是什么（一段话）

**ShareHub**（原名 powerbank / 充電寶專案）是一套面向 **MENA（默认 UAE，扩 KSA）** 市场的**共享充电宝多租户 SaaS**，采「共享设备运营平台」定位（设备类型可扩展至充电桩/储物柜，见 ADR-014）。业务闭环为：**扫码租借 → 自动计费 → 在线支付/免押 → 归还结算 → 商户/代理分账**。

- **三端代码库**：`c-app`（C 端消费者，uni-app/Vue3，App 优先）、`ops-web`（运营管理后台，Next.js/React）、`backend`（Java 21 / Spring Boot 4，模块化单体 + 独立接入网关）。
- **商业形态**：MVP 为**单运营方自营**（`tenant_no=MAIN`），多租户能力照建但作为「休眠口子」预留（ADR-011）。
- **基座复用**：复用 `ai-neargo` 的 8 个 commons + auth-core，支付委托 neargo `nearpay`（ADR-005/006）。

## 二、端与角色全景

### 2.1 端划分（来源：`功能矩阵.md` / `功能矩阵-分端对照.md`）
| 端 | 载体 | 阶段 | 职责 |
|---|---|---|---|
| C 端消费者 | App（P0 主力）+ 微信小程序（P1 niche）+ H5 | P1/P2 | 扫码借还闭环 + 账户/钱包/会员/客服 |
| 运营管理后台 ops-web | Next.js Web | P1+ | 运营方日常经营套件（本文重点） |
| 运维 App | uni-app（复用 C 端基座） | P2 | 现场运维/地推、工单执行、打卡拍照 |
| 商户/门店端 | 小程序/H5 | P2/P3 | 本点位订单/收益/设备、物料二维码 |
| 代理端 | Web/小程序 | P2 | AGENT 角色 + `agent_no` 数据范围自助 |
| 接入网关 access-gateway | TCP/MQTT/HTTP 南向 | P1 | 硬件/供应商设备接入（独立进程） |
| 开放平台 OpenAPI | HTTP + AppKey 签名 | P3 | 第三方/供应商/代理系统对接 |

### 2.2 角色（运营端 RBAC，来源：`权限管理方案.md` / `permissions.ts` 镜像）
`ADMIN`（全部 `*`）· `OPS`（设备/工单/库存/OTA，按区域点位）· `CS`（订单干预/退款申请/风控/报障，全域只读+客服动作）· `FINANCE`（财务/分润/结算/提现/对账，全域财务）· `BD`（点位/场地方/合同/CRM，按区域）· `AGENT`（自己设备/订单/收益只读+提现申请+报修，**强制 `agent_no`**）· `VIEWER`（只读）· 🔒`PLATFORM_ADMIN`（多租户口子，休眠）。

> 三个易混主体（ADR-011/012/013）：**租户**=另一独立运营方（休眠口子，`tenant_id` 隔离）；**代理商**=运营方**体内**经营伙伴（≠租户，用 `agent_no` 数据权限隔离）；**场地方 Venue**=收进场分成的外部商户（`loc_venue`）。

## 三、架构决策全景（ADR-001 ~ 015）

| ADR | 决策一句话 | 关键落地 |
|---|---|---|
| 001 技术栈与服务粒度 | Java21 + Spring Boot 4 + Maven 多模块，Modulith 默认；`RestClient` 调用 | 5 业务域合单体 `sharehub-app` + 独立 `access-gateway`；MyBatis-Plus；不引 Spring Cloud/Feign/RocketMQ |
| 002 多租户隔离 | 单库行级 `tenant_id` 起步，预留分库 | 复用 neargo security/data；JWT→`AuthHeaders`→`TenantContext`；`TenantLineHandler` 自动注列 |
| 003 硬件 Driver 插件化 | access-gateway 内 **DeviceDriver SPI**，一供应商一实现 | 统一 8 指令 + 8 事件；`commandId` 幂等（Redis SETNX）；新增供应商=新增 driver 模块，业务零改 |
| 004 分账双模式 | 分润规则在平台，执行分 `CHANNEL_SPLIT` / `LEDGER` 双模 | MENA 首期主用 `LEDGER`（复式记账→结算单→提现→nearpay 打款）；先记账后执行 + 日切对账 |
| 005 C 端载体与 MENA 支付 | App 优先，支付委托 nearpay 且**延后集成** | `PaymentPort`（pay/preAuth/capture/release/refund）MVP 用 Stub；免押=银行卡预授权冻结 |
| 006 复用 ai-neargo | 私仓坐标依赖，`groupId=ai.neargo.powerbank` | 复用 8 commons + auth-core；独立仓库独立发版；前置阻塞=neargo commons 发私仓 |
| 007 租户隔离键命名 | 隔离列用 `tenant_id`（非 neargo 的 `merchant_id`） | 自写 `PowerbankTenantLineHandler`；场地方实体命名 `venue`（避免与 merchant 语义冲突） |
| 008 前端技术栈 | 运营端 Next.js16+React19+Tailwind4+shadcn；C 端 uni-app(Vue3) | 运营端 TanStack Table + ECharts + 高德/Google Maps；C 端 UnoCSS + wot-design-uni + Pinia |
| 009 市场区域与合规 | 主市场 MENA/UAE，默认币种 **AED**（作废 CNY） | i18n ar/en + RTL；合规双轨 PDPL（`*_pii`+KMS）/ CBUAE（资金轨独立库）；Google Maps + FCM/APNs |
| 010 数据库合并 | neargo 8 库合并为 **3 库** | `pb_core`（全业务域，子域前缀区分）/ `pb_pii`（PDPL+KMS）/ `pb_auth`（`cred_*`，realm 区分员工/消费者） |
| 011 单运营方为主 | MVP 单主租户自营，多租户仅休眠口子 | 隔离机制照建但前台无租户切换；平台管理面后置；`tenant_id` 泛化为「隔离经营实体」 |
| 012 代理商模型 | 代理是体内一等概念 ≠ 租户，用**数据权限 AGENT** 隔离 | `agt_agent` 实体；`dev_cabinet.agent_no`/`loc_site.agent_no`；复用分账链路；新增 AGENT 角色 |
| 013 场所层级 | 两层归属：场地方 Venue → 站点 Site → 点位 Point → 机柜 Cabinet | 归属只挂**站点**（代理/分成/区域数据权限均站点粒度）；`loc_contract` 绑场地方×站点 |
| 014 更名 ShareHub + 设备抽象 | powerbank → ShareHub；引入 `device_type` 一等概念 | 根包 `ai.neargo.sharehub`；`device_type`(POWERBANK/EV_PILE/LOCKER…)；DB schema `pb_core` 不改；迁移 M1-M6 |
| 015 权限模块化打包 | 权限分三层打包：starter jar + iam 业务 jar + 消费方依赖 | **数据权限强制不可服务化**（`DataScopeHandler` 是进程内 MyBatis 拦截器，必须与业务 Mapper 同进程） |

**演进关系（谁取代/精化谁）**：009 驱动 005 修订（市场 CNY→AED、免押改预授权）；007 精化 002（隔离列 merchant_id→tenant_id）；010 取代初版 8 库；011 把 002 的多租户从 P0 降为休眠口子；012 在 011 之上补代理商；013 定稿 `loc_` 场所结构；014 泛化 001/003 设备抽象；015 延续 001（modulith）+006（infra jar 模式）。

## 四、技术方案要点（TDD 系列）

- **后端分层**：Controller 薄（参数校验 + `@PreAuthorize("@perm.can('码')")`）→ Service 接口+Impl → Mapper/Entity；公共抽象 `AbstractCrudService`、`DomainEventPublisher`、`IdGenerator`。接入层包结构 `portal/{ops,mp,south}`；响应统一采纳 neargo `Result{code,message,data}` + `PageResult`（退役自建 `ApiResult`）。
- **交易租借域**（`PRD-trade-rental` / `TDD-trade-rental`）：订单状态机 `CREATED → DISPENSING → IN_USE → RETURNED → SETTLED → CLOSED`（任意态可转 `EXCEPTION`）；`BillingEngine.quote()` 纯函数（免费时长 / `unit_price` 累进 / `cap_daily` 日封顶 / `cap_total` 买断，规则零硬编码）；`PaymentPort` 抽象（Stub→nearpay）；`OverdueScanner` 超期买断；幂等（业务键 + Outbox）。
- **接入网关**（`PRD-access-gateway`）：三栈 TCP(Netty)/MQTT(EMQX)/HTTP+Webhook；**8 指令** EJECT_ANY/EJECT_SLOT/LOCK/UNLOCK/REBOOT/QUERY_SLOTS/LOCATE/VOICE/OTA_PUSH；**8 事件** ONLINE/OFFLINE/HEARTBEAT/SLOT_REPORT/RENT_CONFIRMED/RETURNED/FAULT/OTA_RESULT；90s 心跳判离线；借出确认以 `RENT_CONFIRMED` 事件为准（P95<3s）。
- **认证鉴权**（`TDD-认证鉴权`）：5 条 `SecurityFilterChain` 设计、MVP 落 2 条（`/mp/**` 消费者属主鉴权 + ops 员工鉴权）；**可信头红线**：服务端据 token 反查权限，忽略客户端 `X-Roles`；C 端 5 登录策略 `PhoneOtp/WechatMiniapp/WechatOauth/Apple/Google`，`usr_identity` 按 unionid 归并。
- **国际化 i18n**（`TDD-国际化i18n`，P1 done）：`zh/en/ar` + RTL；`lib/i18n` 自建方案；locale store `ops-locale`；`Accept-Language` 传后端。
- **分期屏蔽**（`TDD-分期屏蔽功能`，**本会话正在 ops-web 落地对齐的机制**）：`lib/phase.ts` 定义 `Phase=1|2|3`，`CURRENT_PHASE` 读 `NEXT_PUBLIC_CURRENT_PHASE`（默认 1，构建期静态注入）；`isPhaseLocked(phase)=phase>CURRENT_PHASE`；`lib/nav.ts` 逐叶 `phase` 字段；`PhaseGuard` 在 AppShell 集中拦截；**perm 锁与 phase 锁正交**（权限过滤只按 perm，分期只按 phase）。
- **三级导航**（`TDD-运营端三级导航`）：域(L1)→模块(L2)→子功能(L3)；Rail + SecondaryNav；偏好 `ops-nav-prefs`（Zustand persist）。
- **前端技术栈**：ops-web `output:export` 纯静态导出，`trailingSlash:true`；env `NEXT_PUBLIC_CURRENT_PHASE`/`NEXT_PUBLIC_USE_MOCK`/`NEXT_PUBLIC_API_BASE`/`NEXT_PUBLIC_DYNAMIC_NAV`；c-app Capacitor 打 APK，Google Maps（GCP 项目 ng-vm-240813）。

## 五、领域模型

- **主体**：`Operator`（=主租户 MAIN）· `Agent`（体内伙伴）· `Venue`（外部场地方）· `Staff`（角色+数据范围）· `Consumer`（openid×租户）· `Advertiser`（未来）。
- **场所层级（ADR-013）**：`Operator → Site（站点）→ Point（点位）→ Cabinet（机柜）→ Slot/Powerbank`，另有 `AdSlot` 广告位。站点 `agent_no` 有值=代理经营，空=平台直营。
- **资金三方分账**：订单收入 = 场地方（`loc_contract` 合同分成）+ 代理（`share_rule` dimension=AGENT）+ 平台净收入；链路 `Order→Payment→ShareRule/ShareRecord→Settlement/Withdrawal`，复式记账 `acct_ledger`。
- **3 库（ADR-010）**：`pb_core`（`iam_/dev_/loc_/wo_/ord_/pay_/acct_/agt_/usr_/gw_` 前缀，两进程共享）· `pb_pii`（`pii_*` + KMS + 区域驻留）· `pb_auth`（`cred_*`，`realm` 区分员工/消费者池）。

## 六、权限 / RBAC 子系统

- **三层模型**：认证（你是谁）→ 功能授权（能做什么）→ 数据授权（能看哪些）；会话/菜单横切。业务代码只经 `SecurityUtils`/`StaffContext`/`ConsumerContext`，**绝不碰 `SecurityContextHolder`**。
- **权限码规范**：`<模块>:<资源>:<动作>`（小写点分），如 `device:command:send`、`finance:withdrawal:audit`。通配三级 `*` / `device:*` / `device:cabinet:*`；前后端匹配语义逐字一致（后端 `Permissions.matches` ⇔ 前端 `can()`）。
- **14 模块**：dashboard/device/location/order/pricing/finance/workorder/user/marketing/cs/org/report/system/agent（+ 休眠口子 tenant）。
- **data-scope 维度**：`ALL/REGION/SITE/LOCATION/VENUE/AGENT/SELF`，存 `iam_data_scope(subject_type, subject_no, scope_type, scope_refs JSON)`（角色级+员工级取并集）；运行期 MyBatis-Plus `DataScopeHandler` 自动注入归属条件（只返回追加段/null，ThreadLocal 传播对齐 `TenantContext`）。
- **SPI 落位**：neargo-common-security 定「无表 SPI 契约 + enforcement」（`PermissionResolver`/`DataScopeResolver`/`PrincipalRefresher`），powerbank-iam 用自己的 `iam_*` 表实现契约；U1（RBAC）+ U2（数据权限引擎）已上推 neargo 并被采纳（29 测试绿）。
- **动态菜单（已冻结契约，YAGNI 暂缓接入）**：`GET /api/auth/permissions`（权限码集合）+ `GET /api/auth/menus`（已按权限过滤的菜单树）；前端「只加不改 + 静态兜底 + 开关灰度」，开关 `NEXT_PUBLIC_DYNAMIC_NAV`（默认 0）。

## 十、文档间不一致与风险点（需比对时重点关注）

1. **载体优先级冲突**：`功能矩阵-分端对照.md` 顶部前提仍写「微信小程序主力/P0」（残留旧问句「小程序 P0→支付宝 P1→App P2」），但 ADR-009 及 C 端清单已改为 **App 优先 P0、小程序 P1** —— 属未清理的过时表述，以 ADR-009 / C 端清单为准。
2. **租户层级口径不一**：`服务端-功能细化.md`（SVR-TN-01/02 租户开通 P0）与 `功能矩阵-分端对照.md` 仍按 SaaS 双级把租户服务列 P0；而 ADR-011 / 运营端清单已定「单运营方自营、管理面 MVP 不做」。**服务端与运营端对租户面的分期口径不一致**。
3. **P0/P1 双语义陷阱**：`运营端功能清单.md` 的「建设优先级 P0/P1/P2」≠ 甲方「交付阶段 P1/P2/P3」（符号相同易混）。**交付阶段以 `PRD-分期路线图.md`（← PDF 原件）为唯一 SSOT**，`ops-web/lib/nav.ts` 逐叶 phase 为权威落地。
4. **发票分期矛盾**：C 端清单标发票 P1，但运营端交付阶段把发票归 P3（生态解锁）—— 需甲方裁定。
5. **模块计数差异（非真实功能差异）**：运营端 14 模块 vs 运营商说明 15 一级模块 vs 单运营方 15 章 —— 源于「点位管理是否独立成模块」「多租户口子是否显式列一级」。
6. **旧版 vs V2 四级体系并存**：`运营端功能清单.md`（旧 7 域心智，留 `main`）与 `运营端功能清单-V2四级体系.md`（platform→operator→merchant→store 四级，14 域/27 模块/130 叶，`feature/ops-nav-v2` 分支）**并行不互斥**；V2 打散了旧「客服 cs」模块（报障→告警/工单、会话→消息中心、退款→订单、黑名单→会员），新增 topup/integrations/messaging 等。
7. **角色→码硬编码同源镜像**：后端 `auth/RolePerms.java` ⇔ 前端 `ops-web/lib/permissions.ts` 必须同步改（种子导入 `iam_role_perm` 后从鉴权路径下线）。
8. **广告屏 4/3 拆分为落地判断**：见 §8.4，PDF 仅两条粗线，待甲方确认。

## 十一、关键结论

1. **SSOT 链条清晰**：交付阶段 = `ref/充電寶專案_V4(1).pdf` →（还原）`PRD-分期路线图.md` →（落地）`ops-web/lib/nav.ts` phase 字段；功能「做什么」= 功能清单；技术「怎么做」= ADR/TDD。三条线各司其职。
2. **架构主线稳定**：Modulith 单体 + 独立网关、3 库合规边界、复用 neargo 基座、支付委托 nearpay、数据权限进程内不可服务化 —— 这些是不轻易动的骨架。
3. **当前落地重心**（本会话）：ops-web V2 四级导航 + 分期屏蔽，130 叶已全部按 PDF 真值对齐（P1 34/P2 60/P3 36），vitest + build 全绿。
4. **需甲方裁定的开放项**：发票分期（P1 vs P3）、广告屏 4/3 拆分、租户面是否进 MVP、是否需独立「区域经理」角色。→ 已整理成 [`甲方确认单-开放项.md`](requirements/甲方确认单-开放项.md)（逐项选项 + 建议默认 + 落地影响，待勾选）。
5. **后端是关键路径**：前端（ops-web/c-app）已跑在 mock/静态前，多处功能等后端域落库与真验签/真凭据接入（见第九节 🔴 阻塞项）。
