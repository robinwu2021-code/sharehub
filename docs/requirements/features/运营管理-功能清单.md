**我们模型里多出来、简电没有的两样东西放在哪**
- **点位**（站点下面的一层）：放在站点详情的「点位」tab 里维护，不单独占一个菜单
- **时段价**（每天重复的时段倍率）：作为收费方案里计费项的一部分维护（`price_schedule` 本来就有 `item_no` 列，可以挂到计费项上），不单独占一个菜单

## 2. 所有页面的共同约定

| 约定 | 做法 |
|---|---|
| 不删除，只归档 | 行操作用「归档 / 取消归档」，列表有「显示已归档」开关；契约里不出现 `delete*` |
| 状态徽标 | 一律用 `<StatusBadge>`，不在页面里内联写 `Badge tone` |
| 只读提示 | 没有写权限时用 `<ReadOnlyNotice>`，写操作按钮不显示 |
| 空态要解释 | 说清楚为什么是空的、下一步做什么，并给出入口按钮 |
| 三语与 RTL | 带 `_en` / `_ar` 列的字段在表单里给三语输入，**中文必填**；阿语界面整页镜像 |
| 数据范围 | 代理商角色只看得到自己名下的站点及其派生数据，由后端控制 |
| 操作留痕 | 所有写操作进审计日志；详情抽屉最后一个 tab 是「操作记录」 |
| 导出 | 导出**当前筛选结果**，列与表格可见列一致 |
| 金额与比率 | 金额带币种（默认 AED）；比率存 0–1 的 4 位小数，界面按百分比显示 |
| 时间 | 库里存 UTC，界面按市场时区显示并标出时区（决策 D5） |
| 列表默认 | 每页 20 条；默认按更新时间倒序；列头可排序的在各页注明 |

## 3. 场站管理

### OM-S1 站点概览 `/operation/overview`

**定位**：场站管理的首页。全局经营看板管「今天整体怎么样」，这一页管「**站点和设备铺得怎么样、哪里出了问题**」。对标简电「站场概览」。

**页面布局**（从上到下）

1. **筛选栏**：区域 · 代理商（含「平台直营」）· 时间（今日 / 近 7 日 / 近 30 日 / 自定义，最长 90 天）
2. **规模指标卡**（不随时间筛选变化，反映当前存量）

   | 卡片 | 口径 | 点击跳转 |
   |---|---|---|
   | 站点数 | 未归档站点；副标题「营业中 X · 暂停 Y」 | 站点管理 |
   | 点位数 | 未归档点位 | 站点管理，并按「有点位」筛选 |
   | 机柜数 | 未归档机柜；副标题「在线 X」 | 设备台账 |
   | 机柜在线率 | 在线且非故障 ÷ 机柜总数，**口径与经营看板一致** | 设备台账，并按「离线」筛选 |
   | 充电宝数 | 副标题「在柜 X · 借出 Y · 异常 Z」 | 充电宝管理 |

3. **经营指标卡**（随时间筛选变化）：订单数 · GMV · 客单价 · 单柜日均订单；每张卡显示与上一个同长度周期的对比
4. **趋势图**：订单数与 GMV 按日双轴折线；下方一行小图显示每周新增站点数
5. **站点排行 Top 10**

   | 要素 | 内容 |
   |---|---|
   | 排序指标 | 可切换：GMV / 订单数 / 单柜日均订单 / 在线率 |
   | 列 | 排名 · 站点 · 场地方 · 机柜数 · 指标值 · 占比 |
   | 交互 | 点击行打开站点详情抽屉；「查看全部」跳到站点管理并按该指标排序 |

6. **待关注站点**（自动识别，按严重程度排序）

   | 规则 | 判定条件 | 严重程度 | 快捷操作 |
   |---|---|---|---|
   | 设备全部离线 | 站点有机柜，且全部离线 ≥ 2 小时 | 高 | 查看机柜 · 开工单 |
   | 营业中但没有设备 | 状态为营业中，但没有未归档机柜 | 中 | 查看站点 |
   | 合同临期或过期 | 合同 30 天内到期；或已过期但站点仍营业（后者为高） | 中 / 高 | 查看合同 |
   | 没有收费方案 | 没有命中任何方案，落到全平台默认价 | 中 | 去配置方案 |
   | 没有分成配置 | 没有任何分成方 | 中 | 去配置分成 |
   | 长期零订单 | 营业中、有设备，但近 7 日零订单 | 低 | 查看统计 |

   列：站点 · 问题 · 说明（例如「3 台机柜全部离线 5 小时」）· 持续时长 · 快捷操作。可以按规则类型筛选。
7. **场景分布**：按场景类型统计站点数和 GMV 占比（环形图 + 表格）
8. **地图**：**暂不开放**。`loc_site.lng/lat` 目前全部为空，页面上占位并说明「站点经纬度补齐后开放」

| 其它要素 | 内容 |
|---|---|
| 空态 | 没有站点时：「还没有站点。站点是机柜的归属单位，先新增站点，概览才会有数据」+「新增站点」按钮 |
| 刷新 | 进入页面取一次；右上角「刷新」按钮；不自动轮询 |
| 接口 | **新增** `GET /api/ops/operation/overview?regionId&agentNo&from&to`，一次返回卡片、趋势、排行、待关注清单、场景分布；复用 `ReportService` 的看板口径和排行口径 |
| 权限 | **新增** `location:overview:read` |
| 验收 | ①同一时刻取数，本页的在线率与经营看板一致 ②每条待关注规则都有正例和反例单测 ③代理商登录只看到自己名下站点的数字 |

#### 新增 / 编辑表单

| 字段 | 类型 | 必填 | 校验与说明 |
|---|---|:-:|---|
| 站点名称 | 文本 | ✓ | ≤ 128 字；同一场地方下不能重名 |
| 阿语名称 | 文本 | | ≤ 128 字 |
| 场地方 | 下拉（可搜索） | ✓ | 只能选未归档的场地方；分成依赖它 |
| 区域 | 下拉 | ✓ | 数据权限按区域收敛 |
| 场景类型 | 下拉 | ✓ | 商场 / 机场 / 餐饮 / 地铁 / 写字楼 / 酒店 / 医院 / 其他 |
| 地址 | 文本 | ✓ | ≤ 256 字 |
| 经纬度 | 两个数字 | | 纬度 -90～90，经度 -180～180；地图选点等地图开放后再做 |
| 营业时间 | 时间段组件 | ✓ | 支持多段（如 10:00–14:00、17:00–22:00）和「24 小时」；各段不能重叠；存为 `HH:mm-HH:mm` 逗号分隔 |
| 所属代理 | 只读 | | **不能在这里修改**，旁边给「去划拨」链接。原因：改归属必须连同点位、机柜一起级联，还要留划拨流水（`AgentOwnershipSync`）；直接改字段会造成归属不一致 |
| 状态 | — | | 新增时默认营业中；编辑表单里不改状态，状态走行操作 |

#### 状态与业务规则

```
营业中 ACTIVE ──暂停营业──▶ 暂停 PAUSED
     ▲                          │
     └────────恢复营业───────────┘
任一状态 ──归档──▶ 已归档（archived_at 非空）──取消归档──▶ 回到归档前的状态
```

- **暂停营业**：C 端附近列表不再显示该站点；站内机柜不允许新借；**已借出的仍可归还**；需要填暂停原因
- **归档**：站点下还有未归档的机柜时不允许，提示「站点下还有 N 台机柜，请先迁出或归档」
- **营业时间外**：C 端显示「已打烊」，不允许借出，允许归还

### OM-S3 收费方案 `/operation/fee-plans`

**定位**：定义「怎么收钱」。数据结构四层：方案 `price_plan` → 计费项 `price_plan_item` → 阶梯价 `price_ladder` → 适用范围 `price_plan_scope`；时段倍率 `price_schedule` 挂在计费项上。
**简电实证**：简电的收费方案有一列「所属运营商」，即方案按运营商隔离。我们是单运营方，方案全平台共用，**暂不做**这一层（D8）。

#### 列表

| 列 | 说明 | 可排序 |
|---|---|:-:|
| 方案编号 · 方案名称 | `plan_no` · `name` | ✓ |
| 设备类型 | 目前只有充电宝（ADR-014 设备类型抽象） | |
| **计费摘要** | 由计费项自动生成，例如「前 15 分钟免费，之后每 60 分钟 AED 5，日封顶 AED 20，总封顶 AED 99（等同买断）；每晚 18:00–23:00 × 1.5」。**运营看这一列就能核对价格** | |
| 适用范围 | 「全平台」或「区域 2 · 站点 5 · 场景 1」 | |
| 命中站点数 | 按取价链实际落到本方案的站点数；点击看站点列表 | ✓ |
| 待生效调价 | 有待生效的预约调价时显示角标和最近生效时间 | |
| 状态 | 启用 · 停用 · 已归档 | |
| 更新时间 | — | ✓ |

**筛选**：关键字 · 设备类型 · 状态 · 适用站点
**行操作**：查看 · 编辑 · **复制为新方案** · 试算 · 预约调价（带上本方案跳到 OM-S4 新建）· 启用 / 停用 · 归档

#### 表单（分四段）

**① 基本信息**

| 字段 | 必填 | 规则 |
|---|:-:|---|
| 方案名称 | ✓ | ≤ 64 字，不能重名 |
| 设备类型 | ✓ | 默认充电宝 |
| 币种 | ✓ | 默认 AED；方案保存后不能改 |
| 说明 | | 内部备注 |

**② 计费项**（至少一项，可多项，可拖动排序）

| 字段 | 必填 | 规则 |
|---|:-:|---|
| 类型 `item_type` | ✓ | 租金 / 超时费 / 买断 |
| 计量方式 `metering` | ✓ | 按时长 / 按次 |
| 免费量 `free_qty` | | ≥ 0；按时长时单位为分钟 |
| 计费单位 `unit_qty` | ✓ | > 0，例如每 60 分钟 |
| 定价方式 | ✓ | **单价**或**阶梯价**二选一 |
| 单价 | 单价时必填 | > 0 |
| 阶梯价 | 阶梯时必填 | 按行填「从 / 到 / 单价」；各段必须**首尾相接、互不重叠**；最后一段可以不填上限 |
| 日封顶 · 总封顶 | | 总封顶必须 ≥ 日封顶；**总封顶即买断价**，到达后订单转为买断 |
| 取整规则 `rounding` | ✓ | 向上取整（默认）/ 四舍五入 / 向下取整 |

**③ 时段倍率**（挂在计费项上，可多条；原「活动 / 时段价」菜单的功能）

| 字段 | 规则 |
|---|---|
| 名称 | 例如「晚高峰」「开斋节」 |
| 时段 | **界面选择，不让运营手写表达式**：时间范围 + 星期多选；或选节假日。由界面生成 `period` 表达式 |
| 倍率 | 0.1～5，允许大于 1；界面显示「× 1.5」 |
| 适用区域 | 为空表示方案适用范围内全部生效 |
| 启用 | 开关 |

### OM-S4 预约调价 `/operation/fee-adjustments`【新功能】

**定位**：提前定好「**某个时间点，把某个方案改成新价格**」，到点由系统自动执行；可选「到某个时间自动恢复原价」，用于限时活动。对标简电 `fee_reserve`（新增 / 编辑 / 查看）。

#### 状态机

```
待生效 SCHEDULED ──到点执行成功──▶ 已生效 APPLIED ──到恢复时间──▶ 已恢复 REVERTED
      │                              │

      ▼
```

#### 业务规则

1. 同一方案的多条待生效调价，时间窗不能重叠
2. 执行时先记录**变更前快照**，再写入方案；恢复时按快照还原
3. 已开始的订单不受影响
4. 定时任务每分钟扫描一次，以调价单号为**幂等键**；服务停机期间错过的调价，重启后补执行，并在执行日志里记录实际执行时间
5. 目标方案被停用或归档后，它名下的待生效调价自动转为已撤销，并通知创建人
6. 调价生效后、恢复前，如果有人手工改过这个方案：恢复时**不覆盖**，转为执行失败，说明「方案在调价期间被人工修改，请确认后手动处理」

| 接口（新增） | `GET/POST /api/trade/price-adjustments` · `POST /api/trade/price-adjustments/{no}` · `POST /{no}/cancel` · `POST /{no}/revert` · `POST /{no}/retry` |
| 权限（新增，先登记到功能权限清单） | `pricing:adjustment:read / :create / :cancel` |

**三步走**
1. **并存**：新菜单上线，旧菜单保持不动；新旧页面读写同一份后端数据，不做数据迁移
2. **切换**：旧菜单项隐藏；旧链接（含 `?tab=` 形式的深链）自动重定向到新页面
3. **下线**：删除旧页面代码；「计费定价」菜单整体下线，「站点与点位」只保留渠道拓展相关的菜单项

## 8. 开工前需要拍板的事

| # | 事项 | 建议 |
|---|---|---|
| **D1** | 新菜单一级可见性怎么判断。现在的规则是「角色有这个模块前缀的权限就显示一级菜单」，但运营管理横跨 location / pricing / finance / system / marketing 五个模块 | 给菜单配置增加「多模块」支持：**只要有一个子菜单可见，一级菜单就显示**。子菜单继续用原有的资源权限码，不为新菜单另造一套 |
| **D2** | 站点分成比例存了两份：分润规则 `share_rule`（按分成方配，**没有站点这一列**）和进场合同 `loc_contract.share_rate`。而且代码里**没有找到从订单生成分润明细的逻辑**，只有演示种子在写 | 先确认分润链路是否真的缺失；如果缺失，比新菜单更优先。模型上建议以「规则 + 站点范围」为唯一来源，合同上的比例只作为签约条款，签约时生成对应规则 |
| **D3** | 差异化定价（`price_rule`）与方案适用范围（`price_plan_scope`）重复建模 | 保留适用范围，迁移差异化定价的数据 |
| **D4** | 多条时段倍率同时命中怎么算 | 先读取价引擎的现有实现，照实现写进页面说明；实现里没定义再定规则 |
| **D5** | 时区。业务在中东，但我部署时在 systemd 里写了 `-Duser.timezone=Asia/Shanghai`，**这是我的失误**。预约调价按时间点执行，时区错了会在错误的时间改价 | 库里存 UTC，界面按市场时区（`Asia/Dubai`）显示；同时改掉服务器上的这个参数 |
| **D6** | 预约调价要不要审批 | 第一版不做审批，只要求填原因并留痕 |
| **D7** | 线上阶段：线上前端按第 1 期运行（`.env.local` 不入库，部署时拿不到），第 2、3 期菜单都显示「功能尚未开放」 | 新菜单不挂阶段标记；已经做好的功能直接开放 |
| **D8** | 简电的收费方案按运营商隔离 | 我们是单运营方，暂不做；将来做加盟或多运营商时再加「所属代理商」 |
| **D9** | 「充电电量」要不要换成「设备规格」字典 | 不在本期范围，由产品另行确认 |
