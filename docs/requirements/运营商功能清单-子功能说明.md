## 1. 经营看板

| 子功能 | 说明 |
|--------|------|
| 经营总览 | 今日 GMV、订单数、活跃柜机、设备在线率、待处理工单等核心 KPI 卡片 |
| 收入趋势 | 近 7/30 日 GMV、订单量折线趋势，支持周期切换 |
| 实时告警 | 柜机离线、异常订单、超时工单的即时提醒条，可跳转处置 |
| 待办中心 | 待派工单、待审退款、待审提现等待办聚合入口 |
| 排名榜单 | Top 点位坪效、低效点位、异常设备排行 |
| 快捷入口 | 常用操作（远程弹出、开工单、查订单）快捷方式 |

## 2. 设备管理

### 2.1 设备台账
| 子功能 | 说明 |
|--------|------|
| 机柜列表 | 机柜/充电桩台账，按供应商/状态/点位/在线/代理 筛选查询 |
| 机柜详情 | 单柜基本信息 + 仓位网格 + 实时状态 + 归属点位/代理 |
| 仓位明细 | 各仓位在仓充电宝、锁态、电量、健康状态 |
| 充电宝管理 | 充电宝清单、状态流转（在库/在用/归还/报废/丢失）、报废标记 |
| 新增/编辑/删除 | 设备建档、信息维护、退役 |
| 导入/导出 | Excel 批量导入台账（校验重复/格式）、导出 |

### 2.2 实时监控
| 子功能 | 说明 |
|--------|------|
| 在线状态监控 | 基于心跳/设备影子的在线态与在线率统计，离线高亮 |
| 离线/故障告警 | 心跳超时判离线、故障上报，生成告警并可联动工单 |
| 设备地图分布 | 柜机 POI 地图分布（中东 Google Maps），点选查看 |

### 2.3 远程控制
| 子功能 | 说明 |
|--------|------|
| 单柜指令 | 弹出任意仓/指定仓、锁仓/解锁、重启、定位（响铃闪灯）、语音播报 |
| 批量指令 | 多柜批量弹出/重启/锁定，带限速 |
| 指令记录 | 指令下发历史、状态（下发/确认/超时/失败）与回执 |

### 2.4 库存调拨（P1）
| 子功能 | 说明 |
|--------|------|
| 库存查询 | 仓库/区域充电宝库存 |
| 调拨单 | 跨点位/仓库调拨，单据流转 |
| 盘点 | 盘点任务、差异记录 |

### 2.5 固件 OTA（P1）
| 子功能 | 说明 |
|--------|------|
| 版本管理 | 固件版本发布（版本号/包/校验/强制位）|
| 灰度投放 | 按 单设备/点位/全部 范围投放，强制/非强制 |
| 升级跟踪 | 逐设备升级任务状态、rollout 进度汇总 |
| 回滚 | 失败自动回滚旧版；失败率超阈自动暂停 |

### 2.6 供应商接入
| 子功能 | 说明 |
|--------|------|
| 供应商注册 | 硬件供应商建档（供应商码/名称/接入方式）|
| 接入配置 | 接入方式（TCP 私有协议 / MQTT 直连 / HTTP 云对接）、API 基址、密钥、回调地址 |
| driver 状态 | driver 挂载状态、在线设备数、热加载生效 |

## 3. 点位管理

| 子功能 | 说明 |
|--------|------|
| 点位 POI | 点位建档（名称/地址/经纬度/场景类型）、设备关联、启停 |
| 场地方档案 | 场地方主体、联系人、行业，增删查改 |
| 进场合同 | 合同（分成比例/进场费/结算周期/期限/附件），驱动分润规则 |
| BD 拓展 CRM（P1）| 商机、跟进记录、签约漏斗 |
| 点位坪效（P1）| 单点位收入、翻台、回本分析 |

## 4. 订单管理

| 子功能 | 说明 |
|--------|------|
| 订单列表 | 按状态/时间/点位/用户/柜机 筛选查询 |
| 订单详情 | 借还柜机、充电宝、计费明细、押金、状态流水（事件时间线）|
| 进行中订单 | 使用中订单实时计费监控 |
| 异常订单处理 | 未弹出/未归还/超时买断/重复扣费 专项清单与一键处置 |
| 订单干预 | 远程弹出、强制归还、免单、补偿（高权限 + 审计）|
| 退款管理 | 退款申请 → 审批 → 执行（经 nearpay）→ 状态跟踪，幂等 |

## 5. 计费定价

| 子功能 | 说明 |
|--------|------|
| 计费模板 | 免费时长、计费单位与单价、日封顶、总封顶（买断价），改动影响新订单 |
| 差异化定价（P1）| 按点位/场景取不同价 |
| 活动/时段价（P2）| 分时段、节假日定价 |

## 6. 财务管理
> 支付/收单/打款委托 nearpay；本模块管账务、分润、结算。

| 子功能 | 说明 |
|--------|------|
| 分润规则 | 按维度（场地方/代理）配置分成模式（渠道分账/平台记账）、比例、优先级 |
| 分润明细 | 逐单分润记录 |
| 账务分录 | 复式记账（借贷平衡）、先记账后执行、只增分录 |
| 结算单 | 周期结算单（对象/周期/金额/状态），生成与确认 |
| 提现审核 | 提现申请审核，通过后经 nearpay 打款 |
| 对账 | nearpay 交易 ↔ 支付引用 ↔ 账务分录 三方核对，差错处理 |
| 发票 | 开票申请、抬头、中东 VAT/TRN 税票 |

## 7. 工单管理

| 子功能 | 说明 |
|--------|------|
| 工单看板 | 按状态列（待派/处理中/已完成…）看板视图 |
| 开单 | 手动创建工单 + 设备告警自动开单 |
| 派单 | 指定人 / 就近 / 负载均衡 派单 |
| 处理与验收 | 接单 → 现场处理（拍照/备注/换件）→ 完成 → 审核关单 |
| SLA 管理（P1）| 响应/解决时限、超时升级通知 |
| 巡检计划（P1）| 周期巡检路线，按计划自动生成工单 |

## 8. 用户管理

| 子功能 | 说明 |
|--------|------|
| C 端用户列表 | 用户查询（昵称/手机/信用分/订单数）|
| 信用与风控 | 信用分（影响免押额度）、风险标记 |
| 黑名单 | 拉黑/解除，拦截下单 |
| 会员/次卡（P1）| 会员权益、次卡管理 |
| 钱包（P1）| 余额、赠金 |

## 9. 营销管理

| 子功能 | 说明 |
|--------|------|
| 优惠券 | 券模板（立减/折扣/门槛/库存）、发放、核销、防刷 |
| 活动 | 活动规则、权益计算 |
| 推送触达 | App Push / 小程序订阅消息 触达用户 |
| 邀请裂变（P2）| 分享有礼、拉新归因 |

## 10. 客服管理

| 子功能 | 说明 |
|--------|------|
| 报障受理 | C 端报障工单受理，转订单干预/退款 |
| 客服会话（P1）| 客服沟通记录 |
| 退款/补偿 | 复用订单退款、免单补偿 |
| 黑名单处理 | 复用用户风控拉黑 |

## 11. 代理商管理
> 代理商 = 运营方体内经营伙伴（[ADR-012](../technical/ADR/ADR-012-代理商模型.md)），非租户。

### 11.1 运营方侧（管代理）
| 子功能 | 说明 |
|--------|------|
| 代理商档案 | 代理主体、联系人、辖域、默认分润比例、结算账户、状态，增删查改 |
| 设备/点位划拨 | 把机柜/点位归属到代理（`agent_no`），代理只经营自己那批 |
| 代理分润配置 | 配置代理分润比例/模式（分润规则 AGENT 维度）|
| 代理收益结算 | 代理分润明细、结算单、提现审核 |
| 代理绩效 | 代理片区 GMV、设备数、在线率排名 |
| 代理账号管理 | 开通/停用代理登录账号（AGENT 角色 + 自己 agent_no 数据范围）|

### 11.2 代理端（代理商自己用，P1）
| 子功能 | 说明 |
|--------|------|
| 我的看板 | 自己辖域的经营概览 |
| 我的设备 | 只看自己归属柜机的状态/在线率 |
| 我的订单 | 自己设备产生的订单（脱敏）|
| 我的收益 | 分润明细、结算、发起提现 |
| 设备报修 | 对自己设备报障开工单 |

## 12. 员工与权限

| 子功能 | 说明 |
|--------|------|
| 组织架构 | 部门/团队 增删查改 |
| 员工管理 | 员工建档、状态、离职 |
| 角色管理 | 角色（功能权限集）增删查改、授权，内置角色只读 |
| 数据权限 | 按 区域/点位/代理(agent_no) 限定可见数据范围 |
| 操作审计 | 关键操作（增删改/审核/干预/退款/指令）留痕，可追溯 |
| 绩效报表（P1）| 运维/客服/BD 绩效统计 |

## 13. 数据报表（P1+）

| 子功能 | 说明 |
|--------|------|
| 设备运营分析 | 在线率、翻台、故障率 |
| 点位坪效 | 点位收入、成本、回本 |
| 财务报表 | 收入、分润、结算汇总 |
| 实时大屏（P2）| 运营大屏 |
| 自定义报表（P2）| 自选指标查询导出 |

## 15. 🔒 多租户（休眠口子 · 不建）

> 仅保留 `tenant_id` 数据列作最低成本口子，**管理面不做、可能永不启用**（AI 时代更可能每租户一套独立部署，[ADR-011](../technical/ADR/ADR-011-单运营方为主多租户为口子.md)）。
> 口子若启用，语义泛指"隔离的经营实体"——最现实场景是**同一运营商跑多业态**（充电宝 / 充电桩 各算一租户），而非招别的运营方。届时再考虑租户开通/切换/大盘等管理面，MVP 全不建。
