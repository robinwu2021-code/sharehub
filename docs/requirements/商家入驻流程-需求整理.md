## 〇、一页结论

| 问题 | 结论 |
|---|---|
| **入口** | 只有运营代建。公开注册页一期关闭 |
| **登录** | 邮箱 + 验证码为主；手机号选填，商家自行验证后可用 |
| **建档** | 两阶段。第一阶段建账号：邮箱、店名、联系人。第二阶段补资料：位置、行业，再加开票、合同、收款账户 |
| **概念** | 商家拿分成；场地方只记录；一个商家对应一个系统自动建的默认站点，商家看不到「站点」这个词 |
| **分成** | 只给商家分。基数为税前金额，即实收扣除 VAT；基数方式做成可配置，每笔明细快照当时的口径 |
| **提现** | 财务手动执行，一般三个月一次：选付款截止日 → 生成付款任务 → 复核 → 导出转账文件 → 线下银行转账 → 批量确认到账。全程只记账，不接渠道 |
| **商家看到** | 首页是营收；另有订单明细、我的分成、结算与对账、**提现记录（只读）**、商家资料、我的站点、我的设备、设备报修 |
| **最大的三处代码缺口** | 分成基数现在是含税实收；场地方现在会生成分成；提现只能逐笔登记，没有批次、导出和批量确认（§十二） |

## 一、概念梳理

| 概念 | 是什么 | 一期在系统里的作用 | 拿不拿钱 | 代码落点 |
|---|---|---|:-:|---|
| **商家** | 与平台结算的经营方，例如一家酒店、一家咖啡店 | 有账号、能登录商家端；设备归属与营收统计的单位；**唯一的结算对象** | ✓ | 运营主体 `agt_agent`，编号列 `agent_no` |
| **场地方** | 提供物理场地的一方，例如商场业主、机场管理方 | **只做档案记录**：名称、联系人、地址、行业、进场合同。不登录、不分成、不出结算单 | ✗ | `loc_venue` |
| 站点 | 设备摆放的物理场所，带地址和坐标 | 一期是**技术载体**：每个商家自动建一个默认站点，地址坐标取自商家位置。用户 App 的「找附近」和分成计算都依赖它 | — | `loc_site` |
| 点位 | 站点内设备的具体摆放处 | 同站点，运营内部使用 | — | `loc_location` |
| 门店 | 一个商家下的多个经营网点 | **一期不做**。将来一个商家可有多个门店，每个门店对应一个站点 | — | 将来的扩展 |
| 商户 | 商家在支付渠道侧的子商户号 | **一期不做**（D5 不进件） | — | 未建 |

### 1.1 商家与场地方的区分

| 情形 | 一期怎么记 |
|---|---|
| 酒店自己经营、设备放在自家大堂 | 酒店建为**商家**。可不建场地方档案 |
| 咖啡店在商场里，设备放在咖啡店内 | 咖啡店建为**商家**；商场可建为**场地方**档案，仅作记录 |
| 平台直接与商场签约、设备放在商场公共区域，没有商家 | 设备归平台直营，无商家分成；商场为场地方档案 |

判断方法：**谁与平台按营收分成，谁就是商家**。只提供地方、不参与分成的，是场地方。

### 1.2 为什么要有默认站点

现有代码有两处硬依赖站点：分成计算在订单没有站点归属时直接跳过并告警；用户 App 按站点坐标排「附近」。
一期不做门店，但不能去掉站点。所以由系统在商家补齐位置时**自动建一个默认站点**，运营与商家都不必手动维护。
将来做门店时，门店就是该商家下的第二、第三个站点，模型不用改。

## 二、角色与范围

| 角色 | 一期做什么 | 登录方式 |
|---|---|---|
| 运营 BD | 创建商家账号，补充资料 | 员工账号 |
| 运营审核员 | 审核并开通；首期可与 BD 为同一人 | 员工账号 |
| 财务 | 生成结算单、发起付款任务、导出转账文件、批量确认到账 | 员工账号 |
| 财务复核 | 审核付款任务；不能与发起人为同一人 | 员工账号 |
| 商家 | 查看营收、分成、结算与提现记录，查看设备，提交报修，修改联系人 | 邮箱 + 验证码 |

**一期不做**：商家自助注册、商家进件、支付渠道代付、门店、场地方分成、商家申请提现、原生商家 App。

## 三、全流程

```
① 创建账号   运营录入 邮箱·店名·联系人（手机号选填）→ 审核开通 → 发邀请邮件
② 补充资料   位置·行业（核心）→ 系统自动建默认站点
             开票信息 · 合同与分润规则 · 收款账户
③ 划拨设备   设备划到该商家的默认站点（位置、行业未补齐不允许）
④ 产生订单   用户借还 → 订单结算
⑤ 生成分成   税前基数 × 商家分成比例 → 分成明细（场地方不生成）
⑥ 月度结算   分成明细按商家 × 月汇成结算单 → 财务确认
⑦ 付款       财务建付款任务 → 复核 → 导出转账文件 → 银行线下转账 → 批量确认到账 → 记账
⑧ 商家查看   营收首页 · 分成 · 结算 · 提现记录
```

## 四、登录标识：邮箱优先

| # | 规则 |
|---|---|
| R1 | 邮箱必填，是主登录方式；所有通知优先发邮箱 |
| R2 | 手机号选填 |
| R3 | 运营录入的邮箱与手机号都先记为未验证，防止录错后把账号交给陌生人 |
| R4 | 商家用邮箱收验证码首次登录成功，邮箱即记为已验证 |
| R5 | 手机号需商家登录后自行验证，验证后才能用手机号登录 |
| R6 | 未验证的标识不占唯一性，录错的号码不会挡住真正的号主 |
| R7 | 同一邮箱属于多个商家时，登录后选择身份，顶栏可切换 |
| R8 | 登录页只有一个输入框，邮箱或手机号均可，由服务端判断 |

**规范化**：邮箱去首尾空格并转小写；手机号转国际格式，默认国家码 +971。查找用不可逆摘要，显示用掩码，发送用加密原文。

**验证码**：6 位数字，5 分钟有效，60 秒可重发；同一标识每日上限，同一 IP 每分钟上限。号码不存在、验证码错误、超频三种情况对外提示一致。

由运营在商家档案中补充，**不阻塞商家登录**，但会卡住后续动作。

## 七、分成与结算

### 7.1 分成对象

一期**只有商家**。场地方即使在站点上有关联、有进场合同，也**不生成分成明细、不出结算单**。进场合同里的分成比例仅作记录。

### 7.2 分成基数：税前

| 项 | 规则 |
|---|---|
| 定义 | 税前基数 = 订单实收 ÷ (1 + VAT 税率)。实收指用户实际支付，不含免单与券抵扣部分 |
| 税率 | 系统参数，默认 5%（阿联酋标准税率），按生效日期配置 |
| 分成金额 | 税前基数 × 商家分成比例，保留两位小数 |
| 可调整 | 基数口径是系统参数，取值为「税前」或「含税实收」；默认税前 |
| 快照 | 每笔分成明细记录当时的基数口径、税率、基数金额与比例。改参数**只影响之后的订单**，不追溯 |
| 退款 | 订单退款按同一口径冲减分成；结算单已确认的，冲减计入下一期调整 |

> 示例：用户实付 10.50 AED，税率 5%，税前基数 10.00 AED；商家比例 30%，分成 3.00 AED。

### 7.3 月度结算

| 步 | 动作 | 权限码 |
|---|---|---|
| 1 | 账期结束后按商家 × 月生成结算单：分成合计、上期调整、本期应结 | `finance:settlement:generate` |
| 2 | 财务核对后确认，确认后金额锁定 | `finance:settlement:confirm` |
| 3 | 已确认未付款的结算单进入「可付款」池 | — |

## 八、提现与付款（平台运营端）

一期的「提现」是**平台向商家付款**，由财务在运营端发起，商家不申请。全程不接支付渠道，系统只做记账，钱由财务在银行线下转出。

### 8.1 付款节奏与生成付款任务

| 项 | 规则 |
|---|---|
| 频率 | **运营方手动执行**，系统不定时自动生成。一般三个月一次 |
| 付款截止日 | 财务手动选择一个日期。账期结束日不晚于截止日、已确认、未付款的结算单纳入本次付款 |
| 预览 | 选定截止日后先看预览：每个商家的结算单数、合计金额、收款账户状态；收款账户未核验或资料不全的商家单列为「本次不能付款」并说明原因 |
| 生成 | 点击「生成付款任务」，每个商家合并为一笔提现单，一笔提现单可含多个月的结算单 |
| 防重 | 已在途付款任务中的结算单不会被再次纳入；同一时刻只允许一个待复核或待转账的付款任务 |
| 遗留 | 未纳入的结算单留在可付款范围，下次付款任务自动带上 |

### 8.2 流程

```
财务选择付款截止日 → 预览
   │ 点击「生成付款任务」（每个商家一笔提现单）
   ▼
待复核 ──复核驳回──▶ 已撤回（结算单回到可付款范围）
   │ 复核通过（复核人 ≠ 发起人）
   ▼
待转账 ── 导出转账文件（可重复导出，每次留记录）
   │ 财务在银行网银批量转账
   ▼
批量确认
   ├─ 全部成功：填银行批次参考号与转账日期 → 批次内全部记为已到账
   ├─ 部分失败：逐笔标记失败并填原因 → 失败的单回到可付款范围，其余记为已到账
   └─ 导入银行回单：按行匹配提现单，自动标记成功或失败
   ▼
已到账 → 结算单置为已付 → 记一笔应付冲减分录 → 通知商家
```

### 8.3 付款任务与提现单

| 对象 | 字段 |
|---|---|
| 付款任务 | 任务号、付款截止日、币种、笔数、合计金额、状态、发起人与时间、复核人与时间、导出记录、确认人与时间、银行批次参考号 |
| 提现单 | 提现单号、任务号、商家编号与店名、对应结算单（可多张）、金额、收款账户快照（开户名、银行、IBAN 掩码）、状态、转账日期、银行参考号、失败原因 |

**收款账户快照**：生成批次时把账户信息复制进提现单。之后商家改了账户，已出的转账文件与记录不受影响。

### 8.4 状态

| 提现单状态 | 商家端显示 | 含义 |
|---|---|---|
| 待复核 | 处理中 | 财务已发起 |
| 待转账 | 处理中 | 复核通过，等待银行转账 |
| 已到账 | 已到账 | 财务已确认转账成功 |
| 失败 | 未成功，平台将重新安排 | 银行退回或信息有误 |
| 已撤回 | 不显示 | 复核驳回，不对商家展示 |

非法迁移在服务层报错。已到账是终态。

### 8.5 转账文件

| 项 | 规则 |
|---|---|
| 格式 | Excel 与 CSV；列：序号、提现单号、收款人开户名、银行、IBAN、SWIFT、金额、币种、附言 |
| 附言 | 提现单号，便于银行回单按行匹配 |
| 完整账号 | 导出文件含完整 IBAN，**仅持导出权限的人可导出**，每次导出记录人、时间、文件摘要 |
| 银行模板 | 默认通用列；对接具体银行的批量转账模板时，按银行增加导出格式 |

### 8.6 记账

| 时点 | 分录 |
|---|---|
| 结算单确认 | 应付商家增加 |
| 提现单已到账 | 应付商家减少，银行存款减少 |
| 失败 | 不记账；结算单回到可付款范围 |

会计系统接入后，「已到账」改为从会计系统读回，见 ADR-032 §二。

### 8.7 权限

| 动作 | 权限码 |
|---|---|
| 查看提现单与批次 | `finance:withdrawal:read` |
| 生成付款任务 | 拟新增 `finance:withdrawal:create` · 待登记 |
| 复核 | `finance:withdrawal:audit` |
| 导出转账文件 | 拟新增 `finance:withdrawal:export` · 待登记 |
| 确认到账与标记失败 | `finance:withdrawal:pay` |

发起、复核、确认三步分码，复核人不能是发起人。商家角色**收回** `finance:withdrawal:apply`，改持 `finance:withdrawal:read`，数据范围为本商家。

## 九、商家端（Web）

| 项 | 规则 |

## 十、商家能看到的信息

核心是营收。首页就是营收，其他页面回答「营收从哪来」和「钱到没到」。数据范围固定为本商家，服务端硬过滤。

### 10.1 口径

| 指标 | 定义 |
|---|---|
| 交易额 | 本商家设备上完成的订单，用户实付合计，含 VAT |
| 订单数 | 完成的订单笔数 |
| 退款 | 已退给用户的金额 |
| 净交易额 | 交易额 − 退款 |
| 税前营收 | 净交易额 ÷ (1 + VAT 税率)，即分成基数合计 |
| 我的分成 | 税前营收 × 分成比例 |
| 待结算 | 已产生分成、尚未进入已确认结算单的金额 |
| 已结算未付 | 已确认结算单中尚未到账的金额 |
| 已到账 | 已确认到账的提现金额合计 |

订单完成后 5 分钟内计入交易额。结算单确认后金额锁定。

### 10.2 营收首页

| 区块 | 内容 |
|---|---|
| 时间选择 | 今日、昨日、本周、本月、上月、自定义区间 |
| 核心数字 | 交易额、订单数、税前营收、我的分成，各带环比 |
| 钱的状态 | 待结算、已结算未付、已到账，点击分别进入分成、结算、提现记录 |
| 趋势 | 按天的交易额与订单数 |
| 设备排行 | 按设备的交易额排行 |
| 提醒 | 离线设备数、无可借电池的设备数 |
| 空态 | 尚无设备时显示「设备上线后这里会显示营收」及划拨进度 |

## 十五、验收标准

| # | 场景 | 期望 |
|---|---|---|
| AC-01 | 运营只填邮箱、店名、联系人，点「创建并开通」 | 开通成功，邮箱收到邀请 |
| AC-02 | 商家以邮箱收验证码首登 | 登录成功，邮箱记为已验证，进入营收首页 |
| AC-03 | 运营补齐位置与行业 | 系统自动建默认站点，地址坐标与商家一致；此后可划拨设备 |
| AC-04 | 位置或行业未补齐时划拨设备 | 被拦下并提示缺什么 |
| AC-05 | 用户实付 10.50 AED，税率 5%，商家比例 30% | 分成明细：税前基数 10.00，分成 3.00，并记录口径与税率 |
| AC-06 | 设备所在站点关联了场地方 | 只生成商家分成，不生成场地方分成 |
| AC-07 | 修改基数口径为含税 | 只影响修改后的订单，历史分成不变 |
| AC-08 | 财务对两个商家发起付款任务，由同一人复核 | 被拒绝；换另一人复核通过 |
| AC-08b | 选择付款截止日 9-30，商家有 7、8、9、10 月已确认结算单 | 只纳入 7–9 月三张，合并为一笔提现单；10 月留待下次。已有待转账的任务时不能再生成 |
| AC-09 | 导出转账文件 | 含完整 IBAN 与金额，导出记录可查；无导出权限的人不可见按钮 |
| AC-10 | 批量确认时一笔失败 | 失败单回到可付款范围；其余记为已到账，对应结算单置为已付 |
| AC-11 | 商家查看提现记录 | 看到金额、状态、转账日期、银行参考号；看不到申请按钮、批次与复核信息 |
| AC-12 | 商家首页「本月」 | 交易额、订单数、税前营收、我的分成与明细逐笔加总一致 |
| AC-13 | 商家打开结算与对账 | 正常显示，不 403 |
| AC-14 | 商家访问其他商家数据 | 返回为空或拒绝 |
| AC-15 | 手机浏览器 375px 宽登录并查看营收 | 全程可用，无横向滚动 |
