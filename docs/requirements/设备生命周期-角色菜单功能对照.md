## 一 生命周期主线与分支

采购／期初 → 实收 → 质检 → 可用库存 → 商家出库 → 签收 → 按商家选择待安装设备 → 绑定 → 安装验收 → 上线 → 监控维护。故障后可现场维修，或停用撤机→退库待检→维修／返厂→复检→重新出库安装。终止分支为采购退货、报废或遗失处理。

同商家现场迁点可以走受控解绑／撤机后留商家待安装，不虚构先退仓再出仓。跨商家变更不能在安装页静默修改出库商家。

## 三 状态分轴和角色责任

| 状态轴 | 必须区分的内容 | 责任与来源 |
|---|---|---|
| 采购 | 已订购、部分收货、已收齐、取消／关闭 | 授权采购经办；采购／收货记录 |
| 实物位置 | 仓库、调拨在途、商家现场、供应商维修处 | 仓实收、接收人交接、运现场记录 |
| 可用性 | 待检、合格可用、不合格隔离、故障、维修中、报废 | 授权质检和维修验收；不是自由改标签 |
| 经营 | 待绑定、待安装、待上线、营业、暂停、已撤机 | 运按工单、点位和门禁动作维护 |
| 交接 | 待签收、已签收、交付确认、差异待处理 | 实际接收人，商家现场确认另记录 |
| 在线 | 在线、离线、未知／过期 | 真实厂商遥测；不可伪造 |
| 财务与权属 | 资产来源、价值、法律权属与经营商家 | 财务／授权经办；出库选商家不自动改变法律所有权 |

以上为业务表达方案，不要求把所有轴塞入CabinetStatus。当前IN_STOCK还参与待上线和撤机状态，不能仅凭该值判定实物在仓或可以出库。

## 五 充电宝与数量物料差异

- 充电宝须追踪在仓、在柜、借出、故障、遗失、买断和报废；PowerbankStatus不能套用机柜部署状态。商家出库候选规则当前代码以机柜链路为主，充电宝独立商家交付／装柜须另核对，不能默认整套已支持。
- 装宝、补宝、取出和用户借还属于柜槽与租赁业务；只有真实仓库发出／实收才改变仓内库存。
- 备件耗材按数量或序列跟踪；领用关联维修工单，剩余退料有来源引用；不要求经过机柜安装上线门禁。
- 供应商未交货、仓间在途、已出库待安装与用户借出分别统计，不合并为同一库存量。

## 六 全流程验收清单

- 100订购／80实收／70合格／10待检：实物、未收、可用和待检分别正确；同一来源重试不重复增库。
- A商家出库只允许A的安装链路；更换商家清空旧选择；伪造设备号、混批、其他商家点位及未签收设备被服务端拒绝。
- 发货、签收、安装、上线四个时点库存仅在真实出入库过账变化；历史商家和位置不覆盖旧订单。
- 现场修复、停用、撤机退库、返厂、复检再投放各走正确分支；故障修复不绕过验收。
- 安装／撤机事件失败可查询、重试与对账；业务工单完成不掩盖设备或库存副作用失败。
- 盘点期间并发作业、差异审批、调整流水、反向纠错及远程响应丢失均有证据。
- 各阶段主责、交接人、时间、原因、单据与证据在设备履历可定位；成本和个人信息按字段授权。
- 管／运／仓／客／财／BD／读／商逐角色验收查询范围、操作权限和深链直调，不能只验ADMIN。
