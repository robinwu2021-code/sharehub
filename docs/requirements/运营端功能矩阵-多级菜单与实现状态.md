## 一 读法与角色

菜单层级为一级模块→二级分组→三级子菜单／页内功能；关键操作是该子菜单必须实现的第四层能力。保留现有路由作为映射，不凭空声明新路由已经存在。共享报表和角色快捷入口复用同一数据源；角色门户不复制后台写权限。

角色：管ADMIN、运OPS、仓WAREHOUSE、客CS、财FINANCE、BD、读VIEWER、商AGENT。下表角色列表示建议可见角色；写动作按原[角色动作授权规则](运营端完整功能矩阵-角色与优化菜单-2026-10-30.md)及本文件的动作分权执行。查看不自动允许导出、审批或执行；角色数据范围由服务端强制。

| 状态 | 意义 |
|---|---|
| 已验证 | 有对应业务范围的运行验收证据；本轮没有将整个子菜单标为已验证 |
| 待验收 | 已有入口或实现证据，但未完成该子菜单的功能及角色验收 |
| 部分实现／待补齐 | 已确认已有能力和具体缺口 |
| 条件／部分 | 依赖SERVICE、OpsKit或真实厂商接口，不能用mock作为上线验收 |
| 待开发 | 代码明确占位或不支持相应能力 |
| 待设计／待核实 | 新增建议或映射不足；待核实不等于没有实现 |
| 预留 | 当前阶段不编码 |

## 四 动作权限和交接约束

- 仓：收货、质检（另授权）、入出库、调拨及盘点录入；另一授权人员复核差异，财务参与价值调整。仓库主数据维护不是当前WAREHOUSE默认权限，需单独授权。
- 运：安装、上线、监控、维护、撤机和维修；只执行所分配现场交接，不因现有库存通配而默认拥有所有仓储写权限。
- 客：报障受理、投诉处置、退款申请和授权订单干预；财务审批与退款执行另行判权。
- 财：采购价税、成本、结算、付款、对账、发票和价值处理；同人不得自审，敏感账户与付款执行分别授权。
- BD：商家、合同、站点需求及授权归属变更；不得把商家配置读权等同于财务规则发布权。
- 商：本商家已出库／已安装设备、订单和收益；只看会话所属商家，联系人编辑和报修另授权。
- 管：配置与授权；ADMIN通配不代替业务复核和审计。只读角色无写动作，导出另授权。
