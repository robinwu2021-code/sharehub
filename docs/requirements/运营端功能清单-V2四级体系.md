# 运营端功能清单 · V2 四级账户体系（powerbank 组织逻辑对齐版）

> 状态：草案 · 创建 2026-07-13 · 分支 `feature/ops-nav-v2` · **不替换** [运营端功能清单.md](运营端功能清单.md)（老 7 域方案继续留在 `main`）。
> 定位：按 **powerbank / 优匠** 运营方视角重排菜单组织逻辑；引入 **四级账户体系** platform→operator→merchant→store；**当前仍为单运营方自营**（platform=根节点，operator 层休眠，只有一个隐式节点=平台自身）。
> 层级模型：与老方案、powerbank 一致的 **3 级**——域(L1) → 模块(L2) → 子功能(L3)。
> 交付阶段 **P1/P2/P3**（一次性开发、按期解锁；`phase > CURRENT_PHASE` 灰锁不可点，不产生 404）。**阶段以 [PRD-分期路线图](PRD-分期路线图.md)（充電寶專案_V4 PDF 原文还原）为权威依据**，逐叶 `phase` 与其运营后台/IoT/第三方三段对齐。较老方案 P1 集合有两处 PRD 驱动调整：客服工单系统（工单列表/看板）P1→P2、财务数据（平台流水）P2→P1。
> 来源标记：`[现]` 老方案平移 · `[新]` powerbank 补入。

## 〇、V2 相对老方案的三项决策（已按建议默认采纳，可否决）

| # | 决策 | 采纳 | 理由 |
|---|------|------|------|
| D1 | **数据报表**保留为独立域（powerbank 无对应顶级，统计散在 orders/dashboard） | 保留为第 14 域 | sharehub 已建 BI，不砍；powerbank 的 orders 统计另在订单域承载 |
| D2 | **客服 cs 模块打散**（powerbank 无 CS 顶级） | 打散 | 报障受理→告警/工单 · 客服会话→消息中心 · 退款/补偿→订单 · 黑名单处理→会员 |
| D3 | **四级账本分期**：operator 层休眠 | operator=P3 · merchant/member=P2 · platform=P1 | 单租户现只有 platform 一个隐式节点；结构预留，按期解锁 |

## 一、角色（7 个，无平台超管）与四级数据范围

| 角色 | 职责 | 四级数据范围锚点 |
|------|------|------------------|
| `ADMIN` 运营管理员 | 全部 | platform（全域） |
| `OPS` 运维 | 设备/工单/告警/库存/OTA | operator·store（区域·点位） |
| `CS` 客服 | 订单干预/退款/风控/报障/会话 | 全域只读 + 客服动作 |
| `FINANCE` 财务 | 四级账本/分润/结算/提现/对账 | 财务全域 |
| `BD` 拓展 | 点位/商户/合同/代理/运营商拓展 | operator·region |
| `AGENT` 代理商（代理端） | 自己设备/订单/收益 | **仅自己 agent_no** |
| `VIEWER` 只读 | 看板/报表只读 | 只读 |

> 四级锚点 = 后端 `DataScopeHandler` 收敛列：platform 无收敛，operator→`operator_no`，merchant→`merchant_no`，store→`site_id`。当前仅 store(`loc_site`) 已注册，operator/merchant 为休眠占位。
