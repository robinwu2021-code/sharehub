# 运营端功能清单（功能矩阵 · 子功能 · 说明）

> 状态：草稿（待确认）· 创建 2026-07-11 · **本文为运营端权威功能清单**
> 定位：单运营方自营。**「租户」概念不在产品层出现**——无租户管理、无平台超管、无切换；`tenant_id` 仅作后端/DB 兼容层（见文末「后端兼容层」）。含代理商（[ADR-012](../technical/ADR/ADR-012-代理商模型.md)）。支付委托 nearpay，MENA/AED/ar-en。
> 优先级 P0(MVP)/P1/P2 · ops-web 实现 ✅已建 ◐部分 ⬜待建。
> **读法**：§二 是 14 模块鸟瞰、§二·B 是模块级分期汇总、**§三 是按真实菜单展开的全量单表（逐行清单，日常查这张）**、§三·B 是跨模块横向缺口。

## 一、角色（运营端内部角色，无平台超管）
| 角色 | 职责 | 数据范围 |
|------|------|---------|
| `ADMIN` 运营管理员 | 全部 | 全域 |
| `OPS` 运维 | 设备 / 工单 / 库存 / OTA | 区域·点位 |
| `CS` 客服 | 订单干预 / 退款 / 用户风控 / 报障 | 全域只读+客服动作 |
| `FINANCE` 财务 | 财务 / 分润 / 结算 / 提现 / 对账 | 财务全域 |
| `BD` 拓展 | 点位 / 场地方 / 合同 / 代理拓展 | 区域 |
| `AGENT` 代理商 | 自己设备/订单/收益（代理端）| **仅自己 agent_no** |
| `VIEWER` 只读 | 看板 / 报表只读 | 只读 |

## 三·B 横向缺口（跨模块，2026-07-29 梳理发现）

> 这些不是单个模块的功能，而是整个 ops-web 缺失的**通用能力**，会同时影响多个 P1 模块，建议在 P1 前统一补齐（一次实现全站受益）。

| # | 缺口 | 影响面 | 现状证据 | 建议阶段 |
|---|------|--------|---------|:---:|
| G1 | **无删除能力** | 全站所有 master 数据（设备/站点/场地方/角色/模板…）只能增改不能删 | `lib/api/contract.ts` 无任何 `delete*`；UI 无删除按钮 | 1 |
| G2 | **无导入/导出** | 设备台账批量建档、财务/报表导出、对账 | 全仓无 Excel/CSV 相关实现 | 1（设备导入）/2（报表导出）|
| G3 | **无批量操作** | 批量指令、批量派单、批量启停 | `components/ui/data-table.tsx` 无行选择列 | 2 |
| G4 | **无地图组件** | 设备地图分布、站点分布、BD 拓展地图 | 仅 recharts，无地图库（C端 c-app 已接 Google Maps 可复用经验）| 2 |

## 四、后端兼容层（产品层不体现）
> 「租户」只活在这层，UI/菜单/角色**完全不出现**。

- **DB**：业务表保留 `tenant_id` 列，MVP 全部默认 `MAIN`；`NeargoTenantLineHandler` 自动注入（防漏写）。表结构就绪，是将来的休眠口子（[ADR-011](../technical/ADR/ADR-011-单运营方为主多租户为口子.md)）。
- **后端**：`TenantContext` 默认注入 `MAIN`，无租户开通/切换/管理的 API 暴露到产品。
- **口子语义**：若将来启用，泛指"隔离经营实体"（最现实=同一运营商多业态 充电宝/充电桩），届时才引入管理面。MVP 不建、界面不体现。
