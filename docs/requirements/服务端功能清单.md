## 一、读法

每个功能一个说明块，第一行是固定格式的元数据：

```
> 包 `<目标包>` · <状态> · <阶段> · 菜单 <支撑的运营端菜单编码 或 C 端> · 需求 <承接的运营方需求编号>
```

| 字段 | 含义 |
|---|---|
| 编号 | `SF-<模块>-<序号>`：OPR 商家 · NET 网点 · SYS 系统 · DEV 设备 · SAL 销售 · CON 用户 · OPS 运维 · FIN 财务 · STL 结算 · INV 发票 · RPT 报表 · AUTH 认证 · GW 设备对接 · INF 平台横切 |
| 包 | [服务端包名规划](../technical/服务端包名规划.md) 中的目标包（省略 `ai.neargo.sharehub.`） |
| 状态 | ✅ 现有（后端已实现，可直接用）· ◐ 改造（已有，需按「差距」补齐）· 🆕 新增 · ⏸ 预留 |
| 阶段 | 一期 · 二期 · 三期 · 预留，与运营端矩阵一致 |
| 菜单 | 支撑的运营端菜单编码（`OM…`）；`C 端` 表示服务 App / 小程序 / H5 |
| 需求 | 运营方原始需求编号（省略 `RQ-`）；`—` 表示原文未要求、为项目既有能力 |
| 做什么 / 规则 | 能力边界与必须遵守的业务规则 |
| 接口 | 现有端点照抄 `contract.json`；标 🆕 的是待建端点（路径为建议） |
| 差距 | 相对运营方需求或已知缺陷还要补什么；缺陷编号 D1–D8 见 [对齐文档 §六](./运营方原始需求-与现有需求对齐.md) |

**通用约定**（每个功能都适用，不在各块重复）：契约 `Result{code,message,data}` / `PageResult{list,total}`；业务键 `xxxNo`；时间 `xxxAt`；
枚举大写下划线；不提供 `delete*`，用 `archive*` / `unarchive*` 与软删；写端点统一进操作审计；跨模块只经 `sharehub-api` 的 Port 或事件。

## 三、功能详述

### 3.1 商家管理 `operator`（sharehub-svc-platform）

商家 = 第一阶段的结算单元，即运营方原文的「商户」；代码里是运营主体 `agt_agent`（ADR-029 / ADR-032）。

#### SF-OPR-01 商家入驻申请与审核
> 包 `operator.apply` · ✅ 现有 · 一期 · 菜单 OM01-01 · 需求 MER-01

- **做什么**：商家自助注册与运营代建落同一张申请单、走同一个状态机；审核通过后生成商家与登录账号。
- **规则**：
  - 来源 `SELF_SERVICE` / `OPS_CREATED` 由服务端按令牌判定，客户端不得传；
  - 状态 `SUBMITTED → REVIEWING → APPROVED / REJECTED`；驳回原因必填，申请人可凭手机号 + 验证码查进度与原因；
  - 幂等按单据不按人：一个手机号可以有多份申请、属于多个商家（ADR-030）。
- **接口**：`POST /api/agent/apply/otp` · `POST /api/agent/apply` · `GET /api/agent/apply/mine`（三者免登录，凭验证码）· `GET/POST /api/agent/applies` · `POST /api/agent/applies/{applyNo}/accept` · `POST /api/agent/applies/{applyNo}/audit`
- **数据与事件**：`agt_apply`；审核通过同事务建 `agt_agent` 与 `agt_account`。
- **差距**：无。

#### SF-OPR-02 商家档案与经营视图
> 包 `operator.profile` · ◐ 改造 · 一期 · 菜单 OM01-02 OM01-07 · 需求 MER-01 MER-05 MER-08 INV-03

- **做什么**：维护商家（运营主体）档案：类型（平台自营 / 代理商 / 城市合伙人）、区域、联系人、状态；提供按商家汇总的经营视图。
- **规则**：平台自营是恒存在的一行哨兵 `PLATFORM`，不可停用；停用走归档不删除；档案改动记字段级审计。
- **接口**：`GET /api/agent/agents` · `POST /api/agent/agents/{agentNo}` · `POST /api/agent/agents/{no}/archive` · `.../unarchive` · 🆕 `GET /api/agent/agents/{agentNo}/overview`（收入、设备数、分润与应付摘要）
- **数据与事件**：`agt_agent` · `agt_agent_region` · `agt_principal`；改状态发 `AgentStatusChangedEvent`。
- **差距**：补营业执照号、TRN、注册地址等结构化字段（今天只在入驻附件 JSON 里）；经营视图新建，读应付台账与分润统计。

#### SF-OPR-03 商家账号与多主体
> 包 `operator.account` · ✅ 现有 · 一期 · 菜单 OM01-03 · 需求 SEC-01

- **做什么**：为商家开通登录账号、启停、重置；一个手机号可属于多个商家，登录后切换当前商家。
- **规则**：切换商家是**换发令牌**，不是改会话字段；账号停用不删历史操作。
- **接口**：`GET/POST /api/agent/accounts` · `GET/POST /api/agent/accounts/{accountNo}` · `POST /api/agent/agents/{agentNo}/login-account`；切换见 SF-AUTH-01。
- **数据与事件**：`agt_account`。
- **差距**：无。

#### SF-OPR-04 渠道商户进件
> 包 `operator.merchant` · 🆕 新增 · 一期（可延后） · 菜单 OM01-04 · 需求 ADR-032

- **做什么**：维护商家在支付渠道侧的「商户」：子商户号、进件材料、进件状态、结算账户。
- **规则**：
  - 一个商家按「渠道 × 市场」各一个商户，唯一键 `(operator_no, channel, market)`；
  - 状态 `待提交 → 审核中 → 已通过 / 已驳回（带原因）→ 已停用`；
  - 进件材料（执照、身份证明、银行证明）是敏感数据，存 `sharehub_pii`；
  - 进件经共用支付服务提交渠道；第一阶段走平台代收（LEDGER）时本功能可延后。
- **接口**：🆕 `GET/POST /api/agent/merchants` · 🆕 `POST /api/agent/merchants/{no}/submit` · 🆕 `/internal/pay/merchant-callback`（进件结果回推）
- **数据与事件**：🆕 `pay_merchant`。
- **差距**：整项新建；依赖共用支付服务的进件能力。

#### SF-OPR-05 资产划拨
> 包 `operator.assignment` · ✅ 现有 · 一期 · 菜单 OM01-05 · 需求 MER-06

- **做什么**：把柜机、点位划给商家，或批量回收到平台直营。
- **规则**：划拨记录只追加；设备与站点归属的回写走事件、最终一致（ADR-019）；**已发生订单的归属不回写**。
- **接口**：`GET /api/agent/assignable-assets` · `GET/POST /api/agent/assignments` · `POST /api/agent/assignments/reclaim`
- **数据与事件**：`agt_assignment`；发 `AssetAssignedEvent`。
- **差距**：无。

#### SF-OPR-06 商家绩效与运维考核
> 包 `operator.performance` · ✅ 现有 · 二期 · 菜单 OM01-08 · 需求 —

- **做什么**：商家经营排名；月度运维考核（达成率、在线率、客诉、被接管数）定出运维分成系数。
- **接口**：`GET /api/agent/performance`（读模型，不落表）· `GET /api/agent/agents/{agentNo}/ops-assessments`
- **数据与事件**：`agt_ops_assessment`；任务 `AgentOpsAssessmentJob`（月度）。
- **差距**：无。

#### SF-OPR-07 商家退出与清算
> 包 `operator.exit` · ◐ 改造 · 二期 · 菜单 OM01-09 · 需求 —

- **做什么**：商家清退：发起、门槛校验（未结订单、未结款、资产回收）、逐步推进到清算完成。
- **接口**：`GET/POST /api/agent/agents/{agentNo}/exit` · `GET /api/agent/exits/{exitNo}` · `GET /api/agent/exits/{exitNo}/gate` · `POST /api/agent/exits/{exitNo}/advance`
- **数据与事件**：`agt_exit`；状态机 `AgentExitStateMachine`。
- **差距**：后端已有，运营端缺菜单。

### 3.2 网点管理 `network`（sharehub-svc-platform）

#### SF-NET-01 拓展线索 CRM
> 包 `network.lead` · ✅ 现有 · 一期 · 菜单 OM02-08 · 需求 —

- **做什么**：BD 线索、跟进、公共池认领、签约转化。

- **接口**：`GET/POST /api/ops/leads` · `GET/POST /api/ops/leads/{leadNo}` · `.../claim` · `.../convert` · `GET/POST .../follow-ups`

#### SF-NET-02 场地方与场地入驻

- **规则**：第一阶段场地方**不是结算对象**，进场合同的分成只作记录（ADR-032）。
- **接口**：`GET/POST /api/ops/venues` · `POST /api/ops/venues/{venueNo}` · `.../archive` · `.../unarchive` · `GET/POST /api/ops/venue-onboardings` · `POST .../{onboardingNo}/review`

#### SF-NET-03 站点管理与生命周期
> 包 `network.site` · ✅ 现有 · 一期 · 菜单 OM02-01 OM02-02 OM02-10 · 需求 MER-02

- **做什么**：站点（即运营方原文的「商户分支机构」）档案、勘察、开业检查、营业 / 暂停 / 关闭，站点责任人，站点概览与生命周期漏斗。
- **规则**：
  - 站点状态与门店生命周期是**一套状态机**（`SiteStateMachine`），状态变化写 `loc_site_status_log`；
  - **暂停 = 停借保还**：已借出的仍可归还；恢复营业须有生效合同；
  - 关闭门禁：无设备、无未结工单、无在借订单；首台设备上线须有通过的勘察记录。
- **接口**：`GET/POST /api/ops/sites` · `GET /api/ops/sites/summary` · `GET/POST /api/ops/sites/{siteNo}` · `.../pause` · `.../resume` · `.../close` · `GET .../close-gate` · `GET .../opening-checklist` · `GET/POST .../surveys` · `GET .../status-logs` · `GET/POST .../agents` · `GET /api/ops/site-lifecycles` · `.../funnel` · `GET /api/ops/operation/overview`；内部 `POST /internal/platform/sites/briefs`
- **数据与事件**：`loc_site` · `loc_site_survey` · `loc_site_agent` · `loc_site_lifecycle*`；发 `SiteClosedEvent`；任务 `SiteGoLiveReconcileJob`。
- **差距**：无。

#### SF-NET-04 点位管理

- **做什么**：安装地点的档案与状态，点位是设备归属的锚点。
- **规则**：设备的商家与站点归属由点位派生，不由调用方传入。
- **接口**：`GET/POST /api/ops/locations` · `POST /api/ops/locations/{locationNo}` · `.../archive` · `.../unarchive`

#### SF-NET-05 进场合同
> 包 `network.contract` · ✅ 现有 · 一期 · 菜单 OM02-06 · 需求 MER-03 MER-04

- **做什么**：场地方 × 站点的进场合同：分成模式 / 比例 / 基数、保底、进场费、押金、结算周期、起止、附件；提交、审核、财务会签、签署、补充协议、续签、提前终止。
- **规则**：
  - 只有草稿可改；**生效合同改条款只能走补充协议**，续签带上一份合同号，历史可追溯；
  - 运营通过后金额超阈值的合同停在财务会签环节；

- **接口**：`GET/POST /api/ops/contracts` · `GET /api/ops/contracts/summary` · `GET/POST /api/ops/contracts/{contractNo}` · `.../submit` · `.../withdraw` · `.../audit` · `.../cosign` · `.../sign` · `.../supplement` · `.../renew` · `.../terminate` · `.../termination/audit` · `.../attachments` · `GET .../logs`
- **数据与事件**：`loc_contract` · `loc_contract_attach` · `loc_contract_log`；签署发 `ContractSignedEvent`。
- **差距**：无。

#### SF-NET-06 合同到期提醒
> 包 `network.contract` · ◐ 改造 · 一期 · 菜单 OM00-03 OM02-07 · 需求 MER-07

- **规则**：提前量**可配置**，默认按日历提前 2 个月（运营方示例：12-26 到期，10-26 提示）。
- **接口**：`GET /api/ops/alarm-todos` · `GET .../count` · `POST /api/ops/alarm-todos/{todoNo}/done`；配置见 SF-SYS-05。
- **数据与事件**：评估器 `ContractExpiryEvaluator`；任务 `ContractLifecycleJob`。

#### SF-NET-07 站点坪效

#### SF-SAL-04 最长时限与最高收费
> 包 `sales.order` · 🆕 新增 · 一期 · 菜单 OM04-02 OM00-02 OM10-03 · 需求 BIL-02 BIL-03 BIL-04 BIL-07 MON-02 MON-03 MON-06

- **做什么**：到达最长租赁时限仍未归还，自动发起最高适用收费；提供临近时限、已超时、已扣最高收费的查询。
- **规则**（按运营方原文；超时扣款模型待裁决 K4）：
  - 定时任务每 5 分钟扫描在租订单，按收费方案中的触发规则判定（到时限 / 到金额 / 先到者）；
  - 触发时先写**最高收费事件**并把订单置为「已扣最高收费、未归还」，**更新影响行数为 1 才请款**，请款业务键 `MAXCHARGE-<orderNo>`；

### 3.10 发票 `invoice`（sharehub-svc-finance）

两类票据分开：**租赁票据**给租赁客户、每笔自动开具；**结算票据**给商家。已开具不可改，更正只能开贷项通知单。

> 包 `common.job` · ◐ 改造 · 一期 · 菜单 — · 需求 —

- **做什么**：业务以 `JobHandler` 声明任务，由共用调度器（ai-shop-job）按 cron 回调；可查任务声明、手动触发。
- **规则**：禁止 `@Scheduled`；多副本只跑一份；任务可在运营台看到上次运行、能停、能手动触发。
- **接口**：`GET /internal/job/declarations` · `POST /internal/job/{name}/trigger`
- **数据与事件**：第一阶段任务：最长时限扫描（5 分钟）· 扣款重试（15 分钟）· 封顶与临近时限提醒 · 合同到期提醒（每日）· 账期结算单 · 票据补开（每小时）· 对账批次（每日）· 导出执行与清理 · Outbox 投递（30 秒）。
- **差距**：共用调度器的多系统改造在 ai-shop 侧（跨仓）。

#### SF-INF-03 流程审批与工单引擎集成
> 包 `integration.opskit` · ◐ 改造 · 一期 · 菜单 OM00-04 OM00-05 OM00-06 OM00-07 OM11-19 OM11-20 · 需求 SEC-03

- **做什么**：退款、提现、合同、调整单等审批与跨业务工单交给 OpsKit；单体负责送审、接收结果回调并推进业务状态。
- **规则**：回调验签；按业务类型找回写实现，同一类型只许一个；送审失败可重新送审，审批通过但业务检查不过可补齐后重试生效。
- **接口**：`POST /internal/opskit/introspect` · `POST /internal/opskit/webhook`
- **数据与事件**：`ApprovalRequestedEvent` · `TicketRequestedEvent`（契约在 `api.flow`）。
- **差距**：未配置 OpsKit 地址时不启用；第一阶段是否启用待确认。

#### SF-INF-04 链路追踪与审计拦截
> 包 `common.trace` · ✅ 现有 · 一期 · 菜单 — · 需求 SEC-04 SEC-08

- **做什么**：每个请求带链路号进日志与审计；写端点统一审计；日志按约定落盘、带操作人。
- **规则**：日志不打敏感信息；每条 WARN / ERROR 要能回答「谁该做什么」。
- **差距**：跨进程透传 `traceparent`（拆进程前必须就绪）。
