# C 端功能清单（功能矩阵 · 子功能 · 详细说明 · App/小程序对照）

> 状态：草稿（待确认）· 创建 2026-07-12 · **本文为 C 端（消费者端）权威功能清单**
> 定位：终端消费者租借充电宝。**App 优先（P0，MENA 主战场）**、**微信小程序次要（P1，海外微信中国用户）**；uni-app 一套码，条件编译隔离端差异。
> 前提决策：MENA/UAE 起步 · **AED · ar/en + RTL** · **支付委托 nearpay**（卡 / Apple Pay / Google Pay，免押=卡预授权；MVP 用 Stub）· PDPL 合规 · 单运营方自营（`tenant_no=MAIN`，产品层无「租户」概念）。
> 端点前缀 `/mp/**`（C 端 BFF，auth-core C 池会话），见 [api/README §六·§七](../api/README.md)。
> 图例：优先级 P0(MVP)/P1(规模化)/P2(增强)；端支持 ✓ 完整 · ◐ 受限/降级 · — 不做。
> 下游细化：[features/C端-功能细化.md](./features/C端-功能细化.md)（交互/字段级）。
>
> 📌 **分级口径（2026-09-23）**：本文的「优先级 P0/P1/P2」**不再是交付分级**，仅表示 C 端内部的建设先后。
> **分级 SSOT = [功能清单-分级矩阵 §4.5](./功能清单-分级矩阵.md)**，那里给出 78 个子功能逐条的 L0–L3
> （L0 45 · L1 10 · L2 15 · L3 8）。大致对应：P0 ≈ L0+L1 · P1 ≈ L2 · P2 ≈ L3，但**有逐条调整**，例如：
> 登录只有手机验证码进 L0，Apple/Google 登录归 L1（App 上架后）；C-BL-04 欠费补缴是 L0（拦下次借出是风控底线）；
> 微信小程序整体 L3（三壳同一套代码，随时可提）。

## 一、用户身份与状态（驱动功能门控）

| 身份/状态 | 定义 | 关键门控 |
|-----------|------|---------|
| 游客 | 未登录 | 可浏览附近网点/价格；扫码借出前强制登录 |
| 已登录 | 手机/Apple/Google（App）或微信 openid（小程序）建户 | 可借；未授权免押则走押金 |
| 已授权免押 | 完成卡预授权（App）/ 微信支付分（小程序 ◐） | 免押额度内先用后付 |
| 会员 | 购买次卡/包月 | 权益计费（免费时长/折扣/免押提额） |
| 风控/黑名单 | 信用过低或被运营端拉黑 | 拦截下单，提示原因与申诉入口 |

> 归属键：账户按 `c_user_no` 隔离；小程序 openid × `MAIN` 建户（后端兼容层，产品不体现租户）。个人数据入 `pb_pii`（PDPL）。

## 四、借还主流程时序（C 端视角，对照 [api §七](../api/README.md)）

```
借出：登录 → 扫码(cabinetNo) → 借出确认页(价格/押金/免押/协议)
      → POST /mp/trade/orders/rent
        → GET /internal/ops/cabinets/{no}/availability（校验可借）
        → 免押 POST /mp/trade/deposit/free（卡预授权） | 押金 POST /mp/trade/pay
        → 业务域 POST /internal/gw/commands (EJECT_SLOT)
      ← DeviceEvent RENT_CONFIRMED → 订单 IN_USE → 借出成功页
使用：GET /mp/trade/orders/{orderNo}（实时计费/封顶）
归还：任意柜机空仓插入 → DeviceEvent RETURNED
      → POST /internal/trade/orders/{no}/return（停计费 → capture 请款 → 用券 → 结算展示）
异常：POST /mp/user/report → 运营端 POST /api/trade/orders/{no}/intervene（强归/免单/补偿/退款）
```

**订单状态机（对齐 `ops-web/lib/types.ts` OrderStatus）**：
`CREATED`（已下单待弹出）→ `DISPENSING`（弹出中）→ `IN_USE`（使用中）→ `RETURNED`（已归还待结算）→ `SETTLED`（已结算）→ `CLOSED`（关闭）；任意态可转 `EXCEPTION`（异常，转报障/干预）。

## 五、端差异与 uni-app 条件编译（`#ifdef APP-PLUS / MP-WEIXIN`）

| 能力 | App（P0 主力） | 小程序（P1 niche） | 隔离方式 |
|------|---------------|-------------------|---------|
| 登录 | 手机 OTP / Apple / Google | 微信 openid 一键 | 条件编译登录模块 |
| 支付 | nearpay 卡 / Apple Pay / Google Pay | 微信 JSAPI | `PaymentPort` 端侧适配 |
| 免押 | 卡预授权（通用主路径）| 微信支付分 ◐ | 条件编译；MP 不可用→降级押金 |
| 推送 | APNs / FCM / UniPush（自主）| 订阅消息（需订阅、模板受限）◐ | 条件编译消息通道 |
| 地图 | Google Maps | 腾讯/微信地图 | 地图组件抽象 |
| 扫码 | `uni.scanCode` | 微信扫一扫 | uni API 统一 |
| 分享 | 分享链 / 深链 ◐ | 小程序分享 ✓ | 条件编译分享 |
| 蓝牙 | BLE 完整 | 受限 ◐ | 条件编译，P2 |
| 发票 | ✓ | ✓ | 共用 |

> 原则：**登录/支付/免押/推送/地图/蓝牙用条件编译隔离，业务逻辑与 UI 共用**；Tailwind 兼容原子类心智（C 端 UnoCSS preset-wind），设计 token 与 ar/en RTL 跨端统一。

## 七、合规与非功能要求

- **合规**：PDPL（明示同意/撤回/注销/数据导出，个人数据入 `pb_pii`）；中东 VAT/TRN 发票；ar/en 用户协议与隐私政策。
- **本地化**：ar/en + **RTL 镜像布局**；AED 货币、日期/数字本地化；阿语字体与断行。
- **性能**：附近网点/扫码/弹出关键路径低延迟；弹出目标 3s 内；弱网降级（蓝牙近场 P2）。
- **安全**：卡信息不落端（nearpay 托管，端不留存 PAN）；受信头由边缘注入，端不伪造；报障/退款幂等。
- **无障碍**：对比度、字号、语音播报（借还状态）；单手可达关键操作。
