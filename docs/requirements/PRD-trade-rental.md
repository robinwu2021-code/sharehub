## 1. 背景与目标

trade 域承接 powerbank 最核心的业务闭环：**用户借充电宝 → 计时计费 → 归还 → 结算**。它编排设备（经 access-gateway）与支付（经 `PaymentPort`→nearpay，延后，MVP 用 Stub），把"设备可控 + 可收费"变成一个可靠、幂等、可对账的订单生命周期。

**一句话目标**：任意租户、任意供应商柜机，用户扫码即借、归还即结、异常可追、资金可对。

## 2. 用户故事

- 作为**用户**，扫码借出后柜机弹出充电宝，页面实时显示计费；归还到任意网点即停止计费并结算。
- 作为**用户**，借时被冻结押金/免押额度，正常归还后按时长扣费、余额解冻。
- 作为**用户**，遇到"没弹出却扣款""无法归还""超时封顶"能自助或经客服处理并退款。
- 作为**财务**，每笔订单的计费、扣款、分润、账务分录清晰可对账。
- 作为**平台**，计费规则按租户/点位可配，不改代码。

## 3. 范围

### 3.1 做（In Scope）
1. **租借订单状态机**：创建 → 弹出中 → 使用中 → 已归还 → 已结算 / 关闭 / 异常。
2. **计费引擎**：时长计费、免费时长、封顶（日/总）、买断价、跨天，规则按租户/点位/计费模板配置。
3. **押金/免押编排**：借出冻结（预授权/押金）、归还请款、解冻——**经 `PaymentPort`**（MVP Stub，后接 nearpay）。
4. **归还结算**：归还事件驱动停止计费、结单、请款、账务记账、触发分润。
5. **异常处理**：未弹出退款、超时封顶、异地归还、坏机归还、买断（丢失转购买）、重复扣费。
6. **退款编排**：退款申请/审批 → `PaymentPort` 退款 → 状态跟踪。
7. **账务与分润**：复式记账、分润规则计算（执行/打款延后随 nearpay）。

### 3.2 不做（Out of Scope）
- 支付渠道/PSP 对接、真实收单 → **nearpay（延后）**；MVP `PaymentPort` Stub。
- 设备弹出/归还指令与事件 → **access-gateway**（trade 只发指令、收事件）。
- 设备台账/仓位/充电宝生命周期 → **ops**。
- 计费模板/定价的后台管理 UI → 运营端（trade 提供 API）。

## 4. 功能需求

### 4.1 订单状态机
| 状态 | 含义 | 迁移触发 |
|------|------|---------|
| `CREATED` | 已创建、押金已冻结、待弹出 | 用户确认借出 + PaymentPort.preAuth 成功 |
| `DISPENSING` | 已下发弹出指令、待设备确认 | 指令下发 access-gateway |
| `IN_USE` | 借出成功、计费中 | 收到 `RENT_CONFIRMED` 事件 |
| `RETURNED` | 已归还、待结算 | 收到 `RETURNED` 事件 |
| `SETTLED` | 已结算（请款+记账+分润）| 结算完成 |
| `CLOSED` | 正常关闭 | 结算后终态 |
| `EXCEPTION` | 异常（未弹出/超时/坏机等）| 各异常触发 |

### 4.2 计费引擎（验收：规则零硬编码）
- 输入：计费模板（`price_plan`）+ 租借时长 + 点位/场景。
- 规则：`免费时长` 内不计费；超出按 `unit_minutes × unit_price` 累进；`cap_daily` 日封顶、`cap_total` 总封顶=买断价；跨天按日封顶累加。
- 输出：应扣金额；封顶即触发买断（充电宝转售出）。

### 4.3 押金/免押编排
- 借出：`PaymentPort.preAuth(freeze_amount)` 冻结（押金或免押额度）；成功才创单弹出。
- 归还：`PaymentPort.capture(实际费用)` 请款 + 解冻余额；或 `release` 全额解冻（免费时长内）。
- 失败降级：预授权失败 → 拒绝借出并提示；请款失败 → 挂账重试 + 告警。

### 4.4 异常场景（必做）
| 场景 | 处理 |
|------|------|
| 未弹出（指令超时/失败）| 订单→EXCEPTION，`PaymentPort.release` 解冻，通知用户 |
| 超时未归还 | 达 `cap_total` 封顶买断，充电宝标记售出（通知 ops） |
| 异地归还 | 正常结算（归还柜机≠借出柜机）|
| 坏机归还 | 归还成功 + 生成工单（ops），必要时补偿 |
| 重复扣费 | 幂等拦截 + 客服干预退款 |

### 4.5 退款
- 来源：用户自助报障、客服审批、异常订单自动。
- 流程：退款单 → `PaymentPort.refund` → 状态跟踪（延后随 nearpay，Stub 直接成功）。

## 5. 非功能需求（验收标准）
| 维度 | 指标 |
|------|------|
| **幂等** | 同订单重复借出/归还/退款不重复扣退（业务键 + Outbox 去重）|
| **一致性** | "创单→弹出指令" 用本地事务 + Outbox；"归还→请款→记账" 顺序可靠、失败可补偿 |
| **可追溯** | 每次状态迁移落 `ord_event_log`；资金动作先记账后执行 |
| **计费准确** | 时长/封顶/免费时长计算有单测覆盖，边界值正确 |
| **可配置** | 计费模板按租户/点位配置，改规则不改代码 |
| **支付解耦** | 业务只依赖 `PaymentPort`，Stub↔nearpay 切换零改动 |

## 6. 依赖
- **access-gateway**：发弹出指令（`/internal/gw/commands`）、消费 `RENT_CONFIRMED`/`RETURNED` 事件。
- **ops**：借出前查可用性、买断/坏机通知、计费模板点位取价。
- **PaymentPort→nearpay**（延后）：MVP Stub。
- commons：`Result`/`IdGenerator`/`DomainEventPublisher`/`BaseEntity`/账务。

## 7. 里程碑
| 批次 | 内容 |
|------|------|
| TR-a | 订单状态机 + 计费引擎 + PaymentPort Stub + 借出/归还闭环（不含分润）|
| TR-b | 异常场景全 + 退款编排 + 账务复式记账 |
| TR-c | 分润规则计算 + 结算单（执行/打款待 nearpay）|

## 8. 待确认
1. 计费维度：是否首期就要分时段/节假日差异化，还是仅时长+封顶？
2. 买断（丢失转购买）触发口径：达总封顶即买断，还是超 N 小时？
3. 免费时长/封顶默认值（随运营策略）。
4. 归还确认口径：以 `RETURNED` 事件为准（同借出）。
