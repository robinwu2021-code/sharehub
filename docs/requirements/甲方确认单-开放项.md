## 二、逐项决策

### D1 · 发票 / 税务分期：P1 还是 P3？

- **矛盾点**：C 端功能清单把「发票」标为 **P1**；运营端交付阶段（`PRD-分期路线图.md` ← PDF 甲特图）把发票归 **P3（生态解锁期）**。`ops-web/lib/nav.ts` 现状：`发票`（`/finance?tab=invoices`）与 `税务与 VAT`（`/finance?tab=tax`）均为 **phase 3**。
- **涉及文档**：`运营端功能清单-V2四级体系.md`、`PRD-分期路线图.md`、C 端功能清单、`ops-web/lib/nav.ts`。
- **选项**：
  - **A（建议默认）· 维持 P3**：首期以「租借-支付-归还」闭环为主；开票依赖财务/税务域成熟（发票抬头、红冲、第三方开票平台对接、VAT），与合规/多币种一同在 P3 落更稳。
  - **B · 提前到 P1**：满足 C 端用户首期报销诉求；但需前置打通开票平台后端域，工作量前移。
- **落地影响（若选 B）**：`nav.ts` 将 `finance:invoice` 两叶 phase 3→1，并前置排期「开票平台对接」后端任务；同步 C 端发票入口。
- **裁定**：☐ A 维持 P3　☐ B 提前 P1　　备注：____________

### D2 · 广告屏 7 叶 4/3 拆分是否成立？

- **背景**：PDF 甲特图广告屏只有**两条粗线**，无法逐叶读出分期。落地据此拆为「**设备屏播控核心 P1（4 叶）**：广告位管理 / 广告素材 / 播放列表 / 广告屏设备」+「**平台广告经营 P3（3 叶）**：广告活动 / 投放与曝光 / 应急插播」。见 `项目全景分析.md` §8.4。
- **涉及文档**：`ops-web/lib/nav.ts`、`PRD-分期路线图.md` §8.4、`运营端功能清单-V2四级体系.md`。
- **选项**：
  - **A（建议默认）· 维持 4/3 拆分**：设备屏是硬件既有能力，先让屏「能播」（设备+素材+播放列表）成本低价值高；广告「经营」（活动编排/曝光计费/应急插播）是独立营销能力，随营销中心 P3。
  - **B · 整体 P1**（7 叶全首期）：首期即完整广告运营，含活动编排/曝光计费等重功能。
  - **C · 整体 P3**（7 叶全后期）：首期不做屏内容，屏仅显示默认物料。
- **落地影响**：改 `nav.ts` 对应叶 phase 即可（B=3 叶 3→1；C=4 叶 1→3），一处改、重构建即生效。
- **裁定**：☐ A 维持 4/3　☐ B 整体 P1　☐ C 整体 P3　　备注：____________

### D3 · 租户管理面是否进 MVP？

- **矛盾点**：`服务端-功能细化.md`（SVR-TN-01/02 租户开通标 **P0**）与 `功能矩阵-分端对照.md` 仍按 SaaS 双级把租户服务列 P0；但 **ADR-011 / 运营端清单**已定「**单运营方自营、租户管理面 MVP 不做**」。服务端与运营端对租户面的分期口径不一致。
- **涉及文档**：`服务端-功能细化.md`、`功能矩阵-分端对照.md`、ADR-011、运营端功能清单。
- **选项**：
  - **A（建议默认）· MVP 不做租户面**：单运营方自营；租户隔离靠 `tenant_id` 列预留（架构不锁死），未来 SaaS 化再增量加面。需把服务端 SVR-TN-01/02 从 P0 降级或标注「架构预留、UI 延后」，统一口径。
  - **B · MVP 做最小租户开通面**：保留 SaaS 双级，运营端加「租户开通/配置」模块。
- **落地影响**：选 A → 回写 `服务端-功能细化.md` / `功能矩阵-分端对照.md` 统一为「单运营方自营」，消除 §十.2 矛盾；选 B → 运营端 nav 增「租户管理」域/模块并配权限码。
- **裁定**：☐ A MVP 不做　☐ B 做最小开通面　　备注：____________

### D4 · 是否新增独立「区域经理」角色？

- **背景**：当前 RBAC 7 角色（ADMIN / OPS / CS / FINANCE / BD / VIEWER / AGENT）。数据范围设计含 **REGION** 维度，但无专门「区域经理」角色——区域范围目前挂在 OPS / BD 上，靠数据范围（data-scope）收敛。
- **涉及文档**：`权限管理方案.md`、`ops-web/lib/permissions.ts`、后端 `auth/RolePerms.java`（同源镜像，须同步改）。
- **选项**：
  - **A（建议默认）· 不新增**：区域是「数据范围」维度而非「功能集」维度，用现有 OPS/BD + scope 绑定更正交。后端 scope 目前仅注册 `loc_site`，尚未到需要该角色的阶段。
  - **B · 新增「区域经理 REGION_MANAGER」**：明确一类「只管某区域全部业务」的岗位。
- **落地影响（若选 B）**：`permissions.ts` + `RolePerms.java` 同源新增角色及权限码集，`nav.test.ts` 补可见性断言，`gen-ops-matrix.mjs` 增列重生成矩阵。
- **裁定**：☐ A 不新增　☐ B 新增区域经理　　备注：____________
