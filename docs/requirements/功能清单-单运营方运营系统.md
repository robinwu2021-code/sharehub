## 运营方全景（一句话）
运营方在**若干点位**投放**多供应商柜机**，用户**扫码借充电宝→计时计费→归还结算**；运营方管好**设备在线、订单资金、故障运维、点位拓展、用户与营销**，并招募**代理商**分片经营（数据受限+分润），钱通过**分润结算**分给场地方/代理，支付**委托 nearpay**。

> 三类"分成/合作方"辨析：**场地方**=提供点位收进场分成；**代理商**=运营方体内的区域/点位经营伙伴（用运营方品牌、数据受限、参与分润，[ADR-012](../technical/ADR/ADR-012-代理商模型.md)）；🔒**租户**=另一个独立运营方（多品牌口子，ADR-011，后置）。

## MVP 建设优先级（P0 净清单）
运营方跑通所需，去掉口子后的 P0：
1. 经营看板（总览+趋势+告警）
2. 设备：台账 / 监控影子 / 远程控制+批量 / 告警 / 供应商接入
3. 点位：POI + 场地方
4. 订单：列表详情 / 异常处理 / 干预 / 退款审批
5. 计费模板
6. 财务：分润规则+明细 / 复式账务
7. 工单：看板 / 开单派单 / 处理关单
8. 用户：列表 / 风控黑名单
9. 客服：报障受理
10. 员工权限：组织 / 员工 / RBAC（含**数据权限**，代理刚需）/ 审计
11. 系统：供应商接入 / 通知模板 / 字典
12. **代理商：代理档案 / 设备点位划拨 / 代理分润配置 / 代理账号（AGENT 角色+数据范围）**

> 支付贯穿其中，走 `PaymentPort` Stub（真实收付待 nearpay，ADR-005）。
