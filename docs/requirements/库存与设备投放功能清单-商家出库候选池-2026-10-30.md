# 库存与设备投放完整功能清单

> 2026-10-30 用户确认：补齐功能清单并对齐运营端；出库必须选择商家；设备出库后安装上线须从待安装设备按商家筛选。本文记录已确认规则及开发差距，未修改业务代码。

## 一 必须遵守的主流程

采购或期初登记 → 实收 → 质检 → 可用入库 → 选择商家出库 → 进入该商家的待安装设备 → 按交付方式完成签收 → 选择商家并筛选候选设备 → 绑定该商家站点点位 → 安装工单及验收 → 上线门禁通过 → 上线。

商家使用代码字段 agentNo；出库分配记录 issuedAgentNo，安装绑定后的经营归属为 agentNo。二者不能混用，也不表示法律所有权因出库自动变更。

1. 出库请求商家必填；商家须处于允许设备投放的状态。选择设备前先明确目标商家；目的站点若填写，必须属于该商家。
2. 可出库设备必须是受管仓内的可用设备，未绑定、未出给其他商家、未归档且质检放行。存量免检属于显式例外，不得把所有空质检结果自动视为新设备合格。
3. 出库过账只扣一次仓内库存并生成可追溯交接记录；待安装设备列表是出库交接及待部署视图，不是第二套仓内余额。
4. 安装新建流程必须先选商家，再查该商家已出库设备清单；不能从全部台账、原仓库存或其他商家池选设备。商家变更立即清空设备、站点和点位旧选择并重新查询。
5. 候选状态分开：待签收可看但不可绑定安装；已签收未绑定可绑定；已绑定待安装用于该设备的安装工单；安装完成待上线用于上线验收。已上线、故障、已退回、报废、归档设备不能混入新安装候选。
6. 查询按 issuedAgentNo 服务端过滤并分页；选择后提交时重新检查商家、签收、状态和点位。不可只在前端过滤当前页；篡改设备号或批量混入其他商家设备必须拒绝。
7. 安装和上线是两个动作。上线针对已选设备核查所属商家、有效安装／绑定链路和上线门禁；不要求该设备上线时仍是“未绑定”池状态，也不重复扣库存。
8. 签收由指定接收人执行；当面交付可按明确业务规则直接签收并留交付方式及凭据。商家确认安装结果与员工签收分别记录。
9. 站点／点位必须属于选定商家；不能在安装处偷偷改商家。未绑定的错误出库通过受控调整并留原因；已安装设备迁移按撤机／迁点流程处理。
10. 服务端绑定仍存在直营点位可从仓直接绑定的旧路径；本次确认的商家部署流程不得使用该路径绕过出库。直营是否保留为独立例外，需要单独明确，不当成商家流程默认行为。

## 二 全流程功能清单与运营端落位

角色：仓=仓管，运=运维，财=财务，BD=拓展，客=客服，商=商家，管=管理员。授权采购人员可由现有员工兼任，不强制新增角色。读权限与执行权限分开。

## 四 必须验收的场景

- 不选商家不能出库；提交空商家、不可投放商家或不属于商家的站点，服务端拒绝。
- 商家A出库后仅出现在A对应池中，不能被B安装；篡改cabinetNo、混批、并发绑定均要验证。
- 新建安装先选商家；未选时不加载全部设备作为可选项；更换商家清空旧设备、站点、点位。
- A的待签收设备可展示原因但不能绑定；签收后才能进入可绑定候选；已绑定设备走待安装阶段，不再次绑定。
- 没出库的仓内设备、其他商家设备、已退回、已上线、故障、报废设备不能进入新安装候选；直接调用安装API同样拒绝。
- 从出库页绑定开单、设备页安装、通用工单INSTALL、派生安装和深链入口执行同一来源约束。
- 安装完工不等于上线；门禁失败保持待上线，能查看原因；上线不重复扣库存。
- 调整出库商家后旧商家候选立即失效；已安装不通过修改出库字段偷换商家；历史记录不覆盖。
- 回仓维修复检后重新出库，须重新选商家；复用的是设备身份，不是旧出库记录或旧签收凭据。
- 采购100收80、待检与可用分列、来源收货防重等君盛条款继续按专项对齐表验收。
