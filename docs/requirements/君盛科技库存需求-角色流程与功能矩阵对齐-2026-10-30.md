## 二 核心对齐结论

现有14个库存页签覆盖主要仓内作业，但不足以直接宣称满足君盛库存需求。主要差距是采购与分批收货、缺票期初依据、完整价税与附件、维修状态闭环及全资产报表。采购可采用采购/收货合并单据加行明细实现；原文没有强制必须单独采购模块，也没有要求复杂采购审批平台。

三层口径必须分开：采购订购与未收；仓内实物与质检可用；仓外已投放及维修资产。实物收80与可用80不是同义词：例如收到80、70合格、10待检，应显示已收80、未收20、合格可用70、待检10，不能把待检算成未收。仓间调拨在途与供应商未交货也不能混在同一余额。

## 四 原文11类库存报表补齐

| 原文统计项 | 当前证据与补齐要求 |
|---|---|
| 全部机柜和充电宝总数 | 设备台账存在；包含仓外、故障、撤出等资产，不能只统计仓内余额。 |
| 期初、采购、收货、安装、调拨、退回、撤出、遗失、期末 | 当前InventoryReport有各仓入出期初期末；补采购、经营和维修事件分类，并区分数量变化与状态转移。 |
| 编号、SN、型号、位置、商家分类 | 当前台账与阶段查询分散；统一筛选并保留历史时点口径。 |
| 新设备和供应商采购历史 | 已有供应商与入库来源；补采购行、采购日期及未到货记录。 |
| 采购数量、单价、金额和VAT | 当前PurchaseRow只有币种、数量和金额；补税基、VAT、供应商与采购期间。 |
| 已采未收 | 必须来自采购行的订购与累计实收差额，不能拿调拨在途替代。 |
| 已收未装 | 分待检、可用在仓、已出库待领取／待安装，不重复汇总。 |
| 已装在商家现场 | 从资产绑定与安装信息汇总；“已安装”与“已上线”分别展示。 |
| 维修中、损坏、遗失、已撤出 | 补状态分轴和维修业务记录；不得统一归故障。 |
| 当前余额和移动历史 | 仓内余额查库存账，仓外位置查资产履历；展示统一但来源独立。 |
| 实盘与系统差异 | 仓内盘点与仓外资产核查分开；差异原因、审批、调整、结案可关联。 |

原文统一筛选：日期范围、供应商、设备类型、机器编号、商家、状态。PRD进一步要求的导出和字段权限应单独验收；仓管默认看数量，成本、VAT等按财务字段授权。

## 五 建议角色交接和菜单调整

| 流程 | 主责与交接 | 应补矩阵项 |
|---|---|---|
| 期初登记 | 仓管录设备与数量，财务核价值与依据 | 期初来源、缺票标记、可靠价值、佐证附件和导入核对结果 |
| 采购→收货 | 授权采购人员维护订单，仓管实收；财务核供应商发票与价税 | 采购/收货台账、订单行、批次收货、未收余额、发票附件；采购岗位可复用现有员工授权 |
| 收货→质检→可用 | 仓管确认实物，授权质检人员出结果，仓管放行 | 待检实物数量、不合格隔离、拒收／退货、一次性放行凭证 |
| 出库→安装 | 仓管发出，指定人接收，运维安装，商家确认现场交付 | 出库与员工签收、安装完工和商家交付证据分开 |
| 迁点／换商家 | 运维及BD按授权处理；仓库仅管真实进出仓 | 前后位置／商家、原因、人员、日期；历史交易归属不覆盖 |
| 维修→复检→再投放 | 运维处理，仓管返修交接，质检复验，财务核费用 | 现场维修／回仓／返厂、修理中、修复验收、再部署门禁；具体审批为建议设计 |
| 盘点与对账 | 仓管盘点，另一授权人员复核差异；财务核金额 | 仓内盘点、仓外资产核查、库存与资产账对账，不建设重复仓外库存账 |

## 六 必须保留的验收场景

1. 无采购发票的存量设备可登记：来源、缺票原因、数量、可靠价值及附件可查；重复导入不能重复建资产。
2. 订100、收80：实物80、未收20；重复提交相同收货不增数；随后收20累计100；超收和退货分别处理。
3. 80台中70合格、10待检：实物80、可用70；出库不能拿待检设备。
4. 同一来源重试、远程成功响应丢失、本地保存失败：查询原结果并复用幂等键，不二次入出库。
5. M-12从Hotel A迁到Mall B：旧订单和财务报表仍属A，迁移后新订单属B；移动记录包含日期、前后位置、人员和原因。
6. 安装后故障回仓维修：仓外停用、撤机、在途、回仓待检、维修、复检、再出库与再安装均能追踪，不能直接把维修完成当上线。
7. 盘点差异只经受控调整单改账；原实盘和账面数据不可覆盖；相关人员和单据可追溯。
8. 11类报表及6类筛选逐项验证，期初／期末／变动与单据一致；仓外移动不能误增减仓内余额。
9. 厂商不支持或数据过期时明确显示不可用／过期；不以demo数据验收在线、故障和可借数。
10. Zoho联调列为后续条件验收，当前保留来源系统、外部记录键及对账引用，不以一期未接Zoho判定库存主流程不合格。
