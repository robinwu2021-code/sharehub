# 带归属列、却没登记数据范围的表 —— **只准变短，不准变长**
#
# 由 DataScopeCoverageRatchetTest 执行。新增一张 → 测试红。
#
# 【为什么要盯】
# DataScopeRegistration 的类注释第一句就写着：
#   「未注册的表 = 全局放行 —— 这是本机制最危险的性质：漏注册不会报错、不会告警，
#     只会静默地让越权数据流出去。所以新增带归属语义的表时，注册是建表的一部分，不是可选项。」
# 而在此之前，**没有任何东西在执行这句话**。
#
# 2026-09-24 实测的代价：dev_alarm 上 agent_no/site_no/region_id 三列俱全、一个都没注册，
# 于是代理登录后工作台列的是全平台最近 10 条告警 —— AG002 看到了 AG006 的柜机号。
# 列表页都没事（那些表注册了），偏偏是聚合首屏漏的，而页面照常渲染。
#
# 【为什么它一直没变短 —— 2026-09-25 实验结论】
# 不是没人做，是当前机制下做不了。handler 的 fail-closed 已用两向实验证实：
#   未注册：ALL=1 / SITE 收敛后=1（不过滤）
#   只登记 AGENT：ALL=2 / SITE 收敛后=**0**
# 也就是说，给一张缺 site_no/region_id 的表登记 AGENT，
# 按站点收敛的员工在那个页面上一行都看不到，而且不报错。
# 库里现在就有 1 个 SITE 范围的员工（iam_data_scope: ALL×56 / SITE×1）。
# 补列也不对：分润规则、代理账号这些表在业务上就没有站点/区域归属，
# 编一个 site_no 等于为了让机制通过而伪造业务语义。
# 四个真正的选项与倾向见 docs/technical/数据范围-51张表为什么注册不了.md，待裁决。
#
# 【条目格式】 表名  # 该表有哪些归属列
#
# 【怎么变短】二选一，都要在 review 里显形：
#   · 该管 → 在 DataScopeRegistration 里登记（⚠️ 把该表有列可用的**所有已提供维度**一起登记，
#     handler 是 fail-closed，漏一个维度 = 那类主体 1=0 全瞎）；
#   · 本就该全局可见（码表、字典、平台级配置）→ 从本台账删掉之前先想清楚：
#     「谁都能看」和「没人想起来要管」在代码里长得一模一样。
#
