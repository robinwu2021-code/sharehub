# 进程内定时任务台账 —— **只准变短，不准变长**。
#
# v4/08 的任务卡口禁止 @Scheduled / @EnableScheduling，理由不是「注解不好」，而是
# **每个定时的东西都必须在运营台可见可控**：能看到上次跑没跑、能停、能手动触发。
# 进程内定时藏在代码里，运维只能靠读源码才知道它存在 —— 出事时这是最难查的一类。
#
# 但在共用调度器接通（v4/14 的 M0 + H1/H4）之前，有些东西必须先转起来。
# 本台账就是这段过渡期的显形处：**每一条都要写清「被什么取代」与「何时删除」**。
#
# 格式：<类名>  <触发方式>  <被什么取代>

OutboxDispatchScheduler  ScheduledExecutorService(30s)  共用调度器的 outbox-dispatch 任务（H4）；届时删除本类，把 OutboxDispatcher.dispatchDue() 挂成 JobHandler

# 注意：本台账里的类**默认都是关闭的**（见各自的 @ConditionalOnProperty），
# 生产要显式开。开了之后多副本会重复执行 —— 依赖消费端幂等兜底，不是「不会重复」。
