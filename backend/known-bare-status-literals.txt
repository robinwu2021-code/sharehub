# 裸状态 / 类型字面量台账 —— **只准变短，不准变长**（L1.5 词表收敛）
#
# 由 BareStatusLiteralRatchetTest 执行。新增一条 → 测试红。
#
# 【为什么要盯】
# 业务状态的合法取值在三处各写一遍、互不相认：建表 DDL 注释（55 套词表）、
# 领域模型文档（12 个对象）、Java 代码里的裸字符串（业务状态 enum：0 个）。
# 没有任何一处对另外两处有约束力，于是分叉是必然的，而且**没有症状**：
#
#   · ACK / ACKED    —— AlarmServiceImpl 查 status IN ('OPEN','ACK')，但 ACK 是事件名、
#                        落库状态是 ACKED。已受理的告警永远开不出工单。已修（0723a29）。
#   · CANCELLED / CANCELED —— 两种拼法都在 DDL 里，代码只用前者。
#   · RECLAIM / REVOKE     —— 领域模型写 RECLAIM，DDL 与代码白名单都是 REVOKE，
#                        RECLAIM 从未被任何代码写入过。已修文档。
#
# 【条目格式】 类名#字段=字面量
#
# 【怎么变短】
# 每个对象一个 enum，**值仍以 String 落库**（实体字段保持 String，不动 MyBatis
# 类型处理器 —— 那是连锁改动，收益不抵风险），只把字面量的来源收到一处：
#
#     public enum AlarmStatus { OPEN, ACKED, CLOSED; public String code() { return name(); } }
#
# 词表以领域模型的「状态 / 生命周期」列为准，与 DDL 注释逐条对齐；打架的在收敛时裁定，
# 不留到 L3 写状态机的时候（那时再改等于把状态机写两遍）。
# 收完一个域，把它下面的行整段删掉。
#
# 【暂不收敛的域】agent / price / share / loc —— 被 ADR-027 / 028 / 029 圈着，
# 等拍板后随该域的 L1–L5 一起做。它们的条目仍在台账里，只是先不动。
#
# 依据：docs/technical/实体-领域对象对账表.md §三 · TDD-backend-layer-cleanup-order L1.5
