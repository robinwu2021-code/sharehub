# 请求体是裸 `Map<…>` 的处理器 —— **只准变少，不准变多**。
#
# 裸 Map 当请求体 = **这个端点没有契约**。没人能从签名上说出它认哪些键，
# 于是三件事同时失去：
#   · 契约抽取（api-extract）抽不出 requestShape，靠它的检查器一个都核不了 ——
#     ops-web 的「表单字段 vs 后端写入面」卡口对这 41 个端点全是盲的，
#     而它上线第一天就查出四处「运营填了存不进去」，其中一处是每次 500；
#   · 拼错的键**静默忽略**。`body.get("userNo")` 与前端发的 `user_no` 差一个字，
#     没有任何东西会响；
#   · 前端类型无从生成，只能靠人两边对着抄。
#
# 换成 record DTO 就都解决了。**但不是所有都能机械换** ——
# 少数端点用 `in.containsKey("x")` 区分「没传」与「传了空」（部分更新语义），
# 那个区别 record 表达不了：`CabinetServiceImpl.save` 就靠它做到
# 「locationNo 缺省=不动、传空=解绑」。这类要先设计（Optional / JsonNullable /
# 显式 patch 字段），照 record 直转是**行为回退**。转之前先读一遍 service。
#
# 格式：<控制器类名>#<方法名>

# ⚠️ 2026-09-26 换 record 时查明、**未修**（要先拍板）：C 端认证的 countryCode 从不参与身份派生。
# c-app 每次都发 {countryCode: "+971", phone: "501234567"} 两个字段，而后端只拿 phone 当键：
# OtpService 的码表按它索引，PhoneOtpStrategy 的 uid = sha256(phone) 也按它派生 ——
# 于是 **+971 501234567 与 +966 501234567 是同一个 OTP、同一个账号**（钱包/订单/券/押金共用）。
# PhoneOtpStrategy 里那句「// 生产：E.164 归一」是没有实现的意图，实际只有 .trim()。
# 修法是把 uid 改成按 E.164 派生，而 uid 就是账号身份 —— 等于给存量账号改身份，
# 要先定迁移方式（惰性重键 / 双读回落 / 停机重算）。
# 现状已由 ConsumerPhoneIdentityTest 钉住：身份改好之后那条会红，届时连本段一起删。
