# 「取一页结果，再在里面找某条特定记录」的台账 —— 只准变短
#
# 由 SinglePageSearchTest 执行。新增一条 → 测试红。
#
# 【为什么盯这个】
# 测试库是**累积**的。这种写法在表小的时候一直对，越过页大小的那天忽然开始失败，
# 而失败的样子是「刚建的东西查不到」—— 看起来像功能坏了，实际是分页没够着。
# 2026-09-24 一天之内为此查错方向六次（分润对账 / 代理商档案 / 合同列表 /
# 场地方 / 站点 / 申请单），每次都先去翻业务代码，因为症状指向那里。
#
# 【加 keyword 不算解决】
# 各列表的 keyword 匹配哪些列各不相同：代理商/提现/申请单匹配业务号，
# 而场地方只匹配名称、站点只匹配名称与区域、合同只匹配场地方名与站点名。
# 按编号传进去一条都匹配不上，而「过滤后是空的」与「确实没有」长得一模一样。
#
# 【正确写法】
#   ApiTestSupport.findInPages(path, 字段, 值, token)   找一条
#   ApiTestSupport.pageAll(path, token)                 要整体聚合
# keyword 想留就留在 path 里，翻页与过滤不冲突。
#
# 【这张表为什么是空的】
# 2026-09-24 把当时命中的 10 处全部迁走了，所以从零开始 ——
# 空台账意味着**没有需要讨论的例外**，新增一条就得先说出理由。
#
# 【格式】 类名#方法名
