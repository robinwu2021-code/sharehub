# 「实体请求体」上的可写字段台账 —— **只准变短，不准变长**。
#
# 为什么要到字段这一级：
#   known-entity-request-bodies.txt 是**实体级**的 —— 给一个已经在册的实体加字段，
#   它一个卡口都不触发，而 MyBatis-Plus 的 updateById 只写非 null 字段，
#   **新字段默认就是客户端可写的**。2026-09-24 给 MktPush 加 7 列时实测确认：
#   全程没有任何东西提醒要不要锁，只能靠人自己想到。
#
# 这条棘轮不判断字段"该不该锁"（那要读 beforeUpdate，靠正则做不可靠），
# 它只强制**每个新字段被显式决定一次**：
#   · 有专门迁移入口的（归属 / 状态机 / 金额 / 审批留痕）→ 在 service 的
#     beforeUpdate 里 `e.setX(current.getX())` 锁死，然后登记到这里；
#   · 本来就该在表单里改的（名称、备注、开关）→ 直接登记。
# 两种都要登记 —— 台账是"看过了"的记录，不是"安全"的白名单。
#
# 实体迁到 Req/Command DTO 后，把它的所有行一起删掉。
