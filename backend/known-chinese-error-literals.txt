# 错误文案里的中文字面量台账 —— 只准变短。
#
# 由 ChineseErrorLiteralRatchetTest 卡住。扫的是主代码里
# `throw new IllegalArgumentException("…中文…")`，它们经 GlobalExceptionHandler 的
# `Messages.msg(非 key 原样返回)` **一字不改地送到两端客户端**，而两端都优先显示 body.message。
# 于是界面切到英文/阿语之后，页面是英文、报错还是中文 —— 不报错，只是读不懂。
#
# ───────────── 两条规则 ─────────────
# ① TOTAL 必须与实测**完全相等**：修好几条就把数字改小。
#    要求相等而不是「不超过」，是为了让每一次变化都在 review 里显形。
# ② 下面的类名集合**只准变短**：允许在已列出的类里增减（重构时难免），
#    但**不许让这个模式出现在新的类里**。
#
# ⚠️ 为什么不按类逐个计数（像 known-bare-status-literals 那样）：
#    这个台账会被每一条并行开发的线碰到，按类计数意味着任何一次无关重构都要改这个文件，
#    而本仓库长期多会话并行 —— 一个天天冲突的台账，第三天就会有人直接删断言。
#    代价是「A 类删一条、B 类加一条」能互相抵消；规则 ② 兜住了最坏的那种（扩散到新类）。
#
# ───────────── 怎么修 ─────────────
# 不是逐条翻译。先看形状（判据见 docs/technical/待办-业务拒绝的状态码.md 同族的分类）：
#   · 「xxx不存在: 键」→ BizException.notFound(键)          （已收口 85 处）
#   · 「<字段名> 必填」→ BizException.badRequest("error.common.missing_parameter", 字段名)（已收口 22 处）
#   · 真正给人看的表单校验 → 自己的 key + 三语，见 messages*.properties
#
