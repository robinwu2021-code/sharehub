# 后端状态机能走、而运营端没有对应动作的迁移 —— **只准变短**
#
# 由 StateMachineEdgeAcrossEndsTest（方向二）执行。新增一条 → 红；修好没删 → 也红。
#
# 【为什么这一向要台账，而方向一零容忍】
# 方向一（前端有、后端无）是会当场报 400 的真缺陷，没有理由留。
# 这一向（后端有、前端无）里有大量合法情况：过程态不单独出按钮、某些迁移只由
# 设备回调 / 定时任务推进、运营端还没建那张表。一刀切零容忍会逼人写假豁免。
#
# 【三类，只有第三类是债】
#   A 过程态：一次走完，不单独出按钮 —— 正常
#   B 非人工推进：设备回调 / C 端动作 / 定时任务 —— 正常
#   C **运营端没建迁移表，页面手写了一份 if** —— 这个才是债，见执行计划 A3
#
# 格式：<状态词表>: <FROM>-><TO>

# ── A 过程态 ────────────────────────────────────────────────────────
# 工单 /close 一次走完 AUDIT→CLOSE（DONE→AUDITED→CLOSED）：AUDITED 是过程态，
# 不单独出按钮，所以运营端的 close 直接声明 DONE→CLOSED。
# 方向一靠传递闭包认这条复合边，这一向则必须把中间两跳登记掉。
WorkOrderStatus: DONE->AUDITED
WorkOrderStatus: AUDITED->CLOSED

# 运营端能做的是**干预**（强制归还 / 免单 / 补偿），那张表是 ORDER_INTERVENTIONS，
